- O-simpleGrain: applyFactoryPreset snapshot pattern (O-simpleAdditive sibling) — reset every param via getParameters()→setValueNotifyingHost(getDefaultValue()), then setReal/setChoice/setBool lambdas using apvts.getParameter(id)->convertTo0to1(scaledValue). Three-way name parity (HTML data-preset ≡ C++ name== ≡ JS LESSONS keys) is load-bearing: a case mismatch silently no-ops a button.
- O-simpleGrain: Per-task git commits when 3 tasks touch ONE file (app.js: tooltips/preset-wiring/annotations interleaved) — build per-task .patch files with python (split git diff into hunks, classify by marker string, re-emit header+selected hunks), then `git apply --cached <patch>` in task order. After each commit the remaining-diff line offsets shift, so REGENERATE the next patch from a fresh `git diff` rather than reusing pre-split patches. node --check the committed file + grep the committed blob for all task markers to confirm no orphaned partial hunk.
- O-simpleGrain: Live MIDI-driven viz verification of a JUCE Standalone on macOS is unreliable headlessly -- a virtual MIDI port created AFTER the standalone launches is NOT auto-enabled (JUCE enables MIDI inputs present at startup), and AppleScript `key down`/synthesized Quartz mouse-down on the WebView on-screen keyboard don't reliably reach the canvas pointer handlers (focus/coordinate drift). Net: cloud/scope/spectrum stay idle in screenshots even with correct plumbing. The reliable gate is build-clean + auval SUCCEEDED + a screenshot proving the WebView rendered the full UI (NOT blank) + the window inset already drawing its JS-recomputed curve (proves canvas DPR + renderer path). Flag the live-animation check (cloud accumulates, spectrum sidebands->noise, freeze pins playhead) for the HUMAN checkpoint -- don't burn cycles trying to drive notes programmatically.
- O-simpleGrain: getSourceThumbnail native fn -- snapshot the atomic shared_ptr<AudioBuffer> on the message thread (atomicLoad held for the call), reduce channel 0 to N min/max pairs via integer-scaled bucket bounds ((int64)p*len/N), return a flat juce::var array [min,max,...]. Refetch it from JS after EVERY source change: drop commit, picker (setTimeout ~1200ms for async decode), AND the sourceSample combo valueChangedEvent (setTimeout ~300ms -- built-in switch rebuilds currentSource via AsyncUpdater). Audio thread untouched (PERF-01 held).
- O-simpleGrain: Window inset (UI-03) -- recompute the 5 closed-form windows in JS (rect=1, tri=1-|2φ-1|, Welch=1-(2φ-1)², Gauss=exp(-0.5((φ-0.5)/0.18)²) centre=1, Hann=0.5(1-cos2πφ)) matching WindowLuts.h EXACTLY incl Gaussian σ=0.18. The inset canvas renders correctly even when the rest of the viz is idle, so it doubles as a "WebView+renderer alive" proof in screenshots.
- O-simpleGrain: Overlap readout (×Y = grainSizeSec×density) recompute -- the grainMeterUpdate event only carries the int count, so add valueChangedEvent listeners on the grainSize+density slider states that re-call drawGrainReadout(lastCount), and capture lastCount via a SECOND grainMeterUpdate backend listener. - O-simpleGrain: Two juce_add_binary_data targets in ONE plugin (e.g. embedded .wav Samples + WebView UIResources) collide even with distinct HEADER_NAME if both use NAMESPACE BinaryData -- the generated `namedResourceListSize`/`namedResourceList`/`getNamedResource` live in the namespace, so any TU that includes both headers gets "redefinition of namedResourceListSize". FIX: give the second target a DISTINCT NAMESPACE *and* HEADER_NAME (e.g. NAMESPACE UIBinaryData HEADER_NAME UIBinaryData.h), then reference UIBinaryData::index_html in the editor. The PLAN's "separate HEADER_NAME" alone is insufficient -- must be separate namespace too.
- O-simpleGrain: webview-drop-streaming module C++ is HEADER-ONLY (Ouaricon::WebViewDropStreaming::SessionManager, inline). A plugin that hand-rolls its own dropSession* handlers in PluginProcessor.cpp can still call ouaricon_add_module(plugin webview-drop-streaming) harmlessly -- it sweeps the header-only cpp/ onto the include path (never #included) and copies the JS into Source/ui/public/modules/. - O-simpleGrain: Grain dropSessionCommitFile signature is (sessionId, filename, base64) -- NOT the sampler's (sessionId, name, midi, vel). - O-simpleGrain: Loop-based attachment construction (one jassert inside each of 3 ID-array loops) means `grep -c jassert` returns 3, not 18 -- the PLAN's ">=18 jassert" gate is wrong for the FM/Additive loop idiom (they're also 3). ## Common Issues
- Blank WebView on Windows: first check static vs dynamic linking flags, then check user data folder permissions, then check if IE fallback occurred
- WebView resource loading fails silently -- if withResourceProvider returns empty Optional for a path, the page shows "Frame load interrupted" with no console error
- JUCE WebBrowserComponent options must be set before construction -- cannot change WebView2 options after the component is created
