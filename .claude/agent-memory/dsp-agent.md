# DSP Agent Memory

## Learned Patterns
- O-Prism: Wavetable mipmap anti-aliasing (FFT -> zero high bins -> IFFT per octave level) is the industry standard approach used by Serum/Vital/Surge -- always prefer over runtime oversampling for polyphonic synths due to CPU scaling with voice count
- O-Prism: JUCE 8 StateVariableTPTFilter only supports LP/BP/HP natively; notch filter = LP output + HP output from the same SVF state (not a separate mode)
- O-Prism: For 24dB filter slopes, cascade two StateVariableTPTFilter instances; apply resonance to first stage only to prevent excessive resonance buildup and self-oscillation
- O-Prism: polyBLEP is near-zero-cost anti-aliasing for classic waveforms (saw/square/triangle) -- preferred for sub oscillators and CPU-constrained contexts
- O-Prism: For synthesizers, always set IS_SYNTH TRUE + NEEDS_MIDI_INPUT TRUE in CMakeLists.txt -- omitting causes silent plugin in DAW (host won't route MIDI)
- O-Prism: Wavetable memory is significant (~20MB per table with float mipmaps at 2048 samples/frame); use lazy loading for large factory libraries
- O-Texture: ANIRA builds as shared library (libanira.dylib) + pulls ONNX Runtime (libonnxruntime.dylib) -- must embed both in plugin bundle Contents/Frameworks/ with rpath @loader_path/../Frameworks and fix anira's own onnxruntime reference via install_name_tool
- General: JUCE 8 getLatencySamples() is NOT virtual -- cannot override. Use setLatencySamples(N) in prepareToPlay() to report latency; the non-virtual getter returns the stored value
- General: Audio clicks come from signal discontinuities (abrupt level changes) -- even stopping at zero crossing can click if the derivative is discontinuous. Always use fade-in/fade-out ramps (5-20ms) for voice start/stop
- General: FFT overlap-add requires COLA-compliant windows (e.g., Hann with 50% overlap) -- non-COLA windows cause periodic clicking at frame boundaries
- General: Parameter changes in processBlock must be smoothed (juce::SmoothedValue or linear interpolation per sample) to prevent zipper noise -- never apply raw parameter values directly to gain/frequency

- O-Gain: For LUFS 400ms overlapping blocks with 100ms hop, use 4 sub-block accumulators (ring buffer of 100ms power sums) and combine all 4 for each 400ms block -- avoids storing raw sample history
- O-Gain: juce::dsp::IIR::Coefficients<double> constructor takes (b0, b1, b2, a0, a1, a2) -- assign via ReferenceCountedObjectPtr to filter.coefficients (not dereference assignment)
- O-Gain: BS.1770 K-weight filter coefficients are ONLY published for 48kHz -- must pre-calculate for 44100/88200/96000 via bilinear transform from analog prototype
- O-Gain: EBU R128 dual-gate runs in power domain: absolute gate threshold = 10^((-70+0.691)/10), relative gate = absoluteGatedMeanPower * 0.1 (which is -10 LU in power)
- O-Gain: BallisticsFilter uses processSample(channel, value) for per-sample processing -- channel index is always 0 when using separate L/R filter instances

- O-Formant: Mipmapped glottal wavetable reuses O-Prism WavetableData/Generator pattern -- replace "frame" axis with "Rd step" axis, bilinear instead of trilinear interpolation (2 Rd x 2 mipmap levels instead of 2 frame x 2 mipmap x 2 sample)
- O-Formant: LF model Newton-Raphson solver for alpha benefits from numerical derivative (finite difference da=0.01) over analytical derivative -- the closed-form df/dalpha is complex and error-prone; numerical approach converges reliably in <50 iterations for all Rd values
- O-Formant: MPESynthesiserVoice::getCurrentlyPlayingNote() returns struct by value -- hoist out of per-sample loop since pitchbend state is constant within a single renderNextBlock call
- O-Formant: juce::dsp::IIR::ArrayCoefficients::makeBandPass returns std::array<float,6> with layout [b0,b1,b2,a0(=1),a1,a2] -- a0 is always 1.0 (pre-normalized)

- O-Bowed: Body resonator normalization: precompute linear gain sums per preset, interpolate sums alongside morph, divide by morphed sum to keep level consistent across material morphs
- O-Bowed: makePeakFilter gainFactor is LINEAR not dB -- always wrap in Decibels::decibelsToGain() before passing; forgetting this causes massive over-boost (e.g., 12.0 linear vs 3.98 from +12dB)
- O-Bowed: Allpass decorrelator for stereo width from mono: single IIR allpass on R channel creates frequency-dependent phase offset; M/S width=0 collapses perfectly to mono (no cancellation)

- O-Reed: Strategy C conical bore (spherical wave scaling) is cheaper than Strategy B (correction filter) -- 2 multiplications vs 4-5 filter ops per sample; round-trip scaling product = 1.0 always (energy neutral)
- O-Reed: One-sample delay in waveguide naturally decouples implicit reed-bore equation -- no Newton-Raphson needed; pop-before-push with previous sample's p_bore_minus makes junction fully explicit
- O-Reed: IIR::Filter default constructor initializes with passthrough Coefficients(1,0,1,0) with capacity>=8 -- subsequent *filter.coefficients = Coefficients(...) copies in-place without allocation (safe for audio thread)
- O-Reed: Physical Z_c values are huge (~2.67e6 for clarinet bore) -- normalize radiated output by reference impedance before applying output gain + tanh safety clip
- O-Reed: Separating processSample to return u_reed (flow) instead of p_bore_plus (wave) enables inserting mouthpiece chamber between reed and bore without changing reed physics
- O-Reed: Mouthpiece chamber symplectic Euler needs initializeState(p_mouth) on activation to prevent transient click from zero-state discontinuity -- smooth param detection with 20ms time constant

- O-Wind: Per-voice oversampling with feedback loops: upsample zeros to get block structure, run ENTIRE feedback loop at 2x rate inside oversampled loop, downsample output. Cannot partially oversample a feedback system.
- O-Wind: For jet-drive waveguide, one-sample feedback delay is natural (jet delay provides temporal separation) -- no iterative solver needed unlike bow-string friction junction
- O-Wind: SmoothedValue reset() must use internal oversampled rate when called per-oversampled-sample; otherwise ramp duration is 2x too long

- O-Bowed: MPESynthesiserVoice migration: remove canPlaySound/startNote/stopNote/pitchWheelMoved/controllerMoved, add noteStarted/noteStopped(bool)/notePitchbendChanged/notePressureChanged/noteTimbreChanged/noteKeyStateChanged. MPE has no Sound concept (remove addSound).
- O-Bowed: MPESynthesiser voice API differences: isActive() not isVoiceActive(), getVoice() returns MPESynthesiserVoice* not SynthesiserVoice*, enableLegacyMode(2) for standard MIDI keyboard compat
- O-Bowed: Per-voice oversampling block pattern: clear voiceBuffer -> AudioBlock -> getSubBlock(0, numSamples) -> processSamplesUp -> per-sample loop on oversampledBlock -> processSamplesDown -> mix to output. Prepare waveguide/bow/friction at sampleRate*2.
- O-Bowed: MPE pitch bend + TuningEngine: compute tuningEngine->getFrequency(midiNote) THEN multiply by pow(2, totalPitchbendInSemitones/12) -- never use MPE's pre-computed 12-TET frequency

- O-Contrabass: Single-rail waveguide bass adaptation (vs O-Bowed's split-rail): incoming sample IS v_string at bow contact; sign-inversion (-x) into bridge LP provides the rigid-bridge boundary reflection -- no separate nut/bridge delays needed for Phase 2.1
- O-Contrabass: In-loop algebraic saturator x/sqrt(1+x²) is cheaper than 4·tanh(x/4) and asymptotes to ±1 cleanly -- preferred for waveguide loop-gain runaway prevention when DC blocker is also in-loop
- O-Contrabass: Constant -1e-20 denormal leak added to bridge filter recurrence is more robust than post-flush (|out|<1e-15→0) -- prevents subnormals from forming rather than flushing after the fact; disable in drone mode (INFINITE_SUSTAIN >= 0.95) so leak doesn't bleed sustained energy
- O-Contrabass: Quadratic loop-gain skew g = 0.997 + 0.00295·x² puts perceptually-rich T60>6s region in upper half of knob; linear skew wastes 99.3% of knob travel
- O-Contrabass: getOversamplingLatency() exposed as voice method (not processor) — processor reads via dynamic_cast<VoiceType*>(synth.getVoice(0)) in prepareToPlay then setLatencySamples(ceil(...)). Forward-compatible with multi-voice (each voice has its own oversampler)

## Common Issues
- WebSearch returns outdated JUCE 6/7 docs; always verify JUCE API by reading local source at /Users/taylorbrook/JUCE/modules/
- Bilinear transform introduces frequency warping near Nyquist -- biquad EQ filters sound compressed at high frequencies without cramping compensation
- Buffer boundary clicks: state variables (filter history, oscillator phase) must persist between processBlock calls -- reinitializing per buffer causes clicks

- O-Bowed: Split waveguide junction (readJunction/writeJunction) enables external friction dispatch without duplicating delay-line logic -- keep original processSample for backward compat (DroneStringEngine)
- O-Bowed: Elasto-plastic bristle z state needs denormal flush (|z| < 1e-15f -> 0) AND clamp (1.5*z_ba) to prevent runaway in high-force scenarios
- O-Bowed: Thermal friction exp() LUT (256 entries, T_glass to T_max range) is sufficient for smooth interpolation -- precompute in prepare(), zero runtime transcendental cost

- O-Reed: 5-segment bore waveguide with C-style arrays of DelayLine: use brace initializer `segDelay{ {2048}, {2048}, ... }` in constructor init list -- explicit constructor works with direct-init braces in C++17
- O-Reed: Keefe three-port tone hole as stateless real-valued scatter: `scatter = -strength/(1+strength)`, applied as `p_scattered = scatter * (fwd + bwd)`, fwd_out = fwd + p_scattered, bwd_out = bwd + p_scattered -- 3 muls + 3 adds per junction
- O-Reed: Per-sample embouchure modulation via lightweight setEmbouchure() setter avoids recomputing all reed params per sample -- only embouchure field needs updating for vibrato/subtone expression
- O-Reed: Runtime 2x/4x oversampling switching: use two Oversampling instances (factor=1, factor=2), detect param change per-block, re-prepare DSP at new oversampled rate. Avoids realloc per-note; only triggers on user dropdown change.
- O-Reed: Reset oversampling state (activeOS.reset()) on both noteStarted (normal onset) and noteStopped (immediate cutoff) to prevent stale filter state bleeding between notes

- O-MicrotonalSampler: Random-access cubic-Hermite (Catmull-Rom) interpolation must inline JUCE's `CatmullRomTraits::valueAtOffset` Horner expansion locally — `juce::CatmullRomInterpolator` is a stateful streaming processor that cannot express loop-wrap semantics; voices doing fractional-position reads with loop wrap need the inline polynomial + a wrap helper
- O-MicrotonalSampler: For sampler varispeed, the playRate formula is `(desiredFreq / refFreqOfSlotRecordedNote) × (slotSourceSR / hostSR)` — the slot's recorded MIDI note (not the played note) determines the reference frequency, and source/host SR ratio compensates when slots are loaded at non-host rates
- O-MicrotonalSampler: `juce::ADSR::setSampleRate` must be wired in BOTH `prepareToPlay` AND a `setCurrentPlaybackSampleRate` override — JUCE's Synthesiser may reset playback SR via the latter without recalling prepareToPlay, leaving ADSR running at stale rate (causes wrong attack/release times)
- O-MicrotonalSampler: `Ouaricon::NoteExpression::applyPendingTuning(table, midi, freq)` is a free function returning the new frequency (NOT mutating in place) — must assign result back: `currentFrequency = applyPendingTuning(...)` not just call
- O-MicrotonalSampler: Background SampleLoader pattern — `juce::AudioFormatManager` MUST be a local variable inside `run()` (never a member); `juce::LagrangeInterpolator` requires a separate instance per channel for stereo source resampling; completion callback dispatched via `juce::MessageManager::callAsync` so processor mutators run on the message thread; `threadShouldExit()` checked between files for clean cancellation; mono → stereo promotion done at load time (D2-10) keeps voice render path branchless on channel count
- O-MicrotonalSampler: Tolerant filename parser bare-integer fallback rule — bare numbers like `60` parse as MIDI only when no other token in the filename parsed as a scientific-pitch or MIDI-form note (RESEARCH R4); resolves the `12_v2.wav` ambiguity in favor of the named-note convention (dominant in EXS24 / Decent Sampler / Kontakt libraries)
- O-MicrotonalSampler: `juce::AudioBuffer<float>::copyFrom(destCh, destStart, srcBuf, srcCh, srcStart, n)` is the ergonomic mono→stereo duplication pattern — copy ch 0 of source to both ch 0 AND ch 1 of dest; cleaner than manual `getReadPointer`/`getWritePointer` loops and uses JUCE's vectorized memcpy path
- O-MicrotonalSampler: Velocity-layer crossfade geometry — fade region must be at LAYER BOUNDARIES not centers (RESEARCH RQ-7 pseudocode had it inverted). Correct: `innerEdge = halfWidth - velocity_crossfade*halfWidth`, gate `|d| >= innerEdge`, then `x = 0.5 * (|d| - innerEdge) / fw` ∈ [0, 0.5]; `equalPowerWeights(x)` yields `(1, 0)` at inner edge and `(0.707, 0.707)` at the boundary itself. EC-5 (vel=64 with 4 layers + xfade=1 → 0.707/0.707) verifies the fix
- O-MicrotonalSampler: For dual-slot voice render with optional second slot, hoist channel/loop/pointer resolution OUT of the per-sample loop and gate the high-slot read on a `highValid` bool — keeps the inner loop branch-predictable and allocation-free; per-slot EC-4 (end-of-sample hold via `juce::jmin(pos, N-1)`) honoured independently for each cursor
- O-MicrotonalSampler: `std::atomic_load(std::shared_ptr<T>*)` consumer side MUST match producer `std::atomic_store(&slot, newPtr)` under the same `__cpp_lib_atomic_shared_ptr >= 201711L` guard — mismatched (one atomic, one plain) is the TSan-flagged bug; both branches need fallback path for older toolchains
- O-MicrotonalSampler: Voice-steal tail-ramp pattern — pre-allocate per-voice scratch buffers in `prepareToPlay` to `ceil(0.005*sampleRate) + 16` samples (5 ms + safety margin); in `startNote` self-detect via `adsr.isActive() && slotLow != nullptr`, snapshot env via single `adsr.getNextSample()`, fill scratch with OLD-note dual-slot read × linear ramp `(1 - i/N)` BEFORE state reset; `renderNextBlock` mixes additively via `out.addFrom` BEFORE the early-out so EC-1/EC-2 (new-note slot lookup failure) still plays out the captured tail. JUCE's default `findVoiceToSteal` is correct — no override needed
- O-MicrotonalSampler: Steal-tail ramp implementation deliberately duplicates the dual-slot inner read pattern from `renderNextBlock` rather than refactoring into a shared helper — keeps the freshly-verified Phase 2.3 render path bit-identical and untouched. Duplication cost (~30 lines) is small; refactor risk to a verified gate is high. Document the duplication choice in code comments

- O-Contrabass: HR (hard rule) literal-zero short-circuit pattern for bit-exact regression preservation through modulator-layer source edits — when adding new DSP layers atop an existing voice with a frozen golden test bar, gate every new mathematical path behind `if (rawDepth > 0.0f)` AND `if (effective > 0.0f)` AND init all SmoothedValues with `setCurrentAndTargetValue(0.0f)`. IEEE 754 specifies `x + 0.0 == x` and `x * 1.0 == x` exactly for finite x, so the multiplicative-identity arithmetic preserves bit-exactness. Combined with `lastSafeDepth.store(0.0f)` UNCONDITIONALLY before the gate (so harness reads see well-defined values every block) this delivers four hard rules HR-1..HR-4 that keep a 5-golden Phase 2.2 regression bar reproducible after ~+356 LOC of new modulator code lands.
- O-Contrabass: For the Schelleng wedge bow-force limits closed-form (architecture line 492), the bass-register operating point produces NEGATIVE headroom at default settings (F_bow=1.0 < fMin≈6.25 with Z=R=R_s=0.5 dimensionless collapse, β=0.10). This is the same Risk #7 pattern as Phase 2.1c E1 dispersion clamp — paper validity envelope is piano/violin range, not contrabass. Ship the clamp-engaged-at-default behaviour for v1.0 (slow-LFO modulation silenced at default bass; user must dial mid-bow region 2–4 N pressure to hear modulation), park calibration polynomial as Phase 2.4 follow-up, and use `clampedDepthMean > 0` instrumentation hook in harness to confirm the wedge math RUNS even when it produces zero modulation
- O-Contrabass: Autocorrelation pitch tracking at bass register (E1 ≈ 41.2 Hz) needs sub-bin resolution that FFT bin-shift cannot reach at typical 4096-sample windows — autocorrelation with parabolic interpolation around the peak τ delivers ~1¢ precision via `tauPeak = bestTau + 0.5*(y[-1]-y[+1])/(y[-1]-2*y[0]+y[+1])`. Search range τ ∈ [400, 1500] samples at sr=44100 covers ~29–110 Hz. Skip 1 s onset window before analysis to avoid attack-envelope contamination
- O-Contrabass: For modulator + macro evaluation order, lock 7 steps verbatim: (1) read raw APVTS atomics; (2) Schelleng wedge → safeDepth; (3) Slow-LFO phase + sin → mods; (4) apply LFO multiplicatively to bow params; (5) layer macro multiplicatively; (6) push to bowModel + brightness; (7) per-sample loop with active-string-only vibrato. Wedge consumes RAW bow params (not macro-lifted) — macro is performance-lift not safety-lift; downstream defenses (algebraic saturator, energy clamp, loop-gain ceiling) catch instability from macro-extreme settings. - O-Contrabass: Polynomial saturator `out = (1-a)·in + a·(xClamp − xClamp³/3)` with `xClamp = jlimit(-1.5, 1.5, in)` is a true wet/dry mix (a=0 is identity bypass). Cubic `x − x³/3` saturates at ±2/3 ≈ ±0.667 with full input range ±1.5 — output peaks at ±2/3 even with extreme input, perfect for soft-clip pre-limiter. 30 ms SmoothedValue ramp on the wet/dry amount avoids zipper noise on automation
- O-Contrabass: Hand-written feedforward limiter (ARCHITECTURE §527 verbatim): stereo-linked envelope via `max(|L|, |R|)` keeps stereo image intact during clip-down events; `attackCoeff = exp(-1/(0.003·sr))` / `releaseCoeff = exp(-1/(0.050·sr))` for 3 ms / 50 ms ballistics. Per-sample conditional `(absMax > env) ? attackCoeff : releaseCoeff` is the cheapest A/R envelope detector and produces negligible branch-prediction cost in tight loops

- O-ReverseDelay: Reverse-delay impulse response math — a grain engine with read law `readAbs = W0−D−n` re-emits an impulse recorded at T at output times `T+D+2n`, so the bloom support is [T+D, T+D+2G] with the envelope peak at T+D+G (NOT near T+D). Probe/acceptance windows sized [T+D−G, T+D+G] clip the true peak at the boundary — extend to 2G
- O-ReverseDelay: Density/overlap loudness-flatness probes MUST use broadband noise, not a pure sine — grains at one output instant read the capture at fixed 2·interval spacings, and when `2·interval·f/fs` is near-integer (e.g. 220 Hz, fs 48k, interval 1200) the copies sum fully coherently, inflating wet RMS by +4 dB at some densities while other densities sum incoherently. Noise decorrelates the read offsets so powers add and 1/sqrt(overlap) compensation measures flat
- O-ReverseDelay: First-difference click detectors on a mixed dry/wet sine must scale the legit-step bound by the equal-power sum (dryGain+wetGain ≤ √2, plus window-envelope slope) — the raw A·2πf/fs single-sine bound false-positives at mix settings near 50%
