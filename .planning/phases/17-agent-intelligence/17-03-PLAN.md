**research-team-protocol.md** — Detailed protocol for research team spawning:
- When to use parallel research (complexity >= 4, novel DSP, 10+ parameters)
- How domains are determined (from creative brief analysis, NOT a fixed set per locked decision)
- Debate format: Round 1 = independent findings, Round 2 = cross-read + contradiction flagging, Round 3 = synthesis attempt
- Maximum 3 debate rounds (per research recommendation)
- Conflict resolution: if incompatible approaches after 3 rounds, BLOCK planning and present both positions to user (per locked decision)
- Output format: merged research document with synthesis section
- Graceful degradation: if Agent Teams experimental feature fails, fall back to sequential subagent research (each researcher runs as subagent, debate via shared files)

**critic-review-protocol.md** — Detailed protocol for post-stage critic reviews:
- Runs after EVERY stage completion (1, 2, 3, 4) per locked decision — not just at cross-stage boundaries
- Stage-to-critic mapping table (from critic-orchestrator, reproduced here for workflow reference)
- Unified report format: severity-ranked (blocker > warning > note)
- Enforcement rules: blockers PREVENT stage progression, warnings/notes advisory
- Token budget awareness: start with minimal critic sets, expand only when value demonstrated
- Integration with existing run-critic.sh: critic-orchestrator replaces manual critic invocation but uses same underlying critic definitions and schemas

**branching-strategy.md** — Configurable branching modes (AGNT-06):
- Three modes:
  1. `none` (default): All work on current branch, no branch creation. Suitable for single-phase work, quick fixes, solo development.
  2. `phase`: Create branch per phase (`phase/17-agent-intelligence`). Merge to main after phase verification. Suitable for multi-phase milestones, parallel phase work.
  3. `milestone`: Create branch per milestone (`milestone/v1.3`). Merge to main after milestone completion. Suitable for large refactors, experimental work.
- Optional squash merge: when enabled, squashes all commits into a single merge commit. Configurable per mode.
- Configuration: Set in `.planning/workflow/config/branching.json` (or convention doc if no runtime config needed — Claude's Discretion). Format:
  ```json
  { "mode": "none", "squash": false }
  ```
- Branch naming convention: `{mode}/{phase-or-milestone-name}`
- When to use each mode: documented with examples
