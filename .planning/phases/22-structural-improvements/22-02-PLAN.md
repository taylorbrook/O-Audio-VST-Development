<objective>
Build an agent memory write-back mechanism that automatically persists learnings from subagent sessions.

Purpose: Currently, agent memory is read-only at session start (inject-agent-memory.py on SubagentStart). This plan adds the write side -- after a subagent finishes, the hook extracts error patterns, fixes, and key learnings from the session transcript and appends them to the per-agent memory file. This closes the learning loop so agents get smarter over time without manual curation.

Output: New write-back-agent-memory.py hook script, updated settings.json with SubagentStop hook entry.

    Create a new Python script at `.claude/hooks/write-back-agent-memory.py` that runs on SubagentStop and extracts learnings from the completed agent session.

    **Input:** Reads JSON from stdin (same as SubagentStop.py). Expected fields:
    - `agent_type`: string identifying which agent ran (e.g., "dsp-agent", "gui-agent")
    - `agent_transcript_path`: optional string path to the session transcript
    - `tool_results`: optional object/array with tool call results from the session

    **Core logic:**
    1. Parse stdin JSON. Extract `agent_type`. If missing or empty, exit 0 silently.
    2. Determine memory file path: `.claude/agent-memory/{agent_type}.md`. If file does not exist, exit 0 (no memory file for this agent type means write-back is not applicable).
    3. Read the existing memory file content.
    4. Extract learnings from the session. The hook should look for patterns in the `tool_results` or `transcript_content` (if `agent_transcript_path` is provided and readable). Focus on:
       - Error messages followed by successful fixes (error-fix pairs)
       - Build failures and their resolutions
       - Workarounds discovered for platform-specific issues
       - API quirks or gotchas encountered
    5. For each candidate learning, check if it is already present in the existing memory file content (substring match on the key phrase -- e.g., if the learning mentions "getLatencySamples" and the memory file already contains "getLatencySamples", skip it). This is the deduplication step.
    6. If new learnings were found, append them to the `## Learned Patterns` section (before `## Common Issues`). Update the `## Last Updated` line with today's date and "(auto write-back)".
    7. Write the updated file.

    **Pattern extraction strategy (Claude's discretion area):**
    The hook processes the `tool_results` field from the stdin JSON. This contains structured data about what the agent did. Look for:
    - Bash tool calls that returned non-zero exit codes followed by successful retries (error-fix pattern)
    - Grep/Read calls to JUCE source files (indicates API investigation -- the conclusion is the learning)
    - Write/Edit calls that fixed compilation errors

    If `agent_transcript_path` is provided, read that file and look for lines containing patterns like:
    - "ERROR:", "FAILED:", "error:", "warning:" followed by resolution text
    - "The fix is", "The solution is", "The issue was", "Root cause:"
    - Build output with "error:" followed by successful build

    Extract a concise one-line learning from each pattern (max 200 chars). Prefix with the plugin name if available from the JSON input.

    **Safety constraints:**
    - NEVER exit with non-zero code (this is a post-hook, must not block workflow)
    - Wrap entire main() in try/except that catches Exception and exits 0
    - Set a 5-second timeout on any file read operations
    - If the memory file exceeds 10KB after append, skip the write (prevent unbounded growth -- the file will be manually curated)
    - If no learnings are extracted, do nothing (do not touch the file)
