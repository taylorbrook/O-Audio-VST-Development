**Part A: Build coverage matrix.**

Read the resource-index.json (all 49 entries from Plan 01) and cross-reference against the existing plugin list. For each domain in the controlled vocabulary (dsp, ui, architecture, tooling, market-research, ml, spatial-audio, cross-platform), list:
1. Which research docs cover that domain (by filename)
2. Which plugin DSP techniques are well-documented
3. Which plugin techniques have NO corresponding research doc (these are gaps)

Specifically identify gaps by looking at what plugins DO vs what research docs EXIST:
- EQ/filtering (O-AnalogEQ) -- any research doc covering parametric EQ, filter design, biquad cascades?
- Saturation/distortion (O-AnalogSaturation) -- circuit-modeling-fundamentals exists, may be sufficient
- Bass synthesis (O-Bass) -- any bass synthesis research?
- Compression/dynamics (O-Comp, O-MultiBandCompressor) -- any dynamics processing research?

- Vocal/formant synthesis (O-Lyrica) -- any formant/vocal synthesis research?
- Tremolo/modulation (O-Tremolo) -- any tremolo/amplitude modulation research?
- Chorus/modulation (O-Chorus) -- any chorus algorithm research?
- Licensing/distribution (tache_plugins) -- any licensing integration research?

Also check for domains with thin coverage (only 1 doc) vs deep coverage (3+ docs).

**Part B: Flag stale documents.**

Scan each of the 49 research doc contents for the deprecated API patterns listed in the interfaces section above. This is a deterministic check -- search for specific strings/patterns, not subjective content analysis.

For any doc that contains deprecated patterns:
1. Add `status: stale` to its YAML frontmatter (add field, do not replace existing frontmatter)
2. Add `stale_reason: "References deprecated API: {pattern}"` to frontmatter
3. Record in coverage-audit.md which docs are flagged

**Part C: Write research/coverage-audit.md.**

Create a standalone document with frontmatter (title, created, domain: tooling, type: research, keywords) containing:
1. Domain Coverage Matrix -- table showing each domain, doc count, doc list
2. Plugin Technique Coverage -- which techniques are documented vs gaps
3. Identified Gaps -- numbered list of specific topics that need new research docs
4. Stale Documents -- list of docs flagged with `status: stale` and why
5. Gap Priority -- suggested priority based on how many existing plugins use the technique

This is a living reference document, not a one-time report.
