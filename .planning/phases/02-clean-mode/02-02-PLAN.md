**HarmonicGenerator.h:**
- Enum Mode { LowLatency, HighFidelity } matching CrossoverFilter
- prepare(const juce::dsp::ProcessSpec& spec), reset() lifecycle

**HarmonicGenerator.cpp:**

1. **Chebyshev polynomials (inline helpers):**
```cpp
inline float T2(float x) { return 2.0f*x*x - 1.0f; }
inline float T3(float x) { return 4.0f*x*x*x - 3.0f*x; }
inline float T4(float x) { return 8.0f*x*x*x*x - 8.0f*x*x + 1.0f; }
inline float T5(float x) { return 16.0f*x*x*x*x*x - 20.0f*x*x*x + 5.0f*x; }
```

2. **Dual oversamplers (like CrossoverFilter pattern):**
- oversamplerIIR: filterHalfBandPolyphaseIIR, factor 2 (4x), useIntegerLatency
- oversamplerFIR: filterHalfBandFIREquiripple, factor 2 (4x), useIntegerLatency
- Both for 1 channel (mono bass processing)

3. **Output bandpass filter:**
- juce::dsp::IIR::Filter with bandpass 60-400Hz
- Limits harmonic output to psychoacoustically useful range
- Use juce::dsp::IIR::Coefficients::makeBandPass

4. **Process method flow:**
```
a. Get active oversampler based on mode (atomic read)
b. processSamplesUp (upsample to 4x rate)
c. For each oversampled sample:
   - Normalize input to [-1, 1] range (soft clip if needed)
   - Apply Chebyshev: output = w2*T2(x) + w3*T3(x) + w4*T4(x) + w5*T5(x)
   - Keep fundamental minimal or zero (harmonics only)
d. processSamplesDown (downsample back)
e. Apply output bandpass filter
```

5. **Default harmonic weights (from research):**
- h2: 0.7 (warm, octave)
- h3: 0.5 (body, fifth)
- h4: 0.3 (clarity)
- h5: 0.15 (presence)

**Key implementation notes:**
- Use atomic Mode flag like CrossoverFilter for RT-safe switching
- Allocate both oversamplers in prepare(), switch between them atomically
- No allocations in process() - everything pre-allocated
- Report latency from active oversampler

```cpp
void HarmonicGenerator::setAdaptiveHarmonics(float fundamentalHz)
{
    // Lower frequencies need more harmonics for psychoacoustic effect
    if (fundamentalHz < 40.0f)
        activeHarmonicCount = 5;  // Sub-bass: maximum
    else if (fundamentalHz < 80.0f)
        activeHarmonicCount = 4;  // Deep bass
    else if (fundamentalHz < 120.0f)
        activeHarmonicCount = 3;  // Mid-bass
    else
        activeHarmonicCount = 2;  // Upper bass: minimal
}
```

**Update process() to respect activeHarmonicCount:**
- Only apply T2..Tn where n <= activeHarmonicCount
- Zero out higher harmonics when count is reduced

This allows CleanModeProcessor to call setAdaptiveHarmonics() with the detected pitch before each process block, giving frequency-aware enhancement.
