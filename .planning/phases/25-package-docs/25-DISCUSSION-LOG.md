## Areas Discussed

### Area 1 — Template granularity

**Question:** Lock template granularity?

**Options presented:**
1. **One omnibus suite (Recommended)** — single `Ouaricon-Microtonal-Suite.dorico_pt` with 8 slots
2. Per-plugin templates — 8 separate `.dorico_pt` files
3. Hybrid — both omnibus + per-plugin

**Selected:** Option 1 — One omnibus suite

**Rationale:** Schema natively supports multi-plugin via `<slots>` in `endpointconfig.xml`; the Ample China sample proves 11-slot multi-plugin templates work. Dorico warns + skips missing-plugin slots rather than failing. Single discoverable entry in `Play → Playback Template`. Lower user friction, lower maintenance surface.

**Locked as D-04.**

---

### Area 2 — Plugin state inclusion

**Question:** Lock plugin state strategy for v1.5?

**Options presented:**
1. **Omit `.pluginstate` (Recommended)** — slot-only; plugins load with factory defaults
2. Author curated states — one-time human Dorico session via `Save Endpoint Configuration`
3. Defer — implement state-less first; promote state-authoring task only if A2 verification fails

**Selected:** Option 1 — Omit `.pluginstate`

**Rationale:** The load-bearing invariant for v1.5 is microtonal routing (expression-map binding), not curated knob positions. Factory `Silence` template demonstrates state-less is supported. Lowest authoring effort, no maintenance debt as plugins evolve, no Dorico-session lock-in. A2 verification (~10 min) gates the assumption inside Plan 25-01 v2 Wave 0.

**Locked as D-05.**

---

### Area 3 — Distribution channel

**Question:** Lock distribution channel?

**Options presented:**
1. **Per-plugin installer bundle (Recommended)** — every plugin's PKG/EXE bundles both files
2. Separate Ouaricon Suite Installer — standalone installer the user runs once
3. Both — per-plugin AND standalone Suite Installer

**Selected:** Option 1 — Per-plugin installer bundle

**Rationale:** Mirrors v1 architecture exactly — minimizes structural change to Plan 25-02. All 8 plugins' installers write the same canonical pair (`.dorico_pt` + `.doricolib`); idempotent overwrite is structurally safe. Users get suite-wide Dorico routing whether they install one Ouaricon plugin or all eight. Avoids friction of a separate installer for single-plugin users.

**Locked as D-10.**
