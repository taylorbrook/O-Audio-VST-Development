Read the existing plugin-execute.md command and add gate invocation at stage start.

**Add gate check section (before stage execution):**

When user invokes `/plugin-execute [plugin] [stage]`:
1. Determine the previous stage (from-stage)
   - 1-foundation: from 0-ideation
   - 2-dsp: from 1-foundation
   - 3-gui: from 2-dsp
   - 4-polish: from 3-gui
2. Invoke run-gate.sh: `.planning/workflow/scripts/run-gate.sh [plugin] [from-stage] [stage]`
3. If gate returns:
   - 0 (PASSED): Proceed with stage execution
   - 1 (BLOCKED): Stop with message "Gate blocked. Fix issues or use --force."
   - 2 (BYPASSED): Log warning and proceed

**Add --force flag:**
- Pass through to run-gate.sh
- Document that --force requires justification

**Preserve existing functionality:**
- Keep all existing stage execution logic
- Gate check is a pre-condition, not a replacement

**Example usage section update:**
```
/plugin-execute O-IntonationPad 2-dsp
# Runs gate check for 1-foundation -> 2-dsp, then executes stage 2

/plugin-execute O-IntonationPad 2-dsp --force
# Bypasses gate (with justification) and executes stage 2
```
