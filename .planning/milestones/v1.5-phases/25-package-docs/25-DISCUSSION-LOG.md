## Areas Discussed

### Area 1 — Distribution: how does the .doricolib reach Dorico?

**Question:** How does the .doricolib reach Dorico after install?

**Options presented:**
1. **Verify auto-discovery first (Recommended)** — v3 Wave 0 retests auto-discovery from `Expression Maps/User/` on Dorico restart; ship there if PASS, fall back to explicit-import if FAIL.
2. Ship + auto-discovery, no fallback — drop into `Expression Maps/User/`; trust auto-discovery; risk dead file if it doesn't work.
3. Ship + require explicit one-time import — Ouaricon shared path only; README directs `Library → Library Manager → Import…`; deterministic, worst UX.
4. Dual-write to both — belt-and-braces.

**Selected:** Option 3 — Ship + require explicit one-time import.

**Rationale:** Most deterministic plumbing. No Dorico-side scan-behavior dependency. One-time manual import per machine is documented and easily understood. Auto-discovery is a v1.6 polish candidate, not a v1.5 blocker. Plan 25-02 v3's installer surface dramatically simplifies (one `[Files]` entry per platform per plugin, no Pascal `[Code]` for Dorico-version detection or `Default Library Additions` directory creation).

**Locked as D-01 + D-07.**

**Carry-forward:** v3 Wave 0 still includes an *informational-only* auto-discovery sanity check; result feeds v1.6 deferred-ideas with concrete evidence but does not affect v3 ship behavior.

### Area 2 — `<pluginNames>` auto-suggestion

**Question:** Should the .doricolib's `<pluginNames>` array be populated for auto-suggestion?

**Options presented:**
1. **Ship populated, verify schema first (Recommended)** — Wave 0 schema verification + 8 plugin names; auto-suggest in Endpoints dropdown.
2. Skip — manual dropdown is fine.
3. Conditional: ship if schema verifies cheaply (~30 min time-box), else skip.

**Selected:** Option 2 — Skip.

**Rationale:** Schema verification cost not paid this milestone. Manual dropdown selection is acceptable for v1.5. Side-effect: shipped asset is CID-free (no `<pluginNames>` + no Path A `<endpointconfig>` = no plugin GUID references in shipped XML). Dev/prod build flavors ship byte-identical content. The dev/prod CID divergence problem v2 solved with `ouaricon_extract_vst3_cids` is moot under Path B — that helper becomes dead code (D-10 deletes it).

**Locked as D-02.**
