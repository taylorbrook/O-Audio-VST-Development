## Milestone Summary

**Decimal Phases:** None.

**Key Decisions:**

- Adopted `/improve [PluginName]` workflow as the single propagation mechanism for Phase 24 — no direct source edits across 7 production plugins. Prevents version drift and enforces tracked changelog/STATUS discipline.
- Module-format split convention: `cpp/` → SharedCode-bound, `cpp/vst3/` → VST3-only, `cpp/au/` → AU-only. Codified in `OuariconModules.cmake` after AU re-link surfaced VST3 SDK symbol leakage.
- Path B over Path A in Phase 25 v3: ship single `.doricolib` + one-time Library Manager Import instead of `.dorico_pt` Playback Template with auto-discovery. Empirical validation showed Dorico does not auto-ingest dropped `.doricolib` files; explicit Library Manager Import is the canonical activation flow.
- CID-free `<pluginNames />` element in the canonical `.doricolib` — endpoint-binding deferred to user via Dorico's `Play → Endpoints → Expression Map` dropdown. Avoids dev/prod CID divergence and per-plugin asset variants.
- D-10 amend-forward strategy for Phase 25 v3 cleanup — surgical deletion of Path A artifacts (playback-template/ subtree, `ouaricon_extract_vst3_cids` helper, `.dorico_pt` packing, dual-write logic) preserves git history clarity vs. revert sequence.

**Issues Resolved:**

- AU re-link failure on O-Lyrica after module integration (Plan 23-04 → 23-05): VST3 SDK symbols leaking into AU TU. Fixed via two-TU split + custom-deleter pimpl + dual dispatch slots; reusable `scripts/verify-au-link.sh` AU verification gate.
- Phase 25 v1 `.doricoexpmap` drop into Dorico's `User/` reverted at d2c86c5 — Dorico does not recognize the `.doricoexpmap` extension.
- Phase 25 v2 `.doricolib` recovery (cd2c2c6) was a fragment, not a Dorico-valid library — missing 48-container kScoreLibrary skeleton. Fixed in v3 by reauthoring from HALion Sonic factory skeleton + injecting ExpressionMapDefinition.
- Phase 25 v2 `endpointconfig.xml.in` had hardcoded prod plugin names + dev/prod CID divergence causing silent slot drop on dev installs. Resolved by Path B pivot (no Playback Template, no CID binding).
- Quarter-sharp playback verified end-to-end on Dorico 6 / macOS 26.3.1 / O-Lyrica-dev: build → cmake-install → Library Manager Import → ~269 Hz, no zipper, polyphonic isolation.

**Issues Deferred (UAT carry-forward):**

- BL-01 (Phase 25): Retest Windows installer on a non-admin Windows account with UAC elevation via separate admin credential. Persisted in `.planning/phases/25-package-docs/25-HUMAN-UAT.md`. Reason: D-08 canary ran on single-account dev box where launcher == admin, masking potential `{userappdata}` divergence under elevation.
- DEF-24-01 (Phase 23/24): O-Lyrica `auval -v` exits 255 with APVTS Meta Param Flag invariant violation on parameter ID 1275870432. AU bundle LOADS; runtime hosting PASS. Pre-existing parameter-implementation issue, NOT a note-expression module regression.

**Technical Debt Incurred:**

- Wave 0 v3 auto-discovery probe FAIL logged for v1.6 deferred-ideas per Plan 25-01 D-08 carry-forward — non-blocking, informational. Path B explicit-import flow is the primary supported activation path.
- `endpointconfig.xml` template / `.dorico_pt` Playback Template machinery unbuilt this milestone (deferred per Path B decision); usable foundation if Path A is revisited in v1.6+.

**Future Requirements Acknowledged (FUT-01..06):** Windows VST3 verification of full microtonal pipeline, MTS-ESP for non-Dorico hosts, additional NE types beyond `kTuningTypeID`, cross-block `noteId → voice` map, expanded test matrix (quarter-flat, ¾-sharp, chords with per-note inflections), end-user manuals/quickstarts on sales website. Not in v1.5 scope.
