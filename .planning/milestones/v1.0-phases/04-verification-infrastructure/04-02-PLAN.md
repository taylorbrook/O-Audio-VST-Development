**Scoring Categories (from RESEARCH.md + dsp-agent.md):**

1. **Real-Time Safety (Threshold: 8/10)**
   - Check for violations: `new`, `malloc`, `vector::push_back`, `push_back`, `std::string` in processBlock
   - File I/O in audio thread (fopen, fread, etc.)
   - Locks/mutexes in processBlock (std::mutex, std::lock_guard, juce::ScopedLock)
   - System calls (printf, cout, etc.)
   - Exceptions (throw, try/catch in processBlock)
   - Unbounded loops (while with external condition)
   - Evidence: exact line numbers and code snippets

2. **Buffer Handling (Threshold: 7/10)**
   - Zero-length buffer check: `if (buffer.getNumSamples() == 0) return;`
   - Channel count validation before iteration
   - Sample rate handling in prepareToPlay
   - Buffer preallocation for delay lines, FFT, etc.
   - Evidence: presence/absence of specific patterns

3. **Parameter Integration (Threshold: 6/10)**
   - All parameters from parameter-spec.md accessed in processBlock
   - Atomic reads: `getRawParameterValue()->load()` or equivalent
   - Parameter values affect DSP behavior (not just stored)
   - Smoothing for click-prone parameters
   - Evidence: parameter mapping table (spec -> implementation)

4. **Numerical Stability (Optional, Threshold: 6/10)**
   - ScopedNoDenormals in processBlock
   - DC offset prevention
   - NaN/Inf checks for feedback paths
   - Gain staging considerations

5. **Architecture Alignment (Optional, Threshold: 5/10)**
   - Implementation matches ARCHITECTURE.md design
   - Component usage matches research findings
   - JUCE module usage appropriate

**Fix Suggestion Format (MANDATORY per CONTEXT.md):**
Every issue MUST include:
- What is wrong (specific location)
- Why it matters (impact on audio/stability)
- How to fix it (approach description, NOT code snippet)

**Escalation Criteria:**
- Same issues persist after 3 attempts
- Issue requires architectural change beyond stage scope
- External dependency needed
- Fix suggestion unclear or infeasible

**Report Output:**
- Must conform to critic-dsp-report.schema.json
- Include all required fields
- Include previousIssueIds for no-progress detection
- Include tokenMetrics if provided

Create slash command for on-demand critic invocation:

**Structure:**
```markdown
---
name: plugin-critique
description: Run domain-specific critic on plugin stage outputs
arguments:
  - name: plugin
    description: Plugin name (e.g., O-IntonationPad)
    required: true
  - name: stage
    description: Stage to critique (2-dsp or 3-gui)
    required: true
  - name: attempt
    description: Attempt number (1-3)
    required: false
    default: "1"
---

# Plugin Critique

[Command instructions]
```

**Workflow:**
1. Validate arguments (plugin exists, stage is 2-dsp or 3-gui)
2. Determine applicable critic from stage
3. Load relevant files for the stage:
   - Stage 2: PluginProcessor.{h,cpp}, parameter-spec.md, ARCHITECTURE.md
   - Stage 3: PluginEditor.{h,cpp}, ui/ directory, parameter-spec.md
4. Load critic template from `.claude/critics/critic-{dsp|ui}.md`
5. Apply critic rules to code, generate scores for each category
6. Generate report conforming to schema
7. If any score < threshold: NEEDS_FIXES with nextAction: fix_and_resubmit
8. If all scores >= threshold: PASSED with nextAction: gate_pass
9. Run `run-critic.sh` to handle iteration tracking and file persistence

**Integration with run-critic.sh:**
- Command calls run-critic.sh with appropriate arguments
- Passes --attempt flag for iteration tracking
- run-critic.sh handles no-progress detection and failure persistence

**Output format:**
Display structured summary:
```
Critic: dsp-critic
Plugin: [name]
Stage: 2-dsp
Attempt: 1/3

Scores:
  realtime_safety: 9/10 (threshold: 8) PASSED
  buffer_handling: 7/10 (threshold: 7) PASSED
  parameter_integration: 4/10 (threshold: 6) FAILED

Issues:
  DSP-001 [error] parameter_integration
    Location: PluginProcessor.cpp:87
    Description: 'resonance' parameter not read in processBlock
    Fix: Add resonance readout and apply to filter Q

Overall: NEEDS_FIXES
Next Action: Fix issues and run /plugin-critique [plugin] 2-dsp --attempt 2
```

**Auto vs Manual invocation:**
- Manual: User calls `/plugin-critique O-IntonationPad 2-dsp`
- Gate: stage-transition-gate.sh can invoke run-critic.sh (Phase 5 integration)
- Both paths use same critic templates and report format
