  <name>Task 1: Create semver parsing and comparison utility</name>
  <files>modules/scripts/semver.py</files>
  <action>
Create semver.py with complete semver implementation based on npm/node-semver semantics.

Functions to implement:

1. parse_version(v: str) -> tuple:
   - Parse "major.minor.patch" or "major.minor.patch-prerelease"
   - Return (major: int, minor: int, patch: int, prerelease: str | None)
   - Raise ValueError on invalid format

2. compare_versions(v1: str, v2: str) -> int:
   - Returns -1 if v1 < v2
   - Returns 0 if v1 == v2
   - Returns 1 if v1 > v2
   - Prerelease handling: 1.0.0 > 1.0.0-alpha (release beats prerelease)

3. is_major_update(old: str, new: str) -> bool:
   - Returns True if new.major > old.major
   - Breaking change indicator

4. is_compatible(installed: str, available: str) -> bool:
   - Returns True if available is higher version
   - Used to check if update is available

5. satisfies_range(version: str, range_spec: str) -> bool:
   - Caret (^1.2.0): Allow minor/patch updates within same major
   - Tilde (~1.2.0): Allow only patch updates within same minor
   - Exact: Exact match required

CLI interface:
```
# Compare two versions
python3 semver.py compare 1.0.0 1.2.0
# Output: -1 (first is older)

# Check if update is major
python3 semver.py is-major 1.0.0 2.0.0
# Output: true

# Check range satisfaction
python3 semver.py satisfies 1.2.3 "^1.0.0"
# Output: true
```

Reference: 07-RESEARCH.md has the complete implementation pattern.

Create check-customizations.py that detects if a plugin has modified a module.

Workflow:
1. Accept plugin name and module name as arguments
2. Load registry.json
3. Find the InstalledModule entry for this plugin/module
4. Compute current content hash of installed files
5. Compare with originalHash stored at install time
6. Report result

CLI interface:
```
# Check single module
python3 check-customizations.py O-IntonationPad scala-tuning-engine

# Output if not modified:
scala-tuning-engine: clean
Hash: sha256:a1b2c3d4e5f6g7h8

# Output if modified:
scala-tuning-engine: MODIFIED
Original: sha256:a1b2c3d4e5f6g7h8
Current:  sha256:x9y8z7w6v5u4t3s2

Modified files detected. Run /module:upgrade with care.
```

Exit codes:
- 0: Module is clean (no modifications)
- 1: Module has been modified
- 2: Error (module not found, etc.)

## Updated Workflow (from CONTEXT.md and RESEARCH.md)

1. **Check for updates**
   - Compare module version in registry vs installed version in each plugin
   - Use semver.py for version comparison
   - List all plugins using this module

2. **For each dependent plugin** (per-plugin choice per user decision):

   a. **Check for customizations**
      - Run check-customizations.py
      - Compare current hash to originalHash

   b. **If modified:**
      - Show warning: "Local customizations detected in {plugin}"
      - Show options:
        - Keep local: Skip this plugin
        - Update (lose customizations): Proceed with overwrite
        - Diff view: Show what files differ (future enhancement)
      - User decision: "Warn on local customizations, give choice to keep or overwrite"

   c. **If not modified:**
      - Show changelog since installed version
      - Ask: "Update {plugin}? [y/n]"

   d. **If major version update:**
      - Show prominent warning: "BREAKING CHANGE: Major version update"
      - List known breaking changes from changelog
      - Require explicit confirmation

3. **Apply update** (if confirmed):
   - Store rollback: Copy current files to .planning/workflow/rollback/{plugin}/{module}/
   - Copy new module files
   - Update InstalledModule entry:
     - version: new version
     - updatedAt: current timestamp
     - contentHash: new hash
     - originalHash: new hash (reset on update)
     - modified: false
   - Trigger rebuild: ninja {plugin}_VST3 {plugin}_AU

4. **On build failure:**
   - Offer rollback: "Build failed. Rollback to previous version? [y/n]"
   - If rollback: restore files from rollback directory, revert registry
   - User decision: "Offer rollback if update causes build failure"

5. **Report result**
   - Show each plugin's status (updated, skipped, failed)
   - Show next steps for any failed plugins
