  <name>Task 2: Create stage-transition-gate.sh gate check script</name>
  <files>.planning/workflow/scripts/stage-transition-gate.sh</files>
  <action>
Create bash script that gates stage transitions on handoff validity.

Script behavior (from RESEARCH.md):
1. Accept 3 arguments: PLUGIN, FROM_STAGE, TO_STAGE
2. Construct handoff path: plugins/${PLUGIN}/.planning/stages/${FROM_STAGE}/HANDOFF.json
3. Check handoff file exists:
   - If missing: "GATE BLOCKED: No handoff document for stage ${FROM_STAGE}"
   - Provide help: "Create handoff with: /plugin-handoff ${PLUGIN} ${FROM_STAGE}"
   - Exit 1
4. Call validate-handoff.sh on the handoff file:
   - If validation fails: "GATE BLOCKED: Handoff validation failed", exit 1
5. Verify receiving stage matches:
   - Extract .contextForNextStage.receivingStage from handoff
   - If doesn't match TO_STAGE: "GATE BLOCKED: Handoff targets ${DECLARED_NEXT}, not ${TO_STAGE}", exit 1
6. All checks pass: "GATE PASSED: Transition ${FROM_STAGE} -> ${TO_STAGE} approved", exit 0

Make script executable.

Integration note: This script will be called by stage transition commands (Phase 5 quality gates will use this).
  </action>

<task type="auto">
  <name>Task 3: Create /plugin-handoff slash command</name>
  <files>.claude/commands/plugin-handoff.md</files>
  <action>
Create slash command for agents to create handoff documents at stage completion.

Command: /plugin-handoff [plugin-name] [stage]

Behavior:
1. Load plugin's STATUS.md and registry entry to get current state
2. Determine target handoff schema based on stage:
   - 0-ideation -> handoff-0-to-1.schema.json
   - 1-foundation -> handoff-1-to-2.schema.json
   - 2-dsp -> handoff-2-to-3.schema.json
   - 3-gui -> handoff-3-to-4.schema.json
3. Gather information for handoff:
   - Read stage's CONTEXT.md, PLAN.md, SUMMARY.md
   - Extract key decisions made during stage
   - List artifacts created (source files, config files)
4. Create HANDOFF.json in plugins/[plugin]/.planning/stages/[stage]/
5. Populate fields:
   - $schema: relative path to schema
   - schemaVersion: "1.0.0"
   - plugin: plugin name
   - timestamp: current ISO 8601 datetime
   - summary: one-sentence stage completion summary
   - stateSnapshot: current stage/phase, stage-specific fields
   - artifacts.required: list of created files with exists: true
   - artifacts.validation: allRequiredPresent, checkedAt
   - decisions: array of DecisionEntry objects from stage
   - contextForNextStage: receivingStage, keyInformation, continueCommand
6. Validate created handoff with validate-handoff.sh
7. If validation passes: append decisions to plugin's DECISIONS.md (central log per CONTEXT.md)
8. Output: path to created handoff + next step command

Example continueCommand: "/plugin-execute O-IntonationPad 2-dsp"
  </action>
