  <name>Task 1: Create gate-report.schema.json</name>
  <files>.planning/workflow/schemas/gate-report.schema.json</files>
  <action>
Create JSON Schema (draft 2020-12) for gate execution reports. Use the schema from 05-RESEARCH.md as the foundation but ensure it matches project conventions:

Required fields:
- gate: string pattern "^gate-[0-9]+-to-[0-9]+$"
- plugin: string (plugin name)
- fromStage, toStage: string (stage names)
- timestamp: string format date-time
- checks: object with critical[] and advisory[] arrays
- overallStatus: enum ["PASSED", "BLOCKED", "BYPASSED"]

Each CheckResult in the arrays:
- name: string (check name)
- status: enum ["passed", "failed", "skipped", "timeout"]
- duration: integer (milliseconds)
- attempts: integer 1-3 (retry count)
- output: string (optional, stdout capture)
- error: string (optional, error message)

Optional fields:
- totalDuration: integer (milliseconds)
- bypass: object with used, justification, failedChecks
- review: object with status, notes, skipped, skipJustification

Use additionalProperties: false for strict validation.
Place $defs at end of schema (not definitions).
  </action>

<task type="auto">
  <name>Task 2: Create run-gate.sh unified gate script</name>
  <files>.planning/workflow/scripts/run-gate.sh</files>
  <action>
Create bash script that orchestrates all quality checks for stage transitions. Implementation details from CONTEXT.md and RESEARCH.md:

**Arguments:**
- Usage: run-gate.sh [plugin] [from-stage] [to-stage] [--force] [--skip-review]
- Exit codes: 0=PASSED, 1=BLOCKED, 2=BYPASSED, 3=USAGE_ERROR

**Critical checks (all must pass to proceed):**
1. Schema validation (invoke validate-handoff.sh)
2. Build (ninja [Plugin]_VST3 [Plugin]_AU)
3. Pluginval (strictness 10 on VST3)
4. DSP critic (critical at stage 2+, invoke run-critic.sh)
5. UI critic (critical at stage 3+, invoke run-critic.sh)

**Advisory checks (report only, never block):**
- Style, naming, documentation (placeholder echo for now - advisory checks are future work)

**Retry logic (per CONTEXT.md):**
- 1 automatic retry on first failure of any check
- Up to 3 total attempts before requiring --force
- Exponential backoff: 2s, 4s, 8s between retries

**Force bypass (per CONTEXT.md):**
- --force prompts for justification (cannot be empty)
- Log to plugins/[Plugin]/.planning/gate-bypasses.log with timestamp, failed checks, justification, user
- Return exit code 2 (BYPASSED)

**Stage-dependent critic applicability:**
- Stage 0->1: No domain critics (no code yet)
- Stage 1->2: No domain critics (DSP not written yet)
- Stage 2->3: DSP critic is critical
- Stage 3->4: DSP + UI critics are critical

**Output:**
- Display formatted output with pass/fail status per check
- Generate gate-report.json in plugins/[Plugin]/.planning/stages/[from-stage]/
- Code review placeholder at end (actual review handled by run-code-review.sh in plan 05-02)

**Source existing scripts:**
- Source or invoke validate-handoff.sh for handoff validation
- Invoke run-critic.sh for domain critics with appropriate stage argument

Make script executable (chmod +x).
