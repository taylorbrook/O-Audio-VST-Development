<objective>
Implement the PreCompact-to-SessionStart(compact) pipeline so that critical plugin context survives compaction events.

Purpose: The current PreCompact.sh prints contract data to stdout, but PreCompact stdout is NOT injected into post-compaction context (only SessionStart stdout is). This means plugin names, parameter IDs, DSP components, and contract paths are lost after compaction. This plan fixes that by having PreCompact write a snapshot file that SessionStart(compact) reads and outputs to stdout.

Output: Rewritten PreCompact.sh, new PostCompact-SessionStart.sh, updated settings.json with compact handler.
</objective>

2. **Focused plugin detection**: Read `.claude/plugin-registry.json` to find the `focused` plugin name (use python3 for JSON parsing). Fall back to finding in-progress plugins from PLUGINS.md.

- The script's stdout should be EMPTY (no echo to terminal) -- all content goes to the file
- Exit 0 always (PreCompact cannot block compaction)
- Use `2>/dev/null` on file reads to handle missing files gracefully
- Reference the research pattern from 15-RESEARCH.md Pattern 1, Stage 1

IMPORTANT: The compact handler must be the SECOND entry in the SessionStart array (after the general handler). This ensures environment validation runs first, then snapshot injection.
