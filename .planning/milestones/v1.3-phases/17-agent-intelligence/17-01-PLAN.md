Create three files:

**research-lead.md** — Agent definition for the research team orchestrator:
- Frontmatter: `name: research-lead`, `description: Orchestrates parallel research team for plugin planning`, `permissionMode: delegate` (satisfies AGNT-04 — coordination-only, no direct file writes)
- Tools: `Task(dynamic-researcher)`, `Read`, `Bash`, `Grep`, `Glob` (read + coordination only, no Write/Edit per delegate mode)
- Body instructions:
  1. Read creative brief to determine plugin complexity (simple = 2 researchers, complex = 3)
  2. Assign domains dynamically at runtime based on brief content, plugin type, and complexity — NOT a fixed set (per locked decision). Example domains: "DSP algorithm approaches for shimmer reverb", "JUCE API mapping for granular synthesis", "UI/UX patterns for spectrum visualization"
  3. Spawn teammates via Agent Teams with domain-specific prompts
  4. After researchers complete, read all findings and run detect-research-conflicts.py
  5. If no conflicts: merge synthesis into final research output
  6. If conflicts found (incompatible approaches): BLOCK planning and surface both positions to user (per locked decision: conflicts block, not just warn)
  7. Maximum 3 debate rounds between researchers. After 3 rounds without consensus, escalate to user with both positions documented
  8. Plan approval gate: auto-approve low-risk plans (fewer than 5 files, no DSP source changes, no new JUCE module deps, complexity score < 2.0). Complex plans require team lead review. On rejection, teammate revises and resubmits. After 3 rejections, escalate to user (per locked decision for AGNT-03)

**dynamic-researcher.md** — Agent definition for individual researchers:
- Frontmatter: `name: dynamic-researcher`, `description: Performs deep domain research. Domain assigned at spawn time via prompt.`
- Tools: `Read`, `Grep`, `Glob`, `Bash`, `WebSearch`, `WebFetch`, `mcp__context7__resolve-library-id`, `mcp__context7__query-docs` (read-heavy research tools, no Write/Edit)
- Body instructions:
  1. Domain is provided in spawn prompt (not hardcoded)
  2. Produce findings document with: domain name, recommendations list, JUCE modules needed, approach description, confidence level
  3. Read other researchers' findings when available and flag contradictions
  4. If contradictions found, message teammates via mailbox to debate
  5. After debate, produce synthesis section: agreed approach, unresolved items

**detect-research-conflicts.py** — Python utility for deterministic conflict detection:
- Read researcher findings JSON files from a provided directory
- Compare approaches for incompatible pairs (time-domain vs frequency-domain, mono vs stereo, zero-latency vs lookahead, stateless vs stateful)
- Check for JUCE module conflicts (same module requested with incompatible configurations)
- Return JSON: `{ "conflicts": [...], "blocking": true/false }`
- Exit 0 if no blocking conflicts, exit 1 if blocking conflicts found
- Include the contradiction_pairs list from research code examples but extend with audio-domain pairs: (FIR vs IIR for same filter stage), (sample-by-sample vs block-based for same processor), (SIMD required vs scalar only)

**task-validator-dispatch.sh** — Create the TaskCompleted hook dispatch script:
- Read task content from stdin JSON (fields: `task_id`, `task_subject`, `task_description`)
- Combine subject + description into `TASK_CONTENT` for keyword matching
- Skip non-code tasks: if TASK_CONTENT does not match any of `.cpp`, `.h`, `.cmake`, `.html`, `.js`, `.css`, `processBlock`, `prepareToPlay`, `parameter`, `APVTS`, `WebView`, `relay`, `CMakeLists` — exit 0 (per locked decision: only code-touching tasks get validated)
- Detect active plugin from TASK_CONTENT (grep for `O-[A-Za-z]+` pattern) or `$ACTIVE_PLUGIN` env var. If no plugin detected, exit 0
- Keyword-to-validator mapping (per research and locked decisions):
  - `processBlock|prepareToPlay|DSP|audio.processing|dsp.component` → `validate-dsp-components.py` + `validate-silent-failures.py`
  - `parameter|APVTS|createParameterLayout|parameter.spec` → `validate-parameters.py`
  - `WebView|relay|index\.html|binding|GUI|editor` → `validate-gui-bindings.py`
  - `contract|ARCHITECTURE|ROADMAP|BRIEF|cross.contract` → `validate-cross-contract.py`
  - `checksum|STATUS\.md|SHA|integrity` → `validate-checksums.py`
  - `research|resource|frontmatter` → `validate-resource-accountability.py`
- Run only matching validators against `plugins/$PLUGIN_NAME`
- Collect errors. If any validator fails: print errors to stderr and exit 2 (blocks task completion with feedback per AGNT-05)
- If all pass: exit 0
- Set timeout expectation: validators should complete within 10-15 seconds total
- Make script executable (`chmod +x`)
