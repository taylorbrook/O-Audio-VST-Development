    Read the current research-planning-agent.md and add a new section for frontmatter requirements. Add a section (near the top, after any existing output format instructions) titled "Research Document Frontmatter" or integrate into existing output requirements:

    ```markdown
    ## Research Document Frontmatter

    When creating or modifying any document in the `research/` directory, you MUST include valid YAML frontmatter with ALL required fields. Documents without complete frontmatter will be rejected from the resource manifest and will not be discoverable by other agents.

    **Required frontmatter template:**
    ```yaml
    ---
    title: "[Descriptive title of the document]"
    created: YYYY-MM-DD
    last_verified: YYYY-MM-DD
    juce_version: "8.0.4"
    summary: "[2-3 sentence summary sufficient for relevance ranking, 10-500 characters]"
    domain: dsp  # One of: dsp, ui, build, workflow
    type: guide  # One of: algorithm, pattern, guide, reference
    keywords:
      - keyword-one
      - keyword-two
      - keyword-three
    stages: [0, 2]  # Which pipeline stages (0-4) this is relevant to
    agents: [dsp]   # Which agent roles benefit: dsp, ui, build, research
    ---
    ```

    **Field rules:**
    - `created`: Use today's date (YYYY-MM-DD format) for new documents
    - `last_verified`: Use today's date (same as created for new documents)
    - `juce_version`: Use the current JUCE version ("8.0.4")
    - `domain`: This is the document's category (one of: dsp, ui, build, workflow)
    - `keywords`: Minimum 3, maximum 15, lowercase alphanumeric with hyphens only
    - `stages`: At least 1 stage (0=ideation, 1=foundation, 2=dsp, 3=gui, 4=polish)
    - `agents`: At least 1 role (dsp, ui, build, research)

    This frontmatter enables automatic discovery and injection of research resources into agent prompts.
    ```
