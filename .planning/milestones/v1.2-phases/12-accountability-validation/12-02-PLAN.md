  <action>
Modify `.claude/hooks/SubagentStop.sh` to call the accountability validator AFTER the existing stage-specific validation (the `case` block), but BEFORE the final `exit 0`.

Add the following block between the `esac` closing and the final `exit 0`:

```bash
# Resource accountability validation (warning-only, NEVER blocks workflow)
# Phase 12: Validates that agents report consulting MUST-READ injected resources
AGENT_TYPE=$(echo "$INPUT" | jq -r '.agent_type // .subagent_name // empty' 2>/dev/null)
TRANSCRIPT_PATH=$(echo "$INPUT" | jq -r '.agent_transcript_path // empty' 2>/dev/null)

if [ -n "$AGENT_TYPE" ]; then
  python3 .claude/hooks/validators/validate-resource-accountability.py \
    "$AGENT_TYPE" "${PLUGIN_NAME:-}" "${TRANSCRIPT_PATH:-}" 2>&1 >/dev/null | while IFS= read -r line; do
    echo "$line" >&2
  done
  # Intentionally ignore exit code -- accountability NEVER blocks workflow
fi
```

Key implementation details:

1. **Field name robustness:** Try `agent_type` first, then fall back to `subagent_name` (per research doc finding that field names may differ between versions). Use the existing `$SUBAGENT` variable which already extracts `subagent_name`, but also try `agent_type` for the accountability call since it's the newer field name.

2. **Transcript path:** Extract `agent_transcript_path` from the hook input JSON. This is the JSONL file containing the agent's conversation where the JSON report lives.

3. **stderr routing:** The validator's stderr output (warnings) must flow through to the user's terminal for real-time visibility. The `2>&1 >/dev/null` redirects stdout to null (we don't want informational output) and pipes stderr through to our stderr via the `while read` loop.

4. **NEVER blocks:** The exit code from the validator is intentionally ignored. Even if the Python script crashes, the hook continues and exits 0.

5. **Expanded agent matching:** The existing hook only matches `foundation-shell-agent|dsp-agent|gui-agent` for stage-specific validation. The accountability block should NOT be gated by this pattern -- it runs for ANY agent that the validator recognizes (the validator itself has the AGENT_STAGE_MAP and silently skips unknown agents).

6. **Placement:** The accountability block goes AFTER the `esac` (existing validation) and BEFORE the final `exit 0`. Do NOT modify the existing `case` block or the contract integrity validation section.

Also update the SubagentStop.sh header comment to mention accountability validation:
```bash
# SubagentStop hook - Deterministic validation after each subagent completes
# Layer 1 validation: Fast pattern matching (1-3s), blocks workflow on failure
# Layer 2 accountability: Resource usage tracking (warning-only, never blocks)
```

CRITICAL: Do NOT change any existing validation logic. The existing checksum, cross-contract, and stage-specific validators must continue to work exactly as they do now.
