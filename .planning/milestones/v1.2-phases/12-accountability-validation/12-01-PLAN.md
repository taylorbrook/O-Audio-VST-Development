The field definition:

```json
"resources_consulted": {
  "type": "array",
  "items": {
    "type": "object",
    "required": ["path"],

      "path": {
        "type": "string",
```

  <name>Task 2: Create resource accountability validator script</name>
  <files>.claude/hooks/validators/validate-resource-accountability.py</files>
  <action>
Create `.claude/hooks/validators/validate-resource-accountability.py` following the existing validator pattern (see validate-checksums.py for conventions).

The script:

1. **Imports discover-resources.py** via importlib.util (hyphenated filename requires this -- same pattern as inject-context.py):
   ```python
   SCRIPT_DIR = Path(__file__).parent
   HOOKS_DIR = SCRIPT_DIR.parent
   CLAUDE_DIR = HOOKS_DIR.parent
   SCRIPTS_DIR = CLAUDE_DIR / "scripts"
   ```

2. **Defines AGENT_STAGE_MAP** mapping agent names to their canonical pipeline stages:
   ```python
   AGENT_STAGE_MAP = {
       "foundation-shell-agent": 1,
       "dsp-agent": 2,
       "gui-agent": 3,
       "research-planning-agent": 0,
       "polish-agent": 4,
   }
   ```

3. **Main `validate(agent_type, plugin_name, transcript_path)` function:**
   - Look up stage from AGENT_STAGE_MAP. If agent not found, return silently (skip unknown agents).
   - Call `discover(stage=stage, agent_role=agent_type)` to get what SHOULD have been injected.
   - Filter to primary tier only: `[r for r in results if r["tier"] == "primary"]`.
   - If no primary-tier results, return silently (nothing to validate).
   - Parse the transcript JSONL file to find the agent's JSON report and extract `resources_consulted`.
   - Compare: for each MUST-READ resource path, check if it appears in the reported `resources_consulted` paths.
   - For each missing (skipped) MUST-READ resource, emit: `WARNING: {agent_type} did not report consulting MUST-READ resource: {path}` to stderr.
   - If the field is entirely missing from the report (agent did not implement accountability), emit: `WARNING: {agent_type} did not include resources_consulted in report (MUST-READ resources were injected)` to stderr.

4. **Transcript parsing logic:**
   - Read the JSONL transcript file line by line.
   - For each line, try `json.loads()`. Look for lines containing a JSON object that has an `"agent"` key matching the agent_type and a `"resources_consulted"` key (or lack thereof).
   - If the report is embedded in an assistant message, try to extract JSON from the message content. Try multiple strategies: (a) full line is valid JSON with `agent` key, (b) line contains a JSON code block with the report.
   - Gracefully handle: file not found, malformed JSONL, no report found in transcript. On any parse failure, emit a single warning: `WARNING: Could not parse {agent_type} transcript for accountability validation` and return.

5. **CLI entry point:**
   ```python
   if __name__ == "__main__":
       agent_type = sys.argv[1] if len(sys.argv) > 1 else None
       plugin_name = sys.argv[2] if len(sys.argv) > 2 else None
       transcript_path = sys.argv[3] if len(sys.argv) > 3 else None
       if agent_type:
           validate(agent_type, plugin_name, transcript_path)
       sys.exit(0)  # ALWAYS exit 0 -- never block workflow
   ```

6. **CRITICAL constraints:**
   - ALWAYS `sys.exit(0)` -- never exit non-zero. Accountability NEVER blocks workflow.
   - Wrap the entire validate() call in a top-level try/except that catches ALL exceptions, prints a warning, and exits 0.
   - Only MUST-READ (primary tier, score >= 0.75) triggers warnings. Supplementary resources do NOT trigger warnings.
   - Keep execution fast (< 2 seconds) to stay well within the 10-second hook timeout.
   - Do NOT modify inject-context.py or discover-resources.py.

Include a module docstring explaining purpose, the warning-only guarantee, and usage.
