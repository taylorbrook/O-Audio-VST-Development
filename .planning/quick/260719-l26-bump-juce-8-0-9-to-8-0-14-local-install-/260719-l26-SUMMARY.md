## Deviations from Plan

### Deferred Issues (out of scope — NOT fixed)

**1. [Scope boundary] O-TextureForge compile failure — umappp↔irlba dependency skew (JUCE-independent)**
- **Found during:** Task 2 full-suite build.
- **Failing target:** `OuariconTextureForge.dir/Source/dsp/UMAPProjection.cpp.o` (blocks both O-TextureForge_VST3 + O-TextureForge_AU via the shared object).
- **First error:** `no member named 'converged' in 'irlba::Results<...>'` at `umappp/spectral_init.hpp:123`.
- **Root cause:** `plugins/O-TextureForge/CMakeLists.txt` pins `umappp` to v3.2.0, but umappp's transitive `irlba` is fetched by umappp's own CMake (unpinned) and drifted — the resolved irlba removed `Results::converged`.
- **Why out of scope:** `UMAPProjection.cpp → umappp → irlba → Eigen` includes zero JUCE headers; the JUCE version cannot affect this translation unit. It surfaced only because Task 2's mandated fresh `rm -rf build` wiped the previously-cached compatible irlba checkout. Ruled out as an NE re-base defect (no VST3/JUCE code) and as a JUCE break (pure third-party template API mismatch).
- **Action:** Logged to `deferred-items.md` (DEF-L26-01) with a suggested future fix (pin irlba to a umappp-v3.2.0-compatible tag, then regression-test O-TextureForge's UMAP path). Not fixed here — re-pinning risks O-TextureForge's load-bearing UMAP grain selection and is separate from a JUCE bump.

Everything else executed exactly as planned — zero JUCE-attributable fallout, matching the
research (`framework-updates-2026-07.md`) breaking-change grep of zero repo exposure.
