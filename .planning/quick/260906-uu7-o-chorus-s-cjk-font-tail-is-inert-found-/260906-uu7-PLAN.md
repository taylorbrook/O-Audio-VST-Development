O-Chorus's CJK font tail is dead code. Six `font-family` declarations in
`index.html` read

    Garamond, 'Times New Roman', serif, 'PingFang SC', 'Microsoft YaHei', sans-serif

and Chromium resolves a bare `serif` against the DOCUMENT'S LANG — under
`zh-Hans` the generic is already a Chinese face, so the tail after it is never
consulted. Proven on wave 4a's tracer with `CSS.getPlatformFontsForNode`
(`.planning/quick/260904-qrc-*/260904-qrc-SUMMARY.md` section 1): O-Chorus's
Chinese renders **Songti SC**, a serif, not the **PingFang SC** sans its stack
names. Every geometry pin on this page was therefore measured against the wrong
face.

Move the CJK faces before the single trailing generic on all six, drop the
second generic, then RE-MEASURE every pin the change can move and rewrite the
comment that records each measured number. Ship 1.6.3.

Purpose: the page currently looks right on macOS only *because* the generic
happens to supply a CJK face. On a host where it does not, the tail would
finally be reached and every metric on this page would change at once.

Output: index.html with a live tail and re-measured pins, a before/after
measurement pair on file, O-Chorus 1.6.3 built, installed and auval-green.
