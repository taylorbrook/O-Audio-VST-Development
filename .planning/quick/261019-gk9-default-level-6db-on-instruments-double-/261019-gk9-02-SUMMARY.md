# Phase quick-261019-gk9 Plan 02: Family-C instruments Summary

O-Bells, O-Wind and O-Lyrica now apply output level once, as the last smoothed stage (Bells and Wind moved it out of the voice and after the effects), default to -6 dB, and ignore it on every preset load. Every dial, knob-like slider and FX readout opens O-Prism-style value entry on double-click, and Alt/Option-click resets in a single gesture.

`commits: 3` is the count of this plan's own path-scoped commits. The shared checkout interleaves seven other executors' commits, so `rev-list base..HEAD` does not measure this plan. That is why the frontmatter lists SHAs instead of `plan_head_before`/`plan_head_after`.

## Per plugin

### O-Bells 4.9.0 -> 4.9.1 — `aef13533`
- **Output:** `outputGain` default 0.0f -> -6.0f (range -24..+12 unchanged; normalised 0.5). The per-voice multiply (BellVoice.cpp) is gone, along with the `outputGain` argument of `BellVoice::updateParameters`, the `currentOutputGain` member and the processor pass-through. `outputGainSmoothed` (Linear, 20 ms) is seeded in prepareToPlay and applied after the EQ, ahead of the WR-09 soft limiter and NaN net.

- **dblclick sites converted (2 handlers, 34+ controls):** the slider loop (every `.slider` and its `.param-value` readout, footer Gain included), and the FX knobs (dial and readout, 16 knobs). The old Family-C linear `parseFloat` editor was deleted.
- **Alt reset:** the sliders use a capture `mousedown` on the slider. It is registered before the drag listener and calls `stopImmediatePropagation`, which also blocks the footer Gain binding that shares the element. **4. [Rule 2 - Missing default source] O-Wind FX knobs had none**

## Disclosures
- **Migration-pin transient (Wind, Lyrica):** the shared `applyPresetJson` runs migrate, then reset-to-default, then apply. The level is therefore written to its default once inside the apply call before being written back. The 20 ms ramp absorbs a single-block glimpse. User presets saved through the shared header still carry the key, and it is ignored on load. Follow-up: a `setUserOwnedParameters` hook in `modules/persistence/preset-manager` (off-limits here).
- **Gain staging change (Bells, Wind):** at the old 0 dB default, voice-level saturation (the Bells pre-FX soft limiter, the Wind per-voice tanh clip) sees the same signal as before. At any other setting, those stages now see unity gain, and the output trim comes after them and after the effects.

## Verification method
The DSP changes were compiled and installed (all three builds exit=0, auval-listed). Rendered audio was not measured. The UI behaviour was proved with headless functional probes (Playwright plus the generic JUCE stub, run from the scratchpad, not committed). They covered typed values across units (ms/s flip, kHz, %, option names, `-inf`), the skew path, exactly one gesture pair per commit and per Alt reset, untouched Enter and Esc writing nothing, and readout writers staying silent while the entry is open. All passed. The only probe miss was a stub artifact: Lyrica has no params.tsv, so the stub clamps its neutral 0.5 to 400 Hz.
