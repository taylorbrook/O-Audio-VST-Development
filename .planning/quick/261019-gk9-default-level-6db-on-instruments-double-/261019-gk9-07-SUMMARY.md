Parsers, each into the C++ unit:
- **Tremolo:** Speed Hz and Depth 0..100 read directly. Synced Speed matches a division name (`1/8T`, or a bare `8T` meaning `1/8T`).
- **Detune:** Blend uses percent/100. Rate (Hz), ct, ms and the 0..100 % knobs read directly. Synced Rate maps a division name (`1/16T`, `2 bars`, `8`) to its page norm through a norm adapter.
- **DigiDelay:** Time is in ms; an explicit `s` multiplies by 1000. Synced Time is a ComboBoxState adapter over the division names (`1/8D`, `16(5)`). The 0..100 % knobs read directly.
- **simpleReverb:** SIZE, WET, DRY and DECAY read directly. LPFREQ is Hz, with `k` meaning ×1000. CHARACTER (−100..100) takes `dark/bright/neutral` words, built from the LABELS table in en/fr/zh, or a signed number. A bare number keeps the side shown on screen. French decimal commas and U+2212 minus signs are accepted.
- **simpleAmbisonics:** signed degrees, m and Hz read directly. Output dB takes `-inf`/`off`, which maps to the range start.
- **SpectralShaper:** Mix and Sensitivity use percent/100. Attack, Sustain and Lookahead are in ms, with an explicit `s` meaning seconds; per WR-01 the C++ unit is ms. Output is dB, with `-inf`/`off` mapping to the start.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Entry stayed open when another dial was grabbed**
- **Found during:** Task 3 (SpectralShaper), confirmed on the already-committed Tremolo.
- **Issue:** On pages whose drag `preventDefault()`s mousedown and does not focus the dial (Tremolo, Detune, DigiDelay, SpectralShaper), clicking another dial doesn't move focus. The input never blurred, so it stayed open with its readout frozen, and the CHANGELOG's "click away applies" was false. Prism avoids this only because its drag calls `knobEl.focus()`.
- **Fix:** `attachValueEntry` now registers a document capture-phase `pointerdown` that blurs, and so commits, the field. It is removed in `close()`. Applied to all six for consistent behaviour.
- **Commits:** folded into d6795c4c and b5c9b65e. Separate `fix(...)` commits for the four already shipped: 2eda4d38, ec933051, cb2df68b, a7235772. These stay in the same unreleased version; no second bump.

**2. [Rule 2] `scaledToNorm` NaN guard** (simpleReverb and simpleAmbisonics already had their own `scaledToNorm(st, scaled)`): reused it rather than adding a second one, and added `skew > 0 ? skew : 1` so a missing skew cannot NaN the pow.

**3. [Rule 3] SpectralShaper test stub:** `tests/ui-stub/juce-stub.js` rejects unregistered natives by design. It now mirrors `getParameterDefaults`, derived from its own RANGES, and its census comment reads EIGHTEEN.

### Plan-verify mismatch (reported, not hidden)

Task 1 and Task 2 `<verify>` check `git log -1 --format=%s -- plugins/<P>` starts with `improve: <P> v`. For O-Tremolo, O-Detune, O-DigiDelay and O-simpleReverb, the newest commit is now the `fix(<P>): …` click-away follow-up. Each one's `improve: <P> vX.Y.Z` commit is the one before it. I did not rewrite history: `main` is shared with seven live executors, so amending or rebasing was not safe. Every other verify clause passes for all six.
