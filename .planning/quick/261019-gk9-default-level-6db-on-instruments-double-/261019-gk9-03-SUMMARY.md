# Phase quick-261019-gk9 Plan 03: Physical-model instruments + IntonationPad Summary

All four instruments now start at −6 dB with the output as a user-owned last stage. Bowed and Marimba gained a 20 ms linear smoother. Every dial opens the O-Prism typed-value field on double-click and resets on Alt/Option-click inside one host gesture. Each plugin was gated, built and installed under the shared lock, listed by auval, and committed path-scoped.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] Syntax gate false positive on literal `<script>` text inside HTML comments**
- **Found during:** Task 1 (Bowed) and Task 3 (IntonationPad)
- **Issue:** `gk9-gate.js --syntax` matches `<script ...>` inside an HTML comment, then node-checks the comment prose. The baseline failed this way before any edit.
- **Fix:** reworded the two comments ("the module <script> below" -> "the module script tag below"; "inline <script type="module">" -> "inline module script"). These were comment-only changes.
- **Files:** plugins/O-Bowed/Resources/ui/index.html, plugins/O-IntonationPad/Source/ui/public/index.html

**2. [Rule 2 - Correctness] `numOf` accepts U+2212**
- **Issue:** Contrabass's `fmtSigned` readouts (Output, detune) print U+2212. A Prism `numOf` would parse "−6.0 dB" as +6.0 when a user retypes what they see.
- **Fix:** `numOf` maps U+2212 to '-' before matching (Contrabass, Marimba, IntonationPad ports). The `-inf` regex accepts it too, and IntonationPad's also accepts `∞`.

**3. [Rule 2 - Correctness] IntonationPad load pin adds a missing PARAM**
- **Issue:** saved user presets now omit masterVolume. On load, `replaceState` would reset an absent PARAM to its default (0.50).
- **Fix:** `pinUserOwnedParameters()` creates the PARAM with the live value when it is absent.

**4. [Rule 3 - Blocking] No default source in Marimba / IntonationPad**
- **Fix:** added a `getParameterDefaults` native fn to each `PluginEditor.cpp`, as the contract (item 9) prescribes. `PluginEditor.cpp` is in both plugins' `files_modified`.

**5. CHANGELOG heading separator**
- New entries match each file's existing `## [X.Y.Z] - YYYY-MM-DD` hyphen form rather than the plan's em-dash. They are still the bracket form the release-notes extractor needs.

## Disclosures
- **Shared-header pin (Bowed, Contrabass):** each preset apply makes one transient default write to the output param inside the apply call (migrate -> reset -> apply). User presets saved by the shared header still carry the output key, which is ignored on load. Follow-up: a `setUserOwnedParameters` hook in `modules/persistence/preset-manager`.
- **Stale factory files on disk:** Bowed's `initializeFactoryPresets()` returns early if the factory folder already has files, so installed factory JSON still carries `outputLevel` 0.833. The migration pin neutralises it on load. Contrabass and Marimba re-seed by version.
- **Render-harness goldens not re-run (per plan, harnesses not built):** O-Contrabass's `tests/render-harness` has WAV-sha256 goldens rendered at the old 0 dB default `OUTPUT_GAIN`. O-Bowed's `tests/render-harness` has a canonical-preset golden at 0 dB, and its output stage is now ramped. Both will diverge by −6 dB. They need either a harness-side `OUTPUT_GAIN` / `outputLevel` = 0 dB pin or a re-bless. This was not entered into `.planning/WINDOWS.md`, because the plan forbids edits outside the four plugin folders and this SUMMARY.
- **IntonationPad randomizer:** "gentle" and "wild" modes still randomise `masterVolume`; only "soundOnly" preserves it. This is a pre-existing behaviour outside D-01's preset scope, and is a candidate follow-up for user-ownership.
- **Contrabass `PluginEditor.cpp`:** two comments still say "double-click reset" (lines 31 and 126). The file is not in this plan's `files_modified`, so they were left. This is cosmetic only.
