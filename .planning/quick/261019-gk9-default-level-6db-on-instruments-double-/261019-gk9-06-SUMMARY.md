# Phase quick-261019-gk9 Plan 06: Inline-index.html effects A Summary

**Double-clicking any dial in six effects opens an O-Prism-style typed-value field (Enter or blur commits inside one host gesture through the live start/end/skew, Esc cancels, untouched text never writes). Reset-to-default moved to an Alt/Option-click capture listener, gesture-bracketed, bound to the drag's own event type.**

| O-Chorus | 1.10.0 -> **1.10.1** | c76d9760 | 8 knobs (dial + readout, both inside `.knob`) | `pointerdown` capture on `.knob` (the drag `preventDefault`s pointerdown) | `p.def`, Voices through `snapVoicesNorm` |

Parsers, all returning the scaled (C++) value or null:
- **AnalogSaturation:** INTENSITY direct (0..100 %).
- **AnalogEQ:** freq `parseFreq` (`k` = x1000, a bare number is Hz); gain direct dB.
- **Comp:** dB / ratio / knee direct. Attack and release take ms, or `s` x1000. SC HPF/LPF take `parseFreq`, and `off` / `-inf` / the localized Off word map to the range start.
- **Bass:** Frequency `parseFreq`. Enhance direct, because C++ is 0..100 and the readout shows %. Output direct dB.
- **Bitrot:** direct in the readout's units; `hzk` (Crush Rate) uses `parseFreq`.
- **Chorus:** Rate direct Hz; depth/spread/width/mix/drive/tone `parsePercent`; Voices rounds to an integer and clamps to 1..8.

Every readout writer skips while `dataset.editing === '1'`. The input stops propagation of `pointerdown`, `mousedown`, `dblclick`, `wheel` and `keydown`. Each Alt listener ignores clicks inside an open field.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] O-Bitrot reset normalised without clamping before the pow**
- **Found during:** Task 3
- **Issue:** `scaledToNormalised` clamped after `Math.pow`, so a below-range value gave NaN (contract item 4).
- **Fix:** The reset uses the ported `scaledToNorm`; the now-unused helper was removed.
- **Commit:** fcae1084

**2. [Rule 2 - Missing critical] Gesture pair added to the O-AnalogEQ and O-Comp resets** (planned under D-07; listed here for traceability)
- **Commits:** dc7404c2, e5ee6bda

**3. [Rule 1 - Bug] O-AnalogEQ value field opened underneath the hover chip**
- **Found during:** Task 2, screenshot review.
- **Issue:** The dB readout is a later sibling that paints over the hover chip, and the 0.9-alpha chip let it ghost through.
- **Fix:** Both rings edit in the chip. While a field is open the chip is held at opacity 1, opaque, and z-index 5 (`.value-tooltip:has(.knob-value-input)`). Normal hover is unchanged.
- **Commit:** dc7404c2

**4. CSS beyond Prism's verbatim block**
- `font-weight: inherit` on `.knob-value-input`, for all five plugins after the tracer. O-AnalogSaturation does not need it: its chip is not bold.
- AnalogEQ also needs `pointer-events: auto`, because its readout is `pointer-events: none`.
