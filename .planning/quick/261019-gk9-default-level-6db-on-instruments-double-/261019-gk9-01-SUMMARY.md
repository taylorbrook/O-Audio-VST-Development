# Phase quick-261019-gk9 Plan 01: simple-synth family Summary

On all six simple synths, Output Level now defaults to -6 dB and belongs to the user: preset loads no longer reset or write it. Double-clicking a dial opens Prism-style inline value entry, and reset-to-default moved to Alt/Option-click, bracketed as one gesture. All six are built, installed, auval-listed and committed path-scoped.

- **Output stage:** I read the processBlock tail in all six. outputLevel is already a smoothed dB-to-linear gain applied last, followed only by the NaN scrub. Nothing was restructured.
- **Factory presets:** no lesson or concept preset in Additive, Subtractive, Sampler, Grain or Beatmaker named outputLevel; the only change there is the reset-loop skip. In PMS I stripped all 6 `{ outputLevel, X }` entries from `Source/FactoryPresets.cpp`.
- **Stripped PMS presets that were not -6 dB** (a voicing follow-up, not a gain fix): Muted Nylon -5 dB; Struck Bar -8 dB; Bell -8 dB. Bright Steel, Koto Harp and Bowed String were already -6.
- **User-preset save:** only PMS has one, and it goes through the shared header. User presets saved there still carry the key, which is ignored on load. A preset load also does one brief write of the default inside the shared apply before the live value is written back.
- **Session state:** `get/setStateInformation` is untouched everywhere. PMS restores through `setStateFromXml` -> `replaceState`, which bypasses the migration hook, so saved sessions recall their stored level.
- **UI defaults:** the initial readout `val-outputLevel` is now "-6.0 dB" in five index.html files (PMS already read -6.0). No JS default tables exist in this family. The Alt reset target comes from C++: outputLevel normalised default is 0.9 (range -60..0, skew 1).

## Dblclick / Alt-click

- Dblclick sites: each plugin binds two dblclick handlers in `bindKnob`, one on the dial and one on its readout, for every knob. Each returns on `e.altKey` and calls `attachValueEntry`. The gate reports 2 OK-ENTRY handlers and 0 failures per plugin.
- Converted: O-simpleBeatmaker's old reset-on-dblclick (app.js:359) is deleted. The reset now lives in the Alt listener, with its gesture pair and `paramDefaults` source kept. The other five had no dblclick before; entry and Alt reset are new there.
- Alt-reset event type: `pointerdown`, the same event the drag starts on, in the capture phase on `.knob-cell`. It calls `preventDefault` + `stopPropagation`, then `sliderDragStarted` / `setNormalisedValue(defaultNorm)` / `sliderDragEnded`.
- Parsers per plugin:
  - percent: stored 0..1 -> /100; stored 0..100 -> direct
  - seconds: ms/s readouts on params scaled in seconds; a bare number keeps the unit on screen
  - freq: `k` multiplies by 1000; a bare number is Hz
  - direct: dB, st, ct, BPM, ms-scaled grainSize and loopCrossfade
  - Subtractive LFO->Pitch: ct/st
  - Sampler Root Key: note names in the C3 = 60 convention, or a MIDI number
  - Beatmaker Swing: 0-75 % -> /75
  - `-inf` / `inf` / `off` / the infinity sign -> range start
  - U+2212 minus is read as "-" (Beatmaker prints it; also in Subtractive, Sampler, Grain, PMS)
- Exemptions (D-08, no dblclick added): Additive's 16 drawbars (faders, never reset on dblclick). Combo boxes, toggles, the step grid, scopes and waveform displays have no dblclick handlers at all.
- i18n: none of the six had "double-click to reset" help text, so no i18n rows changed and no zh 'mt' rows were added. Beatmaker's PluginEditor.cpp comment ("dblclick-to-default") was updated to describe Alt-click.
- Tests: no plugin test pinned dblclick behaviour, and none of the six has `ui_tip_render_check.js`. The render harnesses set outputLevel explicitly to 0 dB, so the new default doesn't move them; they were not built, per plan.
