## 2. THE HEADLINE: 64 knob captions live in `data-label` and NO GATE CAN SEE THEM

This is the single most important paragraph in this brief.

`index.html:1663` runs `expandKnobMarkup()`, an IIFE inside the inline module.
It walks every `div.knob-container[data-knob]` — **65 of them** — and replaces
the container's `innerHTML` with generated knob markup, taking the caption
from the container's own `data-label` attribute:

```js
const label = el.dataset.label || '';
el.innerHTML = '…<span class="knob-label">' + label + '</span>' +
               '<span class="knob-value" id="val-' + paramId + '">' + initial + '</span>…';
```

There are **64 `data-label="…"` attributes**, carrying **35 distinct strings**
(`Attack`, `Coarse`, `Cutoff`, `Damp`, `Decay`, `Dep A`, `Dep B`, `Depth`,
`Detune`, `Drive`, `Feedback`, `Fine`, `Glide`, `High`, `Key Trk`, `Level`,
`Low`, `Mid Freq`, `Mid`, `Mix`, …).

**Every one of them is invisible to every check you would otherwise trust:**

| Detector | Why it is blind |
|---|---|
| `i18n-extract.js` | `data-label` is not one of the attributes it scans. The inventory does not contain the string `data-label` **once**. Verified: `grep -c data-label …/i18n-inventory.tsv` → **0**. |
| `check-i18n` assertion 10 | reads `EXTRACT.scanHtml(htmlSrc)` — the **static parse of index.html** (`check-i18n.js:932`). The caption is never a text node there. |
| `check-i18n` assertion 11 | only walks `aria-label` / `placeholder` / `alt`. Not `data-label`. |
| `check-i18n` assertion 12 | the write is `innerHTML` from a **concatenation whose caption half is a variable**. No English literal to find. |
| `check-ui-labels` | collects `[data-i18n]` at runtime. An unkeyed span is not one. |

So **64 knob captions can ship in English with `ALL CHECKS PASS` on both
gates.** That is the sixth instance in this task of *a gate certifying the
absence of a thing it cannot see*, and it is the largest one yet — a quarter of
the page.

### The obvious fix is BLOCKED by assertions 13 and 15 — do not walk into it

The natural move is to key the generated span from the loop:

```js
'<span class="knob-label" data-i18n="knob.' + paramId + '">' + label + '</span>'   // ✗
setLabel(span, 'knob.' + paramId);                                                  // ✗
```

Both fail, for reasons already written into the gate:

- Assertion 15 builds `injectedKeys` from `EXTRACT.markupKeyRefs()`
  (`i18n-extract.js:719-771`), which parses **whole string literals**. The
  literal above ends at `knob.`, so the gate records a dangling key `knob.`
  and reports all 64 real `LABELS` keys **DEAD**.
- Assertion 13 fails any `setLabel` whose key is not a plain string literal
  (`check-i18n.js:1101`): *"a computed key cannot be checked."*

### THE PRESCRIBED SHAPE — key the STATIC container, move it at expansion

```html
<!-- static markup, one per knob -->
<div class="knob-container" data-knob="filtA_cutoff"
     data-label="Cutoff" data-i18n="label.cutoff"></div>
```

```js
// inside expandKnobMarkup(), before the innerHTML write
const key = el.dataset.i18n || '';
el.removeAttribute('data-i18n');       // MANDATORY — see the warning below
…
el.innerHTML = '…<span class="knob-label"' + (key ? ' data-i18n="…"' : '') + '>…';
// then, after the write:
if (key) el.querySelector('.knob-label').dataset.i18n = key;
```

Why this is the right shape and not a workaround:

- Assertion 15's `markupKeys` set reads `data-i18n` **off the static markup**
  (`check-i18n.js:1123-1126`). The key is registered as referenced. Nothing
  dangles, nothing is dead.
- Assertion 10 finds no LABEL **text node** in the static container, so it
  neither fails nor is silenced — no `I18N_EXEMPT` entry is needed and none
  must be written.
- `check-ui-labels` collects `[data-i18n]` from the **live DOM**, so all 64
  captions are measured in both languages, in geometry and in the `[2]`
  vacuity sweep. **That gate, not `check-i18n`, is your evidence for this
  class.** Say so in your report.
- The English stays in `data-label` as the contract §1 fallback.

**`removeAttribute('data-i18n')` on the container is not optional.** If the
container keeps the key, the language sweep calls `applyLabel(container)`,
which does `el.textContent = s.t` — and that **deletes the entire expanded
knob**: svg, vine, value readout, all of it. It will look like the knob
vanished on the first language switch. Prove you removed it: after
`initI18n()`, assert `document.querySelectorAll('.knob-container[data-i18n]').length === 0`
and that `.knob-label[data-i18n]` is 64.

**Deduplicate.** 64 attributes, 35 distinct strings. Share one key per string
(`label.cutoff` on every Cutoff) unless a French term genuinely differs by
context — and if you split one, say which and why.

**Negative-control it.** Delete the `data-i18n` from ONE container, run both
gates, and confirm they stay GREEN and that `check-ui-labels`' `[2]` count
drops by one. That is the proof that `check-i18n` is blind here and that
`check-ui-labels` is not. Restore from a namespaced scratchpad copy, never

## 8. The four-place rule, for THIS plugin's shapes

The controller is an **inline `<script type="module">` at `index.html:1651`**
— not `js/app.js`. There is a second, **classic (non-module)** script,
`js/wavetable-editor.js`, loaded at `index.html:3828` and reached from the

`check-i18n` builds `pageModules` from every `.js` in the served js dir, so
**`wavetable-editor.js` IS scanned by assertions 12, 13 and 15.** Its strings
are in scope.

All four places, in **one commit**:

1. `Source/ui/public/js/i18n.js` — new file.
2. `CMakeLists.txt` — `Source/ui/public/js/i18n.js` in the
   `juce_add_binary_data(O-Prism_UIResources SOURCES …)` block.

   beside the existing five (`PluginEditor.cpp:93-118`). Mind
   `juce_add_binary_data`'s hyphen stripping: `i18n.js` → `BinaryData::i18n_js`
   (no hyphen to strip here, but verify the symbol name compiles rather than
   guessing it).
4. The canon v2 block + the import line, inside the inline module at 1651,

presents as a missing panel and nothing else. **`boot-all-uis` is blind to the
