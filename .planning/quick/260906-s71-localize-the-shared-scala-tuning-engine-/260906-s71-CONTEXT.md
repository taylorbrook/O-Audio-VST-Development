## Implementation Decisions

### What the codebase actually says about D1's premise (measured 2026-09-06, drives every decision below)

- **There is nothing to `/module-upgrade`.** Five of six consumers embed the module file BY PATH from CMake (`${CMAKE_SOURCE_DIR}/modules/tuning/scala-tuning-engine/js/tuning-panel.js` at O-Bassoon:101, O-Bowed:102, O-Contrabass:122, O-Reed:75, O-Wind:97) and serve it from `PluginEditor.cpp` at `/js/tuning-panel.js`. Editing the module file localizes all five on their next rebuild. D1's "revert risk" of option 1 does not exist for them. `modules/registry.yaml` `used_by` for this module is STALE (lists O-Bells, O-Formant, O-IntonationPad — all forks with private copies — and omits O-Reed, O-Wind, O-MicrotonalSampler); do not drive anything from it.
- **O-MicrotonalSampler is NOT a live consumer.** Its CMake embeds its own `Resources/ui/js/tuning-panel.js` (plugin-owned, 317 lines diverged, header says so), already localized en/fr/zh-Hans since v1.24.0 with 39 keys, zh at `reviewed: 'bt'` (v1.27.0). **Leave it untouched.** It is the PRECEDENT, not a target.
- **The mechanism is already designed and shipped** in that copy: `data-i18n="label.xxx"` attributes inside the panel's own template markup, `data-i18n-vars='{"n":N}'` on the two counted captions, and a `refreshPanelI18n()` call after every `innerHTML` injection because the panel mounts LAZILY (after `initI18n()`) and re-renders sub-trees (`updateIntervalList`, `setGeneratorType`, `drawTrueKeys`, `drawRotationTable`, `renderLibraryList`).
- **The hook already exists in all five consumers**: every one exposes `window.__reapplyI18n = () => applyI18n(uiLanguage)` (O-Bassoon index.html:1548, O-Bowed:2297, O-Contrabass:1418, O-Reed:1820, O-Wind:1555). The module calls `if (typeof window.__reapplyI18n === 'function') window.__reapplyI18n()` after each injection. No consumer JS changes.
- **The vocabulary already exists, reviewed.** O-MicrotonalSampler's i18n.js lines ~1508–1640 carry all 39 keys with en, fr (`reviewed: true`, taken verbatim from O-Bells v4.2.0) and zh-Hans (`reviewed: 'bt'`). Key names: label.vizCircle vizPolar vizMatrix vizTrueKeys vizRotation scaleIntervals tkHint totalSpan rotationMode intervalsCount tonic tuningLibrary catAll catHistorical catJust catEdo catNonOctave catWorld noteCount a4Ref stretch loadScl loadKbm saveScl saveKbm exportHtml generateScale genEdo genHarmonic genRank2 genDivisions genPeriod genStartHarmonic genEndHarmonic genGenerator genR2Period genNotes generate tuningPanelUnavailable. **The module adopts these exact key names** so consumer rows are copies, not authoring. (`label.totalSpan` and `label.tuningPanelUnavailable` may be MTS-only surfaces — take only the keys the module's markup actually renders; the module's `Intervals (N notes)` header becomes the `label.intervalsCount` shape with `data-i18n-vars`.)
- **A missing key RENDERS THE KEY NAME** (`trLabel` returns `key` on a miss, `applyLabel` writes it to textContent). Therefore the module edit and every consumer's rows MUST land in the same change set. A consumer rebuilt against the new module without rows shows `label.vizCircle` on its tuning tab.
- **check-i18n is BLIND to module-served JS.** `pageModules` is index.html's inline scripts plus files in the plugin's own `js/` dir (check-i18n.js ~816–860). A module referenced from CMake is scanned by nothing, so (a) assertion 12 cannot see the panel's prose and (b) keys referenced only from the module read as DEAD under assertion 15 if they live in `LABELS`. All five currently PASS check-i18n; they must still pass after this task WITHOUT hiding the module.

Wave 4f adds the zh column for those four as ordinary table rows.
- Row shape follows each consumer's existing table conventions (I18N vs LABELS placement, `reviewed` flags, `sameAsEn` where fr equals en, e.g. `label.vizRotation`). Look at how each of the five already carries its ONE existing tuning key (`label.tuningLoadFailed` / `label.tuningFailed`) and put the new block beside it.

<specifics>
## Specific Ideas

- Precedent file to mirror: `plugins/O-MicrotonalSampler/Resources/ui/js/tuning-panel.js` (its header block explains the design; its `refreshPanelI18n()` at ~L89 and the `data-i18n-vars` header at ~L338).
- The module's `render()` header is `Intervals (<span id="interval-count">12</span> notes)`; `updateIntervalList()` rebuilds it as `Intervals (${count} notes)`. Adopt MTS's `label.intervalsCount` = `Intervals · notes: {n}` shape with `data-i18n-vars` so no inflection logic lives in a string (check-i18n assertion 13).
- `drawRotationTable`'s `<th>Mode</th>` → `label.rotationMode`; `renderLibraryList`'s `${tuning.noteCount} notes` → `label.noteCount` with vars; `drawTrueKeys`'s hint → `label.tkHint`. Note names (C…B), interval readouts, scale names, and the `${notes[0]}->${notes[i]}: …c` readout are READOUT / data, not copy — exempt, as MTS's I18N_EXEMPT documents.
- Commit discipline (CLAUDE.md): path-scope every commit, re-check `git branch --show-current` and `git status --short` immediately before each; one commit for the module + gate change, one per consumer bump. Another session's staging can join a commit.
