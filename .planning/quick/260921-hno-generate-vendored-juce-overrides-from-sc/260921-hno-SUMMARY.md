## Deviations from Plan

### 1. [Rule 1 — Bug] `patch -t` silently reverse-applies; `-N` added

- **Found during:** Task 2, NC6 — the strongest control, exactly as the plan predicted it would be.
- **Issue:** The Task-1 script ran `patch -p1 -F0 -t`. Against the genuinely patched local JUCE tree,
  Apple `patch 2.0-12u11-Apple` did **not** refuse the already-applied hunks — under `-t` it assumed
  `-R` and **reverse-applied** them, turning a patched tree back into a pristine one, and **exited 0**.
  The gate still failed (exit 1) because the regenerated bytes then lacked the patch, but it failed
  with the *wrong diagnosis*: "the patch and the vendored whole file have drifted apart", blaming the
  repo when the fault was the operator's base tree. The plan anticipated this exact possibility
  ("make sure the message explains it rather than surfacing a raw `patch` error").
- **Fix:** added `-N` (forbid reverse application) so an already-applied patch is *skipped* and patch
  exits non-zero, plus an explicit `DIAGNOSIS:` block emitted when patch output matches
  `reversed|previously applied`. Both documented in a comment at the call site naming NC6.
- **Files modified:** `scripts/gen-juce-overrides.sh`
- **Commit:** `e49ab789`
- **All six controls re-run from the top after the fix**, per the plan's instruction.

### 2. [Rule 2 — Missing critical functionality] `--write` under CI now refuses before any network call

- **Found during:** Task 1 verification. The refusal was implemented inside the write branch, so a
  `CI=true --write` still fetched both upstream files and applied the patch before refusing. Nothing
  was written (the plan's stated criterion was met), but "refuses outright" is better served by
  failing at argument-parse time.
- **Fix:** moved the `CI` guard to immediately after argument parsing. NC5's message now ends
  "Nothing was written; no network call was made."
- **Commit:** `0f5ec87b` (moved before the task-1 commit) — behaviour re-verified in NC5.

### 3. [Sequencing, not a defect] `--check-wiring` landed in Task 1, not Task 3a

The wiring mode was written alongside the rest of the script rather than being bolted on in Task 3.
Consequence verified rather than assumed: before the CI steps existed, `--check-wiring` **failed**
(`PRE_WIRING_EXIT=1`, naming both workflows as having copy sites with no `--check`), which confirms
the assertion is **non-vacuous** — it is not a gate that would have passed no matter what.

### F5 correction 1 — `-t` alone is not safe

The plan listed `-F0`, `-t`, `-r`, `-p1`, `-i` as the portable flag set. **`-N` is also required.**
Without it, `-t` (batch) resolves the "Reversed (or previously applied) patch detected?" prompt by
*assuming yes* and reverse-applying. That is a silent, destructive default for a gate whose entire
job is to derive bytes from a known base. Measured, not inferred — NC6, exit 0 pre-fix.

### F5 correction 2 — `-r <file>` does not redirect *all* rejects

The plan placed the reject file outside `$WORK` "a reject file inside the work tree would be walked
as a generated artifact" — correct reasoning, but incomplete. NC6's output shows Apple patch honoured
`-r` for the **first** file only and wrote the second file's reject **next to its target inside the
work tree**:

```
1 out of 1 hunks ignored--saving rejects to '/var/folders/.../genjuceovrej.cEl96GGXRf'
1 out of 1 hunks ignored--saving rejects to 'modules/juce_audio_plugin_client/juce_audio_plugin_client_VST3.cpp.rej'
```

The script's `find "$WORK" -name '*.rej' -o -name '*.orig'` sweep is therefore **load-bearing, not
belt-and-braces**: with a multi-file patch, `-r` cannot be relied on to catch every reject. Anyone
simplifying this script should not remove that scan.

## For the Next Bump

A JUCE version bump now has a single mechanical recipe, and three independent gates enforce it:

1. Edit `.github/juce-version.txt`.
2. `bash scripts/gen-juce-overrides.sh --check` fails immediately and offline, naming the exact patch
   file to create (NC3).
3. Cut `scripts/juce-patches/note-expression-juce-<new>.patch` against a pristine tree.
4. `bash scripts/gen-juce-overrides.sh --write` regenerates the vendored bytes from it.
5. `bash scripts/check-juce-overrides.sh --update` re-fingerprints the manifest (the generator prints
   this reminder and deliberately does not touch `MANIFEST.txt` itself).

`scripts/apply-juce-patches.sh` follows the pin automatically and will no longer apply an old patch to
a newly bumped tree.
