<objective>
`.gsd/dispatch-isolation-sentinel.json` is tracked in git (added in 71a0e9c7) but it is GSD run-scoped state: `gsd-tools query dispatch-isolation` rewrites its `written_at` timestamp as an unconditional side effect of resolving isolation. Every session therefore leaves ` M .gsd/dispatch-isolation-sentinel.json` in the working tree, which is noise in a repo whose commit discipline depends on reading `git status --short` accurately immediately before every commit (CLAUDE.md, shared-index race).

Untrack it, ignore it, and prove the isolation guard's read path is unaffected — both when the sentinel is present and when it is absent.

Purpose: remove permanent working-tree noise without weakening the #3045 agent-dispatch isolation guard.
Output: one path-scoped commit touching `.gitignore` and removing the sentinel from the index.

**Why this file was tracked at all — the upstream comment is already wrong about this repo.**
`~/.claude/hooks/lib/isolation-sentinel.js:26-30` asserts: *"`.gsd` is gitignored (root `.gitignore`'s bare `.gsd` entry matches at any depth)"*. That is true of the **GSD-core upstream repo**, not of this consumer repo — this repo's root `.gitignore` has no `.gsd` entry (verified: `grep -n gsd .gitignore` finds nothing, and `git check-ignore` currently exits 1). The file was committed because the assumption the library documents was never actually satisfied here. This plan makes it true.

**Scope note — deliberately NOT widening to `.gsd/`.** `.gsd/` currently holds exactly one file, so a directory-wide `.gsd/` rule would be equally correct today and would additionally pre-ignore any future run-scoped sibling GSD writes there. It is not adopted: the task specifies the file path, and a directory rule would silently swallow a future `.gsd/` file that *should* be tracked (the same reasoning this repo's own `.gitignore` already records for the rejected plugin-`dist` wildcard). Ignore the single path. If GSD later writes more run-scoped files under `.gsd/`, widening is a one-line follow-up.
</objective>
