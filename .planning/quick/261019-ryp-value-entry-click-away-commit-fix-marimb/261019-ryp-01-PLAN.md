## The fix (D-01): canonical form, copied from O-Tremolo commit 2eda4d38

```js
            // Clicking away commits even where a dial's drag handler preventDefault()s
            // its mousedown: that suppresses the focus change that would blur this
            // field, so grabbing another dial used to leave it open with its readout
            // frozen. Capture phase on document, so it commits before any drag starts.
            const onOutsidePointer = (e) => { if (e.target !== input) input.blur(); };
            document.addEventListener('pointerdown', onOutsidePointer, true);

            // ...and as the FIRST statement inside the teardown (close()) every exit path runs:
                document.removeEventListener('pointerdown', onOutsidePointer, true);
```

Rules:
1. Register right after the field exists (after it is appended/focused), next to the commit/close definitions. Use the site's own field variable in place of `input` and keep the name `onOutsidePointer` and the comment.
2. Remove it in the single teardown that Enter, blur, Esc/cancel and any re-entry guard all pass through. If some exit path removes the field without that teardown (e.g. an Esc path calling `input.remove()` directly), route it through the teardown or put the same removal line there. A missed path prints `FAIL-NOT-REMOVED`; a listener left behind keeps blurring a detached field on every later press.
3. The handler must COMMIT. Confirm the site's `blur` listener commits (Prism semantics). If a site's blur cancels or does nothing, call that site's commit function from the handler instead of `.blur()`, keeping the `e.target !== input` test.
4. The target test is exactly `e.target !== input`, never `!container.contains(e.target)`. Some fields sit inside the dial or its readout, and presses/Alt-clicks inside the field itself must not trigger it.
5. Change nothing else: no edits to drag handlers, Alt-click resets, other document listeners (tooltip/popover/menu dismissers), entry semantics or CSS.

## Serialized build + install (D-07; all five ryp plans and any straggling gk9 executor share `build/`)

Concurrent ninja runs in one build dir corrupt each other, and `build-and-install.sh` also kills AudioComponentRegistrar and clears the AU cache. So every build + install + auval goes through ONE mkdir lock, one plugin per acquisition. Launch with the Bash tool's `run_in_background: true` and wait for the exit notification (a lock wait plus the full recompile a VERSION bump causes can exceed the 600 s watchdog); never poll in a foreground loop. Substitute NAME:

```bash
bash -c '[ -f scripts/build-and-install.sh ] || { echo "not at repo root"; exit 1; }
L=/tmp/gk9-build.lock
until mkdir "$L" 2>/dev/null; do
  H=$(cat "$L/pid" 2>/dev/null)
  if [ -n "$H" ] && ! kill -0 "$H" 2>/dev/null; then rm -rf "$L"; fi
  sleep 10
done
echo $$ > "$L/pid"; trap "rm -rf $L" EXIT
./scripts/build-and-install.sh "$1" || exit 1
A=$(auval -a 2>/dev/null | grep -iE -- ": $1(-dev)?([[:space:]]|$)") || { sleep 10; A=$(auval -a 2>/dev/null | grep -iE -- ": $1(-dev)?([[:space:]]|$)"); }
echo "$A"; [ -n "$A" ] || { echo "AUVAL: $1 not listed"; exit 1; }
case "$A" in *"Cannot open"*) echo "AUVAL: $1 listed but cannot open"; exit 1;; esac' _ NAME > /tmp/ryp-build-NAME.log 2>&1; echo "RYP-EXIT=$?" | tee -a /tmp/ryp-build-NAME.log; tail -40 /tmp/ryp-build-NAME.log
```

- Never run ninja / cmake / `build-and-install.sh` outside this lock; never pass `--reconfigure` (it deletes the shared `build/`).
- A dead holder's lock is broken automatically (its pid no longer exists).
- `build-and-install.sh` Phase 4 already does the CLAUDE.md dual-variant sweep (`-dev` and unsuffixed bundles) and the AU cache clear.
- The auval match is exact (`O-Bass` does not match `O-Bassoon`) and fails on a listed-but-unopenable component.
- A ninja/CMake regeneration error (rather than a compile error) means another session may be building: wait 60 s and rerun once. A compile error is yours: fix, re-gate, rebuild.
