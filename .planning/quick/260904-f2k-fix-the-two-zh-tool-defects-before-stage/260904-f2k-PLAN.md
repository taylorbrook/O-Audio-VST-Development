Every claim below was measured against the live tree on 2026-09-04, not recalled.
The executor may rely on them; anything else must be re-observed.

1. **The Z3 derivation rule is wrong, not the generator.** The provenance block
   in `scripts/i18n-zh-lint.js` states the rule as `keys(TSCharacters) \
   keys(STCharacters)`. Both source files were re-fetched today and their sha256
   digests are byte-identical to the recorded ones, so the inputs have not
   drifted. Under that rule the set is 4139 characters — and it CONTAINS 像,
   because OpenCC's TSCharacters.txt line 418 reads `像<TAB>像 象`: 像 is a TS
   key whose own value list contains itself, i.e. T→S conversion leaves it
   unchanged. It is therefore a live simplified character. The stated intent
   ("if that same character is ALSO an ST key it is a live simplified form too
   … and must not be flagged") is right; the mechanism misses the whole class of
   self-mapping TS keys, which never appear as ST keys.
2. **941 characters are in the set for exactly that reason.** Adding the
   self-mapping exclusion takes the set from 4139 to 3198 characters
   (9660 bytes UTF-8). Of those 941, 923 map to themselves as the FIRST value
   and 18 map to themselves in a later position (乾 剋 劄 吒 夥 徵 扞 於 昇 氾 祕
   脩 蒐 薹 袷 谿 釐 陞) — the ambiguous both-scripts characters. Excluding on
   "self anywhere in the value list" drops all 941; excluding only on "self is
   the first value" leaves those 18 as false positives of the same class as 像.
   **Use "self anywhere in the value list."**
3. **Spotchecks verified against the 3198-character set:** IN — 這 後 說 龍 幾;
   OUT — 这 音 像 声 乾 徵 於 夥. `声像` produces zero hits.
4. **The blast radius is 42 plugins, and the defect is latent today.** The
   glossary's only accepted rendering for `pan` is `声像`
   (`scripts/i18n-zh-glossary.js:279`), and its three siblings `pan rnd` /
   `pan spray` / `pan sync` all inherit 像. A full lint run right now reports
   `Z3 = 0` across 43 plugins — but only because the corpus holds 33 zh entries
   and the O-Chorus pilot has no pan control. There is no repo-wide count to
   watch go to zero; the control must be a fixture.
5. **The generator no longer exists.** `find` returns nothing for
   `gen-trad-only*` and the only repo reference to `ZH_TRAD_ONLY_SENTINEL` is
   the lint itself. The provenance block's decision to keep it as a scratchpad
   throwaway is precisely why an incorrect derivation could not be re-read or
   re-run. Reverse that decision.
6. **`--ingest` derives the manifest from the wrong file.**
   `const manifestPath = val('--manifest') || \`${file}.manifest.json\`` resolves
   against the file passed to `--ingest` — the RETURNED en' file. `--emit` writes
   the manifest beside its `--out` file. The documented workflow emits to
   `/tmp/b.tsv` and ingests `/tmp/b.en.tsv`, so the lookup lands on
   `/tmp/b.en.tsv.manifest.json`, which never exists. `manifest` stays null,
   `fwd` stays null, and the identity refusal is skipped. The report then prints
   `(none recorded — the manifest was not found beside the batch)` and continues
   to print triples: a refusal that announces its own inertness and proceeds
   anyway.
7. **`--emit` leaks the source in the id column.** A live emit of the pilot
   produced 44 rows beginning `O-Chorus|label|label.rate<TAB>速率`. The key
   names ARE the English: `label.rate`, `label.depth`, `label.voices`. The
   header says "THE ENGLISH IS WITHHELD … this is the independence mechanism";
   for most rows it is handed over in the adjacent column.
8. **Environment:** node v24.19.0. `timeout(1)` is NOT on PATH on this machine —
   do not write it into a verify command. `plugins/O-TextureForge` emits a
