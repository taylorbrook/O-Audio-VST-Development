# DSP Architecture: O-simpleAmbisonics

**CRITICAL CONTRACT:** This specification is immutable during Stages 1-4 implementation. Stage 1 cannot proceed without this file. Stage 2 (DSP) implements this exact architecture.

**Generated by:** Stage 0 Research & Planning (2026-10-11)
**Referenced by:** Stage 1 (Foundation), Stage 2 (DSP), Stage 3 (GUI), Stage 4 (Polish)
**Purpose:** DSP specification for the single-source ambisonic chain (encoder → rotation → decoder → L/R), the embedded-HRTF pipeline, the real-time-safe engine layout, and the lock-free visualization path.

**Plugin type:** Audio effect, stereo-in (mono-in accepted) → stereo-out, no multichannel bus. WebView UI. 12 host parameters.

**Sibling lineage:** Pedagogical template of O-simpleFM / O-simpleSubtractive / O-simpleWavetable (WebView relay editor, 30 Hz viz Timer, CMake, offline render-harness as the Stage 2 gate). DSP prior art lifted from **O-GrainScatter** (`Source/dsp/SpatialEncoder.h` = verified 3rd-order AmbiX encoder; `TripleBuffer.h` = lock-free SPSC handoff; `scripts/generate_hrir_header.py` = the Python → constexpr-header embedding pipeline) and the two research documents `research/ambisonics-encoding-deep-dive.md` (coefficient derivation, reference table) and `research/ambisonics-binaural-decoding-deep-dive.md` (virtual-loudspeaker vs MagLS, UPOLS, rotation structure). All JUCE classes named below were verified against the local JUCE **8.0.15** source at `/Users/taylorbrook/JUCE/modules/`.

## Complexity & Research Summary

- **Complexity Tier:** 6 (frequency-domain convolution + first-class real-time visualization) → research depth **DEEP**, but executed mostly as *synthesis* of the two in-house deep-dives plus the decisions they left open. Complexity score **5.0** (capped; raw 10.0 = params 2.0 + 6 algorithms + 2 features) → **phased implementation**.
- **The eight Stage 0 questions, answered (details in Architecture Decisions):**
  1. **Binaural decoder = MagLS**, filters precomputed **offline** from **SADIE II subject D1 (Neumann KU100), Apache-2.0**, 8802-direction grid, 48 kHz. **256 taps** per filter, **three filter sets** (orders 1/2/3 = 4/9/16 channels × 2 ears = 58 FIRs, ~59 KB) embedded as a **generated constexpr header** (no second BinaryData target). Runtime: **fixed-partition UPOLS, partition P = 64**, FFT 128, K = 4 partitions at 48 kHz; **latency = 64 samples constant** at every sample rate and in both decoder modes.
  2. **SH rotation = Ivanic–Ruedenberg recursion** (orders 2–3 from the order-1 3×3), rebuilt once per block (~1 kflop), applied per sample with linear interpolation between the previous and current block's matrices. Composition **R = Rz(yaw)·Ry′(pitch)·Rx(roll)** (intrinsic yaw → pitch → roll) with sign conventions fixed below.
  3. **Distance model** = soft-knee inverse-distance gain `g(d) = (1 + d_nf)/(d + d_nf)`, `d_nf = 0.25 m` (+8.9 dB at 0.2 m, 0 dB at 1 m, −24.2 dB at 20 m) + one-pole air-absorption LP `f_c(d) = 20 kHz · min(1, 1/√d)` (open at ≤ 1 m, 4.5 kHz at 20 m). **Spread/width deferred to v1.1.** No `distanceModel` on/off parameter (1 m IS the "off" position).
  4. **Click-free switching:** the binaural convolver runs a **dual-bank crossfade (20 ms)** on order change; the Binaural↔Stereo switch is a **20 ms linear crossfade between two always-running decoders**; the stereo path is delayed by exactly **64 samples** so both paths and both modes share one reported latency.
  5. **Block-size independence:** the convolver has an internal 64-sample input/output FIFO, so the host block size (32, 64, 1024, variable, or larger than `samplesPerBlock`) never changes latency or correctness; the processor additionally slices any host block larger than the prepared maximum into ≤ maxBlock chunks. CPU at order 3 / 48 kHz ≈ **82 MFLOPS** total (≈ 1–3 % of one Apple-silicon core at 64-sample buffers).
  6. **Shortest-path smoothing:** azimuth/yaw/pitch/roll run through a wrap-aware one-pole (`delta = wrap(target − current)` into (−180°, 180°]) at **block rate, τ = 20 ms**; the resulting encoder coefficient vector and rotation matrix are **linearly interpolated per sample** across the block. Elevation and distance (gain + cutoff) use plain one-pole smoothing (20 ms).
  7. **Stereo decode = two first-order virtual cardioid microphones at ±60°** (`V = 0.5·W + 0.5·(cos θ·X + sin θ·Y)`), a 16→2 matrix on the *rotated* B-format (uses W, Y, X only). In-phase everywhere, front −2.5 dB, hard side 23 dB separation, rear −12 dB. Scene-locked by construction (rotation precedes it).
  8. **v1.0 keeps the 12-parameter set irreducible.** Deferred to v1.1: source spread, decoder weighting (basic/max-rE/in-phase), channel solo audition, `distanceModel` toggle, head-locked stereo. Each has a documented, additive v1.1 design.
- **HRTF set decision anchored on license:** SADIE II is Apache-2.0 (University of York); the TH Köln KU100 compilation is CC BY-SA 3.0 (ShareAlike on derived data). Both are KU100 heads; SADIE II D1 is the clean choice for an AGPL repo.

## Core Components

### Input Conditioner (stereo → one mono source)
- **JUCE Class:** none (plain loop) + `juce::SmoothedValue<float>` for the output trim later.
- **Purpose:** Produce the single mono source the whole lesson is built on (FUNC-07).
- **Parameters Affected:** `inputMode`.
- **Configuration:**
  - `Mono sum`: `s = 0.5·(L + R)` (−6 dB per leg; a dual-mono input sums to unity, uncorrelated to −3 dB). Documented as the pan law in the tooltip.
  - `Left only`: `s = L`.
  - Mono input bus: `s = in[0]` regardless of mode.
  - Output of this stage feeds the distance model, then the encoder.

### Distance Model (gain + air absorption, pre-encode)
- **JUCE Class:** `juce::dsp::FirstOrderTPTFilter<float>` (verified `juce_dsp/processors/juce_FirstOrderTPTFilter.h`, `setCutoffFrequency`, `processSample`) for the air LP; custom gain law.
- **Purpose:** "Distance = level + air" (DSP-05). Applied to the mono source *before* encoding so it is one filter, not sixteen.
- **Parameters Affected:** `distance`.
- **Configuration:**
  - Gain `g(d) = (1 + d_nf)/(d + d_nf)` with `d_nf = 0.25 m`. Monotonic, ≈ −6 dB per doubling above ~1 m, soft near-field cap (+12.7 dB asymptote, +8.9 dB at the 0.2 m floor). Tooltip: "level roughly halves each time the distance doubles".
  - Air LP cutoff `f_c(d) = 20000 · min(1, (1/d)^0.5)` Hz, clamped to `min(f_c, 0.45·fs)` (Nyquist clamp per project memory). Open at d ≤ 1 m (bypass-equivalent), 10 kHz at 4 m, 4.5 kHz at 20 m. Deliberately exaggerated vs ISO 9613 so the lesson is audible; say so in the tooltip.
  - Both `g` and `f_c` are smoothed (20 ms one-pole at block rate, per-sample linear ramp inside the block). Gain ramp **seeded** to the current parameter value in `prepareToPlay` (no fade-in from silence — project memory `pattern_gain_ramp_without_seeding`).

### SH Encoder (AmbiX ACN/SN3D, orders 1–3) with Order Gating
- **JUCE Class:** Custom — `encodeSH16()` lifted verbatim from `plugins/O-GrainScatter/Source/dsp/SpatialEncoder.h` (two trig pairs + double/triple-angle identities; constants `kSqrt3_2`, `kSqrt15_2`, `kSqrt5_8`, `kSqrt3_8`).
- **Purpose:** Multiply the mono source by the 16 SN3D spherical-harmonic gains for the (smoothed, orbit-offset) source direction (DSP-01). The W/X/Y/Z meters and the polar icons are a direct picture of these gains.
- **Parameters Affected:** `azimuth`, `elevation`, `orbit`, `orbitRate`, `order`.
- **Configuration:**
  - Coefficients per `research/ambisonics-encoding-deep-dive.md` §2.8 (reference table used by the DSP-01 gate, tolerance 1e-5). W = 1 for every direction (SN3D).
  - **Order gating:** three smoothed band gains `orderGain[n]`, n = 1..3, target 1 if `n ≤ order` else 0, 20 ms one-pole. Effective coefficient `c_eff[acn] = Y_acn(az, el) · orderGain[n(acn)]` (`orderGain[0] ≡ 1`). Always 16 channels allocated; lower orders fade the unused bands to exactly zero (DSP-07).
  - Block-rate target computation, per-sample **linear interpolation** of the 16-vector from the previous block's `c_eff` to the new one (chord path — `SmoothedSHCoeffs` rationale in the encoding deep-dive §3.7). Encoding itself = 16 `FloatVectorOperations::addWithMultiply`-style MACs per sample.

### Orbit LFO (automatic azimuth motion)
- **JUCE Class:** Custom phase accumulator (block rate).
- **Purpose:** Continuous, DAW-automation-free motion so the meters and image move on their own (FUNC-06).
- **Parameters Affected:** `orbit`, `orbitRate`.
- **Configuration:**
  - Phase `φ += orbitRate · blockLen / fs` (wrap at 1). Effective azimuth target `az_eff = wrap(azimuth + 360°·φ)`; positive sense = counter-clockwise from above (front → left → back → right), i.e. increasing AmbiX azimuth.
  - `orbit` Off → On: `φ` reset to 0 so the orbit departs from the puck. On → Off: the smoother glides `az_eff` back to `azimuth` along the shortest path.
  - Never writes the host parameter (audio thread must not call `setValueNotifyingHost`); the UI puck follows the published `az_eff`.

### Angle Smoothing System (shortest path around ±180°)
- **JUCE Class:** Custom `WrapSmoother` (one-pole on a wrapped delta) + plain one-pole for non-wrapping values.
- **Purpose:** Zipper-free, long-way-free motion (DSP-06).
- **Parameters Affected:** `azimuth` (incl. orbit), `elevation`, `yaw`, `pitch`, `roll`, `distance`.
- **Configuration:**
  - Wrapping values: `delta = wrapTo180(target − current)`; `current = wrapTo180(current + k·delta)`, `k = 1 − exp(−blockLen/(τ·fs))`, τ = 20 ms. Block-rate update, so a +170° → −170° jump moves +20° through 180°, never −340° through 0° (the DSP-06 gate samples this trajectory at block boundaries).
  - Non-wrapping values (elevation, distance gain, air cutoff): same one-pole without wrap.
  - Downstream consumers (encoder vector, rotation matrix, gain, cutoff) are lerped per sample inside the block, so the audible path is smooth at any host block size.

### SH Rotator (scene rotation in the ambisonic domain)
- **JUCE Class:** Custom `ShRotator` (block-diagonal 1 + 3×3 + 5×5 + 7×7, Ivanic–Ruedenberg recursion).
- **Purpose:** THE lesson that ambisonics is not panning: rotate the whole soundfield after encoding (FUNC-04, DSP-02). Would rotate a thousand sources at once; here it rotates one.
- **Parameters Affected:** `yaw`, `pitch`, `roll`.
- **Configuration:**
  - Angles smoothed (wrap-aware, 20 ms). Once per block build the 3×3 Cartesian rotation `R = Rz(yaw)·Ry′(pitch)·Rx(roll)` (see Algorithm Details for the exact matrices and signs), permute to ACN order (Y, Z, X) for the order-1 block, then recurse to the 5×5 and 7×7 blocks.
  - Per sample: `out = (1−α)·M_prev·in + α·M_cur·in` implemented as one matrix apply with a lerped matrix (83 nonzero elements), α ramping 0 → 1 across the block.
  - Applied to the gated encoder output; bands above `order` are zero and stay zero (block-diagonal structure).
  - SN3D vs N3D: rotation matrices are identical under both normalizations (per-order uniform scaling commutes with each block), so the SN3D bus needs no conversion.

### Binaural Decoder — MagLS filter bank + fixed-partition UPOLS convolver
- **JUCE Class:** `juce::dsp::FFT` (verified `juce_dsp/frequency/juce_FFT.h`: `performRealOnlyForwardTransform(float*, bool)`, `performRealOnlyInverseTransform(float*)`; buffer must be 2·N floats, interleaved re/im on return) + `juce::Interpolators::WindowedSinc` (verified `juce_audio_basics/utilities/juce_Interpolators.h`) for filter resampling in `prepare`. **Not** `juce::dsp::Convolution` (see Architecture Decisions).
- **Purpose:** 16 SH channels → L/R over headphones through precomputed HRTF-derived decoding filters (DSP-03, FUNC-05).
- **Parameters Affected:** `order` (selects the filter set), `decoder` (selects/crossfades the output).
- **Configuration:**
  - **Data:** `Source/dsp/BinauralFilterData.h` (generated): `kBinauralFilterSampleRate = 48000`, `kBinauralFilterTaps = 256`, `kMagLsFilters1[4][2][256]`, `kMagLsFilters2[9][2][256]`, `kMagLsFilters3[16][2][256]` (float32, ear 0 = left), plus `kStereoLevelMatch` (see Stereo Decoder) and provenance constants (set name, license, aliasing frequencies). One common scale across the three sets so an order change does not change loudness.
  - **prepare(fs, maxBlock):** if `fs ≠ 48000`, resample every FIR with `WindowedSinc` (ratio 48000/fs; new length `ceil(256·fs/48000)` rounded up to a multiple of P — 512 taps at 96 kHz, K = 8). Partition each FIR into P-sample blocks, zero-pad to 2P, forward-FFT, store spectra for all three sets (`[set][channel][ear][partition][2P floats]`, ≈ 64 KB per set at 48 kHz). All allocation happens here. Seed nothing audio-wise (the engine starts from zero history — correct for a convolver).
  - **Partition P = 64, FFT size 2P = 128 (order 7).** Per step: 16 forward FFTs (one per SH channel: [previous 64 | new 64]), push into each channel's frequency-domain delay line (K deep), accumulate `Σ_ch Σ_k FDL[ch][k] ⊙ H[set][ch][ear][k]` for both ears, 2 inverse FFTs, keep the last 64 samples (overlap-save). The input FFTs are shared by both ears and by both banks during a crossfade.
  - **FIFO front-end:** `pushSamples` fills a 16 × P input FIFO; every P samples one step runs and writes P output samples into a 2 × P output FIFO that the caller drains. Output lags input by exactly P samples regardless of host block size → `setLatencySamples(64)` in `prepareToPlay`. (`getLatencySamples()` is non-virtual in JUCE 8 — never override it.)
  - **Order-change crossfade (DSP-07):** `requestSet(n)` starts a 20 ms dual-bank fade: both sets are accumulated (two extra IFFTs per step), outputs mixed with a per-sample linear ramp (equal-gain — the two outputs are highly correlated), `ceil(0.02·fs/P)` steps (15 at 48 kHz). A request arriving mid-fade is queued and applied when the fade ends (latest wins). The FDL history is shared, so nothing is reset.
  - **Always running**, even in Stereo mode (≈ 1–3 % of a core; avoids any stale-history edge case on re-entry).

### Stereo Decoder (virtual cardioid pair, no HRTF)
- **JUCE Class:** Custom 16→2 matrix (effectively 3→2: W, Y, X).
- **Purpose:** Laptop-speaker / projector demos (DSP-04); also the "decoding = pointing virtual microphones into the soundfield" lesson.
- **Parameters Affected:** `decoder` (selection only — the matrix is constant).
- **Configuration:**
  - Left mic axis +60° azimuth, right −60°, elevation 0. `L = kStereoLevelMatch · (0.5·W + 0.5·(cos 60°·X + sin 60°·Y))`, `R = kStereoLevelMatch · (0.5·W + 0.5·(cos 60°·X − sin 60°·Y))` (SN3D first-order coefficients are the unit-vector components, so this is exactly a first-order cardioid). Never negative: in-phase for every source direction. Z and all order ≥ 2 channels are ignored (documented: "a stereo pair can only carry what two coincident microphones hear — switch to Binaural to hear what orders 2 and 3 add").
  - Pan behaviour: front −2.5 dB both; +90° left: L 0.933 / R 0.067 (23 dB); rear −12 dB both (present, not vanished); overhead −6 dB both (honest: stereo has no height).
  - `kStereoLevelMatch` is computed by the filter-generation script so a front source at order 3 has the same A-weighted broadband level in both modes (±1 dB), making decoder switching a timbre/space change, not a loudness jump.
  - Delayed by exactly **P = 64 samples** (2-channel ring) so it is time-aligned with the binaural output.

### Decoder Mixer + Output Stage
- **JUCE Class:** `juce::SmoothedValue<float>` ×2 (decoder mix, output gain).
- **Purpose:** Click-free Binaural↔Stereo switching with equal latency (FUNC-05, DSP-07) and the master trim.
- **Parameters Affected:** `decoder`, `outputLevel`.
- **Configuration:**
  - `mix` target 1 (Binaural) / 0 (Stereo), 20 ms linear ramp; `out = mix·binaural + (1−mix)·stereoDelayed`.
  - `outputLevel` dB → linear, 20 ms ramp, **seeded** in `prepareToPlay` to the current value; −inf handled as 0 linear below −60 dB.
  - Block-level `std::isfinite` scrub (suite convention) + `juce::ScopedNoDenormals`.

### Visualization Tap (lock-free, audio → UI)
- **JUCE Class:** `TripleBuffer<MeterFrame>` (copy of `plugins/O-GrainScatter/Source/dsp/TripleBuffer.h`, SPSC, wait-free) + editor `juce::Timer` (30 Hz) → `WebBrowserComponent::emitEventIfBrowserIsVisible`.
- **Purpose:** Feed the B-format channel view (UI-01), source-on-a-sphere puck (UI-02), polar plot (UI-03), signal-path diagram (UI-04), decoder view (UI-05) — all PERF-01 compliant.
- **Configuration:** per block the audio thread writes and publishes one `MeterFrame`:
  - `shGain[16]` — the signed, program-independent **post-rotation effective coefficient vector** `R·c_eff` (the figure-8/lobe pattern values the meters animate; sign is shown as polarity colour).
  - `shPeak[16]` — post-rotation per-channel absolute peaks (program-dependent level meters).
  - `azEff, elEff` (post-orbit, smoothed, pre-rotation) and `azRot, elRot` (the rotated direction = where the listener hears it, for the polar-plot centre and the compass).
  - `orderActive` (channel count after gating), `decoderMix`, `outPeakL/R`, `latencySamples`.
  - No FFT, no allocation, no locks on the audio thread. The polar plot itself is computed in JS from `order` (formula in Algorithm Details).

## Processing Chain

```
Stereo (or mono) input
  ↓
Input Conditioner: s = 0.5·(L+R) | L                              ← inputMode
  ↓
Distance Model: s·g(d) → one-pole air LP f_c(d)                   ← distance (smoothed gain + cutoff)
  ↓
SH Encoder: a[acn] = s · Y_acn(az_eff, el) · orderGain[n(acn)]    ← azimuth(+orbit), elevation, order
  (16 channels always allocated; bands above `order` fade to 0)    ← orbit, orbitRate
  ↓
SH Rotator: a' = R_SH(yaw, pitch, roll) · a   (block-diagonal)     ← yaw, pitch, roll
  ↓                                     └── [TAP] MeterFrame: shGain = R·c_eff, shPeak, az/el, order
  ├─► Binaural: fixed-partition UPOLS, MagLS set[order] (dual-bank fade on order change)   latency 64
  │                                                                 ← order (set select)
  └─► Stereo: ±60° virtual cardioid pair (W, Y, X) → 64-sample delay                      latency 64
  ↓
Decoder Mixer: mix·binaural + (1−mix)·stereo  (20 ms ramp)         ← decoder
  ↓
Output gain (dB→lin, seeded) → isfinite scrub                      ← outputLevel
  ↓
L / R out   (setLatencySamples(64) reported in prepareToPlay, constant)
```

**Routing notes:**
- No feedback paths anywhere; the chain is strictly feed-forward.
- Both decoders run every block; `decoder` only moves the mixer target. This is what makes the switch click-free and latency-invariant.
- Rotation precedes both decoders, so Yaw rotates the scene in Stereo mode too (scene-locked by construction; "head-locked" is not a concept in v1.0).
- Host block > prepared `samplesPerBlock`: the processor loops the whole chain over ≤ maxBlock slices (every stage is a streaming state machine, so slicing is exact). Host block < 64: the convolver FIFO simply accumulates.

## System Architecture

### File I/O System
**Not applicable at runtime.** No SOFA parsing, no file access. The HRTF-derived filters are generated **offline** by `plugins/O-simpleAmbisonics/scripts/generate_binaural_filters.py` (numpy/scipy + `sofar` for SOFA reading; run with `uv run --with numpy,scipy,sofar`) from the SADIE II D1 (KU100) 48 kHz SOFA, which is *not* committed — the script downloads it to a cache or takes a path argument. The **generated header is committed** together with the script and a `FILTERS.md` provenance note (dataset, license text pointer, MagLS settings, git SHA of the generator).

**Offline pipeline (per order N ∈ {1,2,3}):**
1. Load HRIRs (Q = 8802 directions, 2 ears), diffuse-field-equalise (SADIE II ships DFE-ready data; apply the dataset's DFE filter if present), FFT to Q × bins.
2. Build the SN3D SH matrix `Y[(N+1)² × Q]` with the same formulas as `encodeSH16` (the script ships its own copy of the reference table, which is also what the DSP-01 gate compares against).
3. MagLS (Schörkhuber/Zotter/Höldrich 2018; deep-dive §2.4): regularised LS below `f_a = N·c/(2π·0.0875)` (625 / 1250 / 1875 Hz), magnitude-only matching above with phase continued from the previous bin, half-octave crossover blend, average-group-delay continuation at HF (Hold et al. 2023) to avoid phase dispersion.
4. IFFT, circular-shift so the main energy sits inside the window, window-truncate to 256 taps with a 16-sample raised-cosine tail, store float32.
5. Common normalisation across the three sets (front source, order 3 → peak ≤ −3 dBFS for a 0 dBFS input), compute `kStereoLevelMatch`, emit the header + a `.npz` sidecar for the harness goldens (ILD sign / ITD check values at ±90°).

**Fallback generator (Plan B):** if the SOFA download or `sofar` is unavailable in Stage 2, extend O-GrainScatter's synthetic spherical-head generator (Woodworth ITD + Brown-Duda shadow) with the same MagLS step and the same header layout. Audibly worse (no pinna cues → weaker elevation/front-back), but the whole engine, gates and UI are unaffected; swap the data later.

### Multi-Output Routing
**Not applicable.** `BusesProperties().withInput("Input", stereo(), true).withOutput("Output", stereo(), true)`; `isBusesLayoutSupported` accepts input ∈ {mono, stereo}, output = stereo (mono-in/stereo-out explicitly accepted for Logic mono tracks — FUNC-07, COMPAT-02). No B-format bus in v1.0.

### MIDI Routing
**Not applicable.** No MIDI input.

### State Persistence
- **APVTS parameters:** the 12 parameters, automatic.
- **Custom state:** none in v1.0 (no file paths, no solo matrix). Preset tour = factory presets applied via `setValueNotifyingHost` (sibling `applyFactoryPreset` pattern; presets never set `outputLevel`).
- **Restore behaviour:** parameter smoothers snap (not ramp) on `setStateInformation` / preset load only if the transport is stopped is *not* attempted — a preset load is a parameter jump and goes through the normal 20 ms smoothers (QUAL-01 "no clicks on preset load" by construction).

## Algorithm Details

### SH Encoder coefficients (SN3D, ACN)
`Y_n^m(a, e) = N_n^|m| · P_n^|m|(sin e) · T_m(a)` — full table in `research/ambisonics-encoding-deep-dive.md` §2.8; implementation = `encodeSH16()` (O-GrainScatter). Two `sin`/`cos` pairs per evaluation; `sin 2a`, `cos 2a`, `sin 3a`, `cos 3a`, `sin 2e` from identities. Evaluated **once per block** at the smoothed direction, then lerped per sample.

**DSP-01 gate:** for a 13 × 7 (az × el) grid compare all 16 coefficients to the reference table (closed-form double-precision evaluation in the harness) — max |err| < 1e-5; W ≡ 1.

### Distance law
`g(d) = 1.25/(d + 0.25)`; `f_c(d) = 20000·min(1, d^−0.5)` Hz, then `min(f_c, 0.45·fs)`. TPT one-pole coefficient `G = tan(π f_c/fs)/(1 + tan(π f_c/fs))`. Both smoothed. Gate (DSP-05): monotonic decreasing level 0.2 → 20 m; HF/LF ratio decreasing with distance; exact dB values at 0.2 / 1 / 20 m within 0.1 dB of the formula.

### Shortest-path wrap smoother
```
wrapTo180(x): x − 360·floor((x + 180)/360)
step(target):  d = wrapTo180(target − cur); cur = wrapTo180(cur + k·d)
k = 1 − exp(−blockLen / (0.020·fs))
```
Gate (DSP-06): from steady +170°, set −170°, log `cur` per 64-sample block: every sample of the trajectory satisfies `|wrapTo180(cur − 180°)| ≤ 10° + ε` until converged, i.e. it crosses 180°, never 0°. Plus a 1 s full-circle sweep rendered with a 1 kHz tone: no sample-to-sample output jump > −60 dBFS relative (click gate) and spectral flatness unchanged.

### SH rotation (Ivanic–Ruedenberg)
Cartesian conventions (AmbiX: x front, y left, z up), column vectors `d′ = R·d`:
```
Rz(ψ)  = [[ c, −s, 0], [ s,  c, 0], [ 0, 0, 1]]        yaw   (+ → front goes to the left)
Ry′(θ) = [[ c,  0, −s], [ 0, 1, 0], [ s, 0, c]]        pitch (+ → front rises; = Ry(−θ))
Rx(φ)  = [[ 1,  0, 0], [ 0,  c, −s], [ 0, s, c]]       roll  (+ → left side rises)
R = Rz(ψ) · Ry′(θ) · Rx(φ)
```
Order-1 SH block in ACN order (Y=y, Z=z, X=x): `R1[i][j] = R[p(i)][p(j)]` with `p = (1, 2, 0)`. Orders 2 and 3 from the recursion of Ivanic & Ruedenberg (J. Phys. Chem. 1996, with the 1998 erratum; the corrected formulas are reproduced in code form in Green, "Spherical Harmonic Lighting: The Gritty Details", 2003, and in IEM SceneRotator `calcRotationMatrix`): each element `R_l[m][n] = u·U + v·V + w·W` where `U, V, W` are products of `P(i, a, b, l)` terms built from `R1` and `R_{l−1}`, and `u, v, w` are the closed-form coefficient functions of `(l, m, n)`. ~300 flops for the 5×5, ~600 for the 7×7, once per block. The resulting 16×16 is block-diagonal; store the 83 nonzero elements contiguously.

**DSP-02 gate:** for 200 random `(az, el, ψ, θ, φ)`: `R_SH · encodeSH16(az, el)` vs `encodeSH16(dir(R·d(az, el)))` — max |err| < 1e-4 at every order; plus three cardinal sign assertions (`ψ = +90°` maps front to +90° azimuth; `θ = +90°` maps front to +90° elevation; `φ = +90°` maps left to +90° elevation). Both sides use the same `R` builder, so the gate also pins the UI-facing sign convention.

### Fixed-partition UPOLS convolver
```
P = 64, N = 2P = 128, K = ceil(taps_fs / P)
prepare:  for set in {1,2,3}, ch, ear, k:  H[set][ch][ear][k] = FFT_N( [h[kP .. kP+P−1], 0×P] )
step:     for ch < 16: X = FFT_N( [prev[ch] (P), cur[ch] (P)] ); prev[ch] = cur[ch]; FDL[ch].push(X)
          for ear: acc = Σ_ch Σ_k FDL[ch][k] ⊙ H[set][ch][ear][k];  y = IFFT_N(acc)[P .. 2P−1]
```
Complex MAC count per step at K = 4: 16 × 2 × 4 × 65 bins = 8 320 (≈ 67 kflop); FFTs: 18 × N=128 (≈ 40 kflop) → ≈ 110 kflop per 64 samples ≈ **82 MFLOPS at 48 kHz**, ≈ 190 MFLOPS at 96 kHz (K = 8). During a 20 ms bank crossfade the MAC and IFFT cost doubles. Memory ≈ 3 × 64 KB spectra + 16 × (K × 128 + 64) floats FDL ≈ 230 KB at 48 kHz.

**Gates:** (DSP-03) impulse through the processor at order 3 → first nonzero output sample index − input index = `getLatencySamples()` = 64, at 44.1 / 48 / 96 kHz; the same at order 1 and in Stereo mode. +90° source → `rms(L) > rms(R)` by ≥ 6 dB (ILD sign, QUAL-02) and left-ear onset ≤ right-ear onset by 20–40 samples at 48 kHz (ITD consistent with a KU100). Offline convolution of the embedded FIR vs the engine output: max |err| < 1e-5 (UPOLS correctness) for host blocks of 32, 64, 100, 1024 and 4096 samples (block-size invariance, PERF-02). (DSP-07) order 1→3 and 3→1 and Binaural→Stereo→Binaural switches mid-tone: no sample-to-sample jump above the click threshold; the decoder switch changes broadband level by < 1 dB for a front source. (PERF-01) allocation counter = 0 inside `processBlock` for all orders, both decoders, during fades. (PERF-02) order 3 binaural at 64-sample blocks renders ≥ 20× real time in Release on the dev machine.

### Stereo virtual-cardioid decode
`D = kStereoLevelMatch · [[0.5, 0.5·sin 60°, 0, 0.5·cos 60°], [0.5, −0.5·sin 60°, 0, 0.5·cos 60°]]` over (W, Y, Z, X); remaining 12 columns 0. Gate (DSP-04): front source L = R; +90° source L/R ≥ 20 dB; no negative-polarity output for any direction (correlation of L and R with the source ≥ 0).

### Polar plot (UI-side, from `order` only)
Spatial-resolution beam of the order-N truncated panning function, basic weighting:
`g_N(γ) = Σ_{n=0}^{N} (2n+1)·P_n(cos γ) / (N+1)²` (P_0 = 1, P_1 = x, P_2 = (3x²−1)/2, P_3 = (5x³−3x)/2), γ = angle from the (rotated) source direction. Order 1 is the familiar cardioid-ish blob, order 3 a tight beam with small sidelobes. Drawn centred on `azRot` in the top-down view. (v1.1 max-rE / in-phase weightings reuse the same formula with per-order weights.)

### Meters
`shGain = R_SH · c_eff` is already computed per block for the rotator; copy to the frame. `shPeak[ch] = max |a′[ch][s]|` over the block (16 scans, SIMD-friendly, `FloatVectorOperations::findMinAndMax`). No smoothing on the audio thread; ballistics in JS (`requestAnimationFrame`, attack 0.4 / decay 0.15 per the critical-patterns file).

## Integration Points

### Feature Dependencies
- Input Conditioner → Distance Model → Encoder: strictly sequential on the mono source (distance is one filter before fan-out).
- Orbit → WrapSmoother(azimuth) → Encoder: the orbit modifies the smoother's *target*; the smoother guarantees shortest-path even when the orbit wraps past ±180° every revolution.
- Order → Encoder band gains AND → Binaural set select: both fire from one parameter read per block; the encoder fade (20 ms) and the filter-bank fade (20 ms) start in the same block so they overlap.
- Rotator → both decoders and → meter tap: the tap reads the rotated bus so FUNC-01's "Yaw = −Azimuth brings the source back to front in the meters" holds.
- Binaural + Stereo → Decoder Mixer: both always produce output; the stereo delay (64) must equal the convolver partition (64) — one shared constant `kPartition`.
- Filter data → Binaural prepare: `BinauralFilterData.h` is a compile-time dependency; the harness includes it directly (no BinaryData).

### Parameter Interactions
- `order` affects the encoder (which channels exist), the binaural filter set, the meter row count, the polar plot and the signal-path diagram's channel count; **not** the stereo decoder (first-order only — documented behaviour).
- `yaw/pitch/roll` move the *decoded* image and `azRot/elRot`, never `azEff/elEff` or the puck (UI-02 acceptance).
- `orbit` On overrides the audible azimuth; the `azimuth` knob still sets the orbit's start/offset.
- `distance` changes level and tone but not direction; `outputLevel` is post-everything and preset-neutral.
- `decoder` never changes latency (constant 64) or the meters.

### Processing Order Requirements
1. Read all 12 parameters once per block (atomic loads) → update smoother targets.
2. Advance block-rate smoothers (angles, gains, cutoff, order gains, orbit phase).
3. Build this block's encoder vector `c_eff` and rotation matrix; keep the previous block's copies for the per-sample lerp.
4. Per sample: condition input → distance gain/LP → encode (lerped 16-vector) → rotate (lerped matrix) → write the 16-channel bus.
5. Meter tap on the rotated bus (peaks) + `shGain`.
6. Binaural convolver `push/pull` (FIFO) and stereo matrix + 64-sample delay.
7. Decoder mix → output gain → isfinite scrub → publish `MeterFrame`.

Why: direction must be smoothed before coefficient evaluation (shortest path is an angle-domain property); rotation must follow encoding (the lesson); the tap must follow rotation (FUNC-01); the stereo delay must equal the convolver latency before mixing.

### Thread Boundaries
- **Audio thread:** everything in the chain above. No allocation, locks, FFT-plan creation, or file I/O. Parameter reads via `getRawParameterValue()->load()`.
- **Message thread:** editor Timer (30 Hz) reads `TripleBuffer<MeterFrame>::read()`, serialises to JSON, `emitEventIfBrowserIsVisible("meterFrame", …)`; native functions for `uiReady`, `applyFactoryPreset`, and puck drags (which set `azimuth`/`elevation` via the relay/attachment with proper gesture begin/end).
- **No background thread:** filters are compile-time data; resampling happens in `prepareToPlay` (host guarantees no concurrent `processBlock`).
- **Communication:** APVTS atomics (UI → audio), `TripleBuffer` (audio → UI). `prepareToPlay` re-seeds all smoothers from the current parameter values.

## Implementation Risks

### MagLS filter generation pipeline (offline)
**Complexity:** HIGH **Risk:** MEDIUM
- Risk factors: SOFA download/`sofar` availability; getting MagLS phase continuation right (phase dispersion above ~8 kHz if the previous-bin phase is used naively); normalisation across orders; truncation to 256 taps smearing the LF LS region.
- Alternatives: (1) plain LS per order (worse HF colouring at order 1–2); (2) virtual-loudspeaker + HRTF on the SADIE II 26/50-point Lebedev subsets (simpler, more comb-filter colouring).
- **Fallback:** synthetic spherical-head HRIRs (existing O-GrainScatter generator) through the same MagLS/LS step and header layout — the engine, gates and UI do not change.
- Mitigation: validate the generated set offline in the script (plot/assert ILD sign at ±90°, ITD at ±90°, flat W-channel LF response, spectral smoothness) before embedding; harness goldens come from the same `.npz`.

### Fixed-partition UPOLS convolver
**Complexity:** MEDIUM **Risk:** MEDIUM
- Risk factors: overlap-save bookkeeping; JUCE FFT interleaved layout (buffer 2N floats, first N real input; inverse returns reals in the first half); FIFO phase errors creating a latency ≠ 64; dual-bank fade bookkeeping.
- Alternatives: 32 × `juce::dsp::Convolution` (rejected: no shared input FFT, async IR loading via message queue makes order switching and the gates nondeterministic); direct-form FIR (zero latency but 390 MMAC/s at order 3 / 256 taps / 48 kHz, 4× worse at 96 kHz).
- **Fallback:** direct-form FIR lifted from O-GrainScatter `BinauralDecoder.h` with 128 taps (latency 0 — then the stereo delay and reported latency become 0 as well; the FUNC-05 "equal latency" criterion is still met).
- Mitigation: the UPOLS-vs-offline-convolution gate at five block sizes is written **first** (Phase 2.3 step 1), before the engine is wired into the processor.

### SH rotation recursion
**Complexity:** MEDIUM **Risk:** LOW
- Risk factors: index/sign errors in the recursion (the 1996 paper's known errata).
- Alternatives: Z-Y-Z Euler with precomputed `Ry90` tables (IEM); explicit closed-form 5×5/7×7 from the Cartesian matrix (Wigner-D style) — longer to derive.
- **Fallback:** restrict rotation to Yaw only (Rz is a trivial per-order 2×2 cos/sin block), ship pitch/roll as `should` in v1.1. FUNC-04 marks Yaw as the must.
- Mitigation: the DSP-02 gate (rotate-then-encode vs encode-rotated) is mechanical and catches any error.

### Click-free order / decoder switching
**Complexity:** LOW **Risk:** LOW
- Factors: three concurrent fades (encoder bands, filter bank, decoder mix) must all be ramps, never steps; queued set requests.
- Fallback: lengthen fades to 50 ms.
- Mitigation: DSP-07 click gate renders the switch mid-tone at 64 and 1024-sample blocks.

### Shortest-path smoothing + orbit
**Complexity:** LOW **Risk:** LOW — gated directly (DSP-06).

### Real-time safety / block-size invariance
**Complexity:** LOW **Risk:** LOW — FIFO design + slice loop; allocation gate + block-size gate in the harness.

### Overall Project Risk
**Overall complexity:** MEDIUM-HIGH. **Highest-risk component:** the MagLS filter pipeline + UPOLS engine together (~60 % of project risk) — both are offline-validatable and have working fallbacks. Recommended order: encoder + stereo decode + smoothing first (audible in Phase 2.1 with no HRTF work), rotation second, binaural last with its gates written before integration.

## Architecture Decisions

### 1. Binaural method: MagLS, not virtual-loudspeaker + HRTF
**Decision:** precomputed MagLS decoding filters per order.
**Rationale:** at orders 1–3 the aliasing frequency (625–1875 Hz) sits in the most sensitive hearing range; virtual-loudspeaker decoding colours and comb-filters everything above it (deep-dive §1.7). MagLS matches magnitude above `f_a` and is the quality bar set by SPARTA AmbiBIN and IEM BinauralDecoder. Precomputing collapses "decode to speakers, then convolve" into one 16→2 filter bank anyway, so runtime cost is identical.
**Alternatives:** virtual loudspeakers on the SADIE II Lebedev grids (simpler script, worse sound); BiMagLS (better ILD, 2× channels — overkill). **Tradeoff:** a more involved offline script, mitigated by the fallback generator.

### 2. HRTF set: SADIE II D1 (KU100), Apache-2.0
**Rationale:** license (Apache-2.0 is compatible with the AGPL-3.0 repo and permits embedding derived data; TH Köln KU100 is CC BY-SA 3.0 and would impose ShareAlike on the derived filters), 8802 directions (well-overdetermined SH fit), same KU100 head the literature prefers, DFE and Lebedev subsets available. One head only in v1.0 (brief: no personalisation); the script is parameterised so a second head is a data addition.

### 3. Filters embedded as a generated constexpr header, not a second `juce_add_binary_data`
**Rationale:** 58 FIRs × 256 taps ≈ 14.8 k floats (≈ 240 KB of source) — the O-GrainScatter precedent compiles fine; the harness includes the header directly (no BinaryData dependency, no namespace collision — the O-simpleGrain `UIBinaryData` lesson), type-safe, diffable provenance. The UI keeps the single default-namespace BinaryData target. If the data ever moves to binary data, the target must use `NAMESPACE HrtfBinaryData` + distinct `HEADER_NAME`.

### 4. Fixed-partition UPOLS (P = 64) with an internal FIFO, not host-block-sized partitions
**Rationale:** host blocks vary (Logic, Ableton) and may exceed `samplesPerBlock` (project memory: oversampler/convolver sized to the prepared block overruns). A fixed partition gives constant latency (64 at every fs and in both modes — the FUNC-05 acceptance), block-size-invariant output (gate at 32…4096), predictable CPU, and the same structure `juce::dsp::Convolution` uses internally for its `Latency{}` mode (verified in `juce_Convolution.cpp`: `jmax(64, nextPowerOfTwo(requiredLatency))`). Custom rather than `juce::dsp::Convolution` because the 16-in/2-out topology shares the 16 input FFTs across ears and banks (≈ 44 % fewer FFTs than 32 instances), and because `loadImpulseResponse` is asynchronous (background message queue), which would make order switching and the offline gates nondeterministic.
**Tradeoff:** 64 samples of latency (1.3 ms at 48 kHz) and ~400 lines of engine code; accepted — zero-latency direct-form costs 5–7× the CPU at order 3 and scales badly at 96 kHz.

### 5. Rotation by Ivanic–Ruedenberg recursion, applied with a per-sample matrix lerp
**Rationale:** one block-rate build (~1 kflop) is cheaper and simpler than the Z-Y-Z `Ry90` route; the recursion generalises if an order-4 variant is ever wanted; matrix lerp within the block keeps rotation zipper-free at 1024-sample blocks without per-sample trig. Rotating with the SH matrix rather than re-encoding is the *point* of the lesson (the same matrix would rotate any number of sources).

### 6. Distance = soft-knee 1/d + exaggerated one-pole air LP, pre-encode, no on/off switch
**Rationale:** monotonic, two-line explanation, one filter instead of sixteen, and 1 m is exactly "no effect" — so a before/after comparison is "distance = 1 m vs 8 m", no extra parameter. Exaggerated air absorption chosen for audibility (ISO 9613 is ~1 dB at 10 kHz over 20 m, inaudible in a classroom); tooltip states this. Near-field width/spread deferred (v1.1 = per-order attenuation `g_n(spread)` — "widening by weighting down higher orders", zero topology change).

### 7. Stereo decode = first-order virtual cardioid pair at ±60°
**Rationale:** a 2-speaker mode-matching (pseudoinverse) decode at ±30° puts the far channel in antiphase for sources outside the arc (computed: +90° source → R = −0.71) — unacceptable on laptop speakers and confusing for students. A cardioid pair is in-phase for every direction, is the textbook "decoding = virtual microphones" picture (Gerzon), and ±60° balances centre level (−2.5 dB), hard-side separation (23 dB) and rear presence (−12 dB). Order-N in-phase beams were considered (sharper with order, but rear drops to −50 dB at order 3) and rejected; higher-order channels are intentionally unused in Stereo mode and the tooltip says why.

### 8. Three always-running paths with crossfades instead of switching
**Rationale:** both decoders always compute; order changes crossfade two filter banks; encoder bands fade. Steps are impossible by construction, no reset-on-re-entry edge cases, and the whole cost is < 5 % of a core.

### 9. Meters publish the rotated coefficient vector, not just signal peaks
**Rationale:** `|shPeak|` follows the program material; `shGain = R·c_eff` IS the spherical-harmonic pattern value (signed), so the headline "W stays constant while X/Y swing" picture is program-independent and polarity-visible. Both are published; the UI chooses (pattern bars with a level overlay).

### 10. v1.0 parameter set stays at 12
Deferred with sketches: **spread** (v1.1, per-order weighting), **decoderWeighting** basic/max-rE/in-phase (v1.1: 3 × 3 filter sets ≈ 180 KB — the generator takes a weighting argument from day one), **channel solo audition** (v1.1: mono audition of one post-rotation channel to both ears, UI-only non-APVTS state), **distanceModel toggle** (not needed), **head-locked stereo** (meaningless without head tracking; v2 with tracking). Mono-sum pan law fixed at −6 dB (documented), not a parameter.

## Special Considerations

### Thread Safety
- All parameter reads are atomic loads once per block; smoother targets are plain members owned by the audio thread.
- `MeterFrame` handoff via `TripleBuffer` (wait-free SPSC); the editor never touches engine state.
- `prepareToPlay` is the only place that allocates (FFT plans, spectra, FIFOs, resampled FIRs) and re-seeds smoothers; it sizes the SH bus for `max(samplesPerBlock, 64)` and the slice loop guards larger host blocks.

### Performance
- Encoder 16 MAC + 16 lerp/sample; rotator 83 MAC + 83 lerp/sample; distance 1 TPT pole; stereo 6 MAC; meters 16 peak scans → ≈ 10 MFLOPS at 48 kHz.
- Binaural UPOLS ≈ 82 MFLOPS at 48 kHz (190 at 96 kHz), ×2 MAC during a 20 ms bank fade.
- Total ≈ 1–3 % of one Apple-silicon core at order 3; the PERF-02 gate asserts ≥ 20× real time at 64-sample blocks in Release.
- No per-sample transcendental functions anywhere (trig only at block rate: 2 pairs for the encoder, 3 pairs for the rotator).

### Denormal Protection
- `juce::ScopedNoDenormals` in `processBlock`; the convolver's FDL and the TPT pole are the only recursive/stateful elements and both decay to exact zero with zero input within K steps / a few hundred samples; block `std::isfinite` scrub before output.

### Sample Rate Handling
- Embedded filters are 48 kHz; `prepare` resamples with `WindowedSinc` for any other rate (taps = `ceil(256·fs/48000)` rounded up to a multiple of 64; K adapts). Air-LP cutoff clamps to `0.45·fs`. Smoother coefficients recomputed from `fs`. Latency stays 64 samples at every rate (reported once in `prepareToPlay`).

### Latency
- Exactly `kPartition = 64` samples, both decoder modes, all orders, all sample rates: `setLatencySamples(64)` in `prepareToPlay`. The stereo path's 64-sample delay and the convolver's FIFO lag are the same constant. Gate: impulse-measured latency = `getLatencySamples()`.

### Headless testability (Stage 2 gate design)
All DSP lives in `Source/dsp/` as self-contained headers with `prepare(double fs, int maxBlock)` / `reset()` / `process(...)` and no JUCE processor dependencies: `ShEncoder.h`, `DistanceModel.h`, `WrapSmoother.h`, `OrbitLfo.h`, `ShRotator.h`, `BinauralConvolver.h` + `BinauralFilterData.h`, `StereoDecoder.h`, `DecoderMixer.h`, `MeterFrame.h`/`TripleBuffer.h`, composed by `SpatialEngine.h` (`setParams(const Params&)`, `process(const float* const* in, int numIn, float* const* out, int n)`). The render-harness (`tests/render-harness`, sibling CMake pattern) drives `SpatialEngine` for the unit gates (DSP-01/02/04/05/06, UPOLS-vs-offline) and the full `AudioProcessor` for latency, allocation, click and block-size gates.
