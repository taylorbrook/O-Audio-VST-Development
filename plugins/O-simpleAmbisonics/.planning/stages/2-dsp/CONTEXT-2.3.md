## Discussion summary

The binaural leg is closed at the algorithm level: ARCHITECTURE fixes the method (MagLS per order, SADIE II D1 KU100, 256 taps at 48 kHz, generated `constexpr` header, no second BinaryData target), the engine (fixed-partition UPOLS, P = 64, FFT 128, shared input FFTs, dual-bank 20 ms crossfade with queued requests, always running), the sample-rate handling (`WindowedSinc` resample in `prepare`, taps rounded up to a multiple of P), the latency (64 in both modes, one call site) and the gate set (DSP-03 / DSP-07 / PERF-01 / PERF-02 / UPOLS-vs-offline at five block sizes). Discuss did **not** re-open any of that.

What discuss settled is **how the leg lands in the 2.2 engine without disturbing anything 2.1 / 2.2 proved** — and one placement that the contract's wording leaves open with a large consequence: *where the decoder level match is applied*. Putting the generated factor on the stereo leg (the literal reading of `StereoDecoder.h`) changes every Stereo render by a constant and retires both digests and the P1 anchor; putting it on the filter scale (D2) keeps 158 of 160 checks and both digests as a free regression verdict for "the convolver was inserted and nothing else moved". The contract's requirement — equal A-weighted level for a front source at order 3 in both modes — is met either way, so D2 is recorded with its alternative and can be overturned at research.

The other settlements are structural: the convolver is **grid-synchronous** (stepped from the existing control step, so the FIFO-phase risk ARCHITECTURE names cannot exist), the bank fade is **the 2.1 ramp shape** (same step constant, same grid, so slicing invariance carries over by construction), the Binaural output is **bit-exactly the convolver output** when the mix sits at 1, the reference model gains a **direct-form double convolution** (the oracle for UPOLS mechanics, independent of the thing under test), and the generator is **own code with spaudiopy as an outside oracle**, never the generator. No decision needed Taylor's call in the room; D2 is the one to glance at.

## Decisions

| # | Decision | Choice | Rationale |
|---|---|---|---|
| **D1** | Convolver scheduling | **Grid-synchronous.** `BinauralConvolver` owns a `float in[16][64]` the engine fills per sample (`push (tap, gridPos)`), and **its step runs inside `controlStep()`** (at `gridPos == 0`, before the first sample of the new grid): `X_ch = FFT₁₂₈ ([prev64_ch \| last64_ch])` for all 16 channels, FDL push, accumulate both ears over the active set(s), 2 IFFTs, keep samples 64…127 into `out[2][64]`; `renderSample` reads `out[ear][gridPos + j]`. **No separate FIFO phase counter** | `static_assert (kControlGrid == kPartition)` already pins the two to 64 and both counters start at 0 in `prepare` / `reset`, so the UPOLS step and the control step are the same instant by construction. The output written at step *s* is the convolution of the grid that just ended, emitted during the next grid → **exactly 64 samples of structural latency**, the number `setLatencySamples` has reported since Stage 1. ARCHITECTURE's "FIFO front-end" risk ("FIFO phase errors creating a latency ≠ 64") has no mechanism left. Block-size independence is inherited from `gridPos` + the processor slice loop, which P2 / P3 / P2b–P2d already prove; the convolver holds no `maxBlock`-sized buffer at all |
| **D2** | Where the decoder level match lives | **Baked into the filter scale.** The generator applies one common scale to all three MagLS sets such that a front source at order 3 has the same A-weighted broadband level (white excitation, mean of the two ears) as the Stereo decoder's front value (0.75). **`kStereoLevelMatch` stays exactly `1.0f`** — its comment is rewritten to say the match is in the filters; the header emits `kBinauralLevelMatchDb` (the ratio the generator applied, provenance) and the generator **asserts** the match within ±1 dB at order 3 and prints orders 1 / 2. **Alternative (not chosen):** a factor on the stereo leg as `StereoDecoder.h` literally says | The Stereo path is then **untouched by this phase**, so digest-2.1 `9189d911a1fe98d5` and digest-2.2 `7f35bc9f91e321b9` and the P1 anchor `0.75·s[n−64]` become **this phase's regression verdicts** (D13) — 158 checks for free. The binaural absolute level is arbitrary (HRTF sets carry no reference level), so scaling the filters loses nothing; a factor on the stereo leg would be one extra rounding per sample on the leg whose exact literals were chosen for bit-exactness. The contract's requirement — same A-weighted level, ±1 dB, decoder switch = timbre not loudness — is met identically. Headroom note: an HRTF bank has the ear-canal resonance (+10…15 dB around 3 kHz), so a full-scale sine there can exceed 0 dBFS after the match — true of every binaural renderer; `outputLevel` exists; QUAL-01 gates *finite*, not < 1 |
| **D3** | Binaural output exactness | When both mix endpoints are exactly 1 at a control step (`prevMix == curMix == 1`), `renderSample` **copies the convolver output** instead of blending (`outL = binL`); otherwise the A3 blend as now. One `bool` set per control step, no per-sample branch cost worth naming | A3 `dL + mixS·(binL − dL)` with `mixS = 1` is `binL` within one rounding, not bit-exact. The copy makes the engine's Binaural output **identical to the convolver's**, so the UPOLS-vs-offline gate (D7) and the pedalboard measurer read the convolver through the engine without a rounding term, and the "placeholder gone" probe is unambiguous. `mix = 0` is already exact by the A3 form (RESEARCH-2.1 F2) |
| **D4** | Order sets, bank fade, queueing | Set *n* (order *n*) holds `(n+1)²` channel filters and the accumulation loops **only over its channels** (4 / 9 / 16). All 16 input FFTs run every step regardless (constant cost, no staleness). `params.order` is sampled at the control step (as `orderGain` already is); a change calls `requestSet (n)`: if idle, start a **dual-bank fade** — both sets accumulated, two extra IFFTs, `bankMix` = a `LinearRamp` stepped with **the same `kRampStep`** at the control step and **lerped per sample** `yA + m·(yB − yA)` (equal-gain, A3 form); if a fade is running, the request is **queued, latest wins**, applied when the fade arrives exactly (1e-6 snap). The FDL history is shared by both banks, nothing resets | This is the 2.1 ramp shape, so the bank fade and the encoder band fade (both 20 ms, both from the grid) run in lock-step, and the P2b / P3b-style slicing gates extend to the bank fade without new infrastructure. Equal-gain is right because the two bank outputs are highly correlated (same bus, filters that agree below `f_a`). Set-*n* channel loops are where the order-1 CPU saving is (K·4·2 vs K·16·2 complex MACs); 16 FFTs of 128 points are ≈ 40 kflop per step and not worth a conditional |
| **D5** | Sample rates other than 48 kHz | In `prepare`: if `fs ≠ 48000`, resample every FIR with **`juce::Interpolators::WindowedSinc`** (ratio 48000/fs); new length `ceil (256·fs/48000)` rounded **up to a multiple of 64** (44.1 k → 256, K = 4; 88.2 / 96 k → 512, K = 8; 176.4 / 192 k → 1024, K = 16); at exactly 48 k the header floats are used **unmodified** (bit-exact table). ## Phase goal

Replace the A14 placeholder with a real HRTF leg: SADIE II KU100 MagLS filters per order, embedded as a generated header, run by a grid-synchronous UPOLS convolver on the **rotated** bus with a click-free dual-bank order crossfade, level-matched to the Stereo decoder so the decoder switch is a timbre change and not a loudness jump, at a constant 64-sample latency in both modes at every sample rate — and **nothing 2.1 / 2.2 proved changes**: both Stereo digests reproduce bit-for-bit. Close Stage 2 with the roll-up `VERIFICATION.md`.
