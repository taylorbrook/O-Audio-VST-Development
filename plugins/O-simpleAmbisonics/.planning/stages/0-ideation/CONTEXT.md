## What this plugin is

Pedagogical ambisonic spatializer — the spatial-audio sibling of O-simpleFM / O-simpleSubtractive / O-simpleWavetable. One mono source → SH encoder (orders 1–3, AmbiX) → SH-domain rotation → binaural (or stereo) decoder → L/R, all inside a stereo-out plugin so students on headphones in Logic/Ableton hear and see the whole chain. North star: the "oh, THAT's what the B-format channels are" moment in five minutes.

## Resolved decisions (the eight research questions)

1. **Binaural decoder — MagLS, SADIE II D1 (KU100), offline → constexpr header.** MagLS over virtual-loudspeaker because the aliasing frequency at orders 1–3 (625–1875 Hz) is mid-band and VLS comb-filters above it. SADIE II chosen over TH Köln KU100 on **license** (Apache-2.0 vs CC BY-SA 3.0 — ShareAlike would attach to the derived filters in an AGPL repo). 256 taps at 48 kHz, three sets (4/9/16 ch × 2 ears, ≈ 59 KB), generated by `scripts/generate_binaural_filters.py` into `Source/dsp/BinauralFilterData.h` — no second `juce_add_binary_data` target, so no namespace collision and the harness includes the data directly. Runtime: fixed-partition UPOLS, **P = 64, FFT 128, K = 4** at 48 kHz, **latency 64 samples constant**. Fallback: O-GrainScatter's synthetic spherical-head generator through the same MagLS step.
2. **Rotation — Ivanic–Ruedenberg recursion**, built once per block from the smoothed angles (~1 kflop at order 3), applied per sample with a lerp between the previous and current matrices. Composition `R = Rz(yaw)·Ry′(pitch)·Rx(roll)`; signs fixed: yaw + = scene CCW from above (front source → left), pitch + = front rises, roll + = left rises. Z-Y-Z/Ry90 route rejected as more tables for no gain.
3. **Distance — `g(d) = 1.25/(d + 0.25)`** (soft near-field knee, 0 dB at 1 m, +8.9 dB at 0.2 m, −24 dB at 20 m) **+ one-pole air LP `f_c = 20 kHz·min(1, 1/√d)`** (open ≤ 1 m, 4.5 kHz at 20 m; exaggerated for audibility, tooltip says so). One filter on the mono source, pre-encode. **Spread deferred to v1.1** (per-order attenuation design noted). No `distanceModel` toggle — 1 m is "off".
4. **Click-free switching** — encoder order bands fade (20 ms), binaural filter bank dual-bank crossfade (20 ms, queued requests), Binaural↔Stereo = 20 ms crossfade between two **always-running** decoders; stereo path delayed by exactly 64 samples. One reported latency for both modes.
5. **Block-size independence** — convolver has an internal 64-sample FIFO (host block 32…4096 or variable never changes latency/correctness); processor slices host blocks larger than the prepared maximum. CPU ≈ 82 MFLOPS at order 3 / 48 kHz (≈ 1–3 % of a core); gate ≥ 20× real time at 64-sample buffers.
6. **Shortest-path smoothing** — wrap-aware one-pole on azimuth/yaw/pitch/roll at block rate (τ = 20 ms), per-sample lerp of the encoder 16-vector and the rotation matrix inside the block; plain one-pole on elevation/gain/cutoff; all gain ramps seeded in `prepareToPlay`.
7. **Stereo decode — first-order virtual cardioid pair at ±60°** on the rotated W/Y/X. A ±30° pseudoinverse decode was computed and rejected (antiphase far channel for sources outside the arc); order-N in-phase beams rejected (rear −50 dB at order 3). In-phase everywhere, front −2.5 dB, 23 dB side separation, rear −12 dB. Scene-locked by construction.
8. **v1.0 parameter set stays at 12.** Deferred to v1.1 with additive designs: spread, decoder weighting (generator takes a weighting argument from day one; 3×3 sets ≈ 180 KB), channel solo audition (UI-only state), distance toggle (not needed), head-locked stereo (v2 with tracking).

## Other decisions
- Meters publish the **signed rotated coefficient vector** `shGain = R·c_eff` (program-independent SH pattern values, polarity visible) plus per-channel peaks; the tap is post-rotation so "Yaw = −Azimuth brings it back to front in the meters" holds.
- Mono sum = 0.5·(L+R) (documented −6 dB law); mono-in/stereo-out accepted.
- Polar plot computed in JS from `order` alone (`Σ (2n+1)P_n(cosγ)/(N+1)²`), centred on the rotated direction.
- O-GrainScatter's `HRIRData.h` is **synthetic** (Woodworth + Brown-Duda) — its data is not reused (fails QUAL-02 front/back/above); its encoder, TripleBuffer, header-generation pipeline and direct-form decoder (as fallback) are.

## Complexity & strategy
- **Tier 6 / DEEP** (frequency-domain convolution + first-class real-time visualization), executed as synthesis of the two in-house deep-dives.
- **Score 5.0** (capped; raw 10.0 = params 2.0 + 6 algorithms + 2 features) → **phased**: Stage 2 DSP in 3 phases (2.1 encoder+stereo+smoothing, 2.2 rotation, 2.3 binaural pipeline+engine+gates), Stage 3 GUI in 3 phases.
- **Highest risk:** MagLS pipeline + UPOLS engine (~60 %), both offline-validatable with fallbacks; the UPOLS-vs-offline-convolution gate is written before integration.

## Constraints honored
- JUCE 8.0.15 (verified `dsp::FFT`, `Interpolators::WindowedSinc`, `FirstOrderTPTFilter`, `dsp::Convolution` latency semantics in local source); WebView UI; VST3 + AU (macOS), VST3 (Windows) with `NEEDS_WEBVIEW2 TRUE` + `JUCE_USE_WIN_WEBVIEW2_WITH_STATIC_LINKING=1`.
- Stereo in / stereo out only (mono in accepted); no multichannel bus.
- RT-safe `processBlock`; 16 channels + max block pre-allocated; `setLatencySamples(64)` in `prepareToPlay`; lock-free `TripleBuffer` meter handoff.
- Headless-testable `Source/dsp/*.h` + `SpatialEngine.h` for the Stage 2 gates (coefficient table 1e-5, rotation equivalence 1e-4, impulse latency, trajectory, click, allocation, block-size invariance).
