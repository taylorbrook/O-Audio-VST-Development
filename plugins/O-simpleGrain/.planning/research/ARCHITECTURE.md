# DSP Architecture: O-simpleGrain

**CRITICAL CONTRACT:** This specification is immutable during Stages 1-4 implementation. Stage 1 (Foundation) cannot proceed without this file. Stage 2 (DSP) implements this exact architecture.

**Generated by:** Stage 0 Research & Planning
**Referenced by:** Stage 1 (Foundation), Stage 2 (DSP Implementation), Stage 3 (GUI)
**Purpose:** DSP specification defining the granular voice engine (source buffer → windowed grain scheduler → overlap-add → amp ADSR → out), signal flow, JUCE 8 module usage, and the real-time-safe visualization path.

**Plugin type:** Synth (Pedagogical Granular), MIDI-in → audio-out, polyphonic (8 voices), Freeze mode, WebView UI.

**Sibling reference:** O-simpleGrain is the **third pedagogical sibling after the shipped O-simpleFM and O-simpleAdditive** and deliberately inherits their engineering conventions: `juce::Synthesiser` + custom `SynthesiserVoice` voice model, per-block APVTS→voice param push, `juce::ADSR` amp env, `outputLevel` smoothing, and the lock-free `VizRing` + message-thread FFT visualization tap (reused from `FmVizAnalyzer.h`). The grain engine itself is mined from the in-repo granular plugins **O-GrainScatter** (`GrainPool.h` preallocated voice array + round-robin/oldest-steal allocation + `computeEnvelope(phase, shape)` + `TripleBuffer` lock-free struct handoff; `LagrangeInterpolation.h` 4-point random-access fractional read; `GrainScheduler.h` per-sample countdown-to-next-grain) and **O-TextureForge** / **O-Freeze** (overlap-add summation, freeze-buffer pinning), and the macOS WebView drag-drop content-streaming pattern from **O-MicrotonalSampler v1.0.4** (`juce::Base64::convertFromBase64`). All JUCE 8 classes below were verified against the local JUCE 8.0.9 source at `/Users/taylorbrook/JUCE/modules/`.

## Complexity & Research Summary

- **Complexity Tier:** **5–6** (MIDI synth with oscillators escalated by file I/O + load-your-own sample streaming AND four first-class real-time visualizations + FFT). Net research depth: **DEEP**. Most of the *infrastructure* (voice model, amp ADSR, lock-free viz ring, FFT analyzer, WebView wiring, CMake synth flags) is inherited from O-simpleFM/O-simpleAdditive; most of the *grain engine* (preallocated grain pool, overlap-add, window LUTs, fractional read, scheduler) is mined near-verbatim from O-GrainScatter/O-TextureForge. The genuinely new integration work is: (a) marrying a polyphonic `Synthesiser` voice to a per-voice grain budget, (b) the source read head with scan/freeze, (c) MIDI-key→grain-pitch resample coupling, (d) band-limited upward transposition, and (e) embedding + load-your-own source buffers feeding the engine.

### Resolved research decisions (the open questions from BRIEF "Likely additions" + STATUS open items)

1. **Density exposure → expose `density` as grains/second (1–200 g/s), and ALWAYS show a live derived overlap readout.** Grains/sec is the most directly hearable, class-grounded control ("how many grains fire per second"), matching the BRIEF's primary framing and O-GrainScatter's density model. The grain period is its reciprocal; the overlap factor is what the lesson actually cares about and is *derived and displayed* rather than controlled. **Overlap readout formula:** `overlap = grainSizeSeconds × density = (grainSizeMs/1000) × densityGrainsPerSec` (mean simultaneous grains from one voice = grain length ÷ grain period). `overlap < 1` ⇒ audible gaps between grains; `overlap ≥ 1` ⇒ continuous overlap-add cloud (FUNC-01/DSP-02 acceptance: "raise density until period < grain size → continuous"). The UI shows e.g. `Overlap: 1.2× (continuous)` / `Overlap: 0.4× (gaps)`. See Algorithm Details → Density & Overlap.
2. **MIDI-key → grain-pitch coupling → key-tracked resample (the held note transposes the grain read increment), combined multiplicatively with `grainPitch` and `pitchSpray`.** This is the synth-sibling-consistent choice (FUNC-02: "each held note transposes the grain cloud to that pitch") and matches every musical granular instrument (Granulator III, GR-1). Gate-only (note merely starts/stops the cloud at fixed pitch) is rejected — it would make the plugin un-playable as an instrument, breaking the sibling pattern. **Combination:** the per-grain read-increment ratio is `rate = 2^((keySemitones + grainPitch + pitchSprayRand) / 12)`, where `keySemitones = noteNumber − rootNote` (root = C3/60 so the source plays back at original pitch on the root key), `grainPitch` ∈ [−24,+24] st is the global offset, and `pitchSprayRand` ∈ [−pitchSpray, +pitchSpray] is the per-grain random st. A held C3 plays the source at its recorded pitch; an octave up doubles the read increment. See Algorithm Details → Transposition.
3. **Anti-aliasing on upward transposition → 4-point Lagrange fractional interpolation (random-access, from O-GrainScatter `lagrangeInterpolate`) for the read, PLUS a one-pole low-pass pre-filter applied to the *source buffer copy used at high rates*, OR (chosen) a simpler per-grain rate-capped approach.** **Decision:** use 4-point Lagrange interpolation for the fractional read (clean, cheap, random-access — required because grains read arbitrary positions, so the stateful `juce::LagrangeInterpolator` streaming class is unsuitable), and apply a **lightweight per-grain one-pole low-pass whose cutoff tracks the playback rate** (`fc ≈ 0.5·fs / max(1, rate)`) so grains transposed up (rate > 1) are band-limited before they alias. This is the pragmatic granular AA approach (Clouds/Beads use interpolation + gentle filtering, not full oversampling). For v1.0 the Lagrange interpolation alone removes most audible aliasing; the rate-tracking one-pole is the DSP-08 cleanliness guarantee for high pitch-spray grains. **Fallback:** if the one-pole proves audibly dull, drop to interpolation-only (still passes for moderate transposition) or add 2× oversampling on the whole engine output (last resort — adds CPU + latency). See Algorithm Details → Anti-aliasing.
4. **Polyphony → 8 voices** (matches the BRIEF proposal; granular is heavier than FM/additive so it is intentionally lower than the suite's usual 16). Confirmed against the grain budget below: 8 voices × 24 grains/voice = 192 max simultaneous grains, comfortably real-time at 48 kHz (each active grain is one fractional read + envelope LUT lookup + one-pole). See decision #5 and Performance.
5. **Max simultaneous grain cap + graceful grain/voice-stealing → per-voice grain pool of `MaxGrainsPerVoice = 24`, with round-robin allocation that steals the OLDEST grain when full (O-GrainScatter `spawnGrain` pattern verbatim).** A bounded preallocated `std::array<Grain, 24>` per voice means `processBlock` never allocates and high density × grain size × polyphony can never xrun — at worst the engine refuses to spawn a new grain (or steals the oldest), thinning the cloud gracefully instead of dropping out (PERF-02). The global ceiling is `8 × 24 = 192` grains. The CPU readout (decision #8) makes this budget visible — the pedagogical payoff. Voice-stealing for *notes* uses `juce::Synthesiser` default (steal quietest/oldest voice). See Core Components → GrainVoice.
6. **Velocity routing → velocity→amplitude always-on; velocity→density opt-in (`velToDensity`, default 0).** Velocity-to-amp is the expected baseline (hard notes louder). An opt-in velocity→density makes hard notes spawn a denser cloud (a small expressive teaching bonus — "play harder, thicker texture") without complicating the default mental model. `velToAmp` is implicit/always-on (folded into the amp envelope's note-on level), so only `velToDensity` is a parameter. See Parameter Mapping.
7. **Per-grain stereo pan spray → INCLUDED as a minimal optional control `panSpray` (0–100%, default 0).** It is cheap (equal-power pan per grain, already in O-GrainScatter's `GrainPool`), it widens the cloud believably, and a stereo granular texture is far more compelling in the classroom than a mono one. Kept minimal: one knob, default 0 (so the default sound is centered and the lesson stays about grain size/density/window first). At `panSpray=0` every grain is centered. See Parameter Mapping + Algorithm Details → Spray.
8. **Grain-count / CPU readout → a live UI readout (NOT a parameter), driven by the active-grain count published via a lock-free atomic, plus the derived overlap factor and a CPU estimate.** The audio thread maintains `std::atomic<int> activeGrainCount` (cheap increment/decrement) and publishes it each block; the editor reads it on its 30 Hz Timer and displays `Grains: 137 / 192` plus the overlap factor and a coarse CPU bar (`activeGrains / maxGrains` as a proxy, optionally refined with `AudioProcessLoadMeasurer`). This is first-class pedagogy: the class explicitly teaches that *density × grain size × polyphony = CPU cost*, and why producers freeze-and-bounce (UI-05). See Visualization Data Path.
9. **Source-length cap → 10 seconds at the engine sample rate (≈ 1.7 MB mono float @ 44.1 kHz; ≈ 3.5 MB stereo).** Built-ins are short (the BRIEF's worked examples — fire, voice, water, piano hit — are 1–3 s). Loaded files longer than 10 s are truncated (with a UI notice) so the read-head/position math and the waveform display stay bounded and the memory is trivial. The source is stored as a single interleaved-or-planar `juce::AudioBuffer<float>` resampled to the engine rate at load time (off the audio thread). See System Architecture → File I/O.
10. **Built-in sample embedding → embed curated built-ins (fire, voice, water, piano hit) as `.wav` (or `.flac`) binary via `juce_add_binary_data`; at startup decode each through `juce::AudioFormatManager::createReaderFor(std::make_unique<juce::MemoryInputStream>(BinaryData::xxx, BinaryData::xxxSize, false))` and resample to the engine rate into the source buffer.** No in-repo plugin currently embeds audio (they all load from disk), but `juce_add_binary_data` accepts any file type — the `.wav` bytes become `BinaryData::fire_wav` / `BinaryData::fire_wavSize`, wrapped in a `MemoryInputStream` and read by the format manager (both `createReaderFor` overloads verified locally). `WavAudioFormat`/`FlacAudioFormat` are registered via `registerBasicFormats()`. Decoding + resampling happens once at construction / on selection, off the audio thread. See System Architecture → File I/O.
11. **Read-head model → the source read position (the "playhead") advances by the Scan/Time-Stretch rate each sample; Freeze pins it.** `Scan` ∈ [−200%, +200%] is the read-head velocity *through the source* expressed as a fraction of realtime (0% = held at `position`; 100% = realtime forward; −100% = realtime reverse; ±200% = double speed). This is a global per-engine playhead (shared by all voices/grains — grains read offsets relative to it ± position spray), NOT per-grain, so the "freeze one instant / stretch one moment" lesson reads cleanly on the waveform display. `Freeze=on` forces the playhead velocity to 0 and pins it (zipper-free crossfade on engage/disengage — QUAL-01). See Core Components → Read Head.

## Core Components

### Granular Voice (GrainVoice : juce::SynthesiserVoice)
- **JUCE Class:** Custom `GrainVoice : juce::SynthesiserVoice` (owns a preallocated `std::array<Grain, MaxGrainsPerVoice=24>` grain pool, a per-voice `GrainScheduler` countdown, a `juce::ADSR` amp env, and the per-voice key transposition ratio).
- **Purpose:** Render one polyphonic granular voice transposed to its MIDI note: schedule grains at the density-derived period, read each windowed grain from the shared source buffer at `voiceRate × grainPitch × pitchSpray`, overlap-add them, shape by amp ADSR. The shared read-head position + scan/freeze are owned by the processor (global) and read by every voice.
- **Parameters Affected:** `grainSize`, `density`, `windowShape`, `pitchSpray`, `positionSpray`, `scatter`, `grainPitch`, `panSpray`, all amp ADSR params, `velToDensity`, and (via the shared read head) `position`, `scan`, `freeze`.
- **Configuration:**
  - **Per-voice key rate:** at note-on, `voiceRate = 2^((noteNumber − ROOT_NOTE) / 12)` (ROOT_NOTE = 60 / C3). This multiplies every grain's read increment so the held note transposes the cloud (decision #2).
  - **Scheduler (per sample, countdown — O-GrainScatter `processBlockFree` pattern):**
    ```cpp
    // grain period derived from density (+ velToDensity), randomized by scatter:
    float baseIntervalSamp = sampleRate / densityGrainsPerSec;          // mean inter-grain gap
    float jitter = (scatter/100.f) * baseIntervalSamp * (rng.nextFloat()*2.f - 1.f);
    int   nextInterval = jmax(1, (int)(baseIntervalSamp + jitter));     // scatter → async
    if (--samplesUntilNextGrain <= 0) { spawnGrain(...); samplesUntilNextGrain = nextInterval; }
    ```
  - **spawnGrain (round-robin / steal-oldest — O-GrainScatter `GrainPool::spawnGrain` verbatim):** find an inactive grain slot, else steal the oldest; initialize its read position, rate, pan, length, window phase. Bounded by `MaxGrainsPerVoice` (decision #5) ⇒ never allocates, never xruns.
  - **Per-grain read (per active grain, per sample — overlap-add):**
    ```cpp
    float env  = windowLUT.read(grainShape, grain.phase);              // 0..1 from precomputed LUT
    float rate = voiceRate * grainPitchRatio * grain.pitchSprayRatio;  // combined transposition
    float src  = readSourceLagrange(grain.readPos);                    // 4-pt fractional read
    src        = grain.aaFilter.processOnePole(src, rate);             // rate-tracking AA low-pass
    float s    = src * env;
    float panL = cos(grain.pan * halfPi), panR = sin(grain.pan * halfPi);
    outL += s * panL;  outR += s * panR;                               // equal-power pan
    grain.readPos += rate; grain.phase += 1.f/grain.lengthSamples;
    if (grain.phase >= 1.f) grain.active = false;                      // grain done
    ```
  - **Voice output:** `(outL,outR) × ampEnv.getNextSample()`; voice lifetime = `ampEnv.isActive()` (note-off → release tail; Freeze sustains by keeping the playhead pinned and the note held).
  - **Prepare:** custom `prepareToPlay(sampleRate, maxBlockSize)` sets `setCurrentPlaybackSampleRate` + `ampEnv.setSampleRate` **before** first `setParameters` (JUCE 8 `SynthesiserVoice` has NO virtual `prepareToPlay` — confirmed from O-simpleFM `FMVoice`).
  - **Note-on reset:** clear all grains (`active=false`), reset scheduler countdown, compute `voiceRate`, trigger amp ADSR. Grains spawned from note-on inherit the *current* global playhead position.

### Source Buffer + Read Head
- **JUCE Class:** Custom (`juce::AudioBuffer<float>` source + a `double playheadPos` advanced per sample; `FreezeManager`-style pin from O-GrainScatter/O-Freeze).
- **Purpose:** Hold the (resampled-to-engine-rate) source sound and provide the moving read point grains read from. THE raw material + the position/scan/freeze lesson surface (FUNC-03, FUNC-04, DSP-06).
- **Parameters Affected:** `position`, `scan`, `freeze`, `positionSpray` (per-grain offset), `sourceSample` (selection).
- **Configuration:**
  - Source stored as `AudioBuffer<float>` (mono or stereo), length capped at 10 s @ engine rate (decision #9). Read by grains via 4-point Lagrange (random access).
  - **Playhead:** `playheadPos` (in source samples) is the global read point. Per block: `playheadVelocity = (scan/100) × (sampleRate-relative)`; advance `playheadPos += playheadVelocity` per sample, wrap within `[0, sourceLen)`. `Freeze=on` ⇒ velocity forced to 0, `playheadPos` pinned to its current value (smoothed transition to avoid a click — QUAL-01).
  - **Grain spawn position:** `grainReadStart = positionAbsolute + positionSprayRand`, where `positionAbsolute = position% × sourceLen` blended with the moving playhead (manual `position` sets the base; `scan` moves it; `positionSpray` scatters per grain). The playhead and `position` are unified: `position` sets the playhead's resting point; `scan` is its velocity; `freeze` pins it.
  - **Hot-swap on `sourceSample` change / load:** swap the source buffer pointer via a lock-free atomic pointer swap (double-buffer — new buffer built off-thread, atomically published; old buffer freed after a safe interval), so the audio thread never touches a half-loaded buffer (O-MicrotonalSampler / DrumRoulette pattern).

### Window LUTs (five precomputed envelopes)
- **JUCE Class:** Custom (five precomputed `std::array<float, LUT_SIZE>` tables; `computeEnvelope(phase, shape)` from O-GrainScatter `GrainPool` adapted to the five class shapes).
- **Purpose:** The per-grain amplitude envelope — THE single most audible low-level control. The five class-figure shapes; rectangular's per-grain click is a **real, intended teaching artifact, not a bug** (DSP-03).
- **Parameters Affected:** `windowShape`.
- **Configuration:**
  - Five shapes (BRIEF figure): **rectangular** (`1.0` flat — clicks at edges, the teaching artifact), **triangular** (`1 − |2φ−1|`), **Welch** (parabolic: `1 − (2φ−1)²`), **Gaussian** (`exp(−0.5·((φ−0.5)/σ)²)`, σ≈0.18, normalized to 1 at center), **Hann** (`0.5·(1−cos(2πφ))`).
  - Precompute each as a `LUT_SIZE = 2048`-point table at construction (sample-rate-independent — indexed by grain phase 0..1). Read with linear interpolation. **No per-sample transcendental** in the grain loop (cheap, exactly the O-simpleAdditive table rationale).
  - The **window-envelope inset** (UI-03) draws the selected LUT directly — one grain's envelope, redrawn on shape change.

### Grain Scheduler (per voice)
- **JUCE Class:** Custom (per-sample countdown — O-GrainScatter `GrainScheduler::processBlockFree` pattern, free-mode only).
- **Purpose:** Fire grains at the density-derived period, randomized by `scatter` — the synchronous→asynchronous axis (DSP-05).
- **Parameters Affected:** `density`, `scatter`, `velToDensity`.
- **Configuration:**
  - Base period `= sampleRate / effectiveDensity`, where `effectiveDensity = density × (1 + velToDensity·(velocity−0.5)·2)` clamped to [1,200].
  - `scatter` (0–100%) jitters each interval: `interval = base × (1 + scatter%·U(−1,1))` (or jitters the period directly). At 0% the period is constant (synchronous → discrete sidebands, pitched); at high % it is random (asynchronous → noise). This is the one-knob sync↔async control (DSP-05 acceptance: spectrum view shows sidebands→noise).

### Amplitude Envelope (Amp ADSR)
- **JUCE Class:** `juce::ADSR` + `juce::ADSR::Parameters` (verified `juce_audio_basics/utilities/juce_ADSR.h`).
- **Purpose:** Shape per-voice output amplitude; governs voice lifetime (DSP-07).
- **Parameters Affected:** `ampAttack`, `ampDecay`, `ampSustain`, `ampRelease`, velocity→amplitude (always on).
- **Configuration:** times 0–5 s (skew ~0.35 for fine low-end control), sustain 0–1. `setSampleRate` in prepare before first `setParameters`. Mirrors O-simpleFM/O-simpleAdditive exactly. Velocity scales note-on level (velToAmp implicit/always-on).

### Anti-Aliasing Read (per grain)
- **JUCE Class:** Custom (`lagrangeInterpolate` 4-point random-access from O-GrainScatter `LagrangeInterpolation.h` + a per-grain one-pole low-pass).
- **Purpose:** Clean fractional-position reads and band-limited upward transposition so high pitch-spray grains don't buzz (DSP-08).
- **Parameters Affected:** (driven by combined transposition rate; no direct param).
- **Configuration:** 4-point Lagrange for the fractional source read (random access — grains read arbitrary positions). For grains with `rate > 1` (transposed up), a one-pole low-pass with `fc ≈ 0.5·fs / rate` band-limits before aliasing. At `rate ≤ 1` the filter is bypassed (no down-transposition aliasing). See Architecture Decisions §3.

### Output Stage
- **JUCE Class:** `juce::SmoothedValue<float>` gain + final block NaN scrub.
- **Purpose:** Master output trim, summed-voice/grain headroom, suite-wide NaN insurance.
- **Parameters Affected:** `outputLevel` (dB).
- **Configuration:** dB→linear gain, 20 ms smoothing. **Headroom:** overlapping grains sum; normalize by a function of overlap (or a fixed headroom factor + soft-clip safety) so a dense high-overlap cloud doesn't clip, then trim with `outputLevel`. Block-level `std::isfinite` scrub after summing voices.

### Visualization Tap (Scope/Spectrum + Grain-cloud + Playheads + CPU) — REUSED + EXTENDED
- **JUCE Class:** `VizRing` + `FmVizAnalyzer` (lock-free ring + message-thread FFT, lifted from O-simpleFM `FmVizAnalyzer.h`) for the output scope/spectrum (UI-04); a `TripleBuffer<GrainCloudFrame>` (O-GrainScatter, lock-free SPSC) for grain events (cloud scatter UI-01 + waveform playheads UI-02); a `std::atomic<int> activeGrainCount` for the CPU readout (UI-05). FFT runs on the **message thread** (editor Timer), never the audio thread.
- **Purpose:** Feed all four live visualizations + the CPU readout. Audio thread is allocation-free and copy-only.
- **Parameters Affected:** none (read-only taps).
- **Configuration:** see **Visualization Data Path** below. Lift `VizRing`+`FmVizAnalyzer` and `TripleBuffer` essentially unchanged.

## Processing Chain

```
MIDI in
  ↓
[processor, per block]  read APVTS atomics → push to voices; advance GLOBAL read head:
     playheadVelocity = (scan/100)·realtime   (Freeze on ⇒ velocity 0, pin playhead, smoothed)
     playheadPos += playheadVelocity  (per sample, wrapped to [0, sourceLen))   ← position, scan, freeze
  ↓
juce::Synthesiser (8 × GrainVoice)
  │   ── per voice ──
  │     voiceRate = 2^((note − ROOT)/12)                                          ← MIDI key (decision #2)
  │     scheduler: period = fs / (density·velToDensity); jitter by scatter        ← density, scatter, velToDensity
  │        on fire → spawnGrain (round-robin / steal-oldest, bounded 24/voice)    ← PERF-02 grain cap
  │           grain.readStart = playheadPos + positionSprayRand·sourceLen         ← position, positionSpray
  │           grain.rate      = voiceRate · 2^((grainPitch + pitchSprayRand)/12)  ← grainPitch, pitchSpray
  │           grain.length    = grainSize ms · fs                                 ← grainSize
  │           grain.pan       = 0.5 + panSprayRand·0.5                            ← panSpray
  │           grain.shape     = windowShape                                       ← windowShape
  │     ── per active grain, per sample (OVERLAP-ADD) ──
  │        env  = windowLUT[shape].read(grain.phase)                              ← windowShape (precomputed LUT)
  │        src  = readSourceLagrange(grain.readPos)        (4-pt fractional)
  │        src  = aaOnePole(src, grain.rate)               (band-limit if rate>1) ← DSP-08
  │        s    = src · env ; outL += s·panL ; outR += s·panR                     (equal-power)
  │        grain.readPos += grain.rate ; grain.phase += 1/grain.length
  │     voiceOut = (outL,outR) · ampEnv                                           ← amp ADSR + voice lifetime
  ↓ (sum of active voices; headroom-normalized for overlap)
Output gain (SmoothedValue, dB→lin)  ← outputLevel
  ↓
NaN scrub (std::isfinite insurance)
  ↓
[TAPS — audio thread, lock-free, no alloc, no FFT]
   mono-sum → VizRing                                  (output scope/spectrum, UI-04)
   per-spawn grain event → TripleBuffer<GrainCloudFrame> (cloud scatter UI-01 + playheads UI-02)
   activeGrainCount (atomic int)                        (grain-count / CPU readout, UI-05)
  ↓
Audio out (stereo)

   ── message thread (Editor Timer 30 Hz) ──
   VizRing → copy scope window (BEFORE FFT) → scope + FFT(4096/Blackman-Harris) → "scopeUpdate"/"spectrumUpdate" (UI-04)
   TripleBuffer.read() → grain cloud dots (pos×time) + waveform playheads + spray-range shade → "grainCloudUpdate" (UI-01/02)
   activeGrainCount + derived overlap → "grainMeterUpdate" (UI-05)
   window LUT[selected] snapshot → "windowInsetUpdate" (UI-03)
        → emitEventIfBrowserIsVisible(...) → WebView JS draws
```

**Routing notes:**
- **No feedback loop.** Granular overlap-add is feed-forward — no self-modulation, no global feedback path. Removes the single hardest stability risk (vs O-simpleFM's DX7 feedback). Lower-risk than the FM sibling.
- **The global read head is owned by the processor**, advanced once per sample, and read by every voice/grain. `position` sets its resting point, `scan` its velocity, `freeze` pins it. Grains read offsets *relative to it* (± position spray). This keeps the "freeze/stretch one instant" lesson reading cleanly on the waveform display (one moving playhead, not per-grain chaos).
- **Spray and scatter are per-grain RNG** (audio-thread-safe `juce::Random` per voice — no allocation, no lock). Scatter randomizes the *period* (sync↔async); position spray the *read start*; pitch spray the *rate*; pan spray the *pan*.
- **Band-limiting is applied per grain only when transposed up** (`rate > 1`) via a rate-tracking one-pole — cheap, no global oversampling, zero added latency.
- **Visualization is read-only taps**, never in the audio return path. Grain *events* go through `TripleBuffer` (struct handoff); output *samples* through `VizRing`; the grain *count* through an atomic int.

## System Architecture

### File I/O System (built-in embedding + load-your-own)

**File types supported:** `.wav`, `.aiff`, `.flac` (via `AudioFormatManager::registerBasicFormats()`); built-ins ship as embedded `.wav`/`.flac`.

**Loading strategy:** Off-audio-thread decode + resample into an `AudioBuffer<float>`, then atomic pointer-swap to publish to the engine. The audio thread only ever reads a fully-built, published source buffer (never a half-loaded one).

**Built-in embedding (decision #10):**
- Curated built-ins (fire, voice, water, piano hit — the class worked examples) embedded via `juce_add_binary_data(O-simpleGrain_Samples SOURCES Source/samples/fire.wav voice.wav water.wav piano.wav)` → `BinaryData::fire_wav` / `BinaryData::fire_wavSize`.
- Decode: `auto reader = formatManager.createReaderFor(std::make_unique<juce::MemoryInputStream>(BinaryData::fire_wav, (size_t)BinaryData::fire_wavSize, false));` → `reader->read(&buffer, ...)` → resample to engine rate (`juce::LagrangeInterpolator` or `juce::ResamplingAudioSource` / offline ratio resample). Both `createReaderFor` overloads (File + InputStream) verified in local JUCE 8.0.9.
- Done at construction (or on `sourceSample` change) on the message/background thread — never the audio thread.

**Load-your-own (FUNC-05) — macOS WebView content-streaming drag-drop + file-picker fallback:**

- **Source-length cap (decision #9):** truncate loaded files to 10 s @ engine rate (UI notice if truncated).

## Algorithm Details

### Granular overlap-add (the pedagogical core)
A grain is a short (2–200 ms) fragment of the source multiplied by an amplitude **window**. The scheduler fires grains at a period; when the period is **shorter** than the grain length, grains overlap and **sum** (overlap-add) into one continuous sound. `overlap = grainLength / grainPeriod = grainSizeSec × density`. `overlap < 1` → audible gaps (DSP-01: separated grains); `overlap ≥ 1` → continuous cloud (FUNC-01 acceptance). This is the literal overlap-add identity the class teaches; the engine is feed-forward (no feedback).

### Density & Overlap (decision #1)
`density` (grains/s) is the user control; period `= fs/density`; the **derived overlap readout** = `(grainSizeMs/1000)·density`, displayed live (`Overlap: X.X× (continuous|gaps)`). Raising density past `1/grainSizeSec` crosses into continuous overlap-add — the headline DSP-02 demo, made visible by the readout and the thickening cloud.

### Transposition (decision #2 — MIDI key + grainPitch + pitchSpray)
Per-grain read-increment ratio `rate = 2^((noteSemitones + grainPitch + pitchSprayRand)/12)`, `noteSemitones = noteNumber − 60`. The read position advances by `rate` per sample (so `rate=2` reads twice as fast = one octave up). A held C3 plays the source at recorded pitch; chords transpose copies of the cloud. `pitchSprayRand ∈ [−pitchSpray, +pitchSpray]` st is fresh per grain (makes a frozen texture shimmer instead of buzzing — DSP-04).

### Anti-aliasing (decision #3, DSP-08)
Fractional read via 4-point **Lagrange** (`lagrangeInterpolate(ym1,y0,y1,y2,frac)` from O-GrainScatter — random-access, stateless, correct for arbitrary grain positions). For up-transposed grains (`rate > 1`) a per-grain **one-pole low-pass** with `fc ≈ 0.5·fs/rate` band-limits before the read crosses Nyquist (`y += g·(x−y)`, `g` from `fc`). At `rate ≤ 1` the filter is bypassed. This keeps high pitch-spray grains clean without global oversampling (no added latency). Fallback: interpolation-only, or whole-engine 2× oversampling if needed.

### Spray & Scatter (decisions #6/#7, DSP-04/05)
Per-voice `juce::Random` (no alloc, no lock). **Position spray:** `grainReadStart = playheadPos + U(−1,1)·positionSpray%·sourceLen`. **Pitch spray:** `±U·pitchSpray` st into the rate (above). **Scatter:** jitter the scheduler period `interval = base·(1 + scatter%·U(−1,1))` — at 0% constant (synchronous → discrete sidebands), at 100% random (asynchronous → noise; DSP-05 spectrum acceptance). **Pan spray:** `grain.pan = 0.5 + U·panSpray%·0.5`, equal-power.

### Window shapes (DSP-03)
Five precomputed 2048-pt LUTs read by grain phase 0..1: rectangular (flat 1.0 — clicks at hard edges, the teaching artifact), triangular, Welch (parabolic), Gaussian (σ≈0.18), Hann. Linear-interp read in the grain loop (no per-sample transcendental). The window-envelope inset (UI-03) draws the selected LUT.

### Read head: scan / freeze (DSP-06, FUNC-03)
Playhead velocity `= scan%·realtime` (per sample), wrapped to `[0, sourceLen)`; `position` sets the resting point. `Freeze=on` ⇒ velocity 0, pin the playhead (smoothed crossfade on engage/disengage so freeze→unfreeze is click-free — QUAL-01/FUNC-03 acceptance). Negative scan = reverse; |scan|<100% = stretched/slowed; >100% = faster.

### Headroom / clipping
Overlapping grains sum; peak grows with overlap. Normalize the voice sum by a function of overlap (or a fixed headroom factor) so dense clouds don't clip; soft-safety + block-level `isfinite` scrub; `outputLevel` trim.

### Preset Recipes (FUNC-06 — concept-isolating preset tour)
**Star** = the concept each isolates.
| Preset | Settings | Star concept |
|--------|----------|--------------|
| Single Grain | density ~1 g/s, grain 60 ms, no spray | one grain, the atom |
| Pitched Buzz | grain 3 ms, density 200, scatter 0, Hann | few-ms grains = pitched buzz (DSP-01) |
| Fragments | grain 50 ms, density 20, scatter 0 | tens-of-ms = recognizable fragments (DSP-01) |
| Smooth Cloud | grain 40 ms, density 80 (overlap>1), Hann | continuous overlap-add (DSP-02) |
| Frozen Pad | freeze on, grain 50 ms, density 60, pitch+pos spray | one instant → shimmering pad (FUNC-03) |
| Asynchronous Cloud | scatter 100%, pos spray 60%, grain 20 ms | sync→async, noisy cloud (DSP-05) |
| Granular Fire | source=fire, grain 8 ms, scatter 80%, pos spray 70%, density 120 | the class worked example — endless crackle |
| Rect Click | window=rectangular, grain 30 ms, density 30 | why a rectangular window clicks (DSP-03) |

## Integration Points

### Feature Dependency Graph
```
sourceSample / Load… ─► source AudioBuffer (resampled, ≤10 s)  [off-thread, atomic publish]
                          │
position ──► playhead resting point ─┐
scan ──────► playhead velocity ──────┼─► GLOBAL read head (per sample, wrapped)
freeze ────► pin velocity=0 ─────────┘        │
                                              ▼  grain.readStart = playhead + positionSprayRand
MIDI note ─► voiceRate = 2^((note−60)/12) ─┐
grainPitch ────────────────────────────────┼─► grain.rate = voiceRate·2^((grainPitch+pitchSprayRand)/12)
pitchSpray ─► per-grain rand ───────────────┘        │
density (+velToDensity) ─► scheduler period ─┐       ▼  readSourceLagrange → aaOnePole(if rate>1)
scatter ─► jitter period ────────────────────┘       │
windowShape ─► windowLUT[shape].read(phase) ─────────┼─► env ; overlap-add ; equal-power pan(panSpray)
                                                     ▼
ampEnv (Amp ADSR) ─► amplitude + voice lifetime
                                                     ▼
voice sum ─► headroom ─► output gain ─► [VizRing | TripleBuffer<grain events> | activeGrainCount]
```

### Processing Order (load-bearing)
1. **Processor, once per block:** read APVTS atomics; push to each voice via `setParams(...)` (O-simpleFM block-push). **Advance the global read head per sample** (scan/freeze) — it is shared, so it must be computed in the processor, not per voice.
2. **Per note-on:** compute `voiceRate`; clear the voice's grain pool; reset scheduler; trigger amp ADSR.
3. **Per voice, per sample:** run scheduler countdown → spawn grains (bounded pool, steal-oldest); for each active grain, read (Lagrange + AA) → window → overlap-add → equal-power pan.
4. **Sum voices → headroom-normalize → output gain.**
5. **Taps last** (post-gain, copy-only): `VizRing` (samples), `TripleBuffer` (grain events at spawn), `activeGrainCount` (atomic). FFT/cloud/meter built on the message thread.

### Parameter Interactions
- **grainSize × density = overlap.** The central interaction; the overlap readout makes it visible. High both = dense continuous cloud (and the highest CPU — the CPU-cost lesson).
- **density × grainSize × polyphony = grain budget = CPU.** Bounded by `MaxGrainsPerVoice` (steal-oldest) so it can't xrun; the CPU readout shows the cost (UI-05, the explicit class lesson).
- **scatter × everything spectral.** Scatter alone moves the output from pitched (discrete sidebands) to noisy (smeared) — the sync↔async axis (DSP-05).
- **freeze × scan.** Freeze overrides scan (pins the playhead). Position spray still scatters reads *within* the frozen region → a frozen pad shimmers rather than buzzing on one grain (FUNC-03).
- **MIDI key × grainPitch × pitchSpray.** All three multiply into the read increment; held note + global offset + per-grain jitter combine (decision #2).
- **velocity × amp (always) and × density (opt-in).** Harder = louder, and optionally denser.

| 7 | Four real-time visualizations | MEDIUM | Audio-thread alloc/FFT (PERF-01 fail) or laggy UI | **Reuse `VizRing`+`FmVizAnalyzer`** (samples→scope/FFT) + **`TripleBuffer`** (grain events) + atomic int (count) — all lock-free, FFT on message thread. Copy scope window before in-place FFT. |

**Overall complexity:** MEDIUM-HIGH. **Highest-risk component:** load-your-own macOS drag-drop (#2) — but it is fully de-risked by an existing, documented, shipped pattern (O-MicrotonalSampler v1.0.4) and a guaranteed picker fallback, so it is HIGH-effort, LOW-residual-risk. ## Architecture Decisions

1. **Preallocated bounded grain pool + steal-oldest over dynamic grain lists (WHY):** A fixed `std::array<Grain, 24>` per voice (192 global) makes `processBlock` allocation-free and makes xruns structurally impossible — the engine thins the cloud (steals the oldest grain) rather than dropping out. This is the O-GrainScatter `GrainPool` pattern, proven in a shipped granular plugin. **Tradeoff:** a hard ceiling on simultaneous grains — but 192 is plenty for a teaching instrument, and the ceiling is the *point* (the CPU-cost lesson, UI-05). **Alternative rejected:** `std::vector<Grain>` grown on demand — allocates on the audio thread (PERF-01 violation).
2. **Global read head (one playhead) over per-grain read positions (WHY):** A single processor-owned playhead (with `position`/`scan`/`freeze`) keeps the "freeze/stretch one instant" lesson legible — the waveform display shows one moving playhead and a position-spray shade, not per-grain chaos. Grains read offsets relative to it. **Alternative:** each grain owns an independent free-running position — harder to visualize and to teach freeze/stretch.
3. **Per-grain Lagrange interpolation + rate-tracking one-pole over global oversampling (WHY):** Grains read arbitrary random positions, so a stateful streaming resampler (`juce::LagrangeInterpolator`) is unsuitable; the 4-point random-access `lagrangeInterpolate` is correct and cheap. A per-grain one-pole that tracks playback rate band-limits up-transposed grains without the CPU + latency of whole-engine oversampling. This matches how Clouds/Beads handle pitch (interpolation + gentle filtering). **Tradeoff:** not a brickwall AA — acceptable for a teaching tool; fallback to 2× OS documented. **Alternative rejected:** 2× oversampling everywhere — adds latency and CPU for a pedagogical instrument that doesn't need surgical AA.
4. **8 voices (WHY):** Granular is heavier than FM/additive (each voice runs up to 24 grains). 8 × 24 = 192 grains is comfortably real-time and ample for chordal classroom demos. **Alternative:** 16 (suite norm) — unnecessary, and would push the grain budget to 384 with no pedagogical gain.
5. **Key-tracked resample for MIDI (WHY):** A synth sibling must be playable as an instrument (FUNC-02). Key-tracked resample (note transposes the read increment) is what every musical granular engine does and is consistent with O-simpleFM/Additive. **Alternative rejected:** gate-only — un-musical, breaks the sibling pattern.
6. **density = grains/sec with a derived overlap readout (WHY):** Grains/sec is the most directly hearable, class-grounded control; overlap is what the lesson cares about and is shown live. **Alternative:** expose overlap factor directly — less intuitive ("how many grains per second" is concrete; "1.4× overlap" is abstract). Show both, control the concrete one.
7. **Embed built-ins as `.wav` via `juce_add_binary_data` + decode at startup (WHY):** Frictionless projector demo (the class worked examples ship in the binary; no missing-file risk). `juce_add_binary_data` handles any file type; decode via `MemoryInputStream` + `AudioFormatManager`. **Alternative:** ship loose files alongside the plugin — fragile (paths break on install).
8. **TripleBuffer for grain events + VizRing for samples + atomic int for count (WHY):** Three different data shapes (struct events / sample stream / scalar count) → three right-sized lock-free primitives, all proven in-repo. Keeps the audio thread allocation-free and the four visuals truthful. **Alternative:** one big FIFO for everything — awkward and over-engineered.
9. **No feedback, no spectral STFT in v1.0 (WHY):** Overlap-add granular is feed-forward (removes the hardest stability class). Spectral STFT is deliberately deferred to a future sibling (O-simpleSpectral) to preserve the strict one-concept discipline of the trilogy (BRIEF Out-of-Scope).

## Special Considerations

- **Thread safety:** APVTS atomics for params; `VizRing` + `TripleBuffer` + atomic grain count for audio→UI; **atomic pointer swap** for source-buffer hot-swap; no locks on the audio thread; UI never calls processing code (critical-pattern #5). Per-voice `juce::Random` for spray/scatter (no shared RNG state).
- **Performance:** 8 voices × up to 24 grains × (1 Lagrange read + 1 LUT lookup + optional one-pole) per sample. Worst case 192 grains × ~10 flops ≈ trivial-to-moderate at 48 kHz — comfortably under one core. The bounded pool caps it. CPU readout (UI-05) surfaces the cost pedagogically. 4096 FFT @ 30 Hz on the message thread is cheap.
- **Denormals:** `juce::ScopedNoDenormals` at the top of `processBlock`; block-level `std::isfinite` scrub after summing voices; the AA one-pole state and ADSR tails warrant the guard (no feedback loop, so denormal exposure is otherwise low).
- **Sample rate:** the source buffer is **resampled to the engine rate at load** (so grain math is sample-rate-clean); grain lengths (`grainSize ms × fs`), scheduler periods (`fs/density`), and AA cutoffs (`0.5fs/rate`) use current `fs`; recompute on `prepareToPlay`. Window LUTs are sample-rate-independent (indexed by phase). ADSR `setSampleRate` before `setParameters`.
- **Latency:** **Zero added latency** in v1.0 (no oversampling, no lookahead) — report `setLatencySamples(0)` (NB: `getLatencySamples()` is non-virtual in JUCE 8; do NOT override). If the 2× OS fallback (decision #3) is ever needed, report its latency then.
- **Zipper noise (QUAL-01):** `SmoothedValue` on `scan`, `outputLevel`, and the playhead; crossfade on freeze engage/disengage; never hard-jump the playhead or reset grain phase mid-grain. The ONLY intentional click is the **rectangular window** per-grain artifact (a teaching feature, not a bug — DSP-03).

- **Whole-engine 2× oversampling** — only if the per-grain one-pole proves insufficient (AA fallback, decision #3).

Honoring the BRIEF/REQUIREMENTS Out-of-Scope list, v1.0 also excludes: spectral STFT freeze/blur/filter (→ O-simpleSpectral), phase-vocoder/tempo-locked stretch, live-input recording, effects (reverb/delay/chorus), deep modulation matrix / LFO networks.
