# O-ParametricEQ — Stage 2 / Phase 2.1 Execution Plan (Section designer and offline gate)

## Goal

The closed-form section designer exists in C++ as pure headers and is proved offline: all eight types, eight slopes, the Nyquist policy, boost / cut by inversion. Gate G1 passes at the Stage 0 tolerance at five sample rates and the RBJ control fails it. The designer agrees with the Python reference model on a committed golden. The designer's public shape is "band settings in, up to eight section parameter sets out", with the true analog section exposed per section, so Phase 2.1b can wrap it without an interface change.

Out of scope: the polish (Phase 2.1b, `PLAN-2.1b.md`), any change to `PluginProcessor.*`, the SVF / one-pole audio engine (2.2), smoothing (2.3). `Source/dsp/` headers are not included from the processor in this phase, so the plugin binary is unchanged: version stays 0.1.0, no CHANGELOG entry, no install, no pluginval.

## Plan-phase decisions

- **P1 The designer is standard C++17 only.** `Source/dsp/*.h` include `<cmath>`, `<array>`, `<cstdint>`, `<limits>` and nothing from JUCE. ARCHITECTURE says "`juce_core` only"; none of it is needed, and a std-only designer makes the harness a plain executable with no plugin identity macros. Recorded as a narrowing, not a deviation.
- **P2 `eq::Designer` is a small class, not free functions:** `prepare (double sampleRate)` then `design (const BandSettings&, BandDesign&) const noexcept`. In 2.1 `prepare` stores the rate only; in 2.1b it also builds the polish grid. One instance per thread (ARCHITECTURE "Thread Safety").
- **P3 One boost / cut convention from the start** (RESEARCH Q5): every gain-bearing band is designed on its boost side (`gEff ≥ 0`; for shelves and tilt `Gl ≥ 1`) and a cut is the algebraic inverse of each section. This covers the MLR sections and the first-order shelf section alike. Notch and Band Pass are never inverted. At `gEff == 0` the boost path is taken (identity).
- **P4 `Prototype` returns two things per section:** the *design-side* analog section (after the bell re-centre and the notch / band-pass clamps) and the *true* analog section (before them). 2.1 uses the true one only for scoring; 2.1b uses it as the fit target (RESEARCH pitfall 7).
- **P5 The Python model is promoted to `tests/model/` and is the independent reference.** The research directory stays untouched as evidence. `tests/golden/designs.tsv` is generated by the model and committed; the C++ must match it. This is the Stage 1 "a golden cannot certify itself" rule: the C++ never writes this golden.
- **P6 G1 is scored on a log grid plus points tied to each section's peak** (RESEARCH pitfall 4), from 20 Hz to `min (20 kHz, 0.499 fs)`.
- **P7 Notch and Band Pass get regression ceilings below their clamps, and are only reported above them** (RESEARCH Q2). The ceilings bind (rows NB1–NB4): the C++ is tied to the model by D1, so they are deterministic.
- **P8 A G1 failure stops the phase.** ROADMAP's decision point says "switch to the fallback". Research shows MLR passing with margin in the model and in a C++ port, so a failure here is most likely a bug: debug against D1 first. If G1 still fails with D1 green, STOP and escalate; do not write the Vicanek fallback in this session (it has no general-Q shelf, which reopens D7b).
- **P9 The thinnest row is not tightened:** 6 dB/oct shelf at ±12 dB (0.31 against 0.34). Its tolerance stays `0.10 + 0.02 |g|`.
- **P10 Floating-point flags.** No fast-math anywhere (verified at plan time: `juce_recommended_config_flags` is `-O3` / `/Ox`; the suite CMake sets none). The harness target sets no FP option of its own. Bit-identity between the harness TU and the processor TU is a Phase 2.2 row; this phase gates determinism within one binary and across two threads.

## Interface (binding for 2.1b and 2.2)

```cpp
namespace eq
{
enum class Type : int { bell, lowShelf, highShelf, lowCut, highCut, notch, bandPass, tilt };   // = bNN_type index
inline constexpr int slopeOrder[8] = { 1, 2, 3, 4, 6, 8, 12, 16 };                             // = bNN_slope index
inline constexpr int maxSections = 8;

struct BandSettings { Type type; double freqHz; double gainDbEff; double q; int slopeIndex; }; // gainDbEff already scaled and clamped to ±60

enum class SectionClass : std::uint8_t { gain2, gain1, cutLp2, cutHp2, cutLp1, cutHp1, notch, bandPass };

struct AnalogSection { double wz, Qz, wp, Qp, c; };       // rad/sample; first-order sections use wz, wp, c
struct SectionParams                                      // the eight numbers of ARCHITECTURE
{
    double g, k, mL, mB, mH;                              // SVF (unused when !hasSvf)
    double G, cL, cH;                                     // one-pole (unused when !hasOnePole)
    bool hasSvf, hasOnePole;
};
struct BandDesign
{
    int numSections;
    std::array<SectionParams, maxSections> params;
    std::array<SectionClass,  maxSections> cls;
    std::array<AnalogSection, maxSections> trueProto;     // boost side, before re-centre / clamps
    bool inverted;                                        // true when the band was designed as a boost and inverted
};
}
```

Section order within a band: second-order sections in Butterworth index order (`Q0` first), the first-order section last. `gain2` = MLR section (SVF + corrector). `gain1` = Vicanek 2019 shelf one-pole. A cut's 2nd-order section has `hasOnePole = false`; a first-order section has `hasSvf = false`. Tilt's scalar is folded into the last section's `cL, cH` (ARCHITECTURE table).

**T5. `Source/dsp/Prototype.h`** [agent]
- `buildPrototype (const BandSettings&, double fs, AnalogBand& out)` where `AnalogBand` holds, per section: class, design-side `AnalogSection`, true `AnalogSection`, and for `gain1` the section gain and shelf side.
- Per ARCHITECTURE "Per-type prototypes": Butterworth `Qi`, `Q0 ← Q0 · Qu` (D9), `r = Gl^(1/(2N))`, low / high shelf, tilt = high shelf of `gEff` times `10^(−gEff/40)` (D8), bell `Qz = Qu/A`, `Qp = Qu·A`. Always built on the boost side `|gEff|` (P3); the caller inverts.
- Slope is read only for the five slope types (D6). Q is not read at 6 dB/oct (D9).
- Frequency policy (D10): bell re-centre above `0.95 π` with `Ge`, `T`, `Qe` and the fallback / clamp `[0.025, 160]`; notch `min (wc, 0.95 π)`; band pass `min (wc, 0.9 π)`; everything else at the true frequency.
- Depends on: T4.

**T6. `Source/dsp/Designer.h`** [agent]
- `MatchedPair` exactly as ARCHITECTURE (underdamped and overdamped branches, `expm1` forms, `th` clamp at π, `P1 ≥ 1e-12`, `Q = +inf` supported through `q = 0`).
- `mlr`, 3-point matched low-pass, matched high-pass, first-order cut sections, Vicanek 2019 first-order shelf, exact-peak band pass, notch as MLR with `Qz = +inf`.

- `class Designer { void prepare (double fs) noexcept; void design (const BandSettings&, BandDesign&) const noexcept; }`: build the prototype, design each section, fold the tilt scalar, invert every section when `gainDbEff < 0`, fill `trueProto` and `inverted`.

- Depends on: T5.

## Risks

- **R1 A transcription error that both the model and the C++ share.** They are written from the same document. Mitigation: T3 ties the promoted model back to the research tables, and G1 / G2s score against the analog prototypes, which neither implementation produces.
- **R2 `−perm +111` / `find` picks up a stale binary** after a target rename. The target is new; T8.4 uses the path printed by `find` and the log shows the row IDs.
- **R3 Shared `build/` configure.** One configure, CMake edited last, revert-on-failure (T8.2).
- **R4 F1 runtime.** 8e6 designs of up to 8 sections at about 35 ns per section is seconds, not minutes; if it is not, something allocates or the harness scores responses inside F1 (it must not).
- **R5 NB ceilings are from the model at 15 % margin.** If a ceiling fails with D1 green, the harness's scoring region differs from research's ("prototype above −40 dB, to 20 kHz"); fix the scoring, do not raise the ceiling.
- **R6 Gate tokens in prose.** T8.8 greps `Source/dsp` for `juce`, `new `, `throw `: comments must not contain them (write "renewed" carefully; prefer other words).
