# DSP Architecture: O-simpleAdditive

**CRITICAL CONTRACT:** This specification is immutable during Stages 1-4 implementation. Stage 1 (Foundation) cannot proceed without this file. Stage 2 (DSP) implements this exact architecture.

**Generated by:** Stage 0 Research & Planning
**Referenced by:** Stage 1 (Foundation), Stage 2 (DSP Implementation), Stage 3 (GUI)
**Purpose:** DSP specification defining the always-additive 16-partial voice, the wavetable scan/morph dimension, signal flow, JUCE 8 module usage, and the real-time-safe visualization path.

**Plugin type:** Synth (Additive + light Wavetable), MIDI-in → audio-out, polyphonic (16 voices), WebView UI.

**Sibling reference:** O-simpleAdditive is the **additive sibling of the shipped O-simpleFM** and deliberately inherits its engineering conventions: `juce::Synthesiser` + custom `SynthesiserVoice` voice model, 16-voice polyphony, per-block APVTS→voice param push, dual `juce::ADSR` (amp lifetime + mod-env routed to a depth target), `outputLevel` smoothing, and the lock-free `VizRing` + message-thread `FFT` visualization tap (reused verbatim from `FmVizAnalyzer.h`). All JUCE 8 classes below were verified against the local JUCE 8.0.9 source at `/Users/taylorbrook/JUCE/modules/`.

## Complexity & Research Summary

- **Complexity Tier:** 4 (synthesizer with MIDI input + oscillators) escalated toward **6** by first-class real-time spectrum/scope visualization. Net research depth: **MODERATE-to-DEEP** (most of the hard infrastructure — voice model, dual ADSR, lock-free viz, WebView wiring — is inherited from O-simpleFM; the genuinely new work is the additive render + morph + spectral-decay).

### Resolved research decisions (the 9 open questions)

1. **Render strategy → precompute a band-limited single-cycle wavetable per note, then interpolate (read by phase).** Per-sample summing of 16 sines × 16 voices is wasteful and aliases at high keys; instead, when a note starts (and whenever the active spectrum changes), additively fill **one single-cycle table** (sum of the 16 partials at their current amplitudes, harmonics above Nyquist dropped) and read it back per sample with linear interpolation. This is the textbook additive→wavetable optimization (CCRMA): "as the periodic waveform repeats, store one cycle in a table instead of summing oscillators every sample." It is **real-time safe** (the table is a fixed-size pre-allocated buffer; refills are bounded 16-sine writes, throttled to control-rate) AND **pedagogically faithful**: the table IS the summed-partials waveshape the brief wants students to see (QUAL-02). The morph and spectral-decay are applied in the *spectrum* (the 16 amplitudes) **before** the table is filled, so the scope and the drawbar spectrum always reflect exactly what is heard.
   - Refill cadence: at note-on, and at **control rate** (once per processBlock / ~every N samples) when scan, spectral-decay, or any drawbar moved enough to matter. Voices that share the *same* current spectrum (same scan position, same global drawbars) can share one table per note batch — but for v1.0 simplicity each voice owns its table (16 voices × 2048 floats ≈ 128 KB, trivial). See Architecture Decisions §1.
2. **Anti-aliasing → per-note harmonic-count cap with a short taper near Nyquist.** Compute `Kmax = floor(0.5·fs / f0)` (the standard band-limit: highest partial below Nyquist). Partials with harmonic number `k > Kmax` are **dropped (zero amplitude)** when filling the table. To avoid a click/zip when a partial crosses the boundary as pitch bends or as high notes are played, apply a **raised-cosine taper** to the top ~2 harmonics approaching Nyquist (`gain = 0.5·(1+cos(π·(k − (Kmax−2))/2))` for the top band) rather than a hard binary drop. This is "drop above Nyquist + taper the boundary," cheap and exact since we control the partial set directly. (DSP-02, QUAL-01.)
3. **Morph interpolation → linear spectral (per-partial amplitude lerp), NOT rendered-waveform crossfade.** The active spectrum is `A_k(scan) = lerp(frameA_k, frameB_k, scan)` for each of the 16 partials, then that single blended spectrum fills one table. This is **zipper-free** because (a) `scan` is smoothed (`SmoothedValue`, ~20 ms) and (b) all 16 partials stay phase-coherent (the table is rebuilt from a single consistent amplitude vector, so there is no phase-cancellation beating that a two-table waveform crossfade can produce). It is also the pedagogically correct picture: the spectrum *itself* morphs, which is exactly what the drawbar display shows. (DSP-03.)
4. **Frame B editability → preset-only in v1.0 (sine / saw / square / odd), NOT a second drawbar set.** A full B drawbar set would add **+16 params** (33→49) and a second 16-bar surface that fights the single-page, projector-readable pedagogy ("the spectrum is the interface" works when there is *one* spectrum to read). The four B presets each isolate a teaching concept (pure sine, 1/k saw, odd-only square, hollow odds). **Decision: Frame B is a 4-way `AudioParameterChoice` preset.** Deferred to v1.1: "B = snapshot of current drawbars" capture button (no new persistent params, gives power users an editable B without the slider wall). See Deferred to v1.1.
5. **Spectral-decay macro → per-partial exponential tilt as a function of harmonic number, scaled by an internal "decay envelope" over the note.** Define a per-partial multiplier `D_k(t) = exp(−decayAmount · (k−1) · τ(t))` where `k` is harmonic number (1..16), `decayAmount` ∈ [0,1] is the knob (mapped to a max rate), and `τ(t)` ramps 0→1 over the note via a dedicated internal one-shot ramp (attack-free, ~note-length time-constant) so the **spectrum visibly tilts darker over the note** (DSP-04 acceptance: visible tilt + audible darkening). At `decayAmount = 0`, `D_k = 1` for all k (balance holds — acceptance criterion). Higher partials (large `k`) decay faster because the exponent scales with `(k−1)`. This multiplier is applied to the morphed spectrum **before** the table fill, so it is visible in the live drawbar spectrum exactly as heard. (DSP-04.)
6. **Bit depth → discrete `AudioParameterChoice` steps {off, 12, 10, 8, 6, 4, 2 bits}, with "off" as a clean sentinel (= bypass, full float).** Discrete bits make the lesson concrete ("8-bit = early sampler grit") and avoid a meaningless continuous control; "off" guarantees a clean reference (DSP-05 acceptance: max/off = clean). Quantization is applied to the **rendered single-cycle waveform samples** (`q = round(x · L)/L`, `L = 2^(bits−1)`) at read time, so it is part of what the scope shows. (DSP-05.)
7. **Polyphony → 16 voices** (matches O-simpleFM and the Ouaricon suite norm; comfortable for chordal classroom demos; CPU is trivial since each voice is one table read + envelope). (FUNC-05.)
8. **Velocity routing → velocity→amplitude always-on; velocity→spectral-decay opt-in (`velToDecay`, default 0).** Velocity-to-amp is the expected baseline. An opt-in velocity→decay makes hard notes brighter-decaying (a small expressive teaching bonus) without complicating the default mental model. (DSP-06 adjacent.)
9. **Visualization handoff → reuse O-simpleFM's `VizRing` (lock-free power-of-two atomic overwrite ring) + message-thread `FmVizAnalyzer` (4096 FFT / Blackman-Harris + scope downsampler) verbatim.** Audio thread is copy-only; FFT runs on the editor Timer (30 Hz). One addition: the **drawbar spectrum** display is driven directly from the 16 morphed+decayed partial amplitudes (the control values), not from the FFT — so the bars are exact, and the FFT spectrum overlay (optional) confirms it matches the audio. (PERF-01, QUAL-02.)

## Core Components

### Additive Voice (AdditiveVoice)
- **JUCE Class:** Custom `AdditiveVoice : juce::SynthesiserVoice` (per-voice single-cycle wavetable + phase accumulator; `juce::ADSR` amp env; `juce::ADSR` mod env; internal decay ramp).
- **Purpose:** Render one polyphonic additive voice: read the per-note band-limited single-cycle table by phase, apply bit-depth quantization, shape by amp ADSR. The active spectrum (morph + spectral-decay) is computed and the table refilled at control rate.
- **Parameters Affected:** `partial1..16`, `frameBSource`, `scanPosition`, `scanLfoRate`, `scanLfoDepth`, `scanEnvAmount`, `spectralDecay`, `bitDepth`, all amp/mod ADSR params, `velToDecay`.
- **Configuration:**
  - **Per-note table fill (control rate — NOT per sample):**
    ```cpp
    // activeSpectrum[k] for k=0..15 (harmonic 1..16), already morphed + decayed + band-limited:
    //   morphed_k  = lerp(frameA[k], frameB[k], scanSmoothed)
    //   decayed_k  = morphed_k * exp(-decayAmount * k * tau)      // k=0 is fundamental → no decay
    //   bandlim_k  = decayed_k * nyquistTaper(k+1, Kmax)          // drop/taper above Nyquist
    fillSingleCycleTable(table, activeSpectrum, Kmax);             // additive sum into 2048-pt table
    ```
  - **Per-sample read (audio rate):**
    ```cpp
    float s = readTableLinear(table, phase);                      // 2048-pt, linear interp
    s = quantize(s, bitDepth);                                    // bit-depth grit (off = passthrough)
    float out = s * ampEnv.getNextSample();                       // amp ADSR + voice lifetime
    phase += f0 / sampleRate; if (phase >= 1.0f) phase -= 1.0f;   // normalized 0..1 single-cycle phase
    ```
  - **Voice lifetime:** active while `ampEnv.isActive()` (a long mod-env release must NOT keep a silent voice alive — same rule as O-simpleFM).
  - **Note-on reset:** zero `phase`, reset the internal decay ramp `tau→0`, trigger both ADSRs; refill the table immediately so the first sample is correct.
  - **Prepare:** custom `prepareToPlay(sampleRate, maxBlockSize)` sets `setCurrentPlaybackSampleRate` + `ampEnv/modEnv.setSampleRate` **before** first `setParameters` (JUCE 8 `SynthesiserVoice` has NO virtual `prepareToPlay` — confirmed from O-simpleFM `FMVoice` / O-Bassoon `BassoonVoice`).

### Single-Cycle Wavetable Fill (additive)
- **JUCE Class:** Custom (additive sum of sines into a fixed-size buffer; sine via `juce::dsp::LookupTableTransform<float>`, the same `fastSine` primitive O-simpleFM uses).
- **Purpose:** Convert the 16-partial amplitude vector into one band-limited single-cycle waveform that is read back per sample. THE additive→wavetable bridge (DSP-01).
- **Parameters Affected:** all `partial1..16` (via the morphed/decayed active spectrum).
- **Configuration:**
  - Table size **2048 points** (single cycle). 16 harmonics into 2048 points is comfortably oversampled; the highest harmonic (16th) gets 128 points/cycle — clean. Linear interpolation on read (~same SNR rationale as O-simpleFM's 1024-pt sine; cubic unnecessary).
  - Fill: `table[i] = Σ_{k=1..Kmax} A_k · sin(2π·k·i/N)`, normalized so the worst-case sum can't clip (divide by a running peak or a fixed headroom factor; see Output Stage). Use `fastSine` for each term.
  - **Only harmonics k ≤ Kmax are summed** (band-limiting is "don't write the partial," the cheapest possible AA — no filter needed).
  - Phase convention: all partials **cosine-phase-aligned at sine(0)** (pure sine partials, zero phase) — matches the additive-theory picture and keeps the waveshape deterministic for the scope.

### Frame A / Frame B Spectra + Morph
- **JUCE Class:** Custom (two 16-element amplitude vectors + `lerp`; `frameBSource` is a `juce::AudioParameterChoice`; `scanPosition` is a smoothed float).
- **Purpose:** The wavetable dimension — interpolate the spectrum from Frame A (the live drawbars) toward Frame B (a preset shape) (FUNC-02, DSP-03).
- **Parameters Affected:** `partial1..16` (Frame A), `frameBSource` (Frame B preset), `scanPosition`, `scanLfoDepth`/`scanLfoRate` (LFO drive), `scanEnvAmount` (mod-env drive).
- **Configuration:**
  - **Frame A** = the 16 drawbar values (0..1 each), read once per block from APVTS.
  - **Frame B** = one of four hard-coded amplitude vectors:
    - `sine`: `[1,0,0,...]` (pure fundamental).
    - `saw`: `A_k = 1/k` (1, 1/2, 1/3, …) — the canonical "1/n amplitudes fill the ramp" lesson.
    - `square`: odd-only `A_k = 1/k` for odd k, 0 for even (1, 0, 1/3, 0, 1/5, …).
    - `odd`: odds-only flat-ish hollow set (a distinct "hollow" timbre vs square's 1/k roll-off — e.g. odds at 1, 0.6, 0.4, 0.3…).
  - **Active scan position** = `clamp(scanPosition + lfo·scanLfoDepth + modEnv·scanEnvAmount, 0, 1)`, **then smoothed** (`SmoothedValue`, ~20 ms) before the per-partial lerp. (FUNC-03: manual + LFO + mod-env all sum into one pointer.)
  - **Morph:** `active_k = (1 − scan)·frameA_k + scan·frameB_k`.

### Spectral-Decay Macro
- **JUCE Class:** Custom (per-partial exponential multiplier + internal one-shot ramp).
- **Purpose:** One knob makes higher partials decay faster than lower ones over the note — the "expressive heart" of additive in a single control (DSP-04).
- **Parameters Affected:** `spectralDecay`, (`velToDecay` opt-in).
- **Configuration:**
  - Internal **decay ramp** `tau(t)`: a per-voice value that ramps 0→1 from note-on over a fixed musical time (e.g. ~2 s, or scaled by `spectralDecay`), giving the "spectrum tilts darker over the note" motion even on a sustained note.
  - Per-partial multiplier: `D_k = exp(−rate · k · tau)`, `k = 0..15` (so the fundamental `k=0` never decays), `rate = spectralDecay · RATE_MAX` (+ `velocity·velToDecay` if enabled).
  - Applied to the morphed spectrum **before** the table fill ⇒ visible in the drawbar spectrum AND the scope, audible as a darkening tone (DSP-04 acceptance).
  - At `spectralDecay = 0`, `D_k = 1` ∀k (balance holds — acceptance).

### Bit-Depth Quantizer
- **JUCE Class:** Custom (mid-tread quantizer on the rendered sample).
- **Purpose:** Quantize the summed single-cycle waveform to N amplitude levels for early-digital grit (DSP-05).
- **Parameters Affected:** `bitDepth`.
- **Configuration:**
  - `bitDepth` is an `AudioParameterChoice`: `{ off, 12, 10, 8, 6, 4, 2 }`.
  - When `off`: passthrough (no quantization) — the clean reference.
  - Else: `L = 2^(bits−1); q = std::round(x · L) / L;` applied per output sample at table-read time (so the scope shows the staircase). No dither (the grit IS the lesson).

### Amplitude Envelope (Amp ADSR)
- **JUCE Class:** `juce::ADSR` + `juce::ADSR::Parameters` (verified `juce_audio_basics/utilities/juce_ADSR.h`).
- **Purpose:** Shape per-voice output amplitude; governs voice lifetime (FUNC-05, DSP-06).
- **Parameters Affected:** `ampAttack`, `ampDecay`, `ampSustain`, `ampRelease`, velocity→amplitude (always on).
- **Configuration:** times 0–5 s (skew ~0.35 for fine low-end control), sustain 0–1. `setSampleRate` in prepare before first `setParameters`. Mirrors O-simpleFM exactly.

### Modulation Envelope (Mod ADSR → Scan)
- **JUCE Class:** `juce::ADSR`.
- **Purpose:** Independent envelope routed to scan position for once-per-note spectral evolution — the headline wavetable lesson (FUNC-03, DSP-06).
- **Parameters Affected:** `modAttack`, `modDecay`, `modSustain`, `modRelease`, `scanEnvAmount` (bipolar depth, −100..+100%).
- **Configuration:** Mod-env output (0..1) × `scanEnvAmount` (bipolar) is **added** to the scan pointer (then clamped + smoothed). Bipolar amount lets the note morph A→B (positive) or B→A (negative). Mirrors O-simpleFM's mod-env-as-a-routed-source pattern (there it scaled index; here it offsets scan).

### Scan LFO
- **JUCE Class:** Custom phase accumulator + `fastSine` (or a small per-shape table). NB: `juce::dsp::Oscillator` exists but a per-voice/global phase accumulator is lighter and matches the suite's hand-rolled-LFO convention.
- **Purpose:** Sweep the scan position across a held note (the "watch a held note morph" demo) (FUNC-03).
- **Parameters Affected:** `scanLfoRate`, `scanLfoDepth`.
- **Configuration:**
  - **Global (one LFO shared by all voices)** so all notes morph in phase (cleaner classroom visual than per-voice free-run). Advanced per-voice retrigger is deferred.
  - Shape: **sine** in v1.0 (smooth, unambiguous); `scanLfoRate` 0.01–20 Hz (log skew); `scanLfoDepth` 0–100% scales the swing added to scan. Triangle/other shapes deferred to v1.1.

### Output Stage
- **JUCE Class:** `juce::SmoothedValue<float>` gain + final block NaN scrub.
- **Purpose:** Master output trim, summed-voice headroom, suite-wide NaN insurance.
- **Parameters Affected:** `outputLevel` (dB).
- **Configuration:** dB→linear gain, 20 ms smoothing. **Headroom:** the additive sum can reach Σ|A_k| at peak; normalize the table fill (e.g. divide by `max(1, Σ A_k)` or a fixed factor) so 16 maxed drawbars don't clip, then trim with `outputLevel`. Block-level `std::isfinite` scrub after summing voices.

### Visualization Tap (Spectrum + Scope) — REUSED FROM O-simpleFM
- **JUCE Class:** `VizRing` (custom lock-free power-of-two atomic overwrite ring, from `FmVizAnalyzer.h`) + `juce::dsp::FFT` + `juce::dsp::WindowingFunction<float>`. FFT runs on the **message thread** (editor Timer), not the audio thread.
- **Purpose:** Feed the live oscilloscope (UI-02) and the optional FFT spectrum overlay. The **drawbar spectrum** (UI-01) is driven directly from the 16 active partial amplitudes (exact, no FFT).
- **Parameters Affected:** none (read-only tap of mono-summed output + a copy of the active spectrum).
- **Configuration:** see **Visualization Data Path** below. Lift `VizRing` + `FmVizAnalyzer` from O-simpleFM essentially unchanged.

## Processing Chain

```
MIDI in
  ↓
juce::Synthesiser (16 × AdditiveVoice)
  │   ── control rate (per block / on note-on / on param move) ──
  │     Frame A (16 drawbars)  ─┐
  │     Frame B (preset)        ├─ morph: active_k = lerp(A_k, B_k, scanSmoothed)   ← scanPosition + LFO + modEnv
  │     spectral-decay D_k ─────┴─ active_k *= exp(-rate·k·tau)                       ← spectralDecay (+velToDecay)
  │     band-limit:        active_k = 0  for k > Kmax  (taper top 2)                  ← per-note Nyquist cap
  │     fillSingleCycleTable(table, active_k)         (additive sum, 2048 pts)
  │   ── audio rate (per sample) ──
  │     s = readTableLinear(table, phase);  phase += f0/fs
  │     s = quantize(s, bitDepth)                                                     ← bitDepth (off = clean)
  │     voiceOut = s · ampEnv                                                          ← amp ADSR + voice lifetime
  ↓ (sum of active voices, normalized for headroom)
Output gain (SmoothedValue, dB→lin)  ← outputLevel
  ↓
NaN scrub (std::isfinite insurance)
  ↓
[TAP] mono-sum → VizRing (lock-free, no alloc, no FFT on audio thread)
  ↓
Audio out (stereo, mono signal duplicated)

   ── message thread (Editor Timer 30 Hz) ──
   VizRing → copy scope window (BEFORE FFT)
        ├─ Blackman-Harris window → dsp::FFT (4096) → log-freq dB bins → "spectrumUpdate" (overlay, optional)
        └─ raw window (downsampled, max-abs keep sign)                       → "scopeUpdate"
   active-spectrum snapshot (16 amplitudes, atomic) → "drawbarSpectrumUpdate" (the exact bars)
        → emitEventIfBrowserIsVisible(...)  → WebView JS draws
```

**Routing notes:**
- **No feedback loop.** Additive synthesis is feed-forward — no self-modulation, no global feedback path (a key simplification vs O-simpleFM's DX7 feedback). This removes the single hardest stability risk from the sibling.
- **Morph, spectral-decay, and band-limiting all act in the spectrum (the 16 amplitudes) BEFORE the table fill** — so the displayed bars/scope are exactly what is heard (QUAL-02).
- **Scan pointer is the sum of three sources** (manual `scanPosition` + LFO + mod-env), clamped to [0,1], then smoothed (DSP-03 zipper-free).
- **No oversampling needed.** Because band-limiting is exact (partials above Nyquist are simply not written into the table), there is no aliasing to oversample away — a major CPU and latency win over O-simpleFM's 2× OS. Bit-depth quantization is a deliberate distortion the student wants to hear, not an artifact to suppress.
- **Visualization is a read-only tap**, never in the audio return path.

## System Architecture

### MIDI Handling
- **Bus:** MIDI-in → stereo audio-out (no audio input). `IS_SYNTH TRUE` + `NEEDS_MIDI_INPUT TRUE` in CMake (critical-pattern #22 — omitting yields a silent plugin).
- **BusesProperties:** output-only (`.withOutput("Output", stereo(), true)`).
- **Note allocation:** `juce::Synthesiser` default voice stealing; 16 `AdditiveVoice` + one trivial `AdditiveSound`.
- **Pitch:** `f0 = MidiMessage::getMidiNoteInHertz(noteNumber)`; `Kmax` recomputed at note-on from `f0` and current `fs`.
- **Velocity:** velocity→amplitude always; velocity→spectral-decay opt-in (`velToDecay`, default 0).

### Visualization Data Path (PERF-01 — real-time safe)
**Audio thread (allocation-free):**
- After output gain, mono-sum the block and `VizRing::write()` into the pre-allocated atomic ring. **No allocation, no FFT, no locks.** (Verbatim from O-simpleFM `FmVizAnalyzer.h`.)
- Separately, publish the current 16-element **active spectrum** to the editor via a small lock-free snapshot (e.g. `std::atomic<float>` array or a double-buffered struct) so the drawbar spectrum shows the *morphed + decayed* levels (not just the raw drawbar params).

**Message thread — Editor `Timer` at 30 Hz:**
1. `VizRing::readLatest()` a scope window — **copy it BEFORE the FFT** (`performFrequencyOnlyForwardTransform` overwrites its buffer in place).
2. **Scope:** downsample (1024→128, max-abs-in-bucket keeping sign) → `"scopeUpdate"`.
3. **Spectrum overlay (optional):** Blackman-Harris window → `juce::dsp::FFT` order 12 (4096) → log-freq dB bins, rise-fast/fall-slow smoothing → `"spectrumUpdate"`.
4. **Drawbar spectrum:** read the active-spectrum snapshot → `"drawbarSpectrumUpdate"` (the exact bars the engine is summing).
5. `webView->emitEventIfBrowserIsVisible(...)`.

**Critical gotchas (inherited):**
- `performFrequencyOnlyForwardTransform` overwrites its work buffer in place — copy the scope window first.
- FFT runs on the message thread (per the brief: audio thread copy-only).

### State Persistence
- All parameters live in `AudioProcessorValueTreeState`; `getStateInformation`/`setStateInformation` serialize the APVTS value tree (suite standard). No external files.
- **Educational preset tour (FUNC-04):** factory presets via the Ouaricon `preset-manager` module (same as O-simpleFM) or APVTS snapshots. Recipes in **Algorithm Details → Preset Recipes**.

### Cross-Platform WebView (COMPAT-02)
- CMake: `NEEDS_WEB_BROWSER TRUE`, `NEEDS_WEBVIEW2 TRUE`; compile defs `JUCE_WEB_BROWSER=1`, `JUCE_USE_WIN_WEBVIEW2_WITH_STATIC_LINKING=1`, `JUCE_USE_CURL=0` (identical to O-simpleFM CMake).
- Windows: `withUserDataFolder(File::tempDirectory child)` to avoid DAW-host data-folder denial (silent IE fallback → blank UI).
- Resource provider receives **bare paths** (`/`, `/index.html`, `/js/app.js`) — compare by direct equality (critical-pattern #8; project memory).
- ES6 modules: `type="module"` + `import * as Juce` (critical-pattern #21); `WebSliderParameterAttachment` 3-arg ctor with `nullptr` undoManager (critical-pattern #12); `getToggleState`/`getSliderState`/`getComboBoxState` per param type (critical-pattern #19).

## Algorithm Details

### Additive → wavetable bridge (the pedagogical core)
A periodic tone is `x(t) = Σ_k A_k · sin(2π·k·f0·t)`. Because it repeats every `1/f0`, one period fully describes it — so we **store one period in a table** (`N = 2048`) and read it back by phase, instead of summing 16 oscillators every sample. This is the literal additive→wavetable identity the class teaches: *a wavetable frame IS a summed-partials waveshape.* The table is rebuilt whenever the spectrum changes (morph/decay/drawbar move); the read is a single linear interpolation.

### Band-limiting (anti-aliasing, exact)
The maximum alias-free harmonic count for fundamental `f0` is `Kmax = floor(0.5·fs / f0)` (highest partial below Nyquist). We simply **do not write** partials with `k > Kmax` into the table — exact band-limiting with zero filter cost. Recompute `Kmax` at note-on (pitch is fixed per note in v1.0; no pitch bend). Taper the top ~2 surviving harmonics with a raised cosine so a partial fading in/out across the boundary (e.g. at the highest playable keys) does not click. At C7 (~2093 Hz, fs=44.1k) `Kmax ≈ 10`, so partials 11–16 are dropped — high keys stay clean (DSP-02 acceptance).

### Morph (Frame A → Frame B)
`active_k = (1−scan)·A_k + scan·B_k` per partial, with `scan` the smoothed sum of manual + LFO + mod-env. At `scan=0` output = Frame A; at `scan=1` output = Frame B (FUNC-02 acceptance). Linear *spectral* interpolation (not waveform crossfade) keeps all partials phase-coherent and zipper-free (DSP-03).

### Spectral-decay macro (curve)
`D_k = exp(−rate · k · tau(t))`, `k=0..15`, `rate = spectralDecay·RATE_MAX (+ vel·velToDecay)`, `tau(t)` an internal 0→1 ramp over the note. Exponent scales with harmonic number ⇒ higher partials decay faster; fundamental (`k=0`) never decays. At `spectralDecay=0`, all `D_k=1` (steady — DSP-04 acceptance). The spectrum visibly tilts darker over the note and the tone audibly darkens.

### Bit-depth quantization
`off` → passthrough. Else `L = 2^(bits−1); q = round(x·L)/L`. Mid-tread quantizer applied to the rendered sample; no dither (the grit is the lesson; DSP-05 acceptance: lower bits = audible grit, off = clean).

### Frame B preset shapes (and why each teaches)
| Preset | Amplitudes `A_k` (k=1..) | Teaches |
|--------|--------------------------|---------|
| sine | 1, 0, 0, … | the irreducible partial; "morph back to pure" |
| saw | 1, 1/2, 1/3, 1/4, … (1/k) | "1/n amplitudes fill the ramp" (the class demo) |
| square | 1, 0, 1/3, 0, 1/5, … (odd 1/k) | odd-only → hollow/woody |
| odd | 1, 0, 0.5, 0, 0.33, … (odds, flatter) | a brighter hollow variant; contrast with square |

### Preset Recipes (FUNC-04 — preset tour)
Frame A drawbars + scan/decay/bit settings. **Star** = the concept each isolates.
| Preset | Frame A | Scan / B | Decay | Bit | Star concept |
|--------|---------|----------|-------|-----|--------------|
| Pure Sine | H1=100, rest 0 | scan 0 | 0 | off | the atom of additive |
| Sawtooth | (load 1/k into drawbars) | scan 0 | 0 | off | 1/n series builds a ramp |
| Square (hollow) | odd-only 1/k | scan 0 | 0 | off | odd harmonics = hollow |
| Organ | H1,H2,H3,H4 up | scan 0 | low | off | drawbar registration |
| Morph Pad | a few low partials | B=saw, mod-env→scan + LFO | med | off | spectral evolution over a note |
| Lo-Fi Bells | bright odd set | scan 0 | high | 8-bit | spectral-decay + quantization grit |

### Smoothing / zipper avoidance
`SmoothedValue` (~20 ms linear) on `scanPosition` (post-sum), `outputLevel`, and the per-partial active amplitudes if needed. Never reset `phase` mid-note. Drawbar moves refill the table at control rate (a 20 ms scan smoother + control-rate refill is below audible zipper threshold for a slowly-moving spectrum).

## Integration Points

### Feature Dependency Graph
```
partial1..16 (Frame A) ─┐
frameBSource (Frame B)  ─┤ morph: active_k = lerp(A_k, B_k, scan)
scanPosition ───────────┤        ▲

                         ▼

                         ▼
per-note Kmax ► drop/taper k>Kmax (band-limit)
                         ▼
fillSingleCycleTable(active_k)  ──►  readTableLinear(phase)
                         ▼
bitDepth ► quantize(sample)
                         ▼
ampEnv (Amp ADSR) ► amplitude + voice lifetime
                         ▼
voice sum ► normalize ► output gain ► viz tap (ring + active-spectrum snapshot)
```

### Processing Order (load-bearing)
1. Read APVTS atomics **once per block** in the processor; push to each voice via `setParams(...)` (O-simpleFM `setParams` block-push pattern). Voices do not read APVTS directly. Advance the **global** scan LFO once per block.
2. Per note-on: compute `f0`, `Kmax`; reset phase + decay ramp; refill table.
3. Per block (control rate): recompute the active spectrum (morph → decay → band-limit) and **refill the table** when scan/decay/drawbars changed.
4. Per sample: read table → quantize → amp env. (No oversampling stage.)
5. Visualization tap is **last**, post-gain, copy-only; active-spectrum snapshot published alongside.

### Parameter Interactions
- **scan = manual + LFO + mod-env** all sum into one pointer, then clamp [0,1], then smooth. This three-source sum is the FUNC-03 teaching payload — keep it intact.
- **spectralDecay × note length:** the internal `tau` ramp ties the decay tilt to elapsed note time; on a short staccato note the tilt barely engages, on a held note it fully tilts — this is the intended "expressive over the note" behavior.
- **Kmax × pitch:** high notes drop upper partials. A patch that sounds bright low can sound duller high — this is correct (and teachable: "you literally run out of room below Nyquist"). Tapered boundary avoids clicks.
- **bitDepth × amplitude:** quantization step is fixed in amplitude; quieter tails show *more* relative grit — a faithful early-digital characteristic.

## Implementation Risks

| # | Feature | Complexity | Risk | Fallback / Mitigation |
|---|---------|-----------|------|----------------------|
| 1 | Additive table fill timing | MEDIUM | Refilling the 16-sine table too often (per sample) spikes CPU; too rarely zippers on fast scan | Refill at **control rate** (per block / on change), `scanPosition` smoothed 20 ms. If audible zipper on fast LFO, raise refill rate to sub-block (e.g. every 32 samples) — still cheap. |
| 2 | Band-limiting / AA | MEDIUM | Click when a partial crosses the Nyquist boundary at the top of the keyboard | **Drop above Kmax + raised-cosine taper on top 2 harmonics.** Exact band-limit means no aliasing to chase (unlike O-simpleFM). Fallback: lower the cap to `0.45·fs` if any high-key buzz appears. |
| 3 | Morph zipper | LOW | Audible stepping as scan moves | Linear *spectral* interp (phase-coherent) + smoothed scan. Spectral interp categorically avoids the phase-cancellation beating a two-waveform crossfade can cause. |
| 4 | Spectral-decay legibility | MEDIUM | Effect too subtle to see/hear (fails DSP-04 acceptance) | Exponential `(k−1)`-scaled tilt + note-length `tau` ramp; tune `RATE_MAX` so 100% clearly darkens within ~1–2 s. Drawbar display reads the *decayed* levels so the tilt is literally visible. |
| 5 | Headroom / clipping | MEDIUM | 16 maxed drawbars sum to a loud, clipping table | Normalize the table fill (divide by `max(1, ΣA_k)` or fixed headroom); block-level `isfinite` scrub; `outputLevel` trim. |
| 6 | Real-time-safe viz | LOW | Allocation/FFT on audio thread (PERF-01 fail) | **Reuse O-simpleFM `VizRing` + message-thread `FmVizAnalyzer` verbatim** — already proven. Copy scope window before FFT. |
| 7 | Drawbar-display fidelity | LOW | Bars show raw param values, not morphed+decayed levels → display ≠ audio (QUAL-02 fail) | Publish the **active** spectrum snapshot (post morph/decay) to the UI, not the raw drawbar params. |
| 8 | Cross-platform WebView | LOW | Silent IE fallback → blank UI on Windows | `NEEDS_WEBVIEW2 TRUE` + static-linking define + `withUserDataFolder` (project memory); inherit O-simpleFM CMake. |
| 9 | Voice lifetime | LOW | Long mod-env release keeps silent voices alive → voice starvation | Gate lifetime on **amp** envelope activity only (same as O-simpleFM). |

**Note:** O-simpleFM's single hardest risk — DX7 feedback limit-cycle/NaN stability — **does not exist here** (additive is feed-forward). And its HIGH anti-aliasing risk is **downgraded to MEDIUM** because band-limiting is exact (don't write the partial) rather than statistical (oversample). This makes O-simpleAdditive meaningfully *lower-risk* than its sibling despite the higher parameter count.

## Architecture Decisions

1. **Precomputed band-limited single-cycle table over per-sample sum-of-sines (WHY):** Per-sample summing of 16 sines × 16 voices = 256 sine evals/sample, and naive summing aliases at high keys. The table approach is the CCRMA-standard additive→wavetable optimization: build one period when the spectrum changes, read it back with one interpolation per sample. It is faster, exactly band-limitable (just omit partials > Kmax), and — crucially for a *teaching* tool — the table *is* the visible summed waveshape (QUAL-02). **Tradeoff:** the spectrum is quantized to control-rate refills (imperceptible with a 20 ms scan smoother). **Alternative considered:** mipmapped band-limited wavetable bank per octave (Serum/Vital/O-Prism style) — overkill here because we already rebuild per note and per-note Kmax gives exact band-limiting for free.
2. **Linear spectral morph over waveform crossfade (WHY):** Interpolating the 16 amplitudes keeps every partial phase-coherent, so there is no inter-table beating/cancellation; it is zipper-free with a smoothed scan and it is the pedagogically correct picture (the *spectrum* morphs, which is what the bars show). **Alternative:** crossfade two rendered cycles — risks phase-cancellation artifacts and shows a less truthful spectrum.
3. **Frame B = 4 presets, not a second drawbar set (WHY):** Keeps v1.0 at 33 params and one readable spectrum surface (the single-page, projector-readable pedagogy). The four presets each isolate a concept. **Alternative (deferred to v1.1):** a "capture current drawbars as Frame B" button — gives an editable B with zero new persistent params.
4. **No oversampling (WHY):** Because band-limiting is exact (partials above Nyquist are never synthesized), there is no aliasing to remove. This drops O-simpleFM's 2× oversampling stage entirely — lower CPU, zero added latency, simpler. Bit-depth grit is intentional distortion, not an artifact.
5. **16 voices + `juce::Synthesiser` + custom `SynthesiserVoice` (WHY):** Suite norm; proven across O-simpleFM/O-Bassoon/O-Prism/O-Lyrica; free voice allocation/stealing. **Alternative:** 8 voices — needlessly limiting for chordal teaching.
6. **FFT on message thread; drawbar display from the active-spectrum snapshot (WHY):** Brief mandates an allocation-free audio thread; the 30 Hz Timer FFT keeps the audio path copy-only. Driving the *bars* from the exact active amplitudes (not the FFT) makes the spectrum display precise and the FFT overlay a confirmation. **Tradeoff:** ~33 ms visual latency (imperceptible).
7. **Discrete bit-depth choices + "off" sentinel (WHY):** Concrete, namable lesson values; "off" is a guaranteed clean reference. **Alternative:** continuous bits — meaningless control with no clean anchor.

## Special Considerations

- **Thread safety:** APVTS atomics for params; `VizRing` + active-spectrum snapshot for audio→UI; no locks on the audio thread; UI never calls processing code (critical-pattern #5).
- **Performance:** 16 voices × (1 table read + amp env) per sample ≈ trivial. Table refills are bounded 16-sine writes at control rate. **No oversampling.** 4096 FFT at 30 Hz on the message thread is cheap. Estimated well under one core at 48 kHz — lighter than O-simpleFM (no 2× OS, no per-sample feedback).
- **Denormals:** `juce::ScopedNoDenormals` at the top of `processBlock`; block-level `std::isfinite` scrub after summing voices. (No decaying feedback loop, so denormal exposure is much lower than O-simpleFM, but keep the guard for the ADSR tails.)
- **Sample rate:** `Kmax` and phase increments use current `fs`; recompute `Kmax` per note-on. ADSR `setSampleRate` in prepare before `setParameters`. Table size (2048) is sample-rate-independent (it's one cycle).
- **Latency:** **Zero added latency** (no oversampling, no lookahead) — report `setLatencySamples(0)` (NB: `getLatencySamples()` is non-virtual in JUCE 8; do not override).
- **Zipper noise:** `SmoothedValue` on scan/output; control-rate table refill; never reset phase mid-note.
