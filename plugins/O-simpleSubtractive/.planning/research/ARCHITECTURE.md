## Complexity & Research Summary

- **Complexity Tier:** 4 (synthesizer with MIDI input + oscillators) escalated toward **6** by first-class real-time filter-magnitude-over-spectrum + FFT/scope visualization. Net research depth: **MODERATE→DEEP** (the DSP primitives are well-trodden; the genuinely-new work is the multimode self-oscillating filter + its exact magnitude curve + voice modes).
- **HEADLINE DECISION — Filter topology:** Build a **custom Cytomic-style zero-delay-feedback (ZDF) Trapezoidal-Integration (TPT) State-Variable Filter** (Andrew Simper / Vadim Zavalishin equations), NOT a Moog ladder. The SVF gives all four modes (LP/BP/HP simultaneously from one state; **Notch = input − k·BP** = LP+HP) from a single structure, clean 12 dB/oct, **cascade ×2 for 24 dB**, **1-pole for 6 dB**, stable **self-oscillation** when the nonlinear (tanh) variant is used, and — decisively for the teaching tool — an **exact closed-form magnitude response** that matches the running digital filter sample-for-sample (guarantees QUAL-02). See **Architecture Decisions §1** and **Algorithm Details → Filter** for the full transfer function and the UI curve computation.
- **Anti-aliasing decision:** **PolyBLEP** for saw/square (and **polyBLAMP** for triangle); sine via LUT (exact). PolyBLEP composes correctly here because the subtractive oscillator runs at a **steady phase increment** (no FM/phase-modulation) — unlike O-simpleFM where PolyBLEP was rejected. No oversampling needed for the oscillators; near-zero CPU.
- **Self-oscillation decision (DSP-03 MUST):** the **nonlinear SVF** (tanh on the resonant integrator path) self-oscillates into a **clean, bounded sine at cutoff** at max resonance; the nonlinearity is the gain-compensation that stops resonance sweeps from blowing up. JUCE's built-in linear `StateVariableTPTFilter` is documented only as a fallback (it cannot sustain self-oscillation).
- **Key-tracking decision:** add a `keyTrack` parameter (0–100%, **default 0%**) so a self-oscillating filter can play **in tune** (`keyTrack=100%` → cutoff follows the note 1:1). Default 0% keeps the first filter-sweep lesson simple (cutoff is an absolute frequency).
- **Filter-env routing decision:** **bipolar `filterEnvAmount` in OCTAVES** around the base cutoff (exponential), not linear Hz — musically correct, constant perceptual sweep at any base cutoff.
- **Voice-mode decision:** `juce::Synthesiser` (16 voices) for Poly; a thin processor-side **note-priority + glide controller** drives Mono/Legato + portamento. This is the one area genuinely new vs O-simpleFM (which is poly-only) → flagged MEDIUM risk.
- **Parameter resolution (open draft items):** **ADD `keyTrack`**; **DEFER to v1.1**: `velToFilterEnv`/`velToAmp` as params (velocity→amp is always-on, non-param), PWM (`pulseWidth`), master tune/octave. Final v1.0 core = **20 parameters** (see Parameter Mapping).

## Core Components

### Oscillator + Sub + Noise Mixer (per voice)
- **JUCE Class:** Custom `OscillatorBank` (PolyBLEP main osc + PolyBLEP square sub-osc + white-noise generator). Sine path uses `juce::dsp::LookupTableTransform<float>` (verified `juce_dsp/maths/juce_LookupTable.h`).
- **Purpose:** Generate the harmonically-rich source that the filter shapes (DSP-01). Saw gives the filter the most to remove; square is hollow (odd harmonics); triangle is dark; sine gives the filter almost nothing (teaching contrast).
- **Parameters Affected:** `oscWave`, `subLevel`, `noiseLevel`.
- **Configuration:**
  - **Main osc** at note frequency `f0`. Waveforms:
    - **Saw / Square:** naive ramp/pulse + **PolyBLEP** correction at each discontinuity (two-sided, residual added at the wrap; square = saw(φ) − saw(φ+0.5) form or direct pulse + 2 BLEPs). 50% duty (PWM deferred to v1.1).
    - **Triangle:** **polyBLAMP** (integrated BLEP) at the two slope discontinuities, OR leaky-integrate a PolyBLEP square. Already dark; minimal correction needed.
    - **Sine:** 1024-pt LUT, linear interp (~97 dB SNR); no anti-aliasing needed (single partial).
  - **Sub osc:** PolyBLEP **square one octave below** (`f0/2`) for bass weight; scaled by `subLevel` (0–1).
  - **Noise:** fast xorshift / `juce::Random`-seeded white noise, scaled by `noiseLevel` (0–1).
  - **Mix:** `src = mainOsc + subLevel·sub + noiseLevel·noise`. Main osc implicitly unity; headroom managed downstream (filter + `outputLevel`). Mix feeds the filter input.
  - **Phase discipline:** never reset oscillator phase mid-note (click/zipper); reset only on voice (re)allocation. PolyBLEP residual uses `dt = f0/fs`.

### Multimode ZDF State-Variable Filter (per voice) — THE headline component
- **JUCE Class:** **Custom `SvfZDF`** (Cytomic/Zavalishin trapezoidal SVF, ~12-line core). Fallback: `juce::dsp::StateVariableTPTFilter<float>` (LP/BP/HP, verified `juce_dsp/processors/juce_StateVariableTPTFilter.h`) + `juce::dsp::FirstOrderTPTFilter<float>` (1-pole LP/HP, verified) for the 6 dB stage.
- **Purpose:** Multi-mode (LP/HP/BP/Notch) filter at 6/12/24 dB/oct with cutoff + resonance, pushable to clean self-oscillation (DSP-02, DSP-03). The LP is the workhorse default.
- **Parameters Affected:** `filterType`, `filterSlope`, `cutoff`, `resonance`, `filterEnvAmount` (via filter ADSR), `keyTrack`.
- **Configuration:**
  - **One 2-pole SVF core** computes LP, BP, HP **simultaneously** each sample (see Algorithm Details). **Notch = input − k·BP** (= LP + HP). All four modes from one state — this *is* the pedagogical story.
  - **Slopes:** 6 dB = a single 1-pole TPT (`FirstOrderTPTFilter` or one SVF integrator, no resonance — "a 1-pole can't resonate"); 12 dB = one SVF; 24 dB = **two cascaded SVFs** at the same cutoff with **resonance applied primarily to the first stage** (prevents excessive resonance build-up — O-Prism precedent).
  - **Coefficients:** `g = tan(π·fcEff/fs)`, `k = 1/Q` (resonance). `fcEff` = base cutoff modulated per-sample by the filter ADSR (octaves) and key-track (see Algorithm Details). Recompute `g` per sample for zipper-free envelope modulation (16 voices × 1 `tan`/sample is acceptable; a sub-block control-rate `g` update every 8–16 samples is the optimization if profiling demands).
  - **Self-oscillation:** **nonlinear** variant — `tanh` soft-clip on the resonant (BP) integrator state bounds the oscillation into a clean sine at cutoff at max resonance; this is also the gain-compensation that prevents blow-up.
  - **State reset:** clear `ic1eq/ic2eq` (and cascade stage 2) on voice (re)allocation only, never mid-note.

### Filter Envelope (Filter ADSR → cutoff)
- **JUCE Class:** `juce::ADSR` + `juce::ADSR::Parameters` (verified `juce_audio_basics/utilities/juce_ADSR.h`).
- **Purpose:** The expressive heart — modulates cutoff via the **bipolar** `filterEnvAmount` (FUNC-04, the "filter sweep" lesson).
- **Parameters Affected:** `filterAttack`, `filterDecay`, `filterSustain`, `filterRelease`, `filterEnvAmount`.
- **Configuration:** times 0–5 s (skew ~0.35 for fine low-end control), sustain 0–1. Sampled per-sample (`getNextSample()`); its output `eF ∈ [0,1]` drives `fcEff` exponentially (octaves). Independent of the amp ADSR. `setSampleRate` in prepare **before** first `setParameters`.

### Amplitude Envelope (Amp ADSR → VCA)
- **JUCE Class:** `juce::ADSR`.
- **Purpose:** Drives the VCA (FUNC-04) and **governs voice lifetime**.
- **Parameters Affected:** `ampAttack`, `ampDecay`, `ampSustain`, `ampRelease`; velocity→amplitude (always-on, non-param).
- **Configuration:** times 0–5 s, sustain 0–1. Voice is active while `ampEnv.isActive()` (a long filter-env release must never keep a silent voice alive). The two ADSRs are fully independent — independence is audibly + visibly obvious (UI-02 dual display).

### Voice & Glide Manager (Poly / Mono / Legato + portamento)
- **JUCE Class:** `juce::Synthesiser` (16 × `SubVoice : juce::SynthesiserVoice`) for Poly; custom processor-side `MonoController` (held-note stack + glide ramp) for Mono/Legato.
- **Purpose:** FUNC-05 — 16-voice poly, mono, legato, with glide (portamento).
- **Parameters Affected:** `voiceMode`, `glide`.
- **Configuration:**
  - **Poly:** standard `Synthesiser` allocation/stealing; glide off (or intra-note only).
  - **Mono:** all notes route to one voice; **retrigger** both envelopes each note; glide ramps oscillator frequency from previous to new note over `glide` seconds.
  - **Legato:** like Mono but **do not retrigger** envelopes while a note is already held (slur); glide still ramps pitch.
  - **Glide:** per-voice target frequency with a `SmoothedValue<float, Multiplicative>` (or one-pole) ramp over `glide` (0–1 s); `glide=0` → instant.

### Output Stage
- **JUCE Class:** `juce::SmoothedValue<float>` gain + block-level `std::isfinite` scrub.
- **Purpose:** Master trim (`outputLevel`) + suite-wide NaN insurance.
- **Configuration:** dB→linear, 20 ms smoothing; `std::isfinite` scrub after summing voices.

### Visualization Tap (Filter curve + Spectrum + Scope)
- **JUCE Class:** `VizRing` (custom lock-free overwrite ring, copied from O-simpleFM `FmVizAnalyzer.h`) + `SubVizAnalyzer` (message-thread `juce::dsp::FFT` + `juce::dsp::WindowingFunction<float>` + closed-form filter-curve calculator). FFT runs on the **message thread** (editor Timer 30 Hz), never the audio thread.
- **Purpose:** Feed the headline live filter-response-over-spectrum (UI-01), oscilloscope (UI-04), and dual-ADSR display (UI-02).
- **Configuration:** see **Visualization Data Path** below.

## Processing Chain

```
MIDI in
  ↓
Voice/Glide manager (Poly: Synthesiser 16 voices | Mono/Legato: MonoController → 1 voice + glide)
  ↓
juce::Synthesiser (16 × SubVoice)
  │   per voice, per sample:
  │     SRC:  main = polyBLEP(oscWave, f0)                      ← oscWave
  │           src  = main + subLevel·subSquare(f0/2) + noiseLevel·white   ← subLevel, noiseLevel
  │     CUT:  eF   = filterEnv.getNextSample()                  ← filter ADSR
  │           fcEff = clamp( cutoff · 2^(keyTrack·(note−60)/12)
  │                                · 2^(filterEnvAmount·eF·ENV_OCT), 20, min(20k, 0.45·fs) )  ← cutoff, keyTrack, filterEnvAmount
  │           g = tan(π·fcEff/fs),  k = 1/Q(resonance)          ← resonance
  │     FILT: {lp,bp,hp} = SvfZDF(src, g, k)  [×2 cascade if 24 dB; 1-pole if 6 dB]
  │           out = select(filterType): LP=lp, HP=hp, BP=bp, Notch=src − k·bp
  │           (tanh on resonant path → clean bounded self-osc)  ← filterType, filterSlope, resonance
  │     VCA:  voiceOut = out · ampEnv.getNextSample() · vel     ← amp ADSR (also = voice lifetime)
  ↓ (sum of active voices)
Output gain (SmoothedValue, dB→lin)  ← outputLevel
  ↓
NaN scrub (std::isfinite insurance)
  ↓
[TAP] mono-sum → VizRing (no alloc, no FFT, no locks)
  ↓
Audio out (stereo, mono duplicated)

   ── message thread (Editor Timer 30 Hz) ──
   VizRing → copy scope window (BEFORE FFT — in-place transform clobbers it)
        ├─ raw window (downsampled, max-abs keep sign)              → "scopeUpdate"
        ├─ Blackman-Harris window → dsp::FFT(4096) → log-freq dB    → "spectrumUpdate"
        └─ closed-form filter magnitude from live atomics
           {displayCutoffHz, displayK, filterType, filterSlope}      → "filterCurveUpdate"
        └─ filterEnv/ampEnv current values (atomics)                 → "envUpdate" (dual-ADSR display)
        → emitEventIfBrowserIsVisible(...) → WebView JS draws
```

**Routing notes:**
- **Notch** is derived: `input − k·BP` (no separate filter instance). All four modes share one SVF state.
- **Resonant feedback** is internal to the SVF (the ZDF resonance loop); self-oscillation is a bounded limit cycle via the tanh nonlinearity. No global feedback path.
- **Two parallel envelopes:** filter ADSR (→ cutoff, bipolar octaves) and amp ADSR (→ VCA + voice lifetime) are fully independent.
- **`displayCutoffHz` / `displayK`** atomics are updated each block from the **lead voice** (most-recently-triggered active voice) so the headline filter curve MOVES with the live envelope and matches the dominant heard timbre.
- **Visualization is a read-only tap**, never in the audio return path.

## System Architecture

### MIDI Handling
- **Bus:** MIDI-in → stereo audio-out (no audio input). **`IS_SYNTH TRUE` + `NEEDS_MIDI_INPUT TRUE`** in CMake (critical-pattern #22 — omitting yields a silent plugin). `BusesProperties` output-only (`.withOutput("Output", stereo(), true)`).
- **Note allocation:** `juce::Synthesiser` default voice stealing for Poly; `MonoController` (held-note stack, last-note priority) for Mono/Legato.
- **Velocity:** velocity→amplitude always-on (`velToFilterEnv` deferred to v1.1).
- **Pitch wheel:** ±2 semitone bend (O-simpleFM pattern).

### Visualization Data Path (PERF-01 — real-time safe)
**Audio thread (allocation-free):** after output gain, mono-sum the block and write into the pre-allocated `VizRing` (power-of-two atomic overwrite ring). Update `displayCutoffHz`/`displayK` atomics from the lead voice. **No allocation, no FFT, no locks.**

**Message thread — Editor `Timer` at 30 Hz:**
1. Copy the scope window out of the ring **first** (the FFT transform is in-place and clobbers its buffer).
2. **Scope:** downsample (e.g. 1024 → 128, max-abs-in-bucket keeping sign) → `"scopeUpdate"`.
3. **Spectrum:** Blackman-Harris window → `juce::dsp::FFT` order 12 (4096) via `performFrequencyOnlyForwardTransform` → log-frequency dB bins, rise-fast/fall-slow smoothing → `"spectrumUpdate"`.
4. **Filter curve:** evaluate the closed-form SVF magnitude (see Algorithm Details) at the same log-frequency display bins from the live `{displayCutoffHz, displayK, filterType, filterSlope}` atomics → `"filterCurveUpdate"`. **Same `g/k/type/slope` math as the audio thread → exact match (QUAL-02).**
5. **Envelopes:** push current filter-env + amp-env values → `"envUpdate"` for the dual-ADSR display.
6. `webView->emitEventIfBrowserIsVisible(...)`.

**Critical gotchas:**
- `performFrequencyOnlyForwardTransform` **overwrites its work buffer in place** — copy the scope window BEFORE the FFT.
- FFT on the **message thread** (not `processBlock`) keeps the audio thread copy-only (the brief mandates allocation-free audio thread; PERF-01).
- 4096-pt FFT ≈ 10.8 Hz/bin at 44.1 kHz — enough to render the source harmonics the filter curve cuts through.

### State Persistence
- All parameters live in `AudioProcessorValueTreeState`; `getStateInformation`/`setStateInformation` serialize the APVTS value tree (suite standard). No external files.
- **Educational preset tour (FUNC-06):** factory presets via the Ouaricon preset-manager module (`ouaricon_add_module(... preset-manager)`) — recipes in **Algorithm Details → Preset Recipes**.

### Cross-Platform WebView (COMPAT-02)
- CMake: `NEEDS_WEB_BROWSER TRUE`, `NEEDS_WEBVIEW2 TRUE`; compile defs `JUCE_WEB_BROWSER=1`, `JUCE_USE_WIN_WEBVIEW2_WITH_STATIC_LINKING=1`, `JUCE_USE_CURL=0`.
- Windows: `withUserDataFolder(File::tempDirectory child)` to avoid DAW-host data-folder denial (silent IE fallback → blank UI).
- Resource provider receives **bare paths** (`/`, `/index.html`, `/js/app.js`) — compare by direct equality (critical-pattern #8; project memory).
- **BinaryData NAMESPACE:** v1.0 uses ONE `juce_add_binary_data` target (UI resources). If embedded presets ever become a SECOND binary-data target, give it a **distinct `NAMESPACE`** (not just `HEADER_NAME`) to avoid the duplicate-symbol collision seen in O-simpleGrain Stage 3.1.

## Algorithm Details

### Filter — Cytomic ZDF State-Variable Filter (the resolved topology)

**Per-sample core (one 2-pole stage, simultaneous LP/BP/HP):**
```cpp
// Coeffs (recompute when fcEff or resonance changes; per-sample for env modulation):
const double g  = std::tan (juce::MathConstants<double>::pi * fcEff / fs); // prewarped
const double k  = 1.0 / Q;                  // resonance: k=1/Q ; k→0 ⇒ self-oscillation
const double a1 = 1.0 / (1.0 + g * (g + k));
const double a2 = g * a1;
const double a3 = g * a2;

// Per sample (ic1eq, ic2eq are the two integrator states):
const double v3 = x - ic2eq;
const double v1 = a1 * ic1eq + a2 * v3;
const double v2 = ic2eq + a2 * ic1eq + a3 * v3;
ic1eq = 2.0 * v1 - ic1eq;
ic2eq = 2.0 * v2 - ic2eq;

const double lp = v2;
const double bp = v1;
const double hp = x - k * v1 - v2;          // = x − k·BP − LP
const double notch = x - k * v1;            // = input − k·BP  (= LP + HP)
```
- **Mode select:** `LP→v2`, `BP→v1`, `HP→hp`, `Notch→notch`. **All four from one state** — the SVF is the pedagogical "one filter, four shapes" story.
- **Self-oscillation (DSP-03):** use the **nonlinear** form — replace the resonant feedback `k·v1` with `k·tanh(v1)` (or apply `tanh` to `ic1eq` after update). As `k→0` (resonance→max) the filter sustains a clean, bounded sine at `fcEff`; `tanh` caps the amplitude (clean sine, no blow-up) and IS the gain compensation. The linear SVF cannot self-oscillate — this nonlinearity is load-bearing for the "class whistle."
- **Resonance mapping:** `resonance 0..1 → k`. `Q = 0.5·10^(resonance·Qmax)` style, or simpler `k = 2·(1 − resonance^p)` with a taper `p` so the last few percent reach `k≈0` (self-osc). At `resonance=0`, `k≈1.41` (Butterworth, no peak). Clamp `k ≥ 0`.
- **Slopes:** 6 dB = single 1-pole (`FirstOrderTPTFilter` LP/HP; BP/Notch degrade to gentle shelves — "1-pole can't resonate"); 12 dB = one SVF; 24 dB = **two SVFs cascaded** at the same `fcEff`, **resonance on stage 1 only** (prevents runaway peak; O-Prism precedent).

**Cutoff modulation (per sample):**
```
fcEff = clamp( cutoff
             · pow(2, keyTrack · (midiNote − 60) / 12.0)        // key-tracking (DSP-05)
             · pow(2, filterEnvAmount · eF · ENV_OCT),          // bipolar filter env, octaves
             20.0, min(20000.0, 0.45·fs) );
```
where `eF ∈ [0,1]` is the filter ADSR output, `filterEnvAmount ∈ [−1,+1]`, `ENV_OCT ≈ 6–8` (so ±100% sweeps roughly the full audible range). Exponential (octave) mapping = constant perceptual sweep at any base cutoff. Clamp below `0.45·fs` to keep `tan` well-conditioned.

### Filter Magnitude Response for the UI (closed-form — exact match to the digital filter)

The TPT SVF *is* the bilinear transform pre-warped at the cutoff, so the digital filter's response at display frequency `f` equals the analog prototype evaluated at the **normalized frequency** `Ω = tan(π·f/fs) / g`, where `g = tan(π·fcDisplay/fs)`. At `f = fcDisplay`, `Ω = 1` exactly (peak lands on cutoff, **no warping error**). For each log-spaced display bin:
```
Ω    = tan(π·f/fs) / g
D    = (1 − Ω²) + j·k·Ω            // |D| = sqrt((1−Ω²)² + (k·Ω)²)
LP   |H| = 1 / |D|
HP   |H| = Ω² / |D|
BP   |H| = (k·Ω) / |D|             // 0 dB-normalized band (×k = unity peak)
Notch|H| = |1 − Ω²| / |D|
24 dB: square the magnitude   (|H|² — identical cascaded stages)
6 dB : one-pole D1 = 1 + jΩ  ⇒  LP=1/|D1|, HP=Ω/|D1|
dB   = 20·log10(|H|)
```
Computed on the message thread from the live `displayCutoffHz`/`displayK`/`filterType`/`filterSlope` atomics, so the curve tracks the filter envelope and **uses the identical `g/k` math the audio thread uses** → QUAL-02 is guaranteed by construction, not by tuning. Drawn over the live output spectrum = the headline "before/after filter" figure made live (UI-01).

### Anti-Aliasing — PolyBLEP / polyBLAMP
- **Saw:** naive `2·φ − 1`, then subtract the PolyBLEP residual at the `φ=0/1` wrap. **Square:** difference of two phase-shifted saws (or naive pulse + PolyBLEP at both edges). **Triangle:** integrate a PolyBLEP square (leaky integrator) **or** apply polyBLAMP at the slope discontinuities. **Sine:** LUT, exact.
- PolyBLEP `dt = f0/fs`; residual width = one sample either side of the discontinuity. **Near-zero CPU**, no oversampling.
- **Why PolyBLEP here (and not in O-simpleFM):** the subtractive oscillator runs at a **steady phase increment**, which is exactly the assumption PolyBLEP's discontinuity correction relies on. O-simpleFM rejected PolyBLEP because hard phase-modulation violates that assumption — that constraint does not apply to a subtractive osc → filter chain. Wavetable mipmaps (Serum/Vital style) are overkill for four classic waveforms in a teaching tool.

### Self-Oscillation Gain Compensation
1. **Bounding nonlinearity (primary):** `tanh` on the resonant integrator path turns the would-be unbounded pole-on-axis growth into a stable limit cycle = clean bounded sine at cutoff. This is the gain compensation — sweeping resonance to max cannot blow up the level.
2. **Resonance make-up trim (secondary):** as resonance rises, broadband energy concentrates at the peak; apply a gentle resonance-dependent output trim (e.g. `outGain *= 1/(1 + c·resonance)`, small `c`) so resonance sweeps don't jump in perceived loudness. Combined with `ScopedNoDenormals` and the block-level `isfinite` scrub.

### Dual-ADSR scheme & zipper avoidance
- Two independent `juce::ADSR` per voice, sampled per-sample. Filter env → `fcEff` (octaves, bipolar); amp env → VCA + lifetime. **Independence is the teaching payload** (UI-02 shows both on independent scales).
- **Zipper-free:** `SmoothedValue` (~20 ms) on `cutoff`/`resonance`/`outputLevel` UI changes; the ADSRs are inherently smooth; per-sample `g` recompute (or ≤16-sample control-rate) keeps cutoff sweeps continuous. Never reset oscillator/filter phase/state mid-note.

### Voice modes & glide
- **Poly:** `Synthesiser` allocation/stealing, 16 voices.
- **Mono:** route all notes to one voice, **retrigger** envelopes, glide pitch from previous note.
- **Legato:** as Mono but **suppress envelope retrigger** while a note is held (slur); glide still ramps.
- **Glide:** per-voice `SmoothedValue<float, Multiplicative>` frequency ramp over `glide` seconds (multiplicative = perceptually-even pitch glide); `glide=0` = instant.

### Processing Order (load-bearing)
1. Processor reads APVTS atomics **once per block** → pushes to voices (`setParams`) and to the `MonoController`. Voices never read APVTS directly (O-Bassoon/O-simpleFM block-push pattern).
2. Per sample in a voice: **source mix → fcEff (key-track + filter env, octaves) → SVF → mode select → VCA**. fcEff computed BEFORE the SVF coeffs.
3. **24 dB cascade:** stage 1 (with resonance) → stage 2 (resonance reduced/zero).
4. Lead-voice `displayCutoffHz`/`displayK` atomics updated each block (for the curve).
5. Visualization tap is **last**, post-gain, copy-only.

### Parameter Interactions
- **`resonance` × `filterType` × `filterSlope`:** resonance peaks at cutoff (LP/HP/BP); at 6 dB resonance is inert; at 24 dB resonance is applied to stage 1 only. Self-osc only meaningful at 12/24 dB.
- **`filterEnvAmount` × `cutoff` × `keyTrack`:** all three multiply into `fcEff` (octaves). Bipolar amount + low base cutoff = classic upward sweep; negative amount = downward "pluck close."
- **`keyTrack` × `resonance=100%`:** the self-oscillation-in-tune coupling — at `keyTrack=100%` the self-osc sine plays chromatically (the "Self-Osc Sine" preset). This coupling is the teaching payload — keep it intact.
- **`voiceMode` × `glide`:** glide audible in Mono/Legato; in Poly glide is off (or intra-note only).

| # | Feature | Complexity | Risk | Fallback / Mitigation |
|---|---------|-----------|------|----------------------|
| 1 | Self-oscillating multimode SVF | **HIGH** | Linear SVF won't self-oscillate; nonlinear SVF can be unstable / DC-biased / blow up at `k→0` (DSP-03 fail) | **Nonlinear (tanh) Cytomic SVF**; clamp states; `ScopedNoDenormals`; block `isfinite` scrub. **Fallback A:** linear `juce::dsp::StateVariableTPTFilter` for LP/BP/HP + a **separate sine oscillator at cutoff** faked in for the self-osc preset only. **Fallback B:** cap resonance just below self-osc and ship the whistle as a dedicated mode. |
| 2 | Exact magnitude curve (headline) | MEDIUM | Curve drifts from audio (QUAL-02 fail) if analog prototype used without prewarp | Use `Ω = tan(π·f/fs)/g` (prewarped) with the **same g/k** the audio thread uses; verify in render-harness (compare closed-form vs measured sweep). |
| 3 | Anti-aliasing (saw/square) | MEDIUM | Audible buzz at high notes (DSP-06/QUAL-01 fail) — fatal for a teaching tool | **PolyBLEP/polyBLAMP** (composes — steady phase increment); render-harness aliasing probe at high keys; **fallback:** 2× oversample the oscillator section only. |
| 4 | Voice modes + glide | MEDIUM | Mono/Legato note-priority + glide is genuinely new vs O-simpleFM; stuck notes / retrigger bugs | Held-note stack, last-note priority; legato suppresses retrigger; `SmoothedValue` glide. **Fallback:** ship Poly + Mono (retrigger) in v1.0, refine Legato in polish. |
| 5 | Real-time-safe viz | MEDIUM | Alloc/FFT on audio thread (PERF-01 fail); in-place FFT clobbers scope | Audio thread copy-only into `VizRing`; FFT on message Timer; **copy scope before FFT** (reuse O-simpleFM `FmVizAnalyzer` verbatim). |
| 6 | Per-sample cutoff modulation cost | LOW | 16 voices × `tan`/sample CPU | Acceptable on modern CPU; **fallback:** sub-block (8–16 sample) `g` recompute (>1 kHz update, still zipper-free). |
| 7 | Cross-platform WebView | LOW | Silent IE fallback → blank UI on Windows | `NEEDS_WEBVIEW2 TRUE` + static-linking define + `withUserDataFolder` (project memory). |
| 8 | BinaryData namespace | LOW | 2nd binary-data target collides on `BinaryData` namespace | v1.0 ships ONE target; if a 2nd is added, distinct `NAMESPACE` (O-simpleGrain lesson). |

### Overall Project Risk
- **Overall complexity:** MEDIUM-HIGH. The DSP primitives (osc, ADSR, viz) are sibling-ports; the genuinely-new + highest-risk work is the **self-oscillating multimode SVF (#1)** and its **exact magnitude curve (#2)**, then **voice modes (#4)**.
- **Highest risk:** self-oscillating SVF (~50% of project risk). Build the **linear** SVF + all four modes + slopes FIRST (validate magnitude curve), THEN add the tanh self-oscillation. Keep Fallback A (linear SVF + faked self-osc sine) documented.
- **Recommended order:** osc+mixer → linear SVF (4 modes, 3 slopes) + dual ADSR + VCA → magnitude curve match → nonlinear self-osc → voice modes/glide → viz → GUI.

## Architecture Decisions

### 1. Filter topology: custom Cytomic ZDF SVF (NOT Moog ladder) — THE headline decision
**Decision:** A custom **zero-delay-feedback TPT state-variable filter** (Andrew Simper "Solving the continuous SVF equations…" / Zavalishin *The Art of VA Filter Design*) is the primary topology, cascaded ×2 for 24 dB, 1-pole for 6 dB, with a tanh nonlinearity for self-oscillation.

**Rationale:**
- **All four modes from one structure:** LP/BP/HP computed simultaneously each sample; **Notch = input − k·BP**. One filter, four shapes — this *is* the pedagogical narrative.
- **Exact closed-form magnitude response** (`Ω = tan(π·f/fs)/g`) that matches the running digital filter sample-for-sample → the headline "filter-curve-over-spectrum" visual is truthful by construction (QUAL-02), not by tuning. **This is the deciding factor for a teaching tool.**
- **Clean slope story:** 6/12/24 dB = 1/2/4 poles of the *same* SVF (1-pole, one stage, two cascaded) — pedagogically clean.
- **Stable self-oscillation** via the nonlinear variant (clean bounded sine at cutoff).
- **Per-sample cutoff modulation** (filter env) is explicit and cheap; matches O-Formant/O-Bassoon precedent of custom per-voice filter structs at scale (16 voices) over `juce::dsp::IIR` overhead.

**Alternatives considered:**
1. **Moog ladder (`juce::dsp::LadderFilter`, exists in `juce_dsp/widgets/`):** authentic 24 dB self-oscillation, BUT fundamentally a **lowpass** — HP/BP require the Oberheim tap-and-sum trick (JUCE exposes only fixed `LPF12/24, HPF12/24, BPF12/24` modes, **no notch**); slopes are coupled to the 4-pole topology; the multimode taps have less clean magnitude curves for the headline figure. **Rejected:** fails the "all four modes + clean per-slope curves + exact teaching magnitude curve" bar.
2. **`juce::dsp::StateVariableTPTFilter` (built-in, linear):** correct ZDF SVF for LP/BP/HP, BUT **no notch** (must derive) and, being **linear, cannot sustain self-oscillation** (DSP-03 MUST). **Kept as Fallback A** (linear modes + faked self-osc sine).
3. **RBJ biquads (`juce::dsp::IIR`):** standard but coefficient updates are not zipper-clean under fast cutoff modulation, and `IIR::Filter`/`ProcessSpec` overhead at 16 voices is unjustified. **Rejected.**

**Tradeoffs accepted:** writing a ~12-line custom SVF (vs using a built-in) — accepted because the simultaneous-multimode + exact-curve + self-osc requirements can't be met by any single built-in class, and the core is textbook and well-validated (O-Prism precedent).

### 2. PolyBLEP anti-aliasing (NOT wavetable mipmaps, NOT oversampling)
**Decision:** PolyBLEP (saw/square) + polyBLAMP (triangle) + LUT sine. **Rationale:** steady phase increment → PolyBLEP composes perfectly; near-zero CPU; no latency. **Alternatives:** wavetable mipmaps (Serum/Vital) — overkill for 4 classic waveforms; runtime oversampling — needless CPU/latency. **Tradeoff:** PolyBLEP has a tiny residual error vs a perfect band-limit — inaudible and far cheaper.

### 3. `keyTrack` parameter added (default 0%)
**Decision:** add a cutoff key-tracking control so a self-oscillating filter plays in tune. **Rationale:** DSP-05 + the "Self-Osc Sine" lesson need it; default 0% keeps the first sweep lesson simple (cutoff = absolute Hz). **Alternative:** always-on key-track — rejected (confuses the basic "sweep a fixed cutoff" lesson).

### 4. `juce::Synthesiser` + processor-side MonoController for voice modes
**Decision:** reuse the proven `Synthesiser`/`SynthesiserVoice` skeleton; layer Mono/Legato/glide in the processor. **Rationale:** Poly is free and matches the suite; Mono/Legato need note-priority logic `Synthesiser` doesn't provide. **Alternative:** fully custom voice manager — unjustified for a small synth. **Tradeoff:** Mono/Legato is the one genuinely-new area vs O-simpleFM (flagged MEDIUM risk).

### 5. FFT + filter-curve on the message thread
**Decision:** audio thread is copy-only into `VizRing`; FFT and closed-form curve run on the 30 Hz editor Timer. **Rationale:** brief mandates an allocation-free audio thread (PERF-01). **Tradeoff:** ~33 ms visual latency (imperceptible for teaching).

## Special Considerations

- **Thread safety:** APVTS atomics for params; `VizRing` + `std::atomic<float>` for audio→UI; no locks on the audio thread; UI never calls processing code (critical-pattern #5).
- **Performance:** 16 voices × (PolyBLEP osc + 1–2 SVF stages + 2 ADSR) ≈ light. Per-sample `tan` for cutoff is the main cost (acceptable; sub-block fallback documented). 4096 FFT @ 30 Hz on the message thread is cheap. Estimated well under one core at 48 kHz. No oversampling in v1.0.
- **Denormals:** `juce::ScopedNoDenormals` at the top of `processBlock` (resonant filters + decaying envelopes stall hard on denormals); per-voice + block `isfinite` scrub; SVF self-osc bounded by tanh.
- **Sample rate:** all `g = tan(π·fc/fs)` and phase increments use the live `fs`; `fcEff` clamped below `0.45·fs`. ADSR `setSampleRate` in prepare before `setParameters`. SVF/osc state reset in `prepareToPlay`.
- **Latency:** **zero** added latency in v1.0 (no oversampling). Still call `setLatencySamples(0)` explicitly (NB: `getLatencySamples()` is **non-virtual** in JUCE 8 — do not override).
- **Zipper noise:** `SmoothedValue` on cutoff/resonance/output UI changes; per-sample (or ≤16-sample) cutoff modulation; multiplicative glide; never reset phase/state mid-note.
