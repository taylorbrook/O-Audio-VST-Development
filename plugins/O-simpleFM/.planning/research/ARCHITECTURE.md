## Complexity & Research Summary

- **Complexity Tier:** 4 (synthesizer with MIDI input + oscillators) escalated toward **6** by first-class real-time FFT/scope visualization. Net research depth: **DEEP**.
- **Headline DSP decision:** Build **phase modulation (PM), not true FM** — every commercial "FM" synth is PM. PM adds the modulator to phase *after* integration, so DC offset (from feedback/asymmetry) produces only a fixed inaudible phase offset instead of integrating into audible pitch drift. This is what makes feedback and cascaded operators stable.
- **Modulation-index semantics decision:** Expose the **raw radian modulation index `I`** (the Bessel argument), range **0–20**, perceptual taper, displayed linearly. Most pedagogically transparent — it maps 1:1 to the sideband theory the plugin teaches. Optional read-only secondary readout `Δf = I·f_m` (Hz deviation).
- **Polyphony decision:** **16 voices** (Ouaricon suite norm; brief's 8–16 range). Voice lifetime gated by amp-envelope activity.
- **Modulator frequency-mode decision (v1.0 scope confirmed):** ship **both ratio and fixed-frequency modes** (`modFixedMode` toggle + `modFixedHz`). Ratio mode key-tracks (`f_m = f_c·ratio`); fixed mode holds the modulator at a constant Hz that does NOT track pitch — the cleanest way to teach inharmonic/clangorous timbres (the modulator stays put while the carrier moves). Fine detune (`fineCents`) and master tune (`masterTune`) are **deferred to v1.1**.
- **Operator-waveform decision (v1.0 scope confirmed):** **sine-only operators in v1.0** — DSP-04 (selectable tri/saw/square) is **deferred to v1.1**. Keeps the FM math clean for teaching and removes the heaviest anti-aliasing cost.
- **Anti-aliasing decision:** sine LUT operators + **key-tracked index ceiling** (Carson's rule) + **2× polyphase-IIR oversampling always-on**. Because v1.0 is sine-only, **2× OS + index ceiling is the complete v1.0 story**; the 4× + band-limited additive wavetable escalation is the v1.1 plan for when non-sine operators land. Do NOT use PolyBLEP — it does not compose with hard FM.

## Core Components

### FM Voice (FMVoice)
- **JUCE Class:** Custom `FMVoice : juce::SynthesiserVoice` (carrier + modulator phase accumulators; two `juce::ADSR`; feedback history).
- **Purpose:** Render one polyphonic 2-operator PM voice: modulator (with self-feedback) phase-modulates the carrier; carrier shaped by amp envelope.
- **Parameters Affected:** `ratio`, `ratioSnap`, `modIndex`, `feedback`, `modEnvToIndex`, `velToIndex`, `modFixedMode`, `modFixedHz`, all mod/amp ADSR params. (Operators are sine-only in v1.0; `fineCents`/`masterTune` deferred to v1.1.)
- **Configuration:**
  - **PM core (radians convention — committed; do NOT mix with normalized-turns):**
    ```cpp
    double fm     = modFixedMode ? modFixedHz : (fc * ratio);        // fixed Hz (no key-track) OR C:M ratio (snapped if enabled)
    double modEnv = modEnvelope.getNextSample();                      // ADSR ∈ [0,1]
    double I_inst = baseIndex * ((1.0 - envDepth) + envDepth*modEnv); // mod env → index (default depth 1.0)

    double modOut = fastSine(modPhase + feedback * 0.5*(prev1+prev2));// self-feedback (see Feedback below)
    prev2 = prev1; prev1 = modOut;
    modPhase += twoPi*fm/fs;  if (modPhase >= twoPi) modPhase -= twoPi;

    double carOut = fastSine(carPhase + I_inst * modOut);             // index = radian phase deviation
    carPhase += twoPi*fc/fs;  if (carPhase >= twoPi) carPhase -= twoPi;

    double sample = carOut * ampEnvelope.getNextSample();             // independent amp ADSR
    ```
  - **Index taper:** `I = 20.0 * pow(knobNorm, 1.7)` — finer control in the musically dense low end.
  - **Voice lifetime:** active while `ampEnvelope.isActive()` (a long mod release must NOT keep a silent voice alive).
  - **Note-on reset:** zero `fbPrev1/fbPrev2`; never reset carrier/modulator phase mid-note (zipper/click).
  - **Prepare:** custom `prepareToPlay(sampleRate, maxBlockSize)` calls `setCurrentPlaybackSampleRate` + `ampEnv/modEnv.setSampleRate` **before** `setParameters`; resets smoothers. (JUCE 8 `SynthesiserVoice` has NO virtual `prepareToPlay` — confirmed from O-Bassoon `BassoonVoice.h:34`.)

### Sine Operator (fastSine)
- **JUCE Class:** `juce::dsp::LookupTableTransform<float>` (header `juce_dsp/maths/juce_LookupTable.h`, verified present).
- **Purpose:** Allocation-free band-clean sine for both operators (v1.0 is sine-only).
- **Parameters Affected:** none directly.
- **Configuration:**
  - Single-cycle, **1024 points, linear interpolation** (~97 dB SNR — cubic unnecessary, inaudible floor).
  - **Mandatory `floor`-modulo phase wrap** before lookup — the PM argument swings to many multiples of 2π at high index:
    ```cpp
    inline float fastSine(float phase) noexcept {
        constexpr float twoPi = juce::MathConstants<float>::twoPi;
        phase -= twoPi * std::floor(phase / twoPi);  // essential at high index
        return sineTable[phase];
    }
    ```
  - `std::sin` is used ONLY for the one-time table fill.

### Modulator Self-Feedback (DX7)
- **JUCE Class:** Custom (two-sample-average feedback term).
- **Purpose:** Enrich the modulator spectrum toward sawtooth → noise/chaos as feedback rises (FUNC-03).
- **Parameters Affected:** `feedback`.
- **Configuration:**
  ```cpp
  float avg   = 0.5f * (fbPrev1 + fbPrev2);            // Tomisawa two-sample anti-hunting average (US Pat 4,249,447)
  float fbOut = fastSine(modPhase + feedbackCoeff*avg);
  if (!std::isfinite(fbOut)) fbOut = 0.0f;             // kill NaN at source
  fbOut = juce::jlimit(-1.0f, 1.0f, fbOut);            // clamp HISTORY, not just output
  fbPrev2 = fbPrev1; fbPrev1 = fbOut;
  ```
  - The two-sample average is **load-bearing**, not optional: a single-sample feedback term hunts into a Nyquist-rate `+x,−x` limit cycle (screech). Averaging is a cheap LP that suppresses it.
  - UI 0–100% → `feedbackCoeff` with **max ≈ π radians**, square/`x^1.5` taper (bottom 0–60% stays gentle).

### Amplitude Envelope (Amp ADSR)
- **JUCE Class:** `juce::ADSR` + `juce::ADSR::Parameters` (verified `juce_audio_basics/utilities/juce_ADSR.h`).
- **Purpose:** Shape carrier output amplitude; governs voice lifetime (FUNC-05).
- **Parameters Affected:** `ampAttack`, `ampDecay`, `ampSustain`, `ampRelease`, velocity→amplitude (always on).
- **Configuration:** times 0.001–5 s (skew 0.35), sustain 0–1. `setSampleRate` in prepare before first `setParameters`.

### Modulation Envelope (Mod ADSR)
- **JUCE Class:** `juce::ADSR`.
- **Purpose:** Independent envelope scaling the modulation index over the note — the headline expressive feature (FUNC-04).
- **Parameters Affected:** `modAttack`, `modDecay`, `modSustain`, `modRelease`, `modEnvToIndex` (depth, default 1.0).
- **Configuration:** **Multiplicative** application: `I_inst = baseIndex·((1−depth)+depth·modEnv)`. Default depth 1.0 ⇒ `I_inst = baseIndex·modEnv` so sustain 0 yields a pure-sine tail (carrier-null reachable, "knob = max brightness"). Additive is rejected as default (muddies the mental model).

### Operator Waveforms (Non-Sine — DSP-04) — DEFERRED to v1.1
- **Status:** **OUT OF SCOPE for v1.0** (decision: sine-only operators). Documented here as the v1.1 implementation plan; no `carWave`/`modWave` parameters ship in v1.0.
- **JUCE Class (v1.1):** Custom additive **band-limited wavetables**, one table per octave band, read by phase.
- **Purpose (v1.1):** Optional tri/saw/square operators (sine default).
- **Configuration (v1.1):** When any non-sine operator is active, **escalate to 4× oversampling**. **Do NOT use PolyBLEP/BLIT** — their discontinuity correction assumes a steady phase increment, which hard FM violates. Sine remains the always-clean default.

### Anti-Aliasing — Index Ceiling + Oversampling
- **JUCE Class:** `juce::dsp::Oversampling<float>` with `filterHalfBandPolyphaseIIR` (verified `juce_dsp/processors/juce_Oversampling.h:69`). Index ceiling is custom.
- **Purpose:** Keep QUAL-01 across full index/feedback/pitch range.
- **Parameters Affected:** implicitly all (driven by `modIndex` × `ratio` × pitch × `feedback`).
- **Configuration:**
  1. **Key-tracked index ceiling** (per-note, near-free): `indexCeil = (0.9·Nyquist − f_c)/f_m − 1; effIndex = min(userIndex, indexCeil)`. Crossfade/smooth the ceiling (it is a timbral change — bright patches dull when played high).
  2. **2× polyphase-IIR oversampling, always-on**, wrapping the whole voice-sum render (low latency, catch-all). Report added latency via `setLatencySamples()` (NB: `getLatencySamples()` is non-virtual in JUCE 8). **This is the complete v1.0 AA chain (sine-only).**
  3. **(v1.1) 4× only while non-sine operators active** — deferred with DSP-04.

### Output Stage
- **JUCE Class:** `juce::SmoothedValue<float>` gain + final block NaN scrub.
- **Purpose:** Master output trim + suite-wide NaN insurance.
- **Parameters Affected:** `outputLevel` (dB).
- **Configuration:** dB→linear gain, 20 ms smoothing; block-level `std::isfinite` scrub after summing voices.

### Visualization Tap (Spectrum + Scope)
- **JUCE Class:** `juce::AbstractFifo` ring (verified `juce_core/containers/juce_AbstractFifo.h`) + `juce::dsp::FFT` + `juce::dsp::WindowingFunction<float>` (verified `juce_dsp/frequency/juce_FFT.h`, `juce_Windowing.h`). FFT runs on the **message thread**, not the audio thread.
- **Purpose:** Feed the live spectrum analyzer (UI-01) and oscilloscope (UI-02).
- **Parameters Affected:** none (read-only tap of mono-summed output).
- **Configuration:** see **Visualization Data Path** below.

## Processing Chain

```
MIDI in
  ↓
juce::Synthesiser (16 × FMVoice)
  │   per voice, per sample (PM core, radians):
  │     MOD: modOut = sine(modPhase + feedbackCoeff·½(prev1+prev2))   ← feedback
  │          f_m = modFixedMode ? modFixedHz : (fc·ratio)            ← ratio vs fixed-Hz mode
  │          modPhase += 2π·f_m/fs
  │     INDEX: I_inst = baseIndex·((1−depth)+depth·modEnv)            ← modEnvToIndex
  │            effIndex = min(I_inst, keyTrackedCeil)                 ← anti-alias ceiling
  │     CAR: carOut = sine(carPhase + effIndex·modOut)
  │          carPhase += 2π·fc/fs
  │     voiceOut = carOut · ampEnv                                    ← ampEnvToLifetime
  ↓ (sum of active voices)
2× Oversampling wrapper (filterHalfBandPolyphaseIIR, always-on; v1.0 sine-only — 4× path deferred to v1.1)
  ↓
Output gain (SmoothedValue, dB→lin)  ← outputLevel
  ↓
NaN scrub (std::isfinite insurance)
  ↓
[TAP] mono-sum → AbstractFifo ring  ── (no alloc, no FFT on audio thread)
  ↓
Audio out (stereo, mono signal duplicated)

   ── message thread (Editor Timer 30 Hz) ──
   AbstractFifo → copy scope window
        ├─ Blackman-Harris window → dsp::FFT (4096) → log-freq dB bins → "spectrumUpdate"
        └─ raw window (downsampled)                                  → "scopeUpdate"
        → emitEventIfBrowserIsVisible(...)  → WebView JS draws
```

**Routing notes:**
- **Feedback loop:** modulator-internal only (self-feedback), one-sample-delayed two-sample average. No global feedback path.
- **Two parallel envelopes:** amp ADSR (carrier amplitude + voice lifetime) and mod ADSR (index scaling) are fully independent.
- **Modulator frequency mode:** `f_m = fc·ratio` (ratio mode, key-tracks) or `f_m = modFixedHz` (fixed mode, constant — does not track pitch).
- **Oversampling factor:** **2× always-on (v1.0 sine-only)**; the conditional 4× for non-sine operators is deferred to v1.1 with DSP-04.
- **Visualization is a read-only tap**, never in the audio return path.

## System Architecture

### MIDI Handling
- **Bus:** MIDI-in → stereo audio-out (no audio input). `IS_SYNTH TRUE` + `NEEDS_MIDI_INPUT TRUE` in CMake (critical-pattern #22 — omitting yields a silent plugin).
- **BusesProperties:** output-only (`.withOutput("Output", stereo(), true)`).
- **Note allocation:** `juce::Synthesiser` default voice stealing; 16 `FMVoice` + one trivial `FMSound`.
- **UI keyboard injection (optional):** an on-screen keyboard can inject MIDI via a native function into a `MidiBuffer` merged in `processBlock` (O-Marimba `addMidiMessage` pattern) — `nice` only.
- **Velocity:** velocity→amplitude always; velocity→index opt-in (`velToIndex`, default 0).

### Visualization Data Path (PERF-01 — real-time safe)
**Audio thread (allocation-free):**
- After output gain, mono-sum the block and write into a pre-allocated `juce::AbstractFifo`-backed `std::vector<float>` ring. **No allocation, no FFT, no locks.**
- Reference pattern: O-Marimba `WaveformFifo` (atomic overwrite ring) and O-GrainScatter triple-buffered viz snapshot.

**Message thread — Editor `Timer` at 30 Hz:**
1. Copy a scope window out of the ring.
2. **Scope:** downsample the window (e.g. 512 → 128 points, max-abs-in-bucket keeping sign) → JSON.
3. **Spectrum:** apply **Blackman-Harris** window (≈−92 dB sidelobes keep adjacent sidebands distinct — Hann is blurrier), run `juce::dsp::FFT` at **order 12 (4096)** via `performFrequencyOnlyForwardTransform`, map to log-frequency dB bins with **rise-fast/fall-slow** decay smoothing → JSON.
4. `webView->emitEventIfBrowserIsVisible("spectrumUpdate", ...)` and `("scopeUpdate", ...)`.

**Critical gotchas:**
- `performFrequencyOnlyForwardTransform` **overwrites its work buffer in place** — copy the scope window BEFORE the FFT, or the scope reads garbage.
- This is the one intentional deviation from O-MultiBandCompressor (which FFTs in `processBlock`): per the brief, FFT runs on the message thread to keep the audio thread copy-only.
- 4096-point FFT gives ~10.8 Hz/bin at 44.1 kHz — enough to visually separate discrete sidebands, which is the headline teaching visual.

### State Persistence
- All parameters live in `AudioProcessorValueTreeState`; `getStateInformation`/`setStateInformation` serialize the APVTS value tree (suite standard). No external files.
- **Educational preset tour (FUNC-06):** factory presets via the Ouaricon preset-manager convention (or APVTS snapshots). Recipes defined in **Algorithm Details → Preset Recipes** below.

### Cross-Platform WebView (COMPAT-02)
- CMake: `NEEDS_WEB_BROWSER TRUE`, `NEEDS_WEBVIEW2 TRUE`; compile defs `JUCE_WEB_BROWSER=1`, `JUCE_USE_WIN_WEBVIEW2_WITH_STATIC_LINKING=1`, `JUCE_USE_CURL=0`.
- Windows: `withUserDataFolder(File::tempDirectory child)` to avoid DAW-host data-folder denial (silent IE fallback → blank UI).
- Resource provider receives **bare paths** (`/`, `/index.html`, `/js/app.js`) — compare by direct equality (critical-pattern #8; project memory).

## Algorithm Details

### Modulation-Index Semantics (decision rationale)
Three equivalent exposures exist: (a) raw radian index `I` (= the Bessel argument), (b) peak deviation Δf in Hz (`I = Δf/f_m`), (c) modulator output level. **Use (a).** It maps 1:1 to the spectrum theory the plugin teaches (sideband pairs at `f_c ± n·f_m`, amplitudes `Jₙ(I)`). Optionally show `Δf = I·f_m` as a read-only secondary readout.

### Bessel / sideband facts to drive UI annotations
- Significant sideband pairs ≈ **I + 1**.
- **Carson's rule:** `BW ≈ 2·(I+1)·f_m` — grounds analyzer scaling AND the aliasing budget; highest significant component ≈ `f_c + (I+1)·f_m`.
- **Carrier nulls** (J₀ zeros) at **I ≈ 2.405, 5.520, 8.654…** — the fundamental fully disappears. **Annotate I ≈ 2.405** ("watch the fundamental vanish") — the most memorable FM demo.

### C:M ratio → harmonic vs inharmonic
Sidebands land at `f_c·(1 ± n·ratio)`. Integer/simple-rational C:M → harmonic; irrational C:M → inharmonic/bell. Negative-frequency lower sidebands fold through 0 Hz with phase inversion (enriches low ratios).

### Fixed-frequency modulator mode (teaching note)
When `modFixedMode` is on, the modulator runs at a constant `modFixedHz` independent of the played note. The C:M relationship therefore *changes with pitch* — a fixed 110 Hz modulator against a swept carrier produces ever-shifting inharmonic spectra (classic metallic/clangorous DX behavior). This is the most direct way to demonstrate that "inharmonicity = modulator not locked to carrier." At very low `modFixedHz` (≈1–10 Hz) the effect degrades gracefully toward vibrato/tremolo, illustrating the FM↔vibrato continuum.

| C:M | Character |
|-----|-----------|
| 1:1 | Sawtooth-like, full harmonic series |
| 1:2 | Odd-harmonic, hollow / clarinet-ish |
| 2:1 | Brighter harmonic, brass/reed |
| 3:2 | Gapped harmonic, nasal/voweled |
| 1:√2 (1:1.414) | Inharmonic, metallic |
| 1:3.5 | Canonical FM tubular bell |

### Preset Recipes (FUNC-06 — preset tour)
ADSR = (A, D, S 0–1, R). **Star** = the concept each isolates.

| Preset | C:M | Index | Mod ADSR | Amp ADSR | Star concept |
|--------|-----|-------|----------|----------|--------------|
| E-Piano (Rhodes) | 1:1 (or 1:2) | ~2–3 | 0, 0.4, 0.0, 0.2 | 0.002, 1.5, 0.3, 0.4 | Mod env decays index → bright ping + sine body |
| Tubular Bell | 1:3.5 | ~4–6 | 0, 2.5, 0.0, 2.0 | 0.001, 5, 0.0, 3 | Inharmonic ratio |
| Brass | 1:1 | swell 0→~5 | 0.1, 0.2, 0.8, 0.2 | 0.1, 0.1, 0.9, 0.2 | Index env tracks amp env (brightness = loudness) |
| Clarinet | 1:2 (or 1:4) | ~1.5–2 static | 0.15, 0.1, 1.0, 0.1 | 0.15, 0, 1.0, 0.15 | Odd-harmonic ratio + low steady index |
| Clang Bell | 1:1.414 | ~8–12 | 0, 0.5, 0.0, 1.5 | 0.001, 4, 0.0, 2 | High index → wide BW (aliasing demo) + max inharmonicity |

### Smoothing / zipper avoidance
`SmoothedValue` (~20 ms linear) on index/feedback/output. **Ratio uses Multiplicative smoothing** OR integer-snap with a short ramp — linear smoothing of a frequency factor glides pitch oddly. Never reset phases mid-note.

## Integration Points

### Feature Dependency Graph
```
ratio ───────┐
modFixedMode ─┤ (select f_m: fc·ratio OR modFixedHz)
modFixedHz ───┤
              ├─► modPhase increment ─► MOD operator (sine) ─┐
feedback ─► feedback coeff ─► MOD self-feedback ─────────────┤
                                                              ▼
modIndex ─┐                                   carrier phase modulation
modEnvToIndex ─► I_inst ─────────────────────► (effIndex after ceiling)
modEnv (Mod ADSR) ┘            ▲                        │
velToIndex ───────────────────┘                        ▼
                                              CAR operator (sine)
                                                        │
ampEnv (Amp ADSR) ─────────────────────────► amplitude + voice lifetime
                                                        │
                                              voice sum ► oversampling ► output gain ► viz tap
```

### Processing Order (load-bearing)
1. Read APVTS atomics **once per block** in the processor; push to each voice via `setParams(...)` (O-Bassoon `setExpression` block-push pattern). Voices do not read APVTS directly.
2. Per sample inside a voice: modulator (with feedback) **before** carrier (carrier consumes `modOut`).
3. Index ceiling applied **after** `modEnvToIndex` scaling, **before** carrier modulation.
4. Oversampling wraps the **summed** voice render (not per-voice — CPU).
5. Visualization tap is **last**, post-gain, copy-only.

### Parameter Interactions
- **Aliasing is combinatorial:** `modIndex × ratio × pitch × feedback`. The key-tracked index ceiling is the single most important interaction guard.
- **modEnvToIndex × modSustain:** at depth 1.0, `modSustain = 0` gives a pure-sine tail (carrier null reachable). This coupling is the teaching payload — keep it intact.
- **ratioSnap × ratio:** snap applied at read site only; the stored param stays continuous so toggling snap on/off is lossless.

### Thread Boundaries
| Data | Producer | Consumer | Mechanism |
|------|----------|----------|-----------|
| Parameter values | message/host | audio | APVTS atomic `getRawParameterValue()->load()` |
| Audio output samples | audio | message (viz) | `juce::AbstractFifo` lock-free ring (no alloc) |
| Spectrum/scope frames | message (Timer FFT) | WebView JS | `emitEventIfBrowserIsVisible` |
| UI knob ↔ param | WebView JS ↔ message | — | `WebSliderRelay`/`WebComboBoxRelay`/`WebToggleButtonRelay` + attachments |
| UI keyboard MIDI (opt) | WebView JS | audio | native fn → `MidiBuffer` merge in `processBlock` |

## Implementation Risks

| # | Feature | Complexity | Risk | Fallback / Mitigation |
|---|---------|-----------|------|----------------------|
| 1 | PM voice core | MEDIUM | Phase-convention mixing (radians vs turns) → wrong index/feedback scaling | **Commit to radians internally** (1:1 with Bessel math). Single documented convention in `Operator.h`. |
| 2 | Modulator self-feedback | MEDIUM | Nyquist-rate limit-cycle screech; NaN poisoning the whole synth | Two-sample average (mandatory), clamp **history**, `isfinite` scrub at source + block level, reset history on note-on. |
| 3 | Anti-aliasing | **HIGH** | Audible aliasing at high index/feedback/pitch (QUAL-01 fail) | **Tiered fallback:** (a) sine + index ceiling + 2× OS is the v1.0 floor; if still audible, (b) raise to 4× globally; (c) tighten ceiling to 0.85·Nyquist. Non-sine waveforms stay opt-in. |
| 4 | Real-time-safe viz | MEDIUM | Allocation/FFT on audio thread (PERF-01 fail); in-place FFT clobbers scope | Audio thread copy-only into pre-allocated `AbstractFifo`; FFT on message-thread Timer; **copy scope window before FFT**. |
| 5 | Spectrum legibility | MEDIUM | Sidebands blurred together → teaching value lost | 4096 FFT + Blackman-Harris window + rise-fast/fall-slow smoothing; log-freq axis. |

## Architecture Decisions

1. **PM over true FM (WHY):** True FM integrates the modulator through the phase accumulator, so any DC component (feedback, asymmetric waveform, numerical bias) accumulates into audible pitch drift that worsens with depth/cascading. PM adds the modulator after integration → DC is only a fixed inaudible phase offset. Every commercial "FM" synth (DX7, Operator, FM8) is actually PM. **Tradeoff:** none for a sine-modulator synth (identical spectra); pure upside in stability.
2. **Raw radian index (WHY):** Pedagogical transparency — the knob value *is* the Bessel argument the plugin teaches; carrier nulls land at fixed, annotatable values. **Alternatives considered:** Hz deviation (less direct), modulator level (obscures the math). Offered Δf as a secondary read-only readout.
3. **16 voices (WHY):** Suite norm; comfortable for a classroom instrument without CPU concern at 2× OS. **Alternative:** 8 (lighter) — rejected as needlessly limiting for chordal teaching.
4. **`juce::Synthesiser` + custom `SynthesiserVoice` (WHY):** Proven across the suite (O-Bassoon/O-Prism/O-Lyrica); handles allocation/stealing for free. **Alternative:** custom allocator — unjustified complexity for a 2-op synth.
5. **FFT on message thread (WHY):** Brief mandates audio-thread allocation-free; moving FFT to the 30 Hz Timer keeps the audio path copy-only. **Tradeoff:** ~33 ms visual latency (imperceptible for teaching).
6. **Index ceiling + 2× OS as the AA floor (WHY):** For a *teaching* tool, transparency and CPU predictability beat brute oversampling. Index ceiling is near-free and textbook (CCRMA). **Tradeoff:** bright patches dull when played high — accepted (and itself teachable), smoothed to avoid zipper.

## Special Considerations

- **Thread safety:** APVTS atomics for params; `AbstractFifo` for audio→UI; no locks on the audio thread; UI never calls processing code (critical-pattern #5).
- **Performance:** 16 voices × 2 sine LUT lookups + feedback ≈ trivial; 2× polyphase-IIR OS is the main cost (modest). 4096 FFT at 30 Hz on the message thread is cheap. Estimated well under one core at 48 kHz.
- **Denormals:** `juce::ScopedNoDenormals` at the top of `processBlock` (decaying feedback loops stall 10–100× on denormals); per-voice + block `isfinite` scrub.
- **Sample rate:** all phase increments use `2π·f/fs`; index ceiling recomputed per note from current `fs`/Nyquist. ADSR `setSampleRate` in prepare before `setParameters`.
- **Latency:** 2× polyphase-IIR oversampling adds a small fixed latency — report via `setLatencySamples()` in `prepareToPlay` (NB: `getLatencySamples()` is non-virtual in JUCE 8; do not override).
- **Zipper noise:** `SmoothedValue` on index/feedback/output; Multiplicative smoothing (or snap+ramp) on ratio; never reset phases mid-note.
