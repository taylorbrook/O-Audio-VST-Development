# O-Bitrot v1.2+ Improvement Brief — Authenticity & Features

Synthesized from 5 verified review dimensions (Tape+Vinyl authenticity, CD+Packet authenticity, Codec+Crush quality, feature gaps vs research/market, engine architecture). All findings below survived line-level verification; corrections from the verify pass are folded in. Duplicates across dimensions are merged with all evidence retained.

## Summary

O-Bitrot v1.1.0 is a correct, deterministic, well-tested glitch **event** engine — but between events the output is bit-clean, which is the single biggest gap against the brief's core promise: "audio played back by dying media" (BRIEF.md:12). Real dying media is *never* silent about its condition: tape wows and hisses continuously, vinyl crackles between skips, a dying call carries comfort noise — none of which exists anywhere in Source/dsp (verified by grep across every dimension). The biggest wins for v1.2 are therefore the continuous layers (wow/flutter bed, per-family noise beds), plus three cheap authenticity unlocks: a true 0–100% packet-loss range (currently capped at ~30% actual loss), a tape dropout event (the signature dying-cassette artifact, absent), and a tape stop that dies to silence instead of freezing to full-level DC. Two engine-architecture ceilings limit everything above them: the 2.5 s capture ring self-releases every sustained loop after one pass, and winner-take-all arbitration means "Total Media Failure" can only fail one way per tick. Finally, the plugin named *Bitrot* ships none of the research's literal bitrot artifacts (bit flips, wrong-decode stretches, sticky samples — deep-dive §3.5), a marquee identity gap worth a v1.3 family. A cluster of hour-scale correctness fixes (sync-mode inert on stopped transport, fade-collision click, CRUSH_RATE never transparent) rounds out v1.2.

## Tier 1 — High impact (recommended for v1.2)

### 1. PACKET_LOSS reaches true total failure (quality-bug + authenticity, effort: hours)
The knob tops out at ~30% actual loss — a "dropped call" can never actually drop the call. `PacketLossStage.h:125` caps stationary Bad occupancy at `piB = loss01*0.6` and `:235` fixes Bad-state loss probability at 0.5, so at PACKET_LOSS=100% expected loss is 0.6·0.5 + 0.4·0.01 ≈ 30.4%. The "Total Media Failure" preset (PluginProcessor.cpp:445, PACKET_LOSS 55) really delivers ~17%. Research §3.4 gives Good≈1%/Bad≈50% as *nominal* GE points, not a ceiling. **Fix:** scale Bad-state loss prob 0.5→1.0 with loss01 and lift the piB cap toward ~0.95 at full knob. Threshold-only changes — the exactly-2-draws-per-packet convention (`:221-222`) is untouched, so determinism and block-size invariance hold. Re-tune the Dropped Call / Total Media Failure presets. **Companion bug (same file, same pass):** the Good-state 1% floor at `:235` fires even at PACKET_LOSS=0 while enabled — one uninvited dropout every ~2 s. Scale it by loss01.

### 2. Tape dropout event — the signature dying-cassette artifact (feature-gap, effort: hours–day)
A tape win installs only a stop or a bend (`Arbitration.h:164-179`); the most common audible fault of real failing tape — oxide-shed dropouts, 5–200 ms partial level dips with simultaneous HF loss — has no event kind. The DSP shape already exists in-repo: CDSkip's conceal rung is a FirstOrderTPT cutoff dip (CDSkip.h:29-31, applied 165-173) plus a ramped muteGain path (199-210). **Add** a third tape event: ramped gain dip to a random floor (0.1–0.7) held 5–150 ms with a concurrent one-pole LPF cutoff dip, applied to wetL/wetR after `readHead.renderSample`. No position/rate change → composes safely with the ReadHead contract, no ring headroom needed.

### 3. Continuous wow/flutter — the tape family's missing bed (authenticity-gap, effort: 1–2 days)
Between events the tape family is *silent*: `TapeTransport.h:103-141` returns exactly 1.0 when Idle, `ReadHead.h:122-133` is 1.0 + lag trim, and `PluginProcessor.cpp:707-720` selects rate from only those sources — zero wow/flutter code anywhere (grep verified). The "Worn Cassette" preset comment even claims "wow" (PluginProcessor.cpp:373) the engine cannot produce, and CHANGELOG:35 markets the family as "Tape (wow, drag, full stops)". Real failing decks have an always-present speed-modulation bed: wow 0.5–6 Hz (capstan/pinch-roller eccentricity) + flutter 6–100 Hz, 0.1–1% WRMS consumer, several % when dying. **Add** TAPE_WOW (0–100%, default 0) as a rate multiplier composed at step 3 of the sample loop: slow random-walk/sine LFO (0.3–4 Hz, up to ~1.5% deviation) + optional flutter (bandpassed 6–60 Hz noise) from a NEW dedicated RngBank stream (never share — `pattern_rng_stream_interleave_blocksize`). Depth-0 default keeps FUNC-02 bit-exact passthrough (the `frac<=0` fast path at CaptureRing.h:106-107 only survives at depth 0 — document that wow>0 intentionally leaves it). Wow is zero-mean so lag drift is bounded; the ReadHead.h:188-189 overflow clamp is the backstop. The accumulator-never-reset architecture (parameter-spec Design Notes:95) supports continuous rate modulation for free.

### 4. Per-family media noise beds — hiss, crackle, rumble, hum (authenticity-gap, effort: 3–4 days)
ArtifactSynth synthesizes only event-triggered pop/tick/chirp (ArtifactSynth.h:89-125); pops fire ONLY at jump instants (VinylTransport.h:115, 149, 164). No media-noise DSP exists anywhere (verified; CRUSH_DITHER's TPDF hiss is quantization dither gated on Crush, not a media bed). The "dying media" illusion collapses in the gaps between clock ticks. Research §3.3 (deep-dive:155) itself specifies an "optional crackle/hum bed"; RC-20 — the market's lo-fi character winner (README:41) — leads with exactly these layers. **Add** seeded beds on the existing artifact bus (ArtifactSynth already runs every sample, PluginProcessor.cpp:735-737, preserving the FUNC-02 exact-zero property at level 0):
- **Vinyl:** Poisson-scheduled micro-ticks through the existing tick BPF, power-law amplitude (many small, rare large), rate scaled by a VINYL_WEAR param; pinked rumble LPF'd below ~60 Hz.
- **Tape:** filtered-white hiss (gentle 3–4 kHz shelf-down) behind TAPE_HISS.
- **Codec:** deterministic 50/60 Hz hum + 2 harmonics (phase from sample count, RNG-free) + crackle bursts — pairs with the AGC item in Tier 2 (research §3.3's full phone recipe).
Gate audibility per family via the existing EnableFade pattern (Arbitration.h:65-92). New dedicated RNG streams appended to RngBank (per-k derived seeding at RngBank.h:63-68 keeps existing streams bit-identical for old seeds). Optionally one MEDIA_NOISE macro scaling all beds to keep panel count flat.

### 5. Capture ring 2.5 s → 8–10 s + loop-aware lag clamp (architecture, effort: days)
The ring caps every sustained loop. `CaptureRing.h:53` (kRingSeconds=2.5) + `ReadHead.h:64-65` (maxLag ≈ 2.4 s) means a locked groove self-releases after ONE re-pass (VinylTransport.h:34-39 admits it; room gate at :146: 1.8+1.8=3.6 s > 2.35 s) — the headline "locked groove loops with a pop per pass" (BRIEF.md:16, "Locked Groove" preset) plays ~2 passes total. Sustained CD machine-gun loops hit the hidden lag-overflow clamp after ~2.4 s: ReadHead.h:186-189 teleports the head +1.2 s forward while CDSkip still thinks state==Loop and immediately re-jumps (CDSkip.h:185-191) — an audible unplanned slip. **Fix:** raise kRingSeconds to 8–10 s (stereo float ~3.7 MB @48k — cheap; update the static_assert and maxLag derivation), and make the overflow clamp loop-aware: suppress it while `CDSkip::isLooping()` / `VinylTransport::isLocked()` and give CDSkip a lag-budget self-release mirroring vinyl's, so recovery is an intentional jump, not a silent teleport. Version-gate: long-loop renders change.

### 6. Overlay-class arbitration — failures that physically coexist (architecture, effort: days)
One winner per tick (Arbitration.h:157-197); every win releases the other two families, and a tape+vinyl double-fire drops one event entirely (:158-160). Research §4.2's RSBrokenMedia rolls its dice categories independently — failures co-occur. The code already half-layers: CDSkip::release only touches Loop state (CDSkip.h:149-156), so bounded conceal/mute rungs finish under a tape win — but can never *start* while another family owns the tick. **Split** events into OWNER (tape bend/stop, CD loop, vinyl jump/locked groove — keep single-winner: one transport, coherent) and OVERLAY (CD conceal dip, CD mute+tick, standalone vinyl pop/crackle — gain/filter/artifact-domain, already applied orthogonally to head position at CDSkip.h:165-210): overlays fire whenever their family's roll succeeds regardless of the owner. Fixed roll order + fixed overlay-decision draws per tick preserve seeding and block-size invariance. This is what makes "Total Media Failure" sound like everything failing *at once*.

### 7. Codec-domain frame loss — the iconic GSM dropout (feature-gap, effort: days)
Chain order is Packet → Codec (PluginProcessor.cpp:741-748): PCM is lost *before* encoding. Real cellular loss drops encoded GSM frames, and the decoder's concealment (repeat last frame's parameters with attenuation) produces the metallic warbling stutter everyone knows as "bad cell reception." Research §3.3's chain also places loss after the codec round trip; CodecStage has no loss/PLC mechanism (it always decodes the fresh frame, CodecStage.h:204-218). **Add:** when GSM + PACKET are both enabled, drive frame drops from the same GE chain — on a lost frame, re-feed the decoder the *previous* encoded frame with per-repeat attenuation; libgsm's decode of a held frame yields the authentic metallic PLC sound for free. Grids nominally match (20 ms packets, PacketLossStage.h:86; 160-sample GSM frames @ 8 kHz), but note the verify caveat: the GSM frame boundary rides the 8 kHz fractional-latch crossings and is phase-offset from the packet grid — couple via a frame-indexed lookup, not a shared counter. Keep the PCM-domain stage for the codec-off/VoIP case.

### 8. "Rot" family — the literal bitrot artifacts the plugin is named for (feature-gap, effort: 3–5 days, v1.3 candidate)
Research §3.5 (deep-dive:172-177) lists four bitrot mechanisms: PCM bit flips (XOR → crackle/impulses), wrong-decode stretches (byte-offset white-noise bursts at the correct envelope — "the corrupt WAV sound"), sticky sample (decoder hang), buffer shuffling. Only the last exists (via the read-head machinery); grep for xor/bitflip/sticky/byte across Source/dsp finds nothing. BRIEF.md:12 claims "the full physical-to-digital spectrum of broken playback." **Add** a seventh clocked family (or a Crush mode): (a) XOR random bits over a rate-limited window with post-clip, (b) hold one sample 10–80 ms, (c) envelope-matched white-noise burst for a wrong-decode stretch. All cheap time-domain ops on the capture ring, one RngBank stream, clock-arbitrated like the trio. Identity leverage: the plugin finally does what its name says, and no competitor in the README snapshot ships wrong-decode stretches.

## Tier 2 — Medium impact

### 9. Sync mode inert when host transport is stopped (quality-bug, effort: hours)
MediaClock.h:139-168 emits ticks only when `isPlaying && wasPlaying`; free-run fallback fires only for a missing playhead/PPQ (:104-121). In default Sync mode, auditioning live input with the transport stopped = pure passthrough — the plugin appears broken. **Fix:** fall back to `runFree()` when the playhead reports not-playing; reset freePhase on the stopped→playing edge. Delete the dead `lastPPQ` state (:167, :200 — written, never read). Playing behavior untouched, so existing sync harness renders stay green.

### 10. Packet PLC polish bundle (authenticity, effort: hours)
Three small fixes in PacketLossStage.h, one pass: (a) **Decay never reaches silence** — `:247-248` attenuates −3 dB/rep with no floor; real PLC fully mutes by ~60 ms (research §3.4). Hard-floor decayGain to 0 after 3–4 reps or steepen to −6 dB/rep. (b) **Decay repeats packet-aligned, not pitch-aligned** — `:347-351` replays `gL[counter]` restarting each 20 ms boundary, imprinting a 50 Hz buzz; the AMDF machinery to pitch-align already exists (:276-313) but is Substitute-only. Run it for Decay too, with the same auto-degrade rule (:309-312). (c) **Substitute splices cycles hard** — `:333-345` wraps with a bare index reset and the −1 dB step lands exactly at the wrap (the header's ":52-53 period-continuous by construction" claim glosses this). Raised-cosine OLA ~1 ms at each cycle joint, gain step inside the fade.

### 11. Tape stop dies with speed instead of freezing to DC (authenticity-gap, effort: hours)
TapeTransport.h:31-32: at rate 0 the ReadHead re-reads the held sample forever at FULL amplitude (ReadHead.h:176), feeding a DC step into Codec/Crush (PluginProcessor.cpp:748-754). A tape head is a dΦ/dt transducer — output ∝ tape speed, HF dies first, decks mute at transport stop. **Fix:** in Stop state, scale wet output by g = rate^α (α ≈ 0.7–1.0; exactly 0 at rate 0), gain law only below a rate threshold (~0.9) so normal bends keep current loudness. Optional rate-tracking one-pole LPF for the HF-dies-first character. Release ramp restores gain symmetrically.

### 12. Cubic read-head interpolation (quality-bug, effort: hours)
CaptureRing.h:98-114 readFrac is 2-point lerp. At the bend table's own rates (0.5–2.0, TapeTransport.h:52) the mid-sample response is |cos(πf/fs)| ≈ **−16 dB at 0.9·Nyquist** (corrected from the review's −7.8 dB, which is the sinc² figure at Nyquist — the loss is *worse* than first claimed), and the 2.0× bend aliases everything above fs/4 unfiltered. Research's own key sources cite this (KVR t=548568, deep-dive:225; chowdsp variable-rate resamplers at :209). **Upgrade** to 4-point Catmull-Rom: extend the i1 clamp (CaptureRing.h:110) to i+2, keep the `frac<=0` exact-integer fast path verbatim (FUNC-02 untouched). Cost: 2 extra ring reads + a few FMAs on the fractional path only. Optional tracking LPF (cutoff ≈ 0.45·fs/rate) for rate > 1. Bends are the tape family's melodic voice — cubic keeps the character controlled rather than accidental. Tape-bend goldens change; version-gate and re-record.

### 13. Read-head jump robustness: fade-collision fold + post-stop recovery (quality-bug, effort: hours)
(a) **Jump-during-crossfade click:** ReadHead.h:112-116 overwrites oldPos/oldRate and zeroes fadeCount even when fadeActive — the in-flight fade's contribution vanishes as an output step, violating the click-safety contract (BRIEF.md:116). Reachable in ONE tick: Arbitration.h:189-193 kVinyl calls cd.release (recovery jump) then vinyl.onWin (second jump) with no render between. Fix: when a jump arrives mid-fade, retarget the new old-head to the currently dominant head and start from the current crossfade gain. (b) **Deep stops strand the head:** a 2 s stop leaves 2 s of lag; the only recovery is the +2% trim (ReadHead.h:122-133) → ~100 s of catch-up reading stale material, until the hidden clamp (ReadHead.h:186-189) teleports +1.2 s mid-normal-playback, attributable to no family. Fix: when a Releasing ramp completes with lag > ~250 ms, issue ONE intentional crossfaded forward recovery jump toward writeAbs (the CD-recovery pattern, CDSkip.h:216-222) — "content lost while the transport was stalled."

### 14. CD skip authenticity pack (authenticity, effort: hours)
(a) **Hard loop edges:** every loop wrap routes through the single global 3 ms crossfade (ReadHead.h:60-61); at the Skipping Disc preset's 45 ms segment that's ~7% splice per repeat — audibly smoother than research §4.1's "repeating at exact intervals, hard-edged" (CDSkip.h's own header :36 wanted "min ~1 ms"). Add a fade-length argument to clampAndScheduleJump: CD loop wraps pass ~0.25–0.5 ms; vinyl/recovery keep 3 ms; HARD_EDGES semantics unchanged. (b) **Severity-scaled mutes:** eventDur is pinned 2–20 ms regardless of severity (CDSkip.h:140); real E32 mutes lengthen as the disc worsens. One line: ceiling rises to ~150 ms near the Loop threshold. (c) **Sector lock:** CD_SEGMENT is free 10–400 ms (CDSkip.h:112-113); real anti-shock loops land on the 13.33 ms sector quantum (research §4.1: "~1/75 s sector-related"). Toggle (or implicit above severity ~0.5): quantize segmentSamples to round(n·fs/75) — the authentic 75 Hz-family buzz.

### 15. CRUSH_RATE extends to fs/2 with a transparent top (quality-bug, effort: hours + migration gate)
Param caps at 20 kHz (PluginProcessor.cpp:271-280; runtime clamp CrushStage.h:146) but BRIEF.md:87 promises "500 Hz – fs, default fs". At 20 kHz effective rate the latch imposes ~−3.9 dB droop at 10 kHz plus alias hash — a user enabling Crush for bits-only work gets an HF shelf they never asked for (worse at 96 kHz: max rate = 20.8% of fs). **Fix:** extend the top to fs/2 (host-rate-aware display); above ~0.45·fs crossfade latch output toward dry while the phase accumulator keeps advancing (determinism convention, CrushStage.h:45-51; never-reset rule §2.5). Null probe: rate max, bits 16, dither 0 → residual < −60 dB. **Caution:** widening a NormalisableRange shifts saved presets' normalized values — needs its own per-param migration version gate (repo pattern).

### 16. Codec AGC compressor — the missing half of the phone chain (authenticity-gap, effort: hours–1 day)
Research §3.3 (deep-dive:154): "…μ-law OR GSM → fast ~4:1 comp (AGC) → optional crackle/hum bed." CodecStage.h ends at post2 (:232-233) — no dynamics anywhere. The AGC's pumping is a large part of why phones sound like phones; without it quiet sources stay quiet instead of being dragged up into the codec noise. **Insert** a fast feed-forward compressor on the codec sub-path after the mode blend, before post1 (:230-232): per-sample one-pole envelope (attack ~1 ms, release ~50 ms, ~−20 dBFS threshold, ~4:1, fixed makeup). Pure function of signal — no RNG, so the stage's "DETERMINISM: no RNG" contract (:59-68) holds. On by default with the section (or one CODEC_AGC bool). Pairs with the codec hum/crackle bed (Tier 1 item 4).

### 17. Vinyl pop taxonomy — tick / pop / scratch with a resonant ring (authenticity-gap, effort: hours–day)
Every pop is the same shape: a ±impulse pair through a first-order TPT LPF with only ±3 dB / 1–3 kHz variation (ArtifactSynth.h:89-105, 130-136) — a one-pole cannot ring, so pops lack the damped stylus-resonance tail that reads as "stylus hit something." **Extend** triggerPop with a class draw: (a) tick — current doublet, cutoff biased high; (b) pop — doublet exciting a damped 2nd-order resonator (StateVariableTPT, 900–1800 Hz, Q 4–8, rings 1–3 ms); (c) rare scratch — 2–8 ms noise burst + 40–80 Hz arm thump. Weight ~70/25/5. Keep the fixed-draw-count discipline (draws consumed on EVERY call, ArtifactSynth.h:87-89) so seeded renders stay reproducible.

### 18. CD servo-seek terminal stage (feature-gap, effort: ~1 day)
recoveryJump snaps straight to writeAbs−1 the instant a loop releases (CDSkip.h:216-222); the real end-stage of a dying player — buffer runs dry, sled loses tracking, hundreds of ms of *dead silence*, then playback resumes ahead with a re-lock chirp — has no rung. **Add** a Seek state entered from Loop release at severity > ~0.85: full mute 100–400 ms (duration drawn at entry from the cd stream for determinism), then the existing recoveryJump + triggerChirp. Reuses the muteGain ramp machinery (:199-210). Gives CD_SEVERITY an audible fourth region at the top.

### 19. Comfort noise under extended concealment (authenticity-gap, effort: 1–2 days)
renderConceal (PacketLossStage.h:316-353) decays every mode to digital zero. Real VoIP/cellular PLC (G.711 App II CNG, GSM SID) fills extended loss with low-level spectrally-shaped noise matched to the background — the hiss floor is precisely what says "the call is still up but dying." **Add:** after burstLen > ~3 packets (~60 ms), crossfade into a comfort-noise bed: one-pole RMS + tilt estimate from good packets driving filtered white noise at ~−40 dB relative, from a dedicated RNG stream (per-sample unconditional draws precedented by crush jitter/dither, PluginProcessor.cpp:752).

### 20. Crush tracking anti-alias filters — the Decimort half (feature-gap, effort: 1–2 days)
CrushStage.h:114-173 has zero filters — only latch + jitter + EnableFade. Research §2.2 "Anti-aliasing as a feature" and §6's own CrushStage spec ("tracking pre/post AA (ArrayCoefficients, bypassable, resonance)") are unimplemented; the D16 Decimort inspiration (BRIEF.md:109) is *defined* by those resonant tracking filters. Today aliasing is the only crush flavor — the dark resonant dying-sampler voice (SP-1200 / early Akai) is unreachable. **Add** CRUSH_FILTER (Off / Clean / Resonant, default Off → v1.1 renders bit-exact): 2-pole pre-filter tracking ~0.4×rate + post images filter at rate/2, ArrayCoefficients recomputed at control rate (RT-safe pattern; in-repo example CodecStage.h:112-128), ~10 ms crossfade between instances for large jumps; Resonant adds Q≈2–4 on the pre-filter. Optional CRUSH_SOFTEN held/live blend (§2.1 DeRez soften).

### 21. FREEZE — latch the current failure state (feature-gap, effort: 1–2 days)
MediaClock/Arbitration re-roll every tick unconditionally; the only reproducibility tool is the seed — no way to hold a locked groove or machine-gun loop that sounds good *right now* (BRIEF.md:103 promises "a producer can commit a take"). **Add** an automatable FREEZE bool: while on, the clock stops re-rolling and every family sustains its current state (CD loops are already "unbounded and persist while CD keeps winning ticks", CDSkip.h:43 — the machinery mostly exists). Trivially deterministic: no draws occur while frozen. High workflow leverage, very low DSP risk. (Depends on item 5's ring expansion to be worth holding for more than ~2 s.)

### 22. AGE macro — one-knob degradation intensity (feature-gap, effort: 1–2 days)
31 independent params (parameter-spec:86), deliberate no-macro decision (FUNC-05, Design Notes:92) — but the Basinski disintegration use case (BRIEF.md:100) is a slow one-knob decay ride. **Add** AGE (0–100%, default 100%) that *scales* per-family probabilities/intensities (prob' = prob × ageCurve, floors rising with age) — per-module sections stay authoritative at default, so existing presets/automation are untouched (regression-safe). Automating AGE 0→100 over 4 minutes is the disintegration-loops demo that sells the plugin.

### 23. Tape reverse — promised by the brief, absent from the engine (feature-gap, effort: 2–3 days)
BRIEF.md:14 lists "tape-stops, reverse"; research §4.2/§6 specify "ramped line generator × direction"; the interval table is all-positive (TapeTransport.h:52), no negative-rate handling anywhere, and CHANGELOG 1.0.0 quietly renamed the scope to "wow, drag, full stops." ReadHead mechanically supports negative rate today (`pos += rate`, ReadHead.h:176 — lag just grows; the binding constraint is *ring capacity*, not the up-bend headroom check). **Add** negative intervals (−0.5, −1.0) as a bend/stop-overshoot target: ramp through zero (the authentic "stop-then-drag-backwards" for free), bound hold time by (maxLag − lag)/(1 − r) minus release-ramp cost — the mirror of the up-bend early-release (TapeTransport.h:122-132). Gate behind TAPE_REVERSE_SHARE defaulting to 0 so existing seeds render unchanged. Item 5's ring expansion extends usable reverse length from ~1 s to several.

### 24. MIDI-triggered failures (feature-gap, effort: 2–3 days)
`acceptsMidi()` returns false (PluginProcessor.h:64); failures are purely stochastic — THE tape-stop on beat 4 requires automating probability to 100% for one tick. README:42's own gap analysis: "no freeware gesture-triggered tool" (Stutter Edit 2's MIDI gestures are its paid differentiator, :41). **Map** a note-per-family octave (C=tape bend, C#=stop, D=CD skip, D#=vinyl jump, E=packet burst, F=locked groove…) that force-wins arbitration at the next tick (velocity = severity). A forced win consumes the same RngBank draws → seeded bounces still reproduce. Converts the plugin from texture box to performable instrument — the strongest market lever after the aesthetic-depth items.

### 25. Per-family solo + post-stage mixes (feature-gap, effort: hours for solo; days for mixes)
Global MIX and CODEC_MIX are the only blends (parameter-spec:20, :64); the other five families are binary enables. Auditioning one family means toggling five switches. (a) UI-side solo per plate — writes the other five ENABLEs off and restores on un-solo; zero new DSP or automation surface. (b) Wet-blend params for the serial post-stages (PACKET_MIX, CRUSH_MIX) like CODEC_MIX. The clock-arbitrated trio shares one read head (Arbitration.h), so true parallel per-family mix there is architectural — restrict blends to post-stages and document it.

## Tier 3 — Lower impact / later

### 26. Quantizer flavors: mid-riser toggle + mu-law-domain quantize (feature-gap, effort: hours)
QuantStage.h:121-125 is hard-coded mid-tread; BRIEF.md:19 (corrected cite) promised "mid-tread/riser," and research §1.1 notes the riser's ±Δ/2 buzzing LSB floor on silence — a distinctly dying-converter sound — with the D16 toggle as precedent. Riser is one formula branch (`delta*(floor(x/delta)+0.5)`), stateless, defaults to tread. Second flavor: quantize in the mu-law domain (generalize CodecStage.h:270-280 to N bits) as a QUANT_LAW choice — telephone-warm low bit counts. Defer 1st/2nd-order noise shaping; it fights the aesthetic.

### 27. Vinyl physical breadth: forward rev-quantization, warp wow, 78 RPM (authenticity, effort: hours–day each)
(a) Forward skips always teleport to live (VinylTransport.h:111-116) even when ≥1 revolution of lag is affordable after a backward jump/locked groove; research §4.1 specifies "exactly ±1 revolution" *both* directions. Jump +revSamples when lag ≥ revSamples + minLag, else fall back. Draw count unchanged. (b) VINYL_WARP (default 0): sinusoidal rate multiplier at exactly 1/1.8 Hz (0.75 @ 45), depth ≤ ~0.6% — a warped locked groove wobbles identically every pass. Verify caveat: revSamples is only computed in onWin (VinylTransport.h:83-84) — the warp LFO needs its own persistent phase accumulator derived from VINYL_RPM. Note the BRIEF:16 "pitch never changes" rule stays true for *jumps*; warp is opt-in continuous modulation. (c) Append "78" to VINYL_RPM (0.769 s quantum) — nearly free alongside the noise-bed work (denser pops, narrower bandwidth) but REQUIRES the preset-manager v1.0.6 choice-append migration hook (choice appends repoint old saves).

### 28. CRUSH_POSITION pre/post-Codec toggle (feature-gap, effort: hours)
Chain order is fixed Packet → Codec → Crush → Quant (PluginProcessor.cpp:739-754). Full reorderability is expensive (CodecStage owns ALL plugin latency + both alignment rings, CodecStage.h:38-53), but Crush+Quant are zero-latency per-sample stages — moving them before the codec is a two-line call-order swap unlocking "an 8-bit source played down a phone line" vs today's "phone call on a broken converter." Same per-sample draw counts → determinism preserved.

### 29. Segmented G.711 mu-law (authenticity-gap, effort: hours)
muLawRoundTrip is the continuous log1p/pow curve with uniform companded-domain quantize (CodecStage.h:270-280); real landlines quantize on 8 piecewise-linear chords of 16 steps (research §1.4 notes RSBrokenMedia uses the real table codec). Swap in the standard segment-based encode (bias 33) + 256-entry decode LUT — pure lookup, RNG-free, zero-latency, so the mu-path alignment ring (:225-228) is untouched. Expect only sub-−40 dB tail-fizz differences; the one place the "real telephone chain" claim (BRIEF.md:18) is an approximation.

### 30. Streaming codec mode — and an explicit DEFER of MP3/STFT to O-Lossy (product decision, effort: 2–3 days / 0)
Two dimensions collided here. The codec review (correctly) shows the research assigns an STFT hole/birdie processor to CodecStage (deep-dive §6:217, full recipe §3.1–3.2) and that a 512-point FFT would even fit inside the existing kCompLatency budget.
