## Lifecycle Timeline

- **2026-08-17 (v1.7.0):** Vinyl authenticity (improvement brief items 17 + 27) — one new param, one appended choice, and **the vinyl family's render moves at its defaults**. Three of the four changes answer the same complaint: the family was one physical gesture repeated. **Pop taxonomy** — a one-pole cannot ring, so no pop in six releases had the damped stylus resonance that reads as "the stylus hit something"; `triggerPop` now draws ~70/25/5 across **tick** (the historical doublet, cutoff biased high to 2–4 kHz), **pop** (the same doublet into a `StateVariableTPT` resonator, 900–1800 Hz, Q 4–8) and **scratch** (2–8 ms windowed noise burst + a 40–80 Hz tonearm thump). The brief's "Q 4–8, rings 1–3 ms" is internally inconsistent — Q 4–8 at those frequencies decays to −30 dB in **2.4–9.8 ms** (measured across the (f0,Q) corners); Q was the specified parameter so Q shipped, and the ring time is reported rather than restated. Click peaks normalise to the same base level for all three (`1/g` is within 3% of the true doublet-response peak across the box), so the ring sits 7–13 dB under the transient — the shape a stylus impact has. **Forward jumps are revolution-quantized** when `lag >= revSamples + minLag`, with return-to-live as the fallback: research §4.1 says "exactly ±1 revolution" in BOTH directions, and a groove that only skips backward then teleports to the present is half a model. **`VINYL_WARP`** (default 0) is one sinusoid at exactly the platter rate, 0.6% peak deviation. **78 RPM appended** (0.769 s quantum) with shellac surface to match — ticks 1.6x denser, band down to 1.5–4 kHz, gated on the index so 33⅓/45 keep their numbers to the bit. **The warp is a read OFFSET, not the rate multiplier the brief specifies** — a rate multiplier falsifies the `loopOwnsRate` premise that makes ReadHead's clamp suppression safe (and a *locked groove* is exactly what item 27b is about), and at lag 0 it drives the head into the write-slot pin; offsetting the read is the same physics from the other end, per WowFlutter's v1.4.0 note. **Its phase increment is `2π/revolutionSamples()`, not `2π·f/fs`**, because the brief's "wobbles identically every pass" is only exact if the LFO period is the SAME INTEGER as the jump distance — the un-rounded form leaves 0.077 samples of residue per pass at 78/48k. New `VinylGeometry.h` holds the one RPM→samples mapping that the transport, warp and noise bed all read. **Scratch needed its own RNG stream** (`RngBank::scratch`, appended): a per-sample noise burst sharing the tick-scheduled artifactSynth stream is the block-size interleave hazard verbatim; `triggerPop` itself keeps fixed draws, now **five**, taken before any branch. **`VINYL_RPM`'s choice append repoints saved presets** (normalised 1.0 meant "45" over 2 choices, means "78" over 3) — handled with the preset-manager v1.0.6 `setMigrationCallback` hook; sessions store the INDEX and need nothing. Harness **92/92**, 5 probes added, **each verified to FAIL against the code it gates** — `M8`'s revert is the instructive one, since the probe reads its expected quantum from the same function the engine does, so deleting index 2 changes both together and only the `distinct` guard catches it. `V1` **re-anchored again** to `VINYL_ENABLE 0` + `CD_SEVERITY 0`, new digest `0x44a5de77d572facd` recorded by compiling the narrowed probe against the **v1.6.0 tree** at git `16e63620` in a detached worktree (86/87 there — the one failure being V1 measuring against the anchor the narrowing had just superseded, i.e. the run that produced the number). What it preserves: tape bends, the post-stop recovery jump, the CD conceal rung and the overflow clamp bit-unchanged across four releases, plus the read path with VinylWarp wired in and silent. auval PASS, pluginval strictness-10 3/3. Installed.

- **2026-08-17 (v1.6.0):** CD skip authenticity (improvement brief items 14 + 18) — four changes to the CD ladder, all keyed to `CD_SEVERITY`, no new params, and **the first O-Bitrot release that changes the render at a default**. The top two rungs had the right shapes flattened by constants that ignored the one knob meant to drive them. **Loop wraps now splice hard** — 0.5 ms rather than the global 3 ms, which at the Skipping Disc preset's 45 ms segment was spending 6.7% of every repeat inside the crossfade; `clampAndScheduleJump` takes a per-jump fade length and recovery/vinyl/overflow keep the default. **The trap was v1.2.1's mid-fade fold**, whose arithmetic divides `fadeCount` by the fade length: with per-jump lengths the RUNNING fade's length is the only valid denominator, so a splice request arriving 20 samples into a 144-sample fade must spend the running length rather than adopt the short one — built the wrong way on purpose it collapses the outgoing head's weight from 0.861 to 0 in one sample, a **0.357 step against a 0.042 bound** (8.5x click). **Mutes scale with severity** (span, not the 2 ms floor): 20 ms ceiling at severity 0 — the v1.5.0 expression bit-for-bit, since `0.130 * 0.0` is exactly `0.0` — rising to 150 ms by 0.6; measured 61.2 ms longest at 0.2 (ceiling 63.3) and 141.9 at 0.6 (ceiling 150.0). **Loop windows lock to the 1/75 s CD sector above severity 0.5** (100 ms asks 4800, gets 5120) — the 75 Hz-family buzz is why a skipping disc sounds like one; implicit, because "how far gone is the disc" is what the knob already means. **Servo seek above 0.85**: a released loop goes hard silent 100–400 ms (measured 338.2) before the recovery jump + re-lock chirp — the sled losing tracking, giving `CD_SEVERITY` a fourth audible region. Its duration is drawn at loop ENTRY because neither release path has an RngBank and block-size invariance depends on RNG landing only at ticks; that also skips the draw below 0.85, leaving the cd stream bit-identical there. Harness 87/87 over 3 runs, 7 checks added across 5 probes, **each verified to FAIL against the code it gates**. `L5` drives `ReadHead` directly rather than through the plugin — the wrap chirp is 2.3e12x the marker step it would have to be measured against. `V1` **re-anchored** to `CD_SEVERITY 0` with a new v1.3.0-tree digest (`0x972a5d3807538393`, recorded at git `a22ff7c3` where it ran 57/57): the release is genuinely not transparent at the 0.5 default, and what the re-anchor preserves is the real claim — the fade refactor changed nothing for bends, vinyl, the post-stop recovery jump, conceal or the overflow clamp across three releases. auval PASS, pluginval strictness-10 3/3. Installed.

- **2026-08-17 (v1.5.0):** Media noise beds (improvement brief items 4 + 19) — five new params, every one default 0 and exactly transparent there, and **no render-affecting changes at all**. The engine synthesised only event-triggered artifacts, so between clock ticks nothing ran and the "dying media" illusion collapsed in the gaps. `TAPE_HISS` adds a **decorrelated stereo** hiss bed (−48 dBFS RMS full-knob, −9 dB shelf above 3.5 kHz) that **rides `TapeStopGain`'s speed gain** — a tape head is a dΦ/dt transducer, so hiss is recorded material and a stop must mute it; stereo because two tracks carry two independent sources and a mono bed hits the level target exactly while sounding like a plugin fault (measured L/R corr −0.000, asserted). `VINYL_WEAR` adds Poisson micro-ticks with a **cubic power-law amplitude** (bounded, unlike an inverse-CDF Pareto draw — nothing on the audio thread should draw an arbitrarily large impulse; asserted via the tick band's crest factor, 10.9 vs Gaussian's ~4) over pinked bearing rumble (−42 dBFS, AM'd once per platter revolution at the VINYL_RPM rate). `CODEC_NOISE` + `CODEC_MAINS` add mains hum (RNG-free — three partials off one phase accumulator, a pure function of the sample count) plus band-limited crackle bursts; **injected AFTER `CodecStage`, not on the artifact bus**, because 50 Hz in front of a 300–3400 Hz passband is annihilated — which is also where the physics puts it. `PACKET_COMFORT` fills the hole `PacketLossStage` leaves when Decay hard-floors to silence at ~60 ms: a spectrally-matched bed (level + 1 kHz tilt tracked on **good packets only**, each noise half divided by its exact analytic gain so the tilt weights mean what they say) ramping in **additively under all four conceal modes** — replacing rather than adding would have dissolved Repeat's machine-gun identity, so it sits 33 dB beneath it instead. **The levels are sample-rate invariant and that took work:** filtering white noise to a fixed Hz bandwidth gives power ∝ B/fs, so a bare constant is 3 dB quieter per rate doubling; each bed normalises only its white-fed stage by that stage's exact noise gain `sqrt(a/(2−a))`, and normalising the LATER stages the same way would have reintroduced the dependence (measured 48 vs 96 kHz: 0.13 dB). Four RNG streams appended to `RngBank` (stream *k* seeded from *k* alone, so old seeds are bit-identical). Harness 80/80, 14 probes added; `V1` still matches the v1.3.0 digest and a new `N7` matches the **v1.4.0** digest for a packet+codec-active render — V1 runs with both post-stages off, so it says nothing about the two places this release touched downstream code. auval PASS, pluginval strictness-10 3/3. Params APPENDED to the layout end so no later automation slot moves. Installed.
- **2026-08-17 (v1.4.0):** Tape authenticity (improvement brief items 2 + 3 + 11) — two new params, both default 0 and both EXACTLY transparent there, so a v1.3.0 session or preset renders bit-identically (pinned by a cross-version digest probe, not asserted: a canonical forced-bend render digests identically under git `a22ff7c3` and v1.4.0). `TAPE_DROP` adds the dropout event — a triangular gain dip to a random 10–70% floor over 5–150 ms with a concurrent log-swept cutoff dip, reusing CDSkip's conceal-rung shape; it installs NO rate event, so a bend in flight keeps ramping underneath (the first OVERLAY-class event, foreshadowing item 6). `TAPE_WOW` adds the continuous wow/flutter bed on a NEW dedicated `wow` RngBank stream (appended, so every existing stream's seed is untouched): three quasi-periodic partials, measured 1.14% peak deviation at full knob against a 2.0% budget the partial table asserts against itself. **The bed modulates a read OFFSET, not the rate** — a rate multiplier falsifies ReadHead's "a loop holds rate at exactly 1.0" premise for its clamp suppression AND drives `pos` into the write-slot pin at the lag-0 steady state (~8 ms of zero-order hold per wow cycle); offsetting the read is the same physics (pitch deviation is the derivative of delay) with `pos`, the lag budget and the jump contract untouched. ## Latency Scheme (Stage 2)

Constant reported latency of 20 ms in ALL modes:
`setLatencySamples(ceil(0.020 * fs))` once in `prepareToPlay`. CodecStage
owns the alignment: a hand-rolled integer delay of exactly that figure when
the codec is disabled or in Mu-law mode; the GSM 160-frame chain replaces it
structurally in GSM mode (one 8 kHz frame = 0.020 s). `DryWetMixer::
setWetLatency` aligns the dry path. The first 20 ms of GSM output after
engagement is silence (output frame primed with zeros; the 10 ms
CODEC_ENABLE fade covers it). At non-integer `0.020*fs` host rates the GSM
path misaligns by < 1 sample versus the plain delay — accepted.
