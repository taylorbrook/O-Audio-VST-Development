## 2. Multi-built-in embedding + selector (FUNC-02)

### Pattern is already scaffolded — O-simpleGrain is the verbatim reference
O-simpleGrain ships the identical 4-built-in pattern (`fire`/`voice`/`water`/`piano`):
- `builtInBlob()` switch with one `BinaryData::<name>_wav` case per index (`O-simpleGrain/Source/PluginProcessor.cpp:305-313`).
- `juce_add_binary_data(... NAMESPACE BinaryData ...)` listing all four `.wav` SOURCES.

O-simpleSampler already has every moving part **except the embedded blobs**:

- `kBuiltInNames[4]` = `{piano, vocal, flute, vinyl}` (`PluginProcessor.h:373`).
- `kBuiltInRoot[4]` = `{48, 69, 72, 48}` (`PluginProcessor.h:379`) — per-source recorded-pitch roots.
- `builtInIndexForIdentity()`, `loadBuiltInSource()`, `decodeAndPublish()`, `resampleToEngineRate()`, `seedRootForSource()` — all generic over any embedded blob, all off-thread, 30 s cap in place.
- app.js `sourceSample` combo labels (`app.js:68`) + combo binding (`app.js:252`).

### What changes when the user delivers assets (≤3 edits)
1. **CMakeLists.txt:109-113** — add the new files to `O-simpleSampler_Samples` SOURCES (currently `Source/samples/piano.wav` only; the `TODO(Stage 2.3)` comment is right there).
2. **PluginProcessor.cpp:347 `builtInBlob()`** — replace the `default → piano` fallback cases 1/2/3 with real `BinaryData::<name>_wav` / `<name>_wavSize`.
3. **If delivered names differ** from `piano/vocal/flute/vinyl`: update `kBuiltInNames` (h:373), `kBuiltInRoot` (h:379), app.js combo labels (app.js:68), and the parameter-spec built-in table. Names are the **only** contract-adjacent surface — the Choice *count* (4) and the `embedded:<name>` identity scheme must stay consistent across all four sites or state-restore breaks.

No new DSP, no decode-path work — `decodeAndPublish` already handles any WAV/AIFF/FLAC blob via the format manager, resamples to engine rate, caps at 30 s, atomic-publishes.

### Root seeding per source
`kBuiltInRoot` is engine metadata (probed recorded f0 → nearest MIDI), **independent of the frozen `rootKey` default (60)**. piano = **48** (not 60) because its f0 ≈ 131 Hz — root 60 would play an octave flat. For each delivered sample: probe f0 (or take the user's suggested Root Key from the CONTEXT hand-off) and set the matching `kBuiltInRoot[i]`. `seedRootForSource()` already writes the live `rootKey` on selection.

### Gotchas (already handled — do NOT regress)
- **Dual binary-data NAMESPACE** — samples target is `NAMESPACE BinaryData` / `HEADER_NAME BinaryData.h`; UI target is `NAMESPACE UIBinaryData` / `UIBinaryData.h`. Distinct NAMESPACE **and** HEADER_NAME — a distinct header alone re-defines `getNamedResource` in the same namespace → duplicate-symbol link fail (`dual_binary_data_namespace_collision`, O-simpleGrain Stage-3.1). The split is already correct in CMakeLists.txt:63 vs 109 — just append SOURCES, don't touch the namespaces.
- **JUCE filename mangling** — `vocal.wav` → `BinaryData::vocal_wav` / `vocal_wavSize`. Dots/dashes → underscores; keep filenames simple.
- **USER DEPENDENCY** — files land in `Source/samples/`. Until delivered, execute proceeds **piano-only** (current `default → piano` fallback keeps every selection audible, never silent) and the CHANGELOG notes the curated set is pending. The embedding/selector wiring can be written against whatever set exists at execute time.

## 3. Three RT-safety remediations

### Items 1 + 2 close together — adopt the O-TextureForge raw-pointer handoff

**Item 1 — buffer free can land on the audio thread.**
`processBlock` snapshots a `shared_ptr` once per block (`PluginProcessor.cpp:831` `auto src = atomicLoad(currentSource)`). The snapshot keeps the buffer alive for the whole block (correct: never reads freed memory). But if a message-thread publish (`atomicStore`, cpp:435) drops the previous owner's ref mid-block, the audio thread's snapshot becomes the **last** ref → its destructor (`~AudioBuffer` = `free`) runs at end of `processBlock` → **alloc/free in the render path** = PERF-01 violation.

**Item 2 — deprecated atomics.**
`std::atomic_load/store(std::shared_ptr*)` free-function overloads (`PluginProcessor.h:215-223`) are **deprecated in C++20**. The project sets no `CMAKE_CXX_STANDARD` (JUCE 8 default = C++17), so this does **not** warn today — it is forward-compat hygiene, not an active error. Don't treat it as urgent on its own; fix it as a side-effect of item 1.

**Recommended single fix (kills both):** mirror **O-TextureForge** (`PluginProcessor.cpp:272`, `.h:109`), which ships exactly this pattern.
- Audio thread reads a plain `std::atomic<juce::AudioBuffer<float>*> sourceForAudio` (raw ptr, `memory_order_acquire`) once per block. **No shared_ptr on the audio thread at all** → no atomic shared_ptr API (item 2 gone), and the audio thread can never own the last ref (item 1 gone).
- Message thread owns lifetime: keep `std::shared_ptr<AudioBuffer<float>> currentSource` + **one** `std::shared_ptr retiredSource` slot. On publish:
  ```cpp
  retiredSource = std::move(currentSource);   // keeps the old buffer alive one generation
  currentSource = std::move(newBuf);
  sourceForAudio.store(currentSource.get(), std::memory_order_release);
  ```
  The old buffer is freed on the **message thread** at the *next* publish (when `retiredSource` is overwritten) — never on the audio thread.
- Message-thread readers that currently `atomicLoad(currentSource)` (`getSourceThumbnail` cpp:458, `computeZeroCrossSnaps` cpp:781) read `currentSource` directly — they run on the message thread, so no atomic needed.
- **retired-depth-1 is safe here:** source swaps are user-paced (a built-in pick or a file load, each gated through the AsyncUpdater = one per message-thread turn), so two swaps can never complete inside one ~1–10 ms audio block. O-TextureForge ships single-slot retired in production. (If ever paranoid, a `std::array<shared_ptr,2>` ring is a one-line upgrade.)

**Why not C++20 `std::atomic<std::shared_ptr>`?** It fixes item 2 cleanly but **not** item 1 — `.load()` still returns a `shared_ptr` whose destructor can free at block end. The raw-ptr handoff is the only single change that closes both, and it matches a shipped sibling.

### Item 3 — `setValueNotifyingHost` inside `prepareToPlay`
`seedRootForSource()` (which calls `setValueNotifyingHost`, cpp:576) is invoked from `prepareToPlay` (cpp:302), guarded `!stateWasRestored && !rootSeeded` (fresh instance, once). Notifying the host of a parameter change **inside `prepareToPlay`** is discouraged: prepare can be called off the message thread / during plugin scans, before the editor exists; the notification can re-enter, be dropped, or make the host record automation / mark the project dirty. It passed pluginval@5 already, so the risk is low — but the CONTEXT decision is to close it.

**Recommended fix:** defer the one-time fresh-instance seed off `prepareToPlay` onto the **existing AsyncUpdater**:
- In `prepareToPlay`, replace the direct `seedRootForSource(...)` call with `pendingRootSeed = true; triggerAsyncUpdate();` (set a new `std::atomic<bool> pendingRootSeed` and keep the same `!stateWasRestored && !rootSeeded` gate).
- In `handleAsyncUpdate()` (cpp:728, guaranteed message thread, not nested in prepare), consume the flag and call `seedRootForSource(...)`. `handleAsyncUpdate` **already** calls `seedRootForSource` for user source changes (cpp:739) — this reuses proven machinery, adds no new threading surface.

This is minimal and removes the smell without touching the seeding logic itself.

> All three are quality/hardening — none is a known-reproducing bug (Stage-2/3 passed pluginval@5 + render-harness). Re-run the render-harness **after** these edits (it includes an allocation/RT discipline check) and re-confirm pluginval@5.

## 4. Preset param-value authoring (FUNC-07)

### Hook is fully wired — only values remain
`applyFactoryPreset` (cpp:507) resets every param to default, then has 7 stubbed branches (cpp:529-565) with `setReal`/`setChoice`/`setBool` helpers ready. The native fn is registered (`PluginEditor.cpp:172`), app.js has the 7 buttons + `PRESET_LESSONS` + active-button highlight (app.js:417-451). Round-trip (JS → native-fn → APVTS → relay resync) is proven (Stage 3.3).

### CRITICAL authoring finding — the default-reset detunes the source
`applyFactoryPreset` resets **all** params first, which sets `rootKey → 60`. The default piano built-in has recorded root **48**, so every preset would play it an **octave flat**. **Fix once, centrally:** after the default-reset loop (cpp:511) and before the branch dispatch, re-apply the active source's root —
```cpp
seedRootForSource(builtInIndexForIdentity(currentSourceIdentity));
```
This keeps presets **source-agnostic** (per CONTEXT decision: presets set params only, leave the source as-is) while never mistuning whatever source is loaded. Then no preset branch needs to touch `rootKey`.

### Authoring conventions (already in the cpp comment block 500-506 — restate for execute)
- 0–100 raw percent: `start`, `end`, `loopStart`, `loopEnd`, `vintage`, `filterResonance`, `velToAmp`.
- `loopCrossfade` in **ms** (0–500); `filterCutoff` in **Hz** (20–20000, log); ADSR times in **seconds** (0–5); `fine` in **cents** (±100).
- `ampSustain` stored **0–1** (NOT %).
- `rootKey`/`tune` are **INT** params.
- Choice indices: `sourceSample` 0=piano/1=vocal/2=flute/3=vinyl; `loopMode` 0=Off/1=Forward/2=Ping-Pong; `pitchMode` 0=Repitch/1=Stretch.
- `setReal`/`setChoice`/`setBool` take the **string ID** (`"start"`, `"end"`) via `apvts.getParameter(id)` — the `regionStart`/`regionEnd` C++ identifier rename does **not** affect these (`paramid_shadows_juce_free_function` lesson — string IDs stayed `"start"`/`"end"`).
- Because the branch only runs after a full reset, each branch needs to set **only the non-default params** that isolate its concept (explicit is fine too).

### Recommended starting values (audition in execute; each isolates ONE concept)

| Preset | Key params (rest = default) | Concept it isolates |
|--------|------------------------------|---------------------|
| **Raw One-Shot** | loopMode=Off(0); start=0,end=100; ampAttack=0.002, ampDecay=0.0, ampSustain=1.0, ampRelease=0.08; pitchMode=Repitch(0) | the whole sample, once, no loop — the baseline |
| **Tuned Across the Keyboard** | pitchMode=Repitch(0); loopMode=Off(0); full region; neutral amp (defaults) — relies on the central root re-seed | one recording → playable instrument via Root Key |
| **Looped Pad** | loopMode=Forward(1); loopStart=20, loopEnd=80; loopCrossfade=120; ampAttack=1.5, ampSustain=1.0, ampRelease=2.0 | crossfaded loop → endless sustain from a short sound |
| **Reversed Swell** | reverse=on; loopMode=Off(0); ampAttack=1.5, ampDecay=0.0, ampSustain=1.0, ampRelease=1.5 | reverse + slow attack = backwards swell |
| **Repitch vs Stretch A/B** | pitchMode=Stretch(1); loopMode=Forward(1) (indefinite hold for the A/B); loopCrossfade=80; ampAttack=0.01, ampSustain=1.0, ampRelease=0.3 | the headline — toggle pitchMode and hear pitch/time (de)coupling |
| **SP-1200 Crunch** | vintage=80; filterCutoff≈12000; ampAttack=0.002, ampDecay=0.15, ampSustain=0.8, ampRelease=0.15 | decimation + bit-crush grit (clean at 0 elsewhere) |
| **Filtered & Enveloped** | filterCutoff≈1000, filterResonance≈40; ampAttack=0.3, ampDecay=0.6, ampSustain=0.5, ampRelease=0.6 | filter + amp ADSR shape a raw sample |

`PRESET_LESSONS` text (app.js:417) already describes each — keep the values consistent with the prose. Presets are designed to read on **any** loaded source (built-in or user file).
