## Part A — Defect Fixes (PATCH-grade, highest priority)

### A1. Depth parameter is dead
**Current:** `MotionEngine::advance()` computes `currentState.distance` from Depth, but
`processBlock` never reads `endState.distance`. `distanceModel.updateDistance()` receives only
the static `distance` param (`PluginProcessor.cpp:537`), and the UI snapshot stores the raw
param (`uiDistance.store(dist)`), so Depth changes nothing — audibly or visually.
**Proposed:** Effective distance = `distanceParam * endState.distance` (motion distance is a
multiplier around 1.0, floor-clamped). Feed it to both DistanceModel instances and to
`uiDistance` so the visualizer dot moves radially with Depth.
**Note:** This is an "activating a previously-dead param" change — default Depth is 0 so the
default timbre is unchanged, but presets with nonzero Depth (Fast Spiral, Ambient Drift, Deep
Space, etc.) will get audible near/far motion for the first time. Verify each preset by ear.

### A2. Audio-thread allocation every block in DistanceModel
**Current:** `DistanceModel::updateDistance()` executes
`*lpf.coefficients = *IIR::Coefficients<float>::makeLowPass(...)` (`DistanceModel.h:60`) —
heap allocation + ref-counted object churn on the audio thread, every block, for both L and R
instances.
**Proposed:** Use `juce::dsp::IIR::ArrayCoefficients<float>::makeFirstOrderLowPass` (or
matching-order array variant) and `memcpy` into the existing coefficient storage — the
established repo pattern (see memory: ArrayCoefficients RT-safe IIR; 5 normalised vs 6 raw
coefficient trap). Also skip recomputation when (dist, airAbs, curveType) are unchanged.

### A3. Declared-but-unused parameter smoothers
**Current:** `speedSmoothed/widthSmoothed/depthSmoothed/tiltSmoothed/mixSmoothed` are reset in
`prepareToPlay` (`PluginProcessor.cpp:433`) but never advanced or read. Mix, Distance, Air
Absorption step once per block → zipper on automation.
**Proposed:** Either wire the smoothers (per-sample `getNextValue()` for mix; per-block target
+ ramp for distance/air) or delete the members. Mix at minimum should be smoothed per-sample.
**Probe rule:** any no-zipper probe must target a param that is actually wired (memory:
vacuous zipper sweep).

### A4. Dry/wet mix only blends the first min(in,out) channels
**Current:** The mix loop runs `ch < min(totalOut, totalIn)` = 2 (`PluginProcessor.cpp:652`).
On a 5.1/7.1.4 output at mix < 100%, front L/R get dry blended while all other channels stay
100% wet — spatial image tilts frontward as mix decreases.
**Proposed:** Decide and document the intended semantics: (a) dry occupies only its native
input channels but wet is scaled by `mixVal` on ALL channels (recommended — constant-power
motion balance), or (b) equal-power crossfade limited to input channels. Implement (a):
scale every wet channel by `mixVal`, then add `(1-mixVal)*dry` into channels 0..numIn-1.

### A5. Double-click knob reset goes to normalized 0.5, not the parameter default
**Current:** `app.js:126` sets `setNormalisedValue(0.5)` for every knob. With skewed ranges
(Speed skew 0.5, Distance skew 0.5) 0.5 normalized ≠ default; e.g. Speed default is 1.0 Hz but
double-click lands elsewhere.
**Proposed:** Reset to each parameter's actual default via the relay properties (or a small
JS map of defaults). Matches suite behavior.

## Part B — Suite-Standard Features

### B1. Preset-manager module migration
**Current:** 12 factory presets via the legacy Programs API only. No user preset save/load, no
categorized dropdown, no prev/next. O-Orbit predates the preset-manager v1.0.6 rollout.
**Proposed:** Adopt the shared preset-manager module (v1.0.6+): categorized dropdown (Stereo /
Surround / Creative), user preset save with naming, prev/next buttons.
**Known traps (from memory):**
- prev/next must walk the same list the dropdown shows (grouping desync pattern)
- `applyPresetJson` must reset all params to defaults first (partial-preset inheritance)
- factory preset values must be denormalised (skew-aware), not linear fractions
- preset name containing "/" silently fails to save (name is the JSON filename)
- vendored-copy sync: check module version drift against other plugins

### B2. "?" hover-help system
**Current:** No contextual help. O-Bitrot v1.12 established the pattern ("?" toggle + hover
tooltips on all controls).
**Proposed:** Port the same mechanism: help toggle in header, hover tooltips for all 17
params + view toggle, editor interactions, downmix badge. Reuse O-Bitrot's tooltip CSS/JS
(fixed-position tooltips: pin width in px before edge-clamping — memory pattern).

## Part C — Motion Upgrades

### C1. PPQ-locked tempo sync
**Current:** Tempo sync converts division → Hz only; phase free-runs
(`MotionEngine::getEffectiveSpeed()`). Motion is not beat-aligned and offline bounces don't
reproduce playback positions.
**Proposed:** When synced and the host transport provides PPQ position, derive
`phaseAccumulator` directly from PPQ: `phase = fmod(ppq / beatsPerCycle, 1.0) * 2π`. Fall back
to free-run when transport is stopped/unavailable (keep advancing so Standalone still moves).
Makes bounces deterministic and downbeat-aligned.

### C2. Doppler pitch shift
**Current:** No pitch modulation from motion — orbits sound static in pitch.
**Proposed:** New "Doppler" param (0–100%). Implement as a short modulated delay line (a few
ms) whose read position tracks source distance change (radial velocity), scaled by the param.
Applies per-source (L/R split = two delay lines). Off by default (0%) so existing sessions and
presets are untouched. Requires A1 (motion distance actually wired) first.
**Traps:** delay-line seeding (push-without-pop shifts delay — memory), block-size invariance
probe for the velocity estimate.

### C3. Linear path ping-pong
**Current:** Linear path saw-wraps: sweeps −w/2 → +w/2 then jumps back instantly — a
positional discontinuity smoothed only by the per-block gain ramp (possible click/lurch each
cycle).
**Proposed:** Add "Linear ↔" (ping-pong) as a 5th path choice (append to the choice list —
never reorder; saved sessions store indices). Triangle-wave azimuth, no jump.

### C4. Custom path (brief item, larger scope)
**Current:** BRIEF.md promised a "Custom" path; shipped paths are Orbit/Pendulum/Linear/Drift.
**Proposed (deferred candidate):** User-drawn trajectory on the visualizer canvas, stored as a
breakpoint list in plugin state, traversed at Speed. This is its own mini-project (state
serialization, UI drawing mode, resampling); recommend splitting into a separate brief if
pursued. Include in v1.1 only if scope allows.

## Part D — Speaker Editor / 3D UI

### D1. Elevation + distance editing per speaker
**Current:** Editor drag changes azimuth only (`moveSpeaker(index, az, el)` always passes the
existing elevation); no distance editing. 3D layouts can only come from import.
**Proposed:** Modifier-drag for elevation (e.g. shift+vertical drag), scroll or alt-drag for
distance, with a per-speaker az/el/dist readout while hovering (BRIEF.md promised this
readout). Elevation shown as ring size or a small badge.

### D2. Named custom-layout presets (save/load inside the plugin)
**Current:** Custom layouts persist with the session and can be exported/imported as JSON
files, but there's no in-plugin library of named layouts.
**Proposed:** Save/load named layouts to a per-user folder (same pattern as preset-manager
user presets), listed in a small dropdown in the editor toolbar. Keep file import/export for
sharing.

### D3. Height visualization
**Current:** Visualizer is strictly 2D top-down; elevation (source or speakers) is invisible
even with 3D layouts and elevation-enabled paths.
**Proposed:** Lightweight height cue rather than a full 3D view: source dot scales/brightens
with elevation + a small side elevation meter; height-layer speakers drawn with a distinct
ring. Full 3D perspective view is out of scope for v1.1.

### D4. Resizable editor (bonus, small)
**Current:** Fixed 800×600 (`PluginEditor.cpp:311`).
**Proposed:** `setResizable(true, true)` + `setResizeLimits` with fixed aspect ratio; UI is
already relative-unit friendly except the canvas (canvas is a CSS replaced element — needs
explicit width/height + DPR handling on resize; memory pattern. Also add the missing window
resize listener — `resizeCanvas()` currently runs once at init).
