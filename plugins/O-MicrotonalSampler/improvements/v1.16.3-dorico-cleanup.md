# Improvement Brief — v1.16.3 Multi-Family Dorico Support

**Target version:** v1.16.3 PATCH
**Severity:** P2 — distribution coverage gap (plugin is instrument-family-agnostic but ships strings-only Dorico routing) + TC-2 manual-load step
**Type:** Distribution artifacts + 2-line cosmetic C++ patch (label defaults). No DSP / state / threading change.
**Predecessor:** v1.16.2 (TC-5 keyswitch-from-notation, shipped)
**Supersedes:** Original v1.16.3 draft (slot-trim 10→8 + TC-2). Replaced 2026-05-04 after design discussion — multi-exp-map approach beats slot-trim by enabling winds/brass coverage at the same 8-slot cap.

## Context (design discussion 2026-05-04)

User confirmed three things during /improve --discuss:
1. **Need >8 string articulations** (trem, sp-trem, flaut, stacc, spicc on top of current 8). Triggered the slot-cap question.
2. **kMaxTech expansion (8→13) is overkill** — touches RR buffer, preset state size, UI tab strip. MINOR-class surface for what is fundamentally a Dorico-side mapping problem.
3. **Plugin is already instrument-family agnostic** — `kMaxTech=8` is a fine cap if the 8 slots are repurposable per family. Strings-specificity lives entirely in the exp-map's `<techniqueIDs>` bindings.

**Outcome:** ship 4 expression maps in one `.doricolib` (Strings / Winds / Brass / Generic), each binding the same 8 keyswitch slots to family-appropriate Dorico technique IDs. Playback Template uses `<instrumentFamilies>` to route automatically.

## Risk envelope (carried from v1.16.2 brief — re-read before implementing)

- **DO NOT modify plugin C++ source code beyond the 2-line label patch in Task 6.** kMaxTech, RR buffer, threading, state shape — all untouched.
- **DO NOT add XML comments before root elements.** Crashes Dorico on launch with "invalid file format" (Dorico 6's strict user-config parser).
- **DO NOT change `<microtonalPlaybackMethod>` to `kAuto` on any of the four maps.** Breaks TC-4 (microtonal pitch — load-bearing).
- **DO NOT remove top-level `<pitchBendRange>2</pitchBendRange>` or `<microtonalPlaybackMethod>kVST3NoteExpression</microtonalPlaybackMethod>` from any map.** v1.16.2's iteration history showed these are required at top level for TC-4.
- **All four maps must use the same 8 keyswitch slot indices (0..7 on MIDI 0..7).** Plugin's `kMaxTech=8` and `OMtsTrigger` clamp logic is shared across maps; mismatched KS notes would silently misfire.

## Future work (not in v1.16.3)

- **Per-family sample-folder presets** (factory bank shipping Strings/Winds/Brass sample sets) — separate ideation track; not blocking.
- **kMaxTech expansion (8 → 13+)** — only revisit if user reports needing >8 articulations on a single instrument across one piece. Current architecture says: load a second plugin instance with a different family map.
- **Combination technique entries** (e.g. `pt.sulPonticello,pt.tremolo` → dedicated slot) — possible within the current 8-slot cap by trading a singleton slot for a combination slot. Defer until requested.
