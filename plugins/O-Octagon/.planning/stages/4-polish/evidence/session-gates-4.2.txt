RIG SETUP — the root cause that cost the session ~40 minutes
--------------------------------------------------------------------------------
  RECORDED BECAUSE IT IS A REAL USAGE CONSTRAINT, NOT A FUMBLE.

  O-Octagon MUST be instantiated in Logic via the insert slot's
      Stereo -> 7.1
  channel-configuration entry. Clicking the plugin NAME takes Logic's default
  pick for the slot, which is MULTI-MONO: eight independent mono instances, one
  per surround channel. Logic marks this with the multi-mono control bar
      (...) [L-R|Lm-Rm|Ls-Rs|C] [LFE] [Couple]
  above the plugin UI.

  Each multi-mono instance sees a 1-in/1-out bus, so EVERY instance correctly
  raises both banners:
      SAFE  "Stereo fold — not the 8·channel rig"
      MAP   "output set is not 8 channels"
  The banners were accurate throughout. They were describing one of eight mono
  copies. The plugin never misreported anything.

  WHAT WAS RULED OUT BEFORE THE CAUSE WAS FOUND (each measured, not assumed):
    - Project surround format / Audio I/O ... correct at 7.1 the whole time
    - Stale AudioUnitCache ................. cache empty (0 bytes)
    - Stale Logic plugin database .......... no Octagon entries present
    - Dev/release variant shadowing ........ only O-Octagon-dev.component on
                                             disk; no system-wide copy
    - Plugin-side channel support .......... auval reports the explicit set
                                             [1,1] [1,2] [1,8] [2,1] [2,2] [2,8]
                                             and publishes output layout tag
                                             0x810008 = Emagic_Default_7_1,
                                             i.e. Logic's OWN 7.1 tag
    - Plugin real-rig path ................. PROVEN GOOD in Standalone on
                                             BlackHole 64ch with active outputs
                                             pinned to 1-8: both banners clear,
                                             Set = "7.1 Surround"

  A surround-INPUT track does NOT work and cannot: isBusesLayoutSupported
  rejects any input wider than stereo before it looks at the output, so Logic
  finds no matching config and falls back to multi-mono. O-Octagon is a PANNER
  (mono-or-stereo in, 8 out), not a surround processor.

  OWED AT CLOSE: this constraint belongs in COMPAT-02's notes and in the docs.
  No artifact currently states it, and the next person to open this plugin in
  Logic will hit it in exactly the same way. The failure is quiet if the banners
  are not read.
