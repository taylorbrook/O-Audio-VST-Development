**Implementation (ColoredModeProcessor.cpp):**
- Asymmetric tanh saturation formula from research:
  ```cpp
  float asymmetricTanh(float x, float drive, float bias) {
      float biased = x + bias;
      float saturated = std::tanh(drive * biased);
      float dcCorrection = std::tanh(drive * bias);
      return saturated - dcCorrection;
  }
  ```
- Default bias = 0.2f (moderate even harmonics, not muddy)
- Drive range: 1.0 (enhance=0) to 4.0 (enhance=1.0)
  - Formula: `drive = 1.0f + enhanceAmount * 3.0f`
- Process loop applies asymmetricTanh to each sample
- Output soft-limited with tanh() to prevent clipping

**Why asymmetric vs symmetric:**
- Clean Mode (symmetric): tanh(x*drive) generates odd harmonics (3rd, 5th) - clarity
- Colored Mode (asymmetric): DC bias generates even harmonics (2nd, 4th) - warmth

The key verification is mathematical:
- For a sine wave input x = sin(t)
- Symmetric f(x) = tanh(x) produces f(-x) = -f(x), so only odd harmonics in Fourier series
- Asymmetric f(x) = tanh(x + bias) - DC produces f(-x) != -f(x), so even harmonics appear
