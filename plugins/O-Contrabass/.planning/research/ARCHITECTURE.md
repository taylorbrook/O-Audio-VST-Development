## Core Components

### Bow Model (Excitation Shaper)

- **JUCE Class:** Custom — operates on `juce::SmoothedValue<float, ValueSmoothingTypes::Linear>` per parameter (20 ms ramp).
- **Purpose:** Translates user/MIDI/MPE inputs (velocity, CC11, CC2, CC74, MPE Y/Z, Note Expression) into per-sample bow-state values: `v_bow`, `F_bow`, `beta`.
- **Parameters Affected:** `BOW_SPEED`, `BOW_PRESSURE`, `BOW_POSITION`, `EXPRESSION_MACRO`.
- **Configuration:**
  - All three bow parameters smoothed at 20 ms (linear) to absorb DAW automation steps.
  - `EXPRESSION_MACRO` (0–1) layers onto base values: simultaneously raises bow speed (×1.0–1.4), pressure (×1.0–1.6), vibrato depth (×1.0–1.3), and body brightness offset (+0–500 Hz).
  - Outputs feed Friction Junction at the oversampled (2x) rate.

---

### Friction Junction (Nonlinear Bow-String Coupling)

- **JUCE Class:** Custom (candidate `ouaricon_bow_friction` shared module — extracted from O-Bowed `Source/DSP/HyperbolicFriction.h`).
- **Purpose:** Computes friction force as a function of relative velocity `v_rel = v_bow − v_string_incoming`. Drives stick-slip Helmholtz motion in the waveguide.
- **Parameters Affected:** `BOW_SPEED`, `BOW_PRESSURE`, `BOW_POSITION`, `ROSIN`, `SUB_HARMONICS`, `SLOW_LFO_DEPTH`.
- **Configuration:**
  - **Friction model:** Hyperbolic bow table (always-on) — `mu(v_rel) = mu_d + (mu_s − mu_d) · v_0 / (v_0 + |v_rel|)`. Optional elasto-plastic enhancement deferred to v1.1 (see Open Decisions §1).
  - **Bass-tuned defaults:** `mu_s = 0.85`, `mu_d = 0.25`, `v_0 = 0.05 m/s` (vs violin's 0.4/0.15/0.10). `ROSIN` (0–1) maps to `mu_s/mu_d` ratio and `v_0`.
  - **State precision:** `double` for friction-table lookup, slope evaluation, and Newton fallback. Delay-line state is `float`.
  - **Oversampling:** 2x via `juce::dsp::Oversampling<float>` (`filterHalfBandPolyphaseIIR`, `isMaxQuality=true`). Friction junction runs at 2x rate; body resonator and limiter run at host rate.
  - **Sub-harmonic biasing:** When `SUB_HARMONICS` > 0, biases `F_bow` toward `F_max(beta, v_b)` (Schelleng upper bound), tightens `v_0`, widens `mu_s − mu_d` gap. Period-doubling regime emerges from the friction nonlinearity itself — no separate generator. Auto-clamped below `F_max` to avoid raucous chaos.
  - **Schelleng guard:** Each block computes `F_min(beta, v_b)` and `F_max(beta, v_b)` from the current `v_bow` and `beta`. Slow-Bow-LFO depth is then clamped to 80% of remaining wedge headroom (see Slow-Bow LFO).

### String Waveguide Bank (4 strings, EADG)

- **JUCE Class:**
  - `juce::dsp::DelayLine<float, juce::dsp::DelayLineInterpolationTypes::Lagrange3rd>` per string.
  - Allocated buffer: 8192 samples (worst case: E1 with −1200 cents detune at 88.2 kHz internal = 4282 samples; rounded up to next power of two).
  - **NOT Thiran** — Thiran allpass clicks under continuous detune/vibrato modulation (JUCE doc explicitly warns).
- **Purpose:** Models four bowed strings (E1=41.2 Hz, A1=55 Hz, D2=73.4 Hz, G2=98 Hz) with bridge LP loss, dispersion, and per-string detune. Bow engages one string at a time (mono).
- **Parameters Affected:** `STRING_TENSION`, `STRING_STIFFNESS`, `BRIGHTNESS`, `DETUNE_E/A/D/G`, `ACTIVE_STRINGS`, `INFINITE_SUSTAIN`.
- **Configuration:**
  - **Per-string dispersion:** Cascaded first-order allpass (Rauhala/Välimäki 2006 closed-form coefficient).
    | String | Inharmonicity B (default) | Allpass sections M |
    |--------|-----|---|
    | E1 | 1e-4 · stiffness | 4 |
    | A1 | 7e-5 · stiffness | 3 |
    | D2 | 5e-5 · stiffness | 2 |
    | G2 | 3e-5 · stiffness | 1 |
  - **Bridge filter:** One-pole LP, `H(z) = g·(1−p)/(1−p·z⁻¹)`. `p = exp(−2π·BRIGHTNESS/sr_internal)`; `g` from `INFINITE_SUSTAIN` (0.997 → 0.99995, hard ceiling 0.9999999).
  - **Constant leak:** `−1e-20` in bridge filter outside drone mode (defense-in-depth denormal guard).
  - **Per-string detune:** `juce::SmoothedValue<float, Linear>`, 20 ms ramp. Smoothed in delay-samples space, NOT cents (avoids logarithmic warping at low f0). Per-sample `setDelay()` during ramp.
  - **Active strings:** When `ACTIVE_STRINGS < 4`, bow is restricted to the lowest N strings. Note-to-string mapping uses standard double-bass first-position fingering (closest open string to MIDI note).
  - **In-loop saturator:** Algebraic `x / sqrt(1 + x²)` after bridge filter — asymmetric onset at 0.6, asymptote at 1.0 prevents loop-gain runaway.

---

### DC Blocker (in-loop)

- **JUCE Class:** Custom (one-pole, Smith DC blocker pattern).
- **Purpose:** Removes DC drift from accumulated nonlinear residue on long sustains.
- **Parameters Affected:** None (always active).
- **Configuration:**
  - `H(z) = (1 − z⁻¹) / (1 − R·z⁻¹)` with `R = 0.999` → cutoff ~7 Hz at 44.1 kHz, safely below E1 (41 Hz).
  - Placed inside the loop after the bridge filter, before the next round trip.

---

### Slow-Bow LFO

- **JUCE Class:** Custom (sine generator + `juce::SmoothedValue` outputs).
- **Purpose:** Diagonal bow-trajectory modulation (speed + pressure in-phase) for evolving drone material.
- **Parameters Affected:** `SLOW_LFO_RATE`, `SLOW_LFO_DEPTH`.
- **Configuration:**
  - Rate: 0.05–2.0 Hz (sub-audio).
  - Schelleng-aware: depth scaled to 80% of remaining wedge headroom each block.
  - Pressure phase-lag: ~23° (mimics natural arm-motion delay).
  - 20 ms `SmoothedValue` on speed/pressure modulators (prevents friction-junction zero-crossing artifacts).
  - Modulation is multiplicative: `bowSpeed *= (1 + 0.6·s)`, `bowPressure *= (1 + 0.5·p)`.

---

### Vibrato Section

- **JUCE Class:** Custom (sine + onset envelope) → modulates each `juce::dsp::DelayLine::setDelay()`.
- **Purpose:** Bass-tuned vibrato on top of MIDI/MPE input (per Mick 2025 bass mean of 5.17 Hz).
- **Parameters Affected:** `VIBRATO_RATE`, `VIBRATO_DEPTH`, `VIBRATO_ONSET`.
- **Configuration:**
  - Rate: 0.1–12 Hz (default 5 Hz).
  - Depth: 0–50 cents (default 12 cents — gentler than research mean for orchestral aesthetic).
  - Onset: 0–3000 ms (default 600 ms) with S-curve fade-in over 300 ms (half-cosine ramp).
  - Modulates delay-line *length* (physically correct), absorbed cleanly by `Lagrange3rd` interpolation.
  - Note-off: rapid 100–200 ms fade-out (faster than bowing tail) to avoid pulsing decay.
  - Anti-correlation guard: vibrato rate is offset by a small irrational amount (e.g. +0.13 Hz) when Slow-Bow LFO is active to avoid 5:1 beating.

---

### Body Resonator (8-Mode Wood Bank)

- **JUCE Class:** `std::array<juce::dsp::IIR::Filter<float>, 8>` (parallel bank), driven by `juce::dsp::IIR::Coefficients<float>::makeBandPass(sr, fc, Q)`.
- **Purpose:** Bass-tuned wood body radiation — A0 air mode through bridge hill. Anchored to Askenfelt (1982) and Rossing (2010) measurements.
- **Parameters Affected:** `BODY_SIZE`, `BODY_DAMPING`, `BODY_MIX`, `BRIGHTNESS` (indirectly via dry path).
- **Configuration:**
  - **Default 3/4 bass modes (size = 0.75):**
    | # | Mode | Freq (Hz) | Q | Gain (dB) |
    |---|------|-----------|---|-----------|
    | 1 | A0 (Helmholtz / f-hole) | 60 | 14 | −2 |
    | 2 | T1 / B1− (main wood) | 98 | 11 | 0 |
    | 3 | B1+ (corpus) | 115 | 9 | −1 |
    | 4 | Cluster low | 175 | 8 | −3 |
    | 5 | Cluster mid | 235 | 7 | −4 |
    | 6 | Cluster high | 340 | 6 | −5 |
    | 7 | Bridge cluster | 700 | 5 | −7 |
    | 8 | Bridge hill | 1200 | 2.5 | −6 |
  - **Body Size scaling:** `size_scalar = 0.85 + 0.30·s` → 1.83:1 frequency span across knob. Q does NOT scale (size-independent in real wood, per Bissinger/Hutchins). See Open Decision §5.
  - **Body Damping scaling:** `Q_eff = Q_default · (1 − 0.85·damping)` (×0.15 minimum at full damp). Uniform across all modes.
  - **Body Mix:** Wet (8-mode bank) blended with HP-filtered dry (35 Hz HP on dry path to prevent sub-A0 phase-comb artifacts). `out = (1 − mix)·dry + mix·wet`.
  - **Coefficient updates:** Recomputed once per audio block (every 32–64 samples). 30 ms `SmoothedValue` on Size/Damping/Mix prevents zipper noise.
  - **Wolf-tone region (F2–B2):** Default suppression — drop Mode #2 Q from 11 → 7 when fundamental locks within ±15 cents for >150 ms. "Authentic Arco" toggle (deferred to v1.1, see Open Decision §3).

---

### Bow Noise Generator

- **JUCE Class:** Custom — 3 parallel `juce::dsp::IIR::Filter<float>` BPFs driven by `juce::Random`-seeded white noise + `SlipBurst` one-shots.
- **Purpose:** Hair-on-string contact texture (the missing element in SWAM-style polished PM bass).
- **Parameters Affected:** `BOW_NOISE`, `BOW_SPEED`, `BOW_PRESSURE` (envelope drive).
- **Configuration:**
  - 3-band BPF: 700 Hz / 1500 Hz / 3000 Hz (Q ≈ 1.0–1.5 each). Bass close-mic energy concentrated 500 Hz – 4 kHz (vs violin's 1–8 kHz).
  - Envelope: `bowEnergy = clamp(0, 1, |v_bow|·F_bow / (v_ref·F_ref))` with `v_ref = 0.3 m/s`, `F_ref = 2.0 N`.
  - Per-period slip bursts on Helmholtz slip-detection (zero-crossing of friction force from stick to slip), exponential decay `decay = 0.999` at 48 kHz.
  - Sums **after** body resonator (real-world close-mic noise is hair-string emission, not body radiation).
  - Default `BOW_NOISE = 0.35` (heavier than O-Bowed default for "intimate close-mic" sonic target).

---

### Master Saturator + Zero-Latency Limiter

- **JUCE Class:** Custom (polynomial soft-clip + feedforward peak limiter).
- **Purpose:** QUAL-02 — extreme drone settings remain musical; PERF-03 — zero algorithmic latency.
- **Parameters Affected:** `OUTPUT_GAIN` (post-limiter).
- **Configuration:**
  - **Master saturator:** Polynomial `y = x − x³/3` with input pre-clamp to [−1.5, +1.5]. ~6 dB gentle warmth above −3 dBFS.
  - **Zero-latency limiter:** Feedforward (no look-ahead), 3 ms attack / 100 ms release, threshold −1 dBFS, computed on 2x-oversampled signal then downsampled.
  - **Output gain:** Final stage; `OUTPUT_GAIN` linear conversion via `juce::Decibels::decibelsToGain`.

---

### Stereo Width

- **JUCE Class:** Custom — M/S encode → side-gain scale → M/S decode.
- **Purpose:** Stereo spread for orchestral/cinematic placement.
- **Parameters Affected:** `WIDTH`.
- **Configuration:**
  - 0.0 = mono (side = 0), 1.0 = stereo (side = 1.0), 2.0 = 200% wide (side = 2.0, mid clamped to prevent overflow).
  - Body Mix is applied separately to M and S (default 5% drier on side channel) to avoid artificial-sounding stereo body thickness.

---

### Microtonal Tuning Engine

- **JUCE Class:** `modules/tuning/scala-tuning-engine` v2.1.0 (existing shared module) + `modules/tuning/note-expression` (existing patch + helper).
- **Purpose:** FUNC-06 / FUNC-07 — Ouaricon microtonal convention (Note Expression > MTS-ESP > Scala/TUN > MPE pitch-bend > 12-TET priority).
- **Parameters Affected:** `REFERENCE_PITCH`, `TUNING_SYSTEM`, `NOTE_EXPRESSION`.
- **Configuration:**
  - Pattern: O-Lyrica `BowedStringVoice`-equivalent — voice receives `TuningEngine*` and `APVTS*` pointers.
  - VST3 patch: `JUCE-NE-PATCH` already applied at `~/JUCE/`, captures `kTuningTypeID` Note Expression events that JUCE 8 silently drops.
  - Voice-side drain: `pendingTuningSemis[pitch].exchange(0.0)` before DSP trigger in `startNote`.
  - Tuning lookup applied to base frequency before string-selection: `f_final = f_12tet · 2^(detune_cents/1200) · tuning_offset`.
  - Per-string detune (`DETUNE_E/A/D/G`) is applied AFTER tuning lookup (independent of system).

## Processing Chain

```
MIDI / MPE / VST3 Note Expression
    │
    ▼
[Microtonal Tuning Engine]
    │ (resolves f_target per voice)
    ▼
[Bow Model]──────── BOW_SPEED, BOW_PRESSURE, BOW_POSITION, EXPRESSION_MACRO
    │
    ▼
[Slow-Bow LFO]───── SLOW_LFO_RATE, SLOW_LFO_DEPTH (Schelleng-aware)
    │
    ▼
[Vibrato Section]── VIBRATO_RATE, VIBRATO_DEPTH, VIBRATO_ONSET
    │
    ▼  ┌────────────── 2x oversampling boundary (up) ──────────────┐
    │
    ▼
[Friction Junction]◄────► [Selected String Waveguide (1 of 4)]
   │ Hyperbolic           │  ┌─ DispersionFilter (1–4 allpass)
   │ + sub-harmonic       │  ├─ Lagrange3rd fractional delay
   │   bias               │  │  (length = sr/(f0·2^(detune/1200)))
   │ + Schelleng guard    │  ├─ Per-string detune SmoothedValue (20 ms)
   │                      │  ├─ Bridge LP filter (g, p from INFINITE_SUSTAIN, BRIGHTNESS)
   │                      │  ├─ In-loop saturator (algebraic, asym onset 0.6)
   │                      │  ├─ DC blocker (R=0.999)
   │                      │  └─ Tiny denormal leak (−1e-20)
   ▼
   ┌────────────── 2x oversampling boundary (down) ──────────────┐
    │
    ▼
[Body Resonator]──── BODY_SIZE, BODY_DAMPING, BODY_MIX, BRIGHTNESS
    │ 8-mode parallel biquad bank + 35 Hz HP dry path
    │
    ▼
[Bow Noise Generator]── BOW_NOISE (sums after body)
    │ 3-band BPF (700/1500/3000 Hz) + slip bursts
    │
    ▼
[Master Saturator]── (polynomial x − x³/3)
    │
    ▼
[Zero-Latency Limiter]── (feedforward, −1 dBFS, 3 ms / 100 ms)
    │
    ▼
[Stereo Width]────── WIDTH (M/S encode → side scale → decode)
    │
    ▼
[Output Gain]─────── OUTPUT_GAIN
    │
    ▼
Stereo Out
```

**Routing notes:**
- The 2x oversampling region is *only* the friction junction + waveguide loop — body, noise, saturator, limiter, width run at host rate.
- Body resonator is parallel (zero group delay at design frequencies). Bow noise is parallel-summed after the body, NOT fed through it.
- Loop ordering inside waveguide: dispersion → bridge LP → saturator → DC blocker → fractional delay (back to friction junction). Keep this order — Smith's PASP places nonlinearity *after* the lossy filter to avoid amplifying numerical noise.
- Friction junction is one location only (not duplicated per string) — the active string's delay-line state IS the junction's incoming wave.
- Mono path until Stereo Width — all internal DSP is single-channel.

## System Architecture

### MIDI Routing

**Input handling:** Single channel (1) for non-MPE; channels 2–16 (or 1–15) for MPE per VST3 spec.

**Note mapping:**
- MIDI note → string selection: closest open-string fundamental (E1=28, A1=33, D2=38, G2=43 in MIDI), then fingered position above the open string up to G3 (=55).
- Note-on triggers Vibrato onset envelope and bow-engagement; note-off triggers bow-disengagement + release tail.
- Velocity → Initial bow attack character (modulates initial `F_bow` ramp time and starting bow-speed accent).

**JUCE classes:**
- `juce::MidiBuffer` — MIDI event storage in `processBlock`.
- `juce::MidiMessage` — note-on/off + CC parsing.
- `juce::MPEInstrument` + `juce::MPEZoneLayout` — MPE state tracking (per-note pressure, slide, pitch bend).
- `juce::MPESynthesiser` (or `MPESynthesiserBase` direct) — voice management. Use `enableLegacyMode(pitchbendRange=2, channelRange={1,17})` for non-MPE hosts.

**CC mapping:**
- CC11 (Expression) → `BOW_SPEED` (intrinsic).
- CC2 (Breath) / Channel Aftertouch → `BOW_PRESSURE`.
- CC74 / MPE Y (Slide) → `BOW_POSITION` (β).
- MPE Z (Pressure) → per-note `BOW_PRESSURE` modulation (additive).
- MPE Pitch Bend → per-note pitch (combined with Note Expression).

**Processing:** All MIDI events drained at `processBlock` entry, before the 2x oversampler upsample. Note Expression events drained from VST3 raw-event queue (per `JUCE-NE-PATCH`) ahead of `renderNextBlock`.

### State Persistence

**What state is saved:**
- APVTS parameters (29 total) — automatic via `juce::AudioProcessorValueTreeState`.
- Custom state:
  - Last-used Scala/TUN file path (when `TUNING_SYSTEM = Scala/TUN`).
  - Active preset name (for "modified since load" indicator in UI).
  - Note Expression enabled flag (also exposed as APVTS bool).

**Serialization format:**
- APVTS: XML via ValueTree (automatic).
- Custom state: ValueTree child node `<O-ContrabassState>` with attributes `scalaPath`, `currentPreset`, `presetModified`.

**JUCE classes:**
- `juce::AudioProcessorValueTreeState` — parameter persistence.
- `juce::ValueTree` — custom state tree.
- `juce::ValueTree::toXmlString()` — serialization.

**Save/restore methods:** `getStateInformation` / `setStateInformation`.

**Restore behavior:**
- Missing Scala/TUN file → fall back to 12-TET, log warning, keep file path stored for re-resolution attempts.
- Invalid XML → use defaults, no error dialog (silent recovery to maximize host compatibility).
- Tuning System mismatch (e.g., MTS-ESP unavailable) → fall back to 12-TET, do NOT change saved state.

---

### Multi-Output Routing

Not applicable — O-Contrabass is a stereo instrument with a single stereo output bus (mono summed → stereo widener).

### File I/O System

Limited to Scala/TUN tuning import. Loading happens on UI thread (via `modules/tuning/scala-tuning-engine`); audio thread reads from atomic-swapped tuning table pointer. No file I/O in `processBlock`.

## Algorithm Details

### Hyperbolic Friction Curve

**Algorithm:** Static friction table parameterized by relative velocity.

**Formula:**
```
mu(v_rel) = mu_d + (mu_s − mu_d) · v_0 / (v_0 + |v_rel|)
F_friction = mu(v_rel) · F_bow · sign(v_rel)
```

**Implementation notes:**
- Pre-compute lookup table with linear interpolation (1024 entries spanning ±2 m/s) at construction; rebuild table when `mu_s`, `mu_d`, or `v_0` change (control-rate, every block).
- No Newton-Raphson required for hyperbolic curve — it's monotonic in `v_rel`. Solve junction equation directly: `F = (v_bow − (v_sl + v_sr)) · Y_string` with `Y_string = 2/Z_string`.
- Add `eps = 1e-10` guard inside `sqrt` if elasto-plastic enhancement is enabled later.

---

### Cascaded Allpass Dispersion (Rauhala/Välimäki 2006)

**Algorithm:** First-order allpass cascade approximating `f_n = n·f0·sqrt(1 + B·n²)`.

**Formula (per section):**
```
A(z) = (a + z⁻¹) / (1 + a·z⁻¹)
```
Coefficient `a` from closed-form (paper Table 1, simplified):
```
I  = log2(f0/440) · 12 + 49           // virtual key number
lB = log(max(B, 1e-9))
lM = log(max(M, 1))
C  = m1·lB + m2·lM + m3·lB·lM + m4    // m1..m4 from paper
k  = k1 + k2·I + k3·I²                 // k1..k3 from paper
a  = clamp(-C/k, -0.99, 0.99)
```

**Implementation notes:**
- Single state element per section: `y = a·x + z; z = x − a·y` (transposed direct form II).
- Coefficients fixed per note (recomputed in `noteOn` and on `STRING_STIFFNESS` change).
- Cascade is stable for any `|a| < 1`; stability is automatic.
- Loop placement: immediately before bridge filter on the right-going wave.

---

### Lagrange 3rd-Order Fractional Delay

**Algorithm:** 4-tap FIR interpolator (Smith CCRMA).

**Formula:**
```
y(n) = Σ_{k=0..3} h_k(d_frac) · x(n − k)
```
where `d_frac` ∈ [0, 1) is the fractional component and Lagrange basis functions `h_k` are computed in closed form.

**Implementation notes:**
- Use `juce::dsp::DelayLine<float, juce::dsp::DelayLineInterpolationTypes::Lagrange3rd>` directly — JUCE handles coefficient computation.
- Stateless (no transient on `setDelay()` modulation) — critical for vibrato + per-string detune automation without clicks.
- 4 multiplies + 3 adds per sample; ~0.6% CPU per string at 88.2 kHz internal.
- HF accuracy holds up to ~10 kHz at 44.1 kHz host rate / 20 kHz at 88.2 kHz internal — well above any contrabass content.

### Bridge Filter (One-Pole Lowpass + Loop Gain)

**Algorithm:** First-order recursive LP with loop-gain factor.

**Formula:**
```
y[n] = g · ((1 − p) · x[n] + p · y[n − 1])
p    = exp(−2π · BRIGHTNESS / sr_internal)
g    = computeLoopGain(INFINITE_SUSTAIN)        // 0.997 → 0.99995 quadratic
```

**Implementation notes:**
- Constant `−1e-20` leak added to `y` outside drone mode (`INFINITE_SUSTAIN < 0.95`) to prevent denormal accumulation during long fadeouts.
- `g` is hard-clamped to `0.9999999` regardless of `INFINITE_SUSTAIN` (mandatory ceiling).
- `p` clamped to [0.05, 0.95] to ensure non-zero HF damping in all states.

---

### Sub-Harmonic Bias (Period-Doubling)

**Algorithm:** Friction-junction parameter biasing toward Schelleng `F_max` regime.

**Implementation:**
```cpp
void applyBias(float subAmount,
               float& F_bow, float& v_0, float& mu_s, float& mu_d) {
    F_bow *= 1.0f + 0.8f * subAmount;
    v_0    = std::max(0.005f, v_0 * (1.0f - 0.5f * subAmount));
    float gap = mu_s - mu_d;
    mu_s   = mu_d + gap * (1.0f + 0.25f * subAmount);
    // Schelleng clamp:
    F_bow = std::min(F_bow, kFmaxScalar * F_max(beta, v_b));   // kFmaxScalar = 0.95
}
```

**Implementation notes:**
- 30 ms cross-fade on `subAmount` parameter changes (avoids click during automation).
- Optional control-rate (~100 Hz) check: lag-2 RMS > lag-1 RMS *and* non-periodic → back off bias by 20% (chaotic-regime detection).
- No separate sub oscillator — period-doubling emerges from friction physics.

### Slow-Bow LFO (Schelleng-Aware)

**Algorithm:** Sine LFO with diagonal speed/pressure modulation, dynamically depth-clamped to wedge headroom.

**Formula (per block):**
```
phase += 2π · rate · blockDuration
speedMod    = depth · sin(phase)
pressureMod = depth · sin(phase + 0.4)         // ~23° lag
fMin = (Z² · v_b) / (2·R·beta² · (mu_s − mu_d))
fMax = (2·Z · v_b) / (beta · (mu_s − mu_d))
headroom = min((fMax − F_bow)/fMax, (F_bow − fMin)/max(fMin, ε))
safeDepth = min(depth, headroom · 0.8)
```

**Implementation notes:**
- 20 ms `SmoothedValue` on speed/pressure modulators.
- Multiplicative: `bowSpeed *= (1 + 0.6·s)`; `bowPressure *= (1 + 0.5·p)`.
- Headroom clamp computed at control rate (per block), not per sample.

---

### Body Resonator (Parallel Biquad Bank)

**Algorithm:** 8 parallel bandpass biquads, summed with per-mode linear gain.

**Formula:** Per mode, bandpass coefficients from `juce::dsp::IIR::Coefficients<float>::makeBandPass(sr, fc, Q)` where:
```
fc[i] = jlimit(20, sr · 0.45, defaultFreq[i] / size_scalar)
Q[i]  = defaultQ[i] · max(0.15, 1 − 0.85·damping)
g[i]  = decibelsToGain(defaultGainDb[i] + 1.5·(s − 0.75))
```

**Output:**
```
wet = Σ_i g[i] · biquad_i.process(in)
out = (1 − mix) · highpass35Hz(in) + mix · wet
```

**Implementation notes:**
- Coefficients recomputed once per audio block (every 32–64 samples).
- 30 ms `SmoothedValue` on Size/Damping/Mix.
- For preset-recall instant jumps: 50 ms cos²/sin² crossfade between two parallel banks (one with old coefficients, one with new). This is rare path; default uses smoother only.

---

### Zero-Latency Feedforward Limiter

**Algorithm:** Peak-following envelope with threshold-divided gain reduction.

**Formula:**
```
abs_x = |input|
coeff = (abs_x > envelope) ? attackCoeff : releaseCoeff
envelope = coeff · envelope + (1 − coeff) · abs_x
gain = (envelope > threshold) ? threshold / envelope : 1.0
output = input · gain
```

**Implementation notes:**
- `attackCoeff = exp(−1 / (0.003 · sr))`, `releaseCoeff = exp(−1 / (0.100 · sr))`.
- Threshold = 0.891 (linear) ≈ −1 dBFS.
- Run on 2x oversampled signal to catch true peaks, then downsample.
- No look-ahead → preserves PERF-03 (zero algorithmic latency).
- Master saturator upstream prevents true peaks from exceeding 0 dBFS by much, so 3 ms attack is sufficient for catching residual transients.

## Integration Points

### Feature Dependencies

- **Microtonal Tuning Engine → Bow Model:** Voice fundamental frequency must be resolved before string-selection logic runs (`f_target = baseFreq · 2^((semis + perStringDetune)/12)`).
- **Bow Model → Slow-Bow LFO → Vibrato → Friction Junction:** Speed/pressure pipeline is sequential; LFO modulates Bow Model output, vibrato modulates delay-line length (independent), friction junction consumes the layered result.
- **Slow-Bow LFO ↔ Schelleng Guard:** LFO depth must be clamped per-block based on current `F_bow`/`v_b`/`beta` to remain inside the playable wedge — coupling is bidirectional.
- **Friction Junction ↔ String Waveguide:** Bidirectional energy exchange — junction reads the active string's incoming wave, writes back outgoing wave, all at the oversampled rate.
- **Sub-Harmonics → Friction Junction:** Bias is applied INSIDE the junction (parameter shift), not as a separate processing stage. Order: bias → friction lookup → output force.
- **Infinite Sustain → Bridge Filter:** Loop gain `g` derived from `INFINITE_SUSTAIN`; this is the only path. Quadratic mapping ensures most perceptual range is in top quarter of knob.
- **Body Resonator → Bow Noise:** Bow noise sums AFTER body bank (real-world physics: hair-string emission is not body-radiated).
- **Master Saturator → Limiter:** Saturator's soft-clip at ~−3 dBFS limits the work the limiter has to do, allowing 3 ms attack to be sufficient.

---

### Parameter Interactions

- **`INFINITE_SUSTAIN` × `SUB_HARMONICS` × low `BODY_DAMPING`:** Worst-case stability scenario — all three at max simultaneously is the QUAL-01 acceptance test. Loop-gain ceiling (0.9999999), `F_max` Schelleng clamp on sub-bias, and energy clamp at junction (`softClampState` threshold 0.85) are the layered defenses.
- **`EXPRESSION_MACRO`:** Single knob simultaneously modulates `BOW_SPEED` (×1.0–1.4), `BOW_PRESSURE` (×1.0–1.6), `VIBRATO_DEPTH` (×1.0–1.3), and adds offset to `BRIGHTNESS` (+0–500 Hz). Macro layers are additive on top of host automation of those base parameters.
- **`SLOW_LFO_DEPTH` × `BOW_SPEED`/`BOW_PRESSURE` extremes:** When base bow params are near wedge boundary, LFO depth is auto-attenuated to 80% of remaining headroom. User sees their depth slider value but actual modulation is reduced — UI should reflect this with a "Schelleng-limited" indicator (deferred to GUI stage).
- **`VIBRATO_RATE` × `SLOW_LFO_RATE`:** When both are active, vibrato rate is offset by +0.13 Hz to prevent 5:1 beating (anti-correlation guard).
- **`STRING_STIFFNESS` × pitch:** Dispersion is *most audible* during attack transients (before stick-slip mode-locking) and on the E1 string. Higher pitches (G3) get effectively no dispersion (M=1) regardless of slider.
- **`DETUNE_E/A/D/G`:** Independent of `TUNING_SYSTEM` — applied AFTER tuning lookup so just-intoned drones can use both microtonal A4 reference AND per-string detune for 7-limit interval stacking.
- **`ACTIVE_STRINGS = 1`:** Forces all MIDI input to engage E-string only (drone/scordatura mode). Useful for pure-E1 sub drones.

### Processing Order Requirements

**Per-block processing order (REQUIRED):**

1. **Read MIDI/MPE/Note Expression queue** — drain VST3 raw events ahead of `renderNextBlock`; populate per-note tuning offsets.
2. **Update tuning engine** — resolve final note frequencies for any pending NoteOns.
3. **Update Slow-Bow LFO phase** — control rate (once per block).
4. **Compute Schelleng wedge bounds** — `F_min`, `F_max` from current `v_b`, `beta`.
5. **Clamp Slow-Bow LFO depth** — to 80% of remaining headroom.
6. **Apply LFO to Bow Model** — speed and pressure modulators, smoothed to per-sample.
7. **Update Vibrato envelope** — onset/fade-in state, current depth multiplier.
8. **Compute current vibrato cents** — `depth · onsetEnv · sin(2π·rate·t)`.
9. **Update delay-line lengths** — base + per-string detune + vibrato cents (per-sample during ramp).
10. **Apply Sub-Harmonic bias** — modify friction params before junction tick.
11. **Recompute body coefficients** — Size/Damping/Mix smoothed values, once per block.
12. **Upsample buffer** — 2x via `juce::dsp::Oversampling`.
13. **Per-sample loop (at 2x rate):**
    1. Friction junction tick (state in `double`, force output in `float`).
    2. Active string waveguide: dispersion → bridge LP → in-loop saturator → DC blocker → fractional delay → write to junction.
    3. Inactive strings: receive zero excitation but continue running their internal loops (preserves sympathetic ring? — note: not in v1.0; inactive strings simply pause).
14. **Downsample to host rate.**
15. **Process body resonator** — 8-mode parallel bank + dry HP path → wet/dry mix.
16. **Sum bow noise** — 3-band BPF + slip bursts driven by `bowEnergy` envelope.
17. **Master saturator** — polynomial soft-clip.
18. **Zero-latency limiter** — feedforward peak limiting.
19. **Stereo width** — M/S encode → side scale → decode.
20. **Output gain** — final dB-to-linear scale.
21. **Write to host buffer.**

**Parallel processing notes:**
- Inactive strings (those NOT engaged by the bow) do NOT process — their loops are skipped to save CPU. Switching strings mid-note resets the previously-active string state to zero with a 5 ms fade to avoid click.
- 8 body-bank biquads CAN be parallelized via `juce::dsp::ProcessorChain` if profiling reveals it as a hot path, but baseline scalar implementation hits 0.4% CPU and is unlikely to need optimization.

**Why order matters:**
- Tuning engine BEFORE bow model: bow model needs final fundamental frequency for string-selection.
- LFO + vibrato BEFORE friction junction: junction sees fully-modulated `v_b`, `F_bow`, and delay length on the same sample.
- Schelleng clamp BEFORE LFO application: prevents wedge-exit during the same block where headroom is computed.
- Sub-harmonic bias INSIDE junction: must be applied to `mu_s`/`v_0`/`F_bow` *before* friction lookup, not as separate stage.
- Body AFTER waveguide downsample: body operates at host rate; oversampling doesn't help mode-shape biquads.
- Bow noise AFTER body: real-world hair-string emission is not body-radiated.
- Limiter AFTER master saturator: saturator does most of the "soft" work, limiter catches residual peaks.

---

### Thread Boundaries

**Threads:**
- **Audio thread:** All DSP processing in `processBlock` — friction, waveguide, body, noise, saturator, limiter, width, gain. NO allocations, locks, or file I/O.
- **Message thread:** Parameter changes via APVTS, preset loading, UI repaints, Scala/TUN file selection trigger.
- **Background thread:** Scala/TUN file parsing (via `modules/tuning/scala-tuning-engine`); MTS-ESP polling.

**Communication mechanisms:**
- **APVTS atomic reads:** All parameter values read via `getRawParameterValue()->load()` in audio thread (atomic).
- **Tuning table swap:** Background thread builds new tuning table → atomically swaps pointer (`std::atomic<TuningTable*>`); audio thread always reads current pointer.
- **VST3 raw event queue:** Lock-free SPSC (single producer = wrapper, single consumer = audio thread). See `modules/tuning/note-expression`.
- **Pending tuning offsets:** `std::array<std::atomic<double>, 128>` per-MIDI-note; `exchange(0.0)` consumed in `noteOn`.

**Safety guarantees:**
- Audio thread NEVER waits on file I/O or locks.
- All DSP state lives in classes owned by the synthesizer voice; no shared mutable state between voices (mono = single voice anyway, but pattern preserves correctness).
- `juce::ScopedNoDenormals` at top of `processBlock` (mandatory).

## Implementation Risks

### Friction Junction Stability at E1 + Drone Mode

**Complexity:** HIGH

**Risk Level:** HIGH

**Risk factors:**
1. Lowest fundamental (E1 = 41 Hz, 1070-sample delay at 44.1 kHz) is most prone to denormal accumulation and slow numerical drift.
2. Sub-harmonic bias pushes friction into period-doubling regime — can flip into chaotic regime if Schelleng clamp fails.
3. Infinite sustain (loop gain → 0.99995) compounds any nonlinearity-induced gain over thousands of samples per round trip.
4. All three high-risk states can compound: max `INFINITE_SUSTAIN` + max `SUB_HARMONICS` + min `BODY_DAMPING` is the QUAL-01 stress test.

**Alternative approaches:**
1. **Hyperbolic friction only (recommended primary):** Simpler to verify, single nonlinearity, well-documented. Recommended for v1.0.
2. **Hyperbolic + elasto-plastic toggle (deferred to v1.1):** Higher attack realism but Newton-Raphson convergence stalls add risk; defer until v1.0 stability is proven.
3. **Pure bow-table (lookup, no live solver):** Cheapest, used by O-Bowed Phase 1. Already validated in O-Bowed; extract to shared module.

**Fallback architecture:**
- **Primary:** Hyperbolic friction (table-based) + 2x oversampling + Schelleng clamp + softClampState at junction.
- **Fallback 1:** If sub-harmonic bias triggers chaos at extreme settings → reduce `kForceBoost` from 1.8 → 1.4 in `SubHarmonicBias::apply`.
- **Fallback 2:** If E1 + max sustain still unstable → cap `INFINITE_SUSTAIN` slider at 0.99 (lose user-facing 0.99995 ceiling, gain hard guarantee of stability).
- **Fallback 3:** If all junction-level fixes insufficient → add 4x oversampling on the friction junction only (CPU cost: +2.5%, well within budget).

**Mitigation strategy:**
1. Use O-Bowed's `HyperbolicFriction.h` as starting point (already validated in production).
2. Phase 2.1 (DSP Phase 1): Single E-string + hyperbolic + bridge filter — verify 60-second sustain at max `INFINITE_SUSTAIN` produces no NaN/runaway BEFORE adding sub-harmonics.
3. Use lag-2 RMS chaos detector at control rate (~100 Hz, cheap) as runtime backstop.
4. Schelleng clamp on `F_bow` is mandatory; verified in research §1.3.
5. Test matrix: cross-product of `{INFINITE_SUSTAIN ∈ {0, 0.5, 1.0}}` × `{SUB_HARMONICS ∈ {0, 0.5, 1.0}}` × `{BODY_DAMPING ∈ {0, 0.5, 1.0}}` × `{4 strings}` = 108 combinations, 60 second hold each.

### Per-String Detune ±1200 Cents Without Clicks

**Complexity:** MEDIUM

**Risk Level:** MEDIUM

**Risk factors:**
1. ±1200 cents covers a 4:1 delay-length range (E1 octave-down = 2140 samples; +1200 cents = 535 samples). Naïve `setDelay()` causes audible clicks during automation sweeps.
2. Vibrato + per-string detune happen in the same code path — must compose without thrashing the delay line.
3. Stateful interpolators (Thiran allpass) click; only stateless FIR (Lagrange3rd) is glitch-free.

**Alternative approaches:**
1. **Lagrange3rd + linear `SmoothedValue` on delay-samples (recommended):** Stateless, smooth, JUCE-native. Documented in research §5.
2. **Allpass fractional delay with crossfade on retune:** More expensive, no clear benefit. Rejected.
3. **Pre-quantize detune to nearest semitone (cheapest):** Loses musicality, breaks scordatura/JI use cases. Rejected.

**Fallback architecture:**
- **Primary:** `juce::dsp::DelayLine<float, Lagrange3rd>` + linear `SmoothedValue` (20 ms ramp) on delay-samples.

- **Fallback 2:** If Lagrange3rd HF accuracy is insufficient at +1200 cents (octave-up) → switch to Lagrange5th (custom; 6-tap).

**Mitigation strategy:**
1. Use `juce::dsp::DelayLine<float, Lagrange3rd>` (stateless, JUCE-native).
2. Smooth in delay-samples space (linear), not cents (logarithmic) — see research §5 for unison-crossing edge case.
3. Per-sample `setDelay()` during ramp (NOT block-rate) — block-rate updates produce zipper noise.
4. Test: automate `DETUNE_E` from 0 → +1200 cents over 2 seconds while sustained note plays — verify no clicks.

## Architecture Decisions

### Friction Model Choice (Hyperbolic vs Elasto-Plastic)

**Decision:** Ship hyperbolic friction only in v1.0; defer elasto-plastic toggle to v1.1.

**Rationale:**
- Hyperbolic curve is monotonic, requires no Newton-Raphson, has no convergence-failure modes.
- Bass slow attacks reduce the elasto-plastic regime where memory-effect matters (mostly violin/viola attack transients).
- Sub-harmonic generation works equally well with hyperbolic (period-doubling emerges from the curve's nonlinearity at high `F_bow`).
- O-Bowed already validated hyperbolic in production for general bowed strings.
- Elasto-plastic adds Newton-Raphson convergence risk on top of the existing E1 + drone-mode stability challenge — not worth shipping risk for marginal sonic gain.

**Alternatives considered:**
1. **Elasto-plastic primary (Willemsen/Bilbao 2019):** Better attack realism, but Newton convergence + higher CPU + harder to debug. Rejected for v1.0 — defer to v1.1 once core engine is stable.
2. **Thermal friction (Smith ALF model):** Slow integrator state, more sensitive to numerical drift over long sustains. Wrong choice for drone-first plugin. Rejected.

**Tradeoffs accepted:**
- **Slightly less realistic attack onset** vs elasto-plastic. Acceptable because bass attacks are slow by default; the difference is most audible on rapid violin spiccato (not relevant here).
- **Optional toggle deferred:** Power users wanting elasto-plastic won't get it in v1.0. Documented in changelog and v1.1 roadmap.

**When to revisit:** v1.1 milestone, after v1.0 stability is verified across the QUAL-01 test matrix.

### Body Resonator: Fixed Wood vs Morphable

**Decision:** Fixed wood material (no morphing). Parametric size + damping only.

**Rationale:**
- O-Contrabass is bass-only by design; morphable material is O-Bowed's territory.
- 8-mode bank tuned to published double-bass acoustics (Askenfelt 1982, Rossing 2010) — different mode frequencies than violin/cello.
- Fixed material reduces cognitive load: user has 3 body knobs (Size/Damping/Mix) instead of 3 + material selection.
- Differentiates O-Contrabass from O-Bowed in the product positioning.

**Alternatives considered:**
1. **Morphable material (membrane/wood/metal/glass):** O-Bowed pattern. Rejected — duplicates O-Bowed feature; doesn't serve "deep specialization" thesis.
2. **2 fixed materials (spruce-bright + maple-warm):** Adds variety without full morph cost. See Open Decision §6.
3. **Single fixed material (recommended):** Cleanest UI, sharpest identity. Ship this in v1.0.

**Tradeoffs accepted:**
- **Less timbral variety than O-Bowed:** Acceptable because O-Bowed exists and serves that need.
- **No "wrong wood" rescue option:** If the chosen wood profile doesn't suit a specific use case, user can't switch to a different one. Mitigated by Body Damping/Mix flexibility (heavily damped = closer to neutral character).

**When to revisit:** v1.1 — if user feedback demands timber variety, add 2-variant toggle (spruce-bright / maple-warm) per Open Decision §6.

### Oversampling Strategy (2x vs 4x)

**Decision:** 2x oversampling at the friction junction only. No oversampling for body resonator, master saturator, or limiter. Filter type: `filterHalfBandPolyphaseIIR` (minimum-phase, ~1–3 sample latency).

**Rationale:**
- 2x is sufficient for E1–G3 sustained bowing per research §4.1 (8th harmonic of E1 is 328 Hz, well below Nyquist).
- Bass slow attacks reduce aliasing pressure compared to violin (where 4x is sometimes preferred).
- Polyphase IIR has minimum-phase response — preserves "0 algorithmic latency" goal (PERF-03).
- CPU cost: ~0.4% on M1 (within budget).
- Body bank biquads are linear (no aliasing source). Master saturator is preceded by waveguide bandlimiting. Limiter peak detection benefits from oversampling but only if computed on the upsampled friction signal (which we already have).

**Alternatives considered:**
1. **4x oversampling:** ~1% CPU overhead, marginal gain at bass register. Rejected for v1.0; can be added in fallback path if QUAL-01 reveals aliasing artifacts.
2. **No oversampling:** Aliasing audible during sub-harmonic regime (broadband content from period-doubling). Rejected.
3. **Linear-phase FIR oversampling:** Better magnitude response but 32–64 sample latency violates PERF-03. Rejected.

**Tradeoffs accepted:**
- **Marginal HF aliasing under elasto-plastic + extreme sub-harmonics:** Not present in v1.0 (elasto-plastic deferred). Acceptable.

**When to revisit:** If QUAL-01 reveals aliasing artifacts at extreme settings → upgrade friction-junction oversampling to 4x.

## Special Considerations

### Thread Safety

- All APVTS parameter reads use `getRawParameterValue()->load()` (atomic).
- Tuning table swap: background thread parses Scala/TUN → atomic pointer swap → audio thread reads through atomic.
- VST3 raw event queue: lock-free SPSC (single writer = wrapper, single reader = audio thread).
- Pending tuning offsets: `std::array<std::atomic<double>, 128>` per MIDI note; audio thread `exchange(0.0)` consumes.
- Body coefficient updates happen in audio thread (no locks, no allocations).
- LFO/vibrato phase state is per-voice (mono = single voice; future-proof for hypothetical polyphony).
- `juce::ScopedNoDenormals` at top of `processBlock` (mandatory for x86/x64 + ARM).

### Performance

Estimated CPU on M1, 44.1 kHz host, 256-sample block, single voice:

| Component | CPU |
|-----------|-----|
| 2x Oversampling (polyphase IIR up + down) | ~0.4% |
| Active string DelayLine + dispersion + bridge LP @ 2x | ~0.7% |
| Friction junction (table lookup + linear interp) @ 2x | ~0.3% |
| In-loop saturator + DC blocker @ 2x | ~0.1% |
| Per-string detune/vibrato delay updates | ~0.2% |
| Body resonator (8 biquads + HP) | ~0.4% |
| Bow Noise (3-band BPF + slip bursts) | ~0.4% |
| Slow-Bow LFO + Schelleng compute | ~0.1% |
| Vibrato envelope + delay modulation | ~0.1% |
| Master saturator + limiter | ~0.1% |
| Stereo width + output gain | ~0.1% |
| APVTS reads + parameter smoothing | ~0.2% |
| MIDI/MPE/Note Expression dispatch | ~0.1% |
| **Total** | **~3.2%** |

Headroom for: Authentic Arco wolf-coupling, additional bow-noise spectral shaping, optional FFT-based body convolution (future).

### Denormal Protection

- `juce::ScopedNoDenormals` at top of `processBlock` (handles MXCSR FTZ+DAZ on x86/x64, FPSCR FZ on ARM).
- Bridge filter constant leak (`−1e-20`) outside drone mode (defense in depth).
- Opposite-sign delay-line state guards (`+1e-20` and `−1e-20`) at junction — cancel at output, keep both lines numerically warm.
- `1024-entry` friction lookup table avoids `expf`/`sqrtf` per sample, reducing FP edge-case exposure.

### Sample Rate Handling

- All filter coefficients recomputed in `prepareToPlay()`.
- Delay-line buffer size: 8192 samples (worst case at 88.2 kHz internal with E1 −1200 cents detune). Sufficient for host sample rates up to 96 kHz (internal 192 kHz worst case = ~16k samples — would need re-sizing if 96 kHz host is supported).
- Decision: support host rates 44.1, 48, 88.2, 96 kHz. Re-allocate delay buffer to 16384 in `prepareToPlay` if `sampleRate > 48000`.
- Bridge filter pole `p` recomputed on `BRIGHTNESS` change OR sample rate change.
- LFO phase increment uses `2π · rate / sampleRate` (recomputed on rate change).

### Latency

- Algorithmic latency: 0 samples (waveguide is causal; feedforward limiter has no look-ahead).
- Oversampler latency: ~1–3 samples (polyphase IIR), reported via `setLatencySamples(static_cast<int>(std::ceil(oversampler.getLatencyInSamples())))` in `prepareToPlay`.
- **CRITICAL:** `getLatencySamples()` is NOT virtual in JUCE 8 — must call `setLatencySamples(N)` in `prepareToPlay`, NOT override the getter (per memory file).
