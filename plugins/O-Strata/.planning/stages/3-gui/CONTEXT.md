## Findings from this discussion (facts the research + plan must respect)

1. **The fork page is the v1.24.0 shell with zero terrain controls.** `Source/ui/public/index.html` (195 628 bytes): four tabs (`synth / mod / tuning / effects`), no `.card` class, no `oscATerrain` / `oscAQuality` / `#terrain-tab` markup — the Stage 1 second pass bound relays only (its CONTEXT D1). None of the 34 new parameters has a UI control today. `js/i18n.js` differs from O-Prism's by 45 key lines (v1.25.0 geometry-bank + v1.26.0 strings; most retire with the Wavetable tab).
2. **Editor leftovers to remove in Round A:** native stubs `getActiveOscInfo` / `getActiveOscFrame` (`PluginEditor.cpp:481, 486`, return `[]` / `{}` since Phase 2.1); one `evaluateJavascript` at `:806` (`updateHeldNotes` for TrueKeys — becomes a `heldNotes` push per template §5); timer already at 30 Hz (`:761`).
3. **Stage 2 delivered a different processor surface than `v2-PluginEditor-TEMPLATE.cpp` §7 assumed.** Present: `chebPtr[2]` / `imagePtr[2]` (atomic pointers), `chebGeneration[2]`, `chebFit[2]` (0–100), `chebPartialsAtC4[2]`, `chebApproximate[2]`, `imageGeneration[2]`, `imageFit[2]`, `importRevision[2]`, `importTerrainImage (osc, MemoryBlock, name)` / `importTerrainFile (osc, File)`, `getCycleCapture (osc)` (ring of 2048 × `{θ, px, py, y}` floats with an atomic write index, written per sample by the oscillator — `TerrainOscillator.cpp:410-415`), `getBlockGeneration()`, `TerrainImage::view` (64 × 64 float, "Stage 3 heightmap (data only)"), `TerrainScheduler::refreshReadouts`. **Absent:** `getTerrainPlayhead`, `getTerrainGeneration`, `copyTerrainHeightmap`, `getTerrainStatus` / `sourceMissing`, `submitTerrainImport`. Stage 3 adds message-thread editor helpers on the processor that map onto what exists: playhead + trail + ≋ cycle from the ring; heightmap sampled by the processor from the **active** surface (`terrain()` in `Terrains.h:87` for analytic at the pitch-tracked C4 F_eff, Clenshaw over the published `ChebyshevSet` for Bandlimited, `TerrainImage::view` for Imported…); status from the atomics (+ D3's top-note atomic); `sourceMissing` hard-false until 4.1; import = the existing API. Names are the plan's to fix; the template's are proposals.
4. **The ring is shared by every voice of an oscillator** (`StrataVoice::setCaptureTargets` points all voices at the two processor rings), so with a chord the samples interleave voices. Which voice feeds the playhead / ≋ view (e.g. only the most recently started voice writes, or the oscillator with `voiceIndex == 0`) is a research item; the mockup shows one trajectory.
5. **Mute law for D3:** `chebDMax` (`ChebyshevSet.h:116`): D_c = fs / (2·K·f) − 1, D_max = clamp(⌊D_c⌋, 1, 16) with the 2-diagonal raised-cosine taper; 17 A6 rows mute (K ≥ 6 on the five even terrains; K = 4 on Radial Rings at a 0.10 taper weight). Terrain parity decides whether D_max = 1 sounds, hence the scheduler-side computation.
6. **O-Prism is stable at the re-fork base:** the only commit after `4f12ef57` on `plugins/O-Prism` is the `v1.26.0` release tag commit; `index.html:1183` still lacks `min-width: 0`.
7. **UI gate tooling present in `scripts/`:** `check-ui-labels.js` (+ README), `check-i18n.js`, `boot-all-uis.js`, `measure-ui.js` (+ README), `serve-ui.js`, `ui-stub/`, `i18n-fr-lint.js` + `i18n-fr-glossary.js`, `i18n-zh-lint.js` + `i18n-zh-glossary.js` + `i18n-zh-backtranslate.js`, `i18n-canon.js`, `i18n-extract.js`. Memory traps to carry: `pattern_ui_labels_gate_blind_to_width_pinned_data_i18n`, `pattern_console_warn_gate_drops_the_only_runtime_signal`, `pattern_readout_node_is_never_localized_third_arm`, `pattern_declared_font_stack_is_not_the_resolved_face`, `pattern_quiesce_before_stimulus_in_async_ui_gates`, `pattern_rect_gate_cannot_see_paint_order`, `pattern_removing_a_tab_moves_the_rightmost_tab_under_the_popover`, `pattern_appearance_none_select_exposes_caption_width`.
8. **WebView memory traps that apply:** `critical_webview_completion_gated_on_isvisible` (pushes drop while hidden — page re-requests on show), `pattern_webview_native_fn_bridge_gap` (a native name the page calls but C++ never registers hangs the promise silently — every new native function name gate-checked), `pattern_webview_one_shot_state_push_stale_on_preset_load` (re-push after preset apply), `pattern_webview_knob_readout_scaled_value`, `critical_webview_drag_drop_macos`, `pattern_juce_webview_backend_stub_direction` (browser-stubbing for `serve-ui`), `pattern_render_harness_breaks_on_webview_editor`.
9. **Prototype on disk:** `research/wavetable-synthesis-3d-geometry-prototypes/webgl-3d/terrain-proto.html` with `terrain-webgl2.png` / `terrain-canvas2d.png` reference renders; `v2-ui.html` already ports "both renderers" for the mockup — Round B decides which of the two is the base for `terrain-view.js`.
10. **Requirement rows stay as written** except the three Windows notes (D2) — no acceptance re-wording in this discuss.
