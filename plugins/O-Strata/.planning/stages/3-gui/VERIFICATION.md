WebKit suspends `requestAnimationFrame` for an occluded view, so nothing rAF-driven paints; nudging the window so a strip is visible (`System Events … set position`, no activation) made the same page draw both pushed heightmaps within a second. The Chromium + WebKit probe (no page errors, minis painted at DPR 1 / 2) had already excluded a JS or module-import failure. Recorded in memory so the next scripted capture does not misread it as a rendering bug.
2. **PERF-03 has no WKWebView row (process, not product).** Taylor was active on the machine for the whole session (HID idle ≤ 13 ms at every check, Brave frontmost); the ⌥-click burst needs the Terrain tab and a click, which would have pulled focus. The measurement is a 30-second human step (row 1). Nothing in the instrumentation is untested — the ring, the wrap report and the native call all ran in the headless gate.

5. **No defect in the delivered code.** Every SUMMARY figure reproduced on re-measurement (gate-all 111.5 s both times; every other number identical).
