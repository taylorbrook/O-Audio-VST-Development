## Core Components

### Capture Buffer (Circular)
- **JUCE Class:** Custom ring buffer (`juce::AudioBuffer<float>` + write index) — pattern proven in `plugins/O-GrainScatter/Source/dsp/DelayBuffer.h`
- **Purpose:** Continuously records input **+ damped feedback return**. All reverse grains read from this buffer. Single shared buffer closes the feedback loop.
- **Parameters Affected:** none directly (sized from max delayTime + max grainSize)
- **Configuration:**
  - Stereo, length = `ceil(sampleRate * 3.5s)` — covers max read offset `Dmax + 2·Gmax = 2000ms + 2·500ms = 3000ms` plus block-size margin. Allocated in `prepareToPlay()` only.
  - Write: `capture[w] = input[n] + feedbackReturn[n]` per channel, `w = (w+1) % size`.
  - `clear()` is alloc-free (no `setSize` outside prepare) — matches O-GrainScatter WR fix.
  - Linear-interpolated fractional read (grain read positions are integer-stepped in v1.0 — see Grain Engine; interpolation kept for future pitch work, LOW cost).

### Reverse Grain Engine (scheduler + pool + windowed reverse read)
- **JUCE Class:** Custom (preallocated grain pool + per-block scheduler) — patterns proven in `plugins/O-simpleGrain/Source/dsp/` (WindowLuts, Grain) and `plugins/O-GrainScatter/Source/dsp/` (GrainScheduler, GrainPool)
- **Purpose:** Assembles the wet signal as overlapping Hann-windowed grains, each playing a region of the capture buffer **backwards** — the continuous reverse smear (FUNC-01), not chunked block reversal.
- **Parameters Affected:** `delayTime`/`syncMode`/`noteDivision` (grain anchor delay D), `grainSize` (grain length G), `density` (overlap → spawn interval + gain compensation), `width` (per-grain pan)
- **Configuration:**
  - **Reverse read law:** grain spawned when write head is at `W0`, with delay `D` samples and length `G` samples, outputs at local sample `n ∈ [0, G)` the capture sample at absolute position `(W0 − D) − n`. Relative to the advancing write head the read offset is `D + 2n` (grows 2 samples per output sample — the classic reverse-delay double-speed offset). Region `[W0−D−G, W0−D]` is always already written (offset ≥ D ≥ 0), and the offset only *increases*, so the read head can never collide with the write head. Max offset = `D + 2G` → buffer sizing above.
  - **Window:** Hann LUT, 2048 points, built at construction (never on audio thread), linear-interp read by phase `n/G` — direct reuse of O-simpleGrain `WindowLuts` (Hann table only).
  - **Overlap from density:** `overlap = 1 + (density/100) · (kMaxOverlap − 1)`, `kMaxOverlap = 8`. Spawn interval `I = G / overlap` samples. density 0% → back-to-back Hann grains (audible amplitude ripple = the intended "choppier" character); 100% → 8-deep continuous wash.
  - **Amplitude compensation:** per-grain gain `= 1 / sqrt(overlap)` (Hann power-sum law; final constant tuned in render harness so density sweeps are loudness-flat).
  - **Grain pool:** fixed 32 preallocated grain slots (max sustained overlap is 8; headroom covers delay-time transitions). Spawn requests hard-capped per block (O-GrainScatter WR-04 pattern). Oldest-grain steal on exhaustion. Zero allocation in `processBlock`.
  - **Per-grain latching:** D, G, pan, gain are snapshotted at spawn. Parameter changes therefore affect only *new* grains — delay-time, grain-size, and mode changes are click-free by construction (QUAL-01, DSP-01) with no smoothing needed on these parameters.

### Tempo Sync Engine
- **JUCE Class:** `juce::AudioPlayHead` → `getPosition()` → `PositionInfo::getBpm()` (verified present in local JUCE 8.0.14 `juce_AudioPlayHead.h`)
- **Purpose:** Derives effective delay D from host tempo in Sync mode; falls back to the free `delayTime` knob when the host provides no BPM (COMPAT-02).
- **Parameters Affected:** `syncMode`, `noteDivision`, `delayTime`
- **Configuration:**
  - Division → beats table: `1/16=0.25, 1/16D=0.375, 1/16T=1/6, 1/8=0.5, 1/8D=0.75, 1/8T=1/3, 1/4=1.0, 1/4D=1.5, 1/4T=2/3, 1/2=2.0, 1/2D=3.0, 1/2T=4/3, 1/1=4.0` (order matches `noteDivision` AudioParameterChoice).
  - `delayMs = beats · 60000 / bpm`, clamped to [50, 2000] ms (buffer sizing bound). Acceptance anchor: 120 BPM, 1/4 → 500 ms.
  - BPM read once per block on the audio thread; `getBpm()` returns `Optional<double>` — absence (or `playhead == nullptr`) selects the free-mode path for that block. `jmax(1.0, bpm)` hardens the divide (O-GrainScatter IN-06 pattern).
  - D is latched per grain, so tempo changes glide naturally grain-by-grain with no zipper.

### Feedback Damping Filters (in-loop)
- **JUCE Class:** `juce::dsp::IIR::Filter<float>` (2 per channel) with `juce::dsp::IIR::ArrayCoefficients<float>::makeHighPass / makeLowPass` — verified in local JUCE 8.0.14 `juce_IIRFilter.h`
- **Purpose:** Darken/thin regenerations each pass through the loop (FUNC-03): `lowCut` = 2nd-order Butterworth high-pass, `highCut` = 2nd-order Butterworth low-pass, applied to the wet feedback return before it is written back into the capture buffer.
- **Parameters Affected:** `lowCut`, `highCut`
- **Configuration:**
  - **RT-safe update (DSP-02, suite-mandated):** `ArrayCoefficients::makeXXX` returns a stack `std::array` — assign the values in place into the existing `Coefficients` object (`*filter.state = ...` element copy via `Coefficients` assignment). **Never** call `Coefficients::makeXXX` on the audio thread (heap-allocates) and **never** memcpy raw arrays over `getRawCoefficients()` (JUCE `Coefficients` stores 5 normalised values vs ArrayCoefficients' 6 raw — suite pattern `pattern_arraycoefficients_rt_safe_iir` + O-MultiBandCompressor v1.6.0 lesson).
  - Per-block coefficient update when smoothed target moved; the cached-value guard must **only** gate coefficient recomputation, never any enabled/bypass flag (suite pattern `pattern_conditional_coeff_update_leaks_enabled_flag`). v1.0 keeps both filters always-on (no bypass flag exists — ranges never reach "off").
  - Cutoffs smoothed with `juce::SmoothedValue` (~20 ms) before coefficient computation to kill zipper on knob sweeps.
  - Clamp cutoff to `[20 Hz, 0.49·fs]` before `tan()` prewarp territory (O-Bells v4.1.3 Nyquist lesson) — relevant at 44.1 kHz where highCut max 20 kHz is close to Nyquist.

### Feedback Loop + Stability Stage
- **JUCE Class:** Custom (gain + `std::tanh` soft-clip) in the feedback return path
- **Purpose:** Regeneration of the reverse tail; guaranteed loop-stable at feedback = 100% (DSP-03).
- **Parameters Affected:** `feedback`
- **Configuration:**
  - Tap: summed wet grain output (post grain gain, pre width/mix), per channel.
  - `fbReturn = tanh(feedbackGain · damping(wet))` where `feedbackGain = feedback/100` (0..1.0), smoothed (~20 ms).
  - Stability argument: Hann windowing + overlap compensation keeps loop gain ≤ 1 at unity feedback; damping filters remove band energy every pass; `tanh` bounds any constructive-interference peaks to ±1.0 in the loop. 60 s render at 100% feedback must stay below ceiling with no NaN/Inf (acceptance DSP-03).
  - Non-finite guard at the loop write point: if a non-finite sample is detected, reset both damping filters **and** zero the feedback return for that block, keeping last-known-good coefficients (suite pattern `pattern_biquad_nan_guard_sticky_silence` — guard must reset the source, not only the filters).
  - `feedback = 0%` → exactly one wet generation (acceptance FUNC-03).
  - **Accepted characteristic:** because regenerations pass through the same reverse engine, generation 2 is reverse-of-reverse (forward-ish), generation 3 reverse again — the classic alternating-direction reverse-delay feedback character (Strymon TimeLine REV behaves this way). Documented as intended; see Architecture Decisions for the always-reverse alternative.

### Stereo Width (per-grain placement)
- **JUCE Class:** Custom equal-power per-grain pan
- **Purpose:** Spreads grain placement across the stereo field (FUNC-04); wet collapses to center at 0%.
- **Parameters Affected:** `width`
- **Configuration:**
  - At spawn: `pan = 0.5 + (width/100) · 0.5 · spread`, `spread` drawn from `juce::Random` in [−1, 1] with alternating-sign bias so consecutive grains ping left/right rather than clumping.
  - Equal-power gains `gL = cos(pan·π/2)`, `gR = sin(pan·π/2)` latched per grain (click-free; no smoothing needed).
  - Grains read their source from the corresponding capture channel mixed to a mono grain source `0.5(L+R)` **only when width > 0 placement is active**; simpler v1.0 rule: grain reads stereo and pan gains cross-blend — final rule fixed in Stage 2 harness by ear/measurement, both are RT-equivalent cost.

### Dry/Wet Mix (equal-power)
- **JUCE Class:** Custom equal-power crossfade (chosen over `juce::dsp::DryWetMixer` — see Architecture Decisions)
- **Purpose:** Final blend; delay effect reports zero latency so no latency-compensated mixer is required.
- **Parameters Affected:** `mix`
- **Configuration:** `dryGain = cos(mixNorm·π/2)`, `wetGain = sin(mixNorm·π/2)`, `mixNorm` smoothed (~20 ms). Default 35% keeps the dry signal dominant per brief.

## Processing Chain

```
Input (stereo)
  │
  ├──────────────────────────────► Dry path (unprocessed) ─────────────┐
  │                                                                    │
  ▼                                                                    │
[+] ◄── feedback return (damped, soft-clipped) ──────────────┐         │
  │                                                          │         │
  ▼                                                          │         │
Capture Buffer (circular, 3.5 s, write head W)               │         │
  │                                                          │         │
  ▼                                                          │         │
Reverse Grain Engine ← delayTime/syncMode/noteDivision (D)   │         │
  │  (Hann-windowed grains, read offset D+2n,                │         │
  │   overlap from density, 1/sqrt(overlap) gain,            │         │
  │   per-grain latch)      ← grainSize (G), density         │         │
  │                                                          │         │
  ├── wet tap ──► [feedback gain ← feedback]                 │         │
  │                    │                                     │         │
  │                    ▼                                     │         │
  │              HP (lowCut) → LP (highCut)                  │         │
  │              (ArrayCoefficients, in-loop damping)        │         │
  │                    │                                     │         │
  │                    ▼                                     │         │
  │              tanh soft-clip ─────────────────────────────┘         │
  ▼                                                                    │
Per-grain Width placement ← width                                      │
  │                                                                    │
  ▼                                                                    ▼
Wet ──► equal-power Mix ← mix ◄──────────────────────────────── Dry ───┘
  │
  ▼
Output (stereo)
```

**Routing notes:**
- Feedback loop closes through the **capture buffer** (single shared buffer): feedback return is summed with input at the write head. Loop period ≈ effective delay D.
- Feedback tap is pre-width/pre-mix so `width` and `mix` never affect loop stability or regeneration character.
- No conditional routing: `syncMode` only selects the source of D (control-rate decision, per block, latched per grain).

## Algorithm Details

### Reverse Grain Read (the core algorithm)

**Algorithm:** overlap-add of Hann-windowed grains whose read heads move backwards through a circular capture buffer at −1 sample per output sample while the write head advances at +1 — a net read-offset growth of +2 samples per output sample.

**Implementation notes:**
- Spawn at write position `W0`: `readStartAbs = W0 − D`; at grain sample `n`: `readAbs = W0 − D − n`, `out[n] += hann(n/G) · grainGain · capture[readAbs mod size]`.
- Why this produces "reverse bloom": a transient recorded at capture time `T` appears inside every grain whose region spans `T`; within each grain it is emitted at output time `spawn + (W0 − D − T)`, so across the overlapping grain series the transient's echoes arrive with *increasing* window amplitude toward the reversed position — a swell, not a gated block (acceptance FUNC-01: envelope ramps up; verified in harness with an impulse + envelope-slope probe, plus a single-grain reversed-ramp probe for direction).
- Grain phase uses integer sample stepping (reverse speed is exactly 1.0; no pitch change) → the Lagrange/linear fractional read is not required for correctness in v1.0; keep integer reads for the hot path.
- All grain state (readAbs, n, G, gL, gR, gain) lives in the preallocated pool slot; advancing a grain is: LUT lerp + 2 multiplies + 2 adds per channel.

### Density → Overlap → Loudness

**Algorithm:** spawn-interval control with power-law gain compensation.
- `overlap = 1 + (density/100)·7`; `intervalSamples = max(1, G/overlap)`; countdown timer per block emits spawn offsets (O-GrainScatter free-mode scheduler shape, without probability).
- Hann window power sum over `k` overlapped grains ≈ `0.375·k` → RMS grows `∝ sqrt(k)`; compensation `1/sqrt(overlap)` holds wet loudness ~flat across the density sweep (acceptance DSP-01 density sweep, tuned ±1 dB in harness).
- When G changes, interval recomputes; in-flight grains finish with their latched G (no retroactive changes → no clicks).

### Damping Filter Coefficient Update (RT-safe)

**Algorithm:** per-block smoothed-target biquad update.
```cpp
// audio thread, per block, per channel pair:
const float lc = juce::jlimit(20.0f, 0.49f * fs, lowCutSmoothed.getNextValue());
if (lc != lastLowCut) {
    lastLowCut = lc;
    const auto a = juce::dsp::IIR::ArrayCoefficients<float>::makeHighPass(fs, lc); // stack array
    *hpState = a;   // in-place assignment into existing Coefficients — no allocation
}
```
- Identical pattern for `highCut` / `makeLowPass`.
- The `lc != lastLowCut` guard gates **only** the recompute (no enabled/bypass flag exists to leak).

### Loop Stability

**Algorithm:** bounded-energy feedback: `fb[n] = tanh(g_fb · LP(HP(wet[n])))`.
- Worst case `g_fb = 1.0`: damping removes energy outside [lowCut, highCut] every generation; in-band, tanh compresses peaks toward ±1 → bounded, wash-like sustain ("approach self-sustaining without runaway", per brief).
- tanh at low levels is ≈ identity (no tone change at normal feedback settings).
- Denormal safety: `juce::ScopedNoDenormals` in `processBlock`; long tails decay through the damping filters into denormal range — flushed by FTZ/DAZ.

### Equal-Power Mix & Width

- Mix: `out = cos(m·π/2)·dry + sin(m·π/2)·wet`, `m` = smoothed mix normalised.
- Width: per-grain equal-power pan (formulas above); at width 0 all grains at pan 0.5 → `gL = gR = 1/√2` each side, wet is centered dual-mono.

## Integration Points

### Feature Dependencies

- Capture Buffer → Grain Engine: grains only read regions already written; buffer must be prepared (sized/cleared) before scheduling starts.
- Grain Engine → Feedback Loop: the feedback tap is the summed wet grain output; loop cannot be tested before the grain engine renders.
- Feedback Loop → Capture Buffer: feedback return is summed into the write head — closing the loop couples all three; the write must happen *after* the grain reads for the current sample index conceptually, but because the minimum read offset is D ≥ 50 ms ≫ one block, block-level ordering (read grains for block → compute feedback → write block into buffer) is safe with zero intra-block hazards.
- Tempo Sync → Grain Engine: D source selection is per-block, consumed only at grain-spawn time.
- Width / Mix → independent post stages: no coupling into the loop (deliberate — see Parameter Interactions).

### Parameter Interactions

- `feedback` × `lowCut`/`highCut`: damping *is* the stability budget — narrower band → faster decay even at 100% feedback; the acceptance render (DSP-03) uses default damping. Wide-open damping (20 Hz / 20 kHz) at 100% relies on tanh alone → sustained wash at ceiling, by design.
- `density` × `feedback`: overlap compensation keeps per-generation loop gain independent of density (compensation applies before the feedback tap) — REQUIRED, otherwise high density would multiply loop gain and break DSP-03.
- `grainSize` vs `delayTime`: fully independent — the reverse read law reads *older* material when G > D (region `[W0−D−G, W0−D]`); no clamp coupling needed. Perceptually, G approaching/exceeding D turns discrete swells into continuous smear (a feature).
- `syncMode` change mid-playback: D jumps; latched-per-grain design makes this click-free (in-flight grains finish at old D, new grains spawn at new D — a natural crossfade).
- `width`/`mix` deliberately outside the loop: automating them can never destabilize feedback.

### Processing Order Requirements

Per block (order is REQUIRED):
1. Read playhead BPM, resolve effective delay D (Sync w/ fallback, or Free).
2. Advance smoothed values (feedback, mix, cutoffs); update filter coefficients if targets moved.
3. Run grain scheduler for the block (spawn offsets from density/G countdown, latch D/G/pan/gain at each spawn).
4. Render all active grains into the wet accumulation buffer (overlap-add).
5. Compute feedback return: wet → feedback gain → HP → LP → tanh → non-finite guard.
6. Write `input + feedbackReturn` into the capture buffer for the block.
7. Width is already baked per-grain (step 4); apply equal-power mix of dry input and wet buffer → output.

Why the order matters: filters must update before the feedback path uses them (2 before 5); grain rendering must precede the feedback write (4 before 6) so this block's regeneration is captured for future grains; dry must be taken from the untouched input buffer, so the wet path renders into a separate preallocated scratch buffer (never in-place over input before step 7).

### Thread Boundaries

- **Audio thread:** everything above — grain pool, scheduler, buffer writes, filter updates (ArrayCoefficients in-place), tanh, mix. Parameter reads via `getRawParameterValue()->load()` (atomic). Zero allocations, zero locks, zero logging (PERF-01).
- **Message thread:** APVTS writes from UI/host, preset load/save.
- **Background thread:** none needed (no file I/O, no long operations).
- **Communication:** APVTS atomics only. `prepareToPlay` (host thread) does all allocation (capture buffer, scratch wet buffer, pool vectors, Hann LUT already constructed).

## Implementation Risks

### Reverse Grain Engine

**Complexity:** MEDIUM  **Risk Level:** MEDIUM

**Risk factors:**
- The reverse read law (offset D+2n) is easy to get off-by-one/inverted — symptom is forward echoes or double-speed pitch artifacts.
- Overlap-add amplitude compensation mistuned → density sweep changes loudness or loop gain (breaks DSP-03 indirectly).
- Pool exhaustion during rapid delay-time automation could steal audible grains.

**Alternative approaches:**
1. Chunked block reversal (classic DD-7 style): LOW complexity, but explicitly rejected by the brief (hard rhythmic blocks, not smear).
2. Dual crossfaded reverse read heads (yaleD-style, no grain pool): LOW-MEDIUM complexity, continuous but with periodic crossfade signature; less "washy" than a grain cloud, no density control.

**Fallback architecture:** dual crossfaded reverse heads with Hann crossfades (alternative 2) keeps FUNC-01's "no hard blocks" acceptance while dropping `density` to a crossfade-length control. Fall back only if the grain engine cannot pass DSP-01 click criteria after tuning.

**Mitigation strategy:** in-suite reference code (O-simpleGrain grains/LUTs, O-GrainScatter scheduler/DelayBuffer) is proven; build the offline render harness FIRST (single-grain reversed-ramp probe for direction, impulse envelope-slope probe for bloom) before wiring feedback.

### Feedback Loop Stability

**Complexity:** MEDIUM  **Risk Level:** MEDIUM

**Risk factors:**
- Loop gain > 1 from mistuned overlap compensation or window sum → runaway (caught by tanh but audibly slammed at ceiling).
- NaN/Inf injection sticking in IIR state (suite has shipped this bug class twice).
- pluginval strictness-10 fuzz has caught latent feedback NaN in this suite before (`pattern_ci_pluginval10_catches_latent_nan`).

**Alternative approaches:**
1. Hard feedback-gain cap at 0.95 internal (simple, but 100% ceases to be "near self-sustaining").
2. RMS-tracking energy limiter in loop (smoother than tanh, more state/tuning).

**Fallback architecture:** if tanh coloration at high feedback is objectionable, swap to alternative 2 (RMS limiter targeting −3 dBFS loop energy); interface point is a single `processFeedbackSample` function.

**Mitigation strategy:** 60 s automated stability render at feedback 100% in the harness from Phase 2.2 onward; non-finite guard resets filters + zeroes the feedback source; run pluginval-10 locally 3× before publishing.

### Tempo Sync

**Complexity:** LOW  **Risk Level:** LOW

**Risk factors:** hosts with absent/zero BPM (harness has no playhead); FL Studio-style bogus transients on loop points.
**Alternative approaches:** none needed — per-block Optional check with free-time fallback is the suite-standard pattern.
**Fallback architecture:** n/a (fallback IS the feature — COMPAT-02).
**Mitigation strategy:** harness runs a no-playhead pass (acceptance COMPAT-02); latched-per-grain D absorbs BPM jitter.

### Damping Filters (RT-safe updates)

**Complexity:** LOW  **Risk Level:** LOW

**Risk factors:** the two suite-documented footguns (heap-allocating `Coefficients::makeXXX` on audio thread; memcpy raw 6-array over normalised 5-value storage) — both have explicit correct patterns above.
**Alternative approaches:** `juce::dsp::StateVariableTPTFilter` / `FirstOrderTPTFilter` (setCutoffFrequency is RT-safe by design) — viable, but REQUIREMENTS DSP-02 names ArrayCoefficients, and 2nd-order Butterworth is the wanted damping slope.
**Fallback architecture:** StateVariableTPTFilter pair (12 dB/oct) if IIR assignment proves fiddly — requires a REQUIREMENTS DSP-02 amendment note.
**Mitigation strategy:** code-review checklist item + allocation-guard run in harness.

### Overall Project Risk

**Overall complexity:** MEDIUM — one custom engine (well-precedented in-suite) + one feedback loop; everything else is LOW.
**Highest risk component:** Reverse Grain Engine (~50% of risk) — it feeds everything, including the loop-stability budget.
**Recommended approach:**
1. Build harness + capture buffer + grain engine + mix first (validates FUNC-01/DSP-01 in isolation, feedback at 0).
2. Add feedback + damping + stability (DSP-02/03, FUNC-03) with the 60 s stability render.
3. Add tempo sync + width + smoothing polish (FUNC-02/04, COMPAT-02, QUAL-01 sweeps) last — all LOW risk.

## Architecture Decisions

### Granular smear vs chunked reversal vs dual read heads

**Decision:** overlapping Hann-windowed reverse grains over a shared capture ring.
**Rationale:** the brief's core identity is the *smear* ("swells that bloom backwards… rather than snapping in"); a grain cloud gives the density control its meaning and matches the Strymon-grain-machine/ambient-pedal character targeted. In-suite grain infrastructure (O-simpleGrain, O-GrainScatter) de-risks it.
**Alternatives considered:**
1. Chunked block reversal — rejected: exactly the hard rhythmic character the brief defines itself against (kept as contrast reference only).
2. Dual crossfaded reverse heads — rejected as primary: no density dimension, periodic crossfade signature; retained as documented fallback.
**Tradeoffs accepted:** more state (pool) and a tuning pass for overlap compensation, in exchange for the defining sound and two expressive parameters (grainSize, density).

### Single shared capture buffer for input + feedback (alternating-direction regenerations)

**Decision:** feedback writes into the same capture buffer the grains read.
**Rationale:** simplest stable topology; loop period ≈ D emerges naturally; memory ~3.5 s stereo once. The audible consequence — generation 2 plays forward (reverse of reverse), generation 3 reversed again — is the classic hardware reverse-delay feedback behavior and reads as "evolving wash", which serves the ambient brief.
**Alternatives considered:** separate always-reverse feedback path (re-granulate a wet-only ring each generation) — rejected for v1.0: doubles buffer/engine state and the alternating character is desirable; revisit only if listening tests in Stage 2 find generation-2 forward echoes distracting (then: mode or hidden re-granulation).
**Tradeoffs accepted:** regeneration direction alternates (documented, intended).

### tanh soft-clip as the loop stability mechanism

**Decision:** `tanh` on the feedback return, unity max loop gain, damping as the decay budget.
**Rationale:** zero-state, RT-trivial, transparent below ~−6 dBFS loop level, and the brief explicitly requests "soft-clip or energy cap in loop". 
**Alternatives considered:** internal 0.95 cap (kills near-self-sustain), RMS energy limiter (more tuning; kept as fallback).
**Tradeoffs accepted:** slight saturation coloration only in the extreme wash regime — on-character for the use case.

### Custom equal-power mix instead of juce::dsp::DryWetMixer

**Decision:** manual `cos/sin` crossfade.
**Rationale:** wet path is inherently a delay (no latency to compensate); DryWetMixer's latency-compensation machinery buys nothing and adds a second internal delay buffer. Equal-power is one smoothed value + two gains.
**Alternatives considered:** `juce::dsp::DryWetMixer` with `MixingRule::sin3dB` — rejected as unnecessary weight; trivially swappable later.
**Tradeoffs accepted:** none material.

### 2nd-order Butterworth IIR (ArrayCoefficients) for damping

**Decision:** `juce::dsp::IIR::Filter` + `ArrayCoefficients::makeHighPass/makeLowPass`, per-block in-place updates.
**Rationale:** REQUIREMENTS DSP-02 mandates the ArrayCoefficients pattern; 12 dB/oct is the right damping steepness for "darken and thin naturally" (6 dB/oct too gentle for the lowCut range up to 2 kHz).
**Alternatives considered:** TPT filters (RT-safe setters, but 12 dB SVF band-splits aren't Butterworth and DSP-02 names the pattern); FirstOrderTPTFilter (too gentle).
**Tradeoffs accepted:** manual coefficient-update discipline (patterns documented above).

## Special Considerations

### Thread Safety
- All parameter reads: `apvts.getRawParameterValue(id)->load()` (atomic) once per block.
- Choice params (`syncMode`, `noteDivision`) read as float index, `static_cast<int>` per block.
- No shared mutable state outside the audio thread; no locks anywhere in the audio path.
- `prepareToPlay` may be called concurrently with editor existence — all allocation confined there; `reset()`/`clear()` paths are alloc-free.

### Performance
- Grain rendering: ≤ 8 concurrent grains × 2 ch × (LUT lerp + mul-add) ≈ negligible.
- Filters: 4 biquads total. Estimated total: **< 5% of one core at 48 kHz / 128 samples** — no oversampling, no FFT.
- Hot path is the grain loop; keep per-sample work branch-free (precompute per-grain constants at spawn).

### Denormal Protection
- `juce::ScopedNoDenormals` in `processBlock` (mandatory — long feedback decays sweep through denormal range).
- IIR filters + tanh naturally bounded; non-finite guard at loop write (see Feedback component).

### Sample Rate Handling
- `prepareToPlay`: size capture buffer (`3.5 s · fs`), size wet scratch buffer (max block), reset pool/filters/smoothers, recompute ms→samples constants. All ms-domain parameters converted per use (`ms · fs / 1000`).
- Sample-rate change mid-session: full re-prepare, buffers cleared (audible tail reset is acceptable and standard).
- highCut clamp `min(highCut, 0.49·fs)` protects 44.1 kHz.

### Latency
- **Zero reported latency** (`setLatencySamples(0)` implicit) — the delay IS the effect; dry passes through unbuffered. No host compensation.
