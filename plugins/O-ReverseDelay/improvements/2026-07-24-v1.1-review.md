## A. Defects found in shipped v1.0.0

These are correctness issues, not taste. All three are invisible to auval / pluginval-10 / the
current 41-probe harness, which is why they survived Stage 4.

### A1 — Tempo sync silently clamps at the tempos this plugin targets ⚠️ HIGH

`PluginProcessor.cpp:323`

```cpp
effectiveDelayMs = static_cast<float>(juce::jlimit(50.0, 2000.0, ms));
```

`delayTime`'s range maxes at 2000 ms, and sync-derived times are clamped into it. But
`kDivisionBeats[12] = 4.0` (1/1 = 4 beats):

| Division | Beats | Clamps below |
|----------|-------|--------------|
| 1/1      | 4.0   | **120 BPM**  |
| 1/2D     | 3.0   | **90 BPM**   |
| 1/2      | 2.0   | **60 BPM**   |
| 1/2T     | 1.333 | 40 BPM       |

The brief's stated use cases are ambient swells, pads, guitar/vocal washes — material that
typically sits at **70–100 BPM**. In that range, selecting `1/1` gives 2000 ms, not a bar, and
`1/2D` gives 2000 ms at 85 BPM instead of 2118 ms. The UI reports the division name, so the
plugin is showing the user a division it is not playing. Two divisions collapse onto the same
delay time with no indication.

**Fix options:**
1. Raise `delayTime` max to **4000 ms** (covers 1/1 down to 60 BPM) and grow the capture ring.
   Ring must cover `Dmax + 2·Gmax` → 4.0 + 1.0 = 5.0 s, so `capture.prepare(sampleRate, 5.5f)`.
   Cost: ring grows 3.5 s → 5.5 s stereo = **~2.1 MB at 48 kHz**. Negligible.
2. Cheaper, no ring change: keep 2000 ms but have the UI show the *effective* ms next to the
   division and visibly flag the clamp. Honest, but still doesn't let you get a bar of reverse
   at 80 BPM, which is exactly what an ambient reverse delay is for.

**Recommend option 1.** It is the difference between the sync mode working and not working for
the target material. Note that raising `delayTime` max also changes the `setSkewForCentre(316)`
curve's endpoint — the skew centre should stay at 316 ms so short times keep their resolution.
**Existing sessions/presets recall by normalised fraction, so changing the max WILL shift every
saved `delayTime`.** Requires a state-version migration or acceptance that v1.0 sessions move.

### A2 — Grains reading unwritten capture at large block sizes ⚠️ MEDIUM

`PluginProcessor.cpp:366–374` vs `:474`

`blockStartAbs = capture.getTotalWritten()` is sampled **before** the block's capture write, and
a grain spawning at block offset `i` latches `readAbs = blockStartAbs + i − D`. Grains then
render in step 4 — still before step 6 writes this block's input.

For every read index to be already-written we need `i < D`. `i` reaches `numSamples − 1`, and
`D_min = 0.05 · fs` (2205 samples @ 44.1 kHz).

So at **blockSize ≥ 2206 with `delayTime` near its 50 ms minimum**, grains spawned late in the
block read ring positions not yet written this pass — i.e. audio from one full ring lap ago
(3.5 s), or silence early on. Audible as a stale blip at the head of those grains.

Triggers: 2048/4096-sample buffers (common in offline bounce and in high-latency live setups),
short delay times. At 96 kHz, `D_min` = 4800, so the threshold moves to blockSize ≥ 4801.

**Fix:** move the capture write (step 6) before the grain render (step 4), or clamp
`D ≥ numSamples`. Moving the write is correct and free — the feedback return for the *current*
block is what step 6 needs, and that comes from step 5 which depends on step 4. So the real fix
is to write **input** into capture first, then render grains, then add the feedback return as a
second pass — or simply clamp `D = jmax(D, numSamples)`.

**Harness repro:** run any existing probe at `blockSize = 4096`, `delayTime = 50`. The harness
currently never varies block size, which is why this is unreported.

### A3 — Density below ~14 % is a full-depth tremolo, not a wash ⚠️ LOW (character)

`PluginProcessor.cpp:332–333`

```cpp
const float overlap = 1.0f + (densityPct * 0.01f) * 7.0f;   // 1 … 8
const int intervalSamples = max(1, (int)(G / overlap));
```

At `density = 0`, `overlap = 1` → `interval = G` → grains **abut with zero overlap**. A Hann
window runs 0 → 1 → 0, so the wet output amplitude-modulates to **full silence** at every grain
boundary: at `grainSize = 200 ms` that is a 5 Hz, 100 %-depth tremolo.

Hann reaches constant-overlap-add at hop = G/2, i.e. `overlap ≥ 2`, which needs
`density ≥ 14.3 %`. So the bottom ~14 % of the density knob is a gated pulse region.

Not a crash and arguably a usable effect — but it is not what "Density: grain overlap amount,
higher = denser" tells the user, and the knob's low end reads as broken rather than intentional.

**Fix options:** remap to `overlap = 2 + density·6` (density becomes purely "smooth → dense",
the pulse region disappears), or keep the range and rename/retip the low end as a deliberate
stutter zone. Remapping changes the sound of every existing preset at a given density value.

## B. The four areas you named

### B1 — Controlling the grain window

**Today:** `WindowLut.h` is hard-coded Hann, 2048 points, built once. The header explicitly notes
it was trimmed from O-simpleGrain's 5-shape `WindowLuts.h`, so the prior art exists in-suite.

Two separate controls are worth having, and the second is the more valuable one:

**(a) Window shape** — Hann / Tukey / Gaussian / Triangular / Expo-decay.
Straightforward: build N LUTs at construction, add a `grainShape` choice param, index the LUT
at spawn (latched per grain, same as everything else — no click risk).

⚠️ **Load-bearing detail:** `grainGain = 1/sqrt(overlap)` assumes Hann's power duty cycle, and
the CHANGELOG records the feedback loop's −4.3 dB/generation loss as specifically the *Hann²
duty*. A Tukey window has a much higher duty (≈0.75 vs Hann's 0.375) → swapping shapes at fixed
density would jump wet level by several dB **and** change the feedback decay rate. Each shape
needs its own power-normalisation constant folded into `grainGain`, or shape changes will read
as volume/feedback changes.

**(b) Window tilt / asymmetry — the highest-value single change in this document.**

This is a *reverse* delay. Every grain plays its source backwards under a **symmetric** Hann, so
each grain swells in and out identically — the effect is a smear, but not a *bloom*. An
asymmetric window whose peak sits late in the grain (slow attack, fast release) applied to
reversed material produces the classic backwards-swell-into-a-transient shape that reverse delay
is bought for. Sliding the peak the other way gives a plucked/decaying reverse grain.

Implementation is cheap: one `grainTilt` param (0 = peak early, 0.5 = symmetric Hann, 1 = peak
late), a warped phase lookup `read(pow(phase, k))` or a small family of pre-tilted LUTs. Latched
per grain. Same power-normalisation caveat as (a).

**Effort:** shape (a) small; tilt (b) small. Both need harness probes for level-matching.

### B2 — Number of grains

**Today:** never directly controllable. `density` → `overlap ∈ [1,8]` → `interval = G/overlap`.
Actual concurrent grain count is `≈ overlap`, so it is fully coupled to grain size. `GrainPool`
holds 32 slots; `kMaxSpawnsPerBlock` is 32.

Observations:

- **Max overlap 8 against a 32-slot pool = 4× unused headroom.** The pool was sized for
  delay-time transitions, but there is room to extend max overlap to 16 and still have 2×
  headroom. Denser = smoother, more reverb-like wash — directly serves the brief's
  "near-self-oscillating wash beds" use case. One constant change plus a re-tuned `grainGain`.
- **Grain steal is a hard cut** (`ReverseGrain.h:63–82`). `obtain()` overwrites the oldest slot's
  state, so a stolen grain's Hann envelope jumps from mid-window to zero instantly → click. With
  32 slots and max overlap 8 this is unreachable in steady state, but *is* reachable on a fast
  `grainSize`/`delayTime` sweep while 500 ms grains are in flight. If max overlap is raised, this
  becomes much more likely. Fix: refuse the spawn when no slot is free (drop one grain, inaudible)
  rather than stealing, or fade the stolen grain over ~64 samples.
- **The spawn cap is silent.** `GrainScheduler.h:66` drops requests past 32/block with no
  indication. Unreachable today (`G_min` = 2205 samples, `overlap_max` = 8 → `interval` ≥ 275),
  but it becomes reachable the moment `grainSize`'s minimum drops below ~50 ms or max overlap
  rises. If either changes, this needs a harness probe.
- **Worth exposing:** a readout of live grain count / effective overlap. `grainPool.countActive()`
  already exists and is currently called by nothing. Cheap, and it makes density legible.

### B3 — Randomisation of timing

**Today: there is none.** `GrainScheduler` is a strictly periodic countdown (`GrainScheduler.h:60–69`).
The only stochastic element in the entire engine is the pan spread (`kPanBias` + xorshift). That
is the biggest gap between this and a granular engine — periodic spawning at a fixed interval
produces a comb/metallic quality on sustained material, and it is why the wash currently reads
as "many delays" rather than "cloud."

Four independent randomisations, in descending musical value. The RT-safe xorshift
(`PluginProcessor.h:103–111`) is already in place for all of them.

1. **Spawn-time jitter** — `interval · (1 ± jitter·r)`. Breaks the comb. ~5 lines in the
   scheduler. Highest value per line of code in this document.
2. **Per-grain delay scatter** — randomise each grain's latched `D` by ±scatter ms. Thickens the
   smear dramatically without moving the rhythmic anchor, because the *average* D is unchanged.
   ⚠️ Constrained by the ring: capture is sized `Dmax + 2·Gmax` = 3.0 s in a 3.5 s buffer, so
   only **500 ms of headroom** exists for positive scatter today. Any meaningful scatter range
   needs the ring grown — which A1 already requires, so these two should land together.
3. **Per-grain size randomisation** — ±% on latched `G`. Removes the residual periodicity that
   jitter alone leaves, since all grains currently share one envelope length.
4. **Per-grain gain randomisation** — subtle; adds shimmer/depth. Interacts with the loop, so
   randomised gain must be applied *after* the feedback tap or it modulates the decay rate.

⚠️ **Determinism:** `rngState` is reset to a fixed seed in `prepareToPlay` (`:202`) specifically
so the harness is reproducible. Every added randomisation inherits that, which is good for
testing — but it also means two instances on two tracks get **identical** random sequences and
will correlate. Consider seeding from an instance hash in release builds while keeping the fixed
seed under the harness define.

### B4 — Extending parameters

Ordered by (musical payoff ÷ effort):

| # | Parameter | Payoff | Effort | Notes |
|---|-----------|--------|--------|-------|
| 1 | **Freeze / Hold** | Very high | Very low | Stop writing input to the capture ring; grains keep reading. Infinite frozen reverse wash. One bool in step 6. Prior art: O-Freeze. |
| 2 | **Forward/Reverse blend** | High | Low | Per-grain direction flag; step `readAbs` **+1** instead of −1. The read law is the *only* change. Morphs from reverse delay → forward granular delay, or mixes both for a bidirectional cloud. |
| 3 | **Regen makeup** | High | Very low | The D11 constant you declined at v1.0 — but as a *user* control rather than a hidden constant, defaulting to the shipped 0 dB so v1.0 sound is untouched. The topology loses ≈7.3 dB/generation, so "Near-Infinite" cannot actually self-sustain today. This makes true infinite wash reachable without changing anyone's default. (See `pattern_activating_dead_param_default_timbre` — default it to the no-op value.) |
| 4 | **Ducking** | High | Low | Wet attenuated by the dry input envelope; wash blooms in the gaps. Near-universal in ambient delays; the brief's "vocal ambience behind a lead" use case wants this specifically. |
| 5 | **Stereo source mode** | Medium-high | Low | `CaptureBuffer::readAbs(ch, …)` **already exists and is called by nothing** — grains always read `monoSum`, so source stereo is discarded and `width` only pans mono copies. A mode that reads L or R per grain preserves the source image. |
| 6 | **Delay-time modulation** | Medium | Low | Slow LFO/drift on D → pitch wobble on the tail, tape-ish. Applied at spawn (latched), so click-free by construction. |
| 7 | **Diffusion in the loop** | Medium | Medium | 2–4 allpasses between the damping filters and `tanh`. Pushes the tail toward reverb; smooths the discrete-repeat quality at low density. |
| 8 | **Loop drive** | Medium | Very low | The `tanh` is already there as a limiter — a pre-gain exposes it as saturation character rather than just a safety net. |
| 9 | **Grain pitch / shimmer** | Very high | **High** | The expensive one. `ARCHITECTURE` deliberately dropped Lagrange interpolation and per-grain AA filtering *because* reverse speed is exactly 1.0 with integer stepping (`CaptureBuffer.h:16–17`, `ReverseGrain.h:7–9`). Pitch means reinstating fractional `readPos` (double), interpolated reads, and AA filtering on the grain — i.e. rebuilding what was intentionally removed. Octave-up shimmer grains in a reverse wash are a genuinely marquee feature, but this is a Stage-2-sized change, not a patch. |
| 10 | Separate wet level | Low | Very low | `mix` is equal-power only; no independent wet trim. |

## C. Other findings

- **`processBlock` bails to total silence** on `numSamples > wetScratch.getNumSamples()`
  (`:272`) — a host that raises block size without re-calling `prepareToPlay` gets *nothing*,
  not even dry. Passing dry through is the safer failure mode.
- **No `AudioProcessor::reset()` override.** Hosts calling reset leave the capture ring, grain
  pool and filter states populated, so a stale tail survives a host-level reset.
- **Dead code:** `GrainScheduler::sampleRate` (`GrainScheduler.h:75`) is stored in `prepare()`
  and never read. `CaptureBuffer::readAbs()` is never called (until B4 #5 lands).
- **`width` has a hole in the middle** — `kPanBias = 0.5` means at width 100 % pan lands in
  [0, 0.25] ∪ [0.75, 1]; no grain is ever centred. Deliberate per D5, noted only so it isn't
  rediscovered as a bug.
- **Grain summing is partially coherent.** `1/sqrt(overlap)` compensation assumes incoherent
  summing, but overlapping grains read the *same* reversed material at nearby offsets, so the
  real level rise sits between √N and N. Density therefore isn't perfectly level-neutral. This
  is character, not a defect — but it should be measured before max overlap is raised (B2).
- **Factory presets are frozen behind a version sentinel** (`:101–104`): edits to the preset
  table are a **silent no-op** at a static 1.0.0 until `~/Library/O-ReverseDelay/Presets/Factory`
  is deleted. Any release that touches preset values must bump the version, or the change ships
  invisible.

## D. UI cost — read this before choosing scope

The editor is a **fixed 940 × 484** with four pinned-width panels summing to exactly 940
(`styles.css:248–252` — TIME | GRAIN | FEEDBACK | OUTPUT, panel height 215 px). There is no
flex slack; the Stage-4 preset bar was only affordable because the 44 px band and the 44 px
height increase cancelled, leaving panels and footer unmoved.

**Every new parameter forces a layout decision.** Adding ~6 controls means one of:
- widen the window and re-pin all four panel widths,
- add a second 215 px row (→ 940 × 743),
- or add a fifth panel / a "MORE" page toggle.

Also load-bearing: the tooltip edge-clamp gate is **viewport-sensitive** — the frontend check
must be re-run at the real shipping width or the clamp never fires and the test proves nothing
(`pattern_tooltip_clamp_gate_viewport_sensitive`). Any window resize invalidates the current
C5 tooltip verification and it must be re-measured at the new width.

## E. Recommended packaging

**v1.0.1 — patch, DSP-correctness only, no new params, no UI change**
A1 (sync clamp + ring grow), A2 (unwritten-capture read), plus the `reset()` override and dead
code. Note A1 shifts saved `delayTime` values — either migrate or accept and document.

**v1.1.0 — minor, "granular character," moderate UI change**
B3 #1 spawn jitter · B3 #2 delay scatter · B3 #3 size randomisation · B1(b) window tilt ·
B1(a) window shape · A3 density remap. This is the package that closes the gap between "many
reverse delays" and "granular cloud," and it is mostly small, well-isolated DSP. Needs the grown
ring from A1, so v1.0.1 should land first. ~4 new controls.

**v1.2.0 — minor, "performance & space"**
B4 #1 Freeze · #2 Forward/Reverse blend · #3 Regen makeup · #4 Ducking · #5 stereo source.
High payoff, low individual effort, but ~5 more controls — this is where the second UI row or a
MORE page becomes unavoidable.

**v2.0.0 — major**
B4 #9 grain pitch/shimmer. Reinstates fractional reads + AA filtering that Stage 2 deliberately
removed. Treat as a new Stage-2 cycle with its own harness probes, not an improve pass.

## Verification notes for whoever implements this

- The offline render harness (41 probes) is the correctness gate. It currently **never varies
  block size** — add a large-block probe or A2 stays invisible.
- Any change to `grainGain`, window shape, or overlap range alters the feedback loop's
  per-generation loss. Re-measure the decay rate at `feedback = 100` (the "Near-Infinite"
  preset probe N already renders 30 s for exactly this) before and after.
- Re-run `ui_frontend_check.js` **at the shipping viewport width**, not the default browser size.
- Preset table edits require a version bump or they are a silent no-op (see C).
