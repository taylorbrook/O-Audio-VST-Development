## Core Components

### 1. LF Glottal Pulse Source (LFGlottalSource)

- **JUCE Class:** Custom implementation (no JUCE glottal pulse class)
- **Purpose:** Generate the voice excitation signal using the Liljencrants-Fant model. The Rd parameter morphs the waveform from pressed/buzzy (Rd=0.3) through modal (Rd=1.0) to breathy (Rd=2.7).
- **Parameters Affected:** `glottalRd`, `breathiness`
- **Module Dependency:** None (pure math, uses `juce::jlimit` from `juce_core`)
- **Configuration:**
  - Rd range: 0.3-2.7 (voice quality control)
  - Rd -> R-parameter mapping via Fant 1995 regression: Ra, Rk, Rg, OQ
  - Newton-Raphson solvers for alpha and epsilon (run once per F0 cycle, not per sample)
  - Phase accumulator: float, wraps at 1.0
  - v1 approach: Direct LF time-domain computation with PolyBLEP at Te discontinuity
  - v1.1+ upgrade path: Pre-computed mipmapped wavetable (128 Rd x 2048 samples)
- **Anti-aliasing (v1):**
  - PolyBLEP correction applied at the glottal closure instant (Te) where the waveform has a discontinuity
  - PolyBLAMP correction at the return-phase slope change
  - Sufficient for musical use; mipmapped wavetable deferred to polish phase

### 2. Aspiration Noise Mixer (AspirationNoise)

- **JUCE Class:** `juce::Random` for noise generation (from `juce_core`)
- **Purpose:** Mix white noise with glottal pulse to add breathiness/aspiration
- **Parameters Affected:** `breathiness` (also MPE pressure target)
- **Module Dependency:** `juce_core`
- **Configuration:**
  - White noise source: `juce::Random::nextFloat() * 2.0f - 1.0f`
  - Gentle lowpass shaping at ~4kHz (single-pole IIR) to simulate glottal noise spectrum
  - Mix: `output = (1.0 - breathiness) * glottal + breathiness * filteredNoise`
  - Smoothed via `juce::SmoothedValue` (~20ms ramp)

### 3. Formant Filter Bank (FormantFilterBank)

- **JUCE Class:** Custom biquad struct using `juce::dsp::IIR::ArrayCoefficients<float>::makeBandPass()` for coefficient computation
- **Purpose:** 5 parallel bandpass filters that impose vowel character on the excitation signal
- **Parameters Affected:** `vowelX`, `vowelY`, `vowelFocus`, `formantShift`, `formantSpread`
- **Module Dependency:** `juce_dsp` (for `IIR::ArrayCoefficients` coefficient helper only)
- **Configuration:**
  - 5 formant bands (F1-F5) with per-band: center frequency, bandwidth, gain
  - Custom `FormantBiquad` struct for cache locality (no JUCE ProcessorState overhead per voice)
  - Topology: Parallel (all 5 filters process the same input; outputs summed with per-band gain)
  - Coefficient updates: Block-rate every 32 samples (avoids per-sample trig)
  - Formant shift: Multiply all center frequencies by `pow(2.0, formantShift / 12.0)` (semitone shift)
  - Formant spread: Scale spacing from center-of-mass of formant frequencies by `formantSpread` multiplier
  - Coefficient clamping: Frequencies clamped to [20, sampleRate/2 - 100] to prevent instability

### 4. Vowel Interpolation Engine (VowelMorpher)

- **JUCE Class:** Custom implementation (no JUCE interpolation class)
- **Purpose:** Interpolate between 5 cardinal vowels (A, E, I, O, U) based on XY pad position using Shepard (modified IDW) interpolation
- **Parameters Affected:** `vowelX`, `vowelY`, `vowelFocus`
- **Module Dependency:** None (pure math)
- **Configuration:**
  - 5 vowel anchor points at acoustically-derived XY positions:
    - I: (0.00, 1.00), E: (0.31, 0.43), A: (0.83, 0.00), O: (1.00, 0.35), U: (0.98, 0.93)
  - Shepard interpolation: `w_i = 1/d_i^p` where `p = vowelFocus` (1.0-6.0)
  - Formant frequencies interpolated in log domain: `exp(sum(w_i * log(f_i)))`
  - Bandwidths and gains interpolated linearly
  - Two-layer smoothing:
    1. XY position: Exponential filter (~30ms time constant)
    2. Formant parameters: `juce::SmoothedValue` per formant frequency (~20ms ramp)

### 5. Consonant Noise Branch (ConsonantEngine)

- **JUCE Class:** Custom implementation with `juce::Random` for noise source
- **Purpose:** KLATT-derived parallel noise branch for fricatives, plosives, and sibilants
- **Parameters Affected:** `consonantLevel`, `consonantTone`, `sibilance`, `autoConsonant`
- **Module Dependency:** `juce_core`
- **Configuration:**
  - Noise source: White noise from `juce::Random`
  - Tone control: Variable-cutoff bandpass using custom biquad
    - `consonantTone` 0.0 = LP at ~2kHz (dark /f/), 1.0 = HP at ~6kHz (bright /s/)
    - Implemented as crossfade between LP and HP filtered noise
  - Sibilance: Peaked resonance at 4-8kHz (bandpass, Q controlled by `sibilance` parameter)
  - Auto-consonant plosive burst generator:
    - Triggered on `noteStarted()` if `autoConsonant` is enabled
    - 10-25ms noise burst with falling amplitude envelope
    - Burst spectrum shaped by `consonantTone`
    - Crossfades into vowel ADSR attack
  - Output mixed with formant output: `final = formantOut + consonantLevel * consonantOut`

### 6. Vibrato System (VibratoLFO)

- **JUCE Class:** Custom sine LFO (no JUCE LFO class suitable for per-voice use)
- **Purpose:** Apply periodic pitch modulation to F0 for natural vocal vibrato
- **Parameters Affected:** `vibratoRate`, `vibratoDepth`, `vibratoDelay`
- **Module Dependency:** None (pure math)
- **Configuration:**
  - Sine LFO with per-voice phase accumulator
  - Frequency: `vibratoRate` Hz (0.5-12.0)
  - Depth: `vibratoDepth` cents (0-100), applied as: `f0 * pow(2.0, depth_cents / 1200.0 * sin(phase))`
  - Onset delay: Linear ramp from 0 to full depth over `vibratoDelay` ms after note-on
  - Optional micro-jitter: +/-0.5% random F0 perturbation per cycle for naturalness

### 7. ADSR Envelope (VoiceEnvelope)

- **JUCE Class:** `juce::ADSR` (from `juce_audio_basics`)
- **Purpose:** Shape voice amplitude over time
- **Parameters Affected:** `attack`, `decay`, `sustain`, `release`
- **Module Dependency:** `juce_audio_basics`
- **Configuration:**
  - `juce::ADSR::Parameters{ attack, decay, sustain, release }` set from APVTS values
  - Applied per-sample: `output *= adsr.getNextSample()`
  - `noteOn()` triggers attack; `noteOff()` triggers release
  - Voice calls `clearCurrentNote()` when envelope reaches zero in release

### 8. Pitch Glide System (PitchGlide)

- **JUCE Class:** Custom implementation (exponential smoother)
- **Purpose:** Portamento between notes
- **Parameters Affected:** `pitchGlide`
- **Module Dependency:** None
- **Configuration:**
  - Exponential one-pole smoother on target frequency
  - Time constant from `pitchGlide` parameter (0-1000ms)
  - When `pitchGlide == 0`, frequency snaps immediately (no smoothing)
  - Glide is monophonic-style: last-note priority, applied to existing voice if legato

### 9. Stereo Spread (StereoSpread)

- **JUCE Class:** Custom implementation (simple per-voice panning)
- **Purpose:** Distribute voices across stereo field based on pitch
- **Parameters Affected:** `stereoWidth`
- **Module Dependency:** None
- **Configuration:**
  - Per-voice pan position: `pan = (noteNumber - 60) / 60.0 * stereoWidth`
  - Clamped to [-1, +1]
  - Applied as: `left *= cos(pan * pi/4)`, `right *= sin(pan * pi/4)` (equal-power pan law)
  - Low notes panned left, high notes panned right
  - `stereoWidth = 0` gives mono center; `stereoWidth = 1` gives full spread

### 10. Output Stage (OutputGain)

- **JUCE Class:** `juce::dsp::Gain<float>` (from `juce_dsp`)
- **Purpose:** Master output level control
- **Parameters Affected:** `outputGain`
- **Module Dependency:** `juce_dsp`
- **Configuration:**
  - `juce::dsp::Gain<float>` with `setGainDecibels(outputGain)`
  - Smoothing built into the JUCE Gain class
  - Applied post voice-sum, pre-output

## Processing Chain

```
MIDI/MPE Input
  |
  v
MPESynthesiser (voice allocation, 16 voices, legacy mode fallback)
  |
  v  (per voice)
+------------------------------------------------------------------+
| F0 from MPENote::getFrequencyInHertz()                           |
|   |                                                               |
|   +-> Pitch Glide (portamento) -> Vibrato LFO -> Final F0        |
|   |                                                               |
|   v                                                               |
| LF Glottal Pulse (Rd from glottalRd, PolyBLEP anti-aliased)     |
|   |                                                               |
|   +-> Aspiration Noise (breathiness mix, MPE pressure modulates) |
|   |                                                               |
|   v  (glottal + aspiration mixed)                                |
| 5 Formant BPFs [PARALLEL]                                        |
|   (coefficients from Vowel Morpher: XY + shift + spread)         |
|   F1 -> gain1 -> +                                               |
|   F2 -> gain2 -> +                                               |
|   F3 -> gain3 -> +   = formantOut                                |
|   F4 -> gain4 -> +                                               |
|   F5 -> gain5 -> +                                               |
|   |                                                               |
|   +-> Consonant Noise Branch [PARALLEL]                          |
|   |   Noise -> Tone filter -> Sibilance peak -> consonantOut     |
|   |   + Plosive burst (if autoConsonant, on note-on)             |
|   |                                                               |
|   v                                                               |
| Mix: formantOut + consonantLevel * consonantOut                  |
|   |                                                               |
|   v                                                               |
| ADSR Envelope (amplitude shaping)                                |
|   |                                                               |
|   v                                                               |
| Voice output (mono)                                              |
+------------------------------------------------------------------+
  |
  v  (sum all active voices)
Stereo Spread (per-voice pan by pitch, stereoWidth control)
  |
  v
Output Gain (dB, smoothed)
  |
  v
Stereo Output Buffer
```

**Routing notes:**
- Formant filters and consonant noise are parallel branches, summed before ADSR
- Each voice outputs mono; stereo spread applied during voice summation
- No feedback loops in signal path
- No sidechain inputs
- All parameter reads via atomic `getRawParameterValue()->load()` from APVTS

**Input handling:** MPE-aware via `juce::MPESynthesiser` with `enableLegacyMode()` fallback for standard MIDI

## Algorithm Details

### LF Glottal Pulse Model

**Algorithm:** Liljencrants-Fant (1985) time-domain model with Fant 1995 Rd regression

**Implementation notes:**
- Time-domain piecewise function: open phase (sine * exponential) + return phase (exponential decay)
- Rd parameter mapped to R-params (Ra, Rk, Rg) via Fant 1995 regression:
  - `Ra = max(0.001, (-1 + 4.8*Rd) / 100)`
  - `Rk = (22.4 + 11.8*Rd) / 100`
  - OQ from Rd: piecewise regression, clamped [0.3, 0.98]
  - `Rg = (1 + Rk) / (2 * OQ)`
- Timing: `Tp = 1/(2*Rg)`, `Te = Tp*(1+Rk)`, `Ta = Ra`
- Alpha solved via Newton-Raphson (zero-integral constraint), max 30 iterations
- Epsilon solved via Newton-Raphson (return phase constraint), max 20 iterations
- Solvers run once per glottal cycle (when phase wraps), not per sample
- PolyBLEP correction: 2-sample polynomial at Te discontinuity
- Phase accumulator: `phase += f0 / sampleRate` per sample, wraps at 1.0

**Key formulas from research:**
```
U'(t) = E0 * exp(alpha*t) * sin(omega_g*t)    for 0 <= t <= Te
U'(t) = (-Ee/(eps*Ta)) * [exp(-eps*(t-Te)) - exp(-eps*(Tc-Te))]   for Te < t <= Tc
```

### Vowel Interpolation (Shepard)

**Algorithm:** Modified Inverse Distance Weighting with tunable power parameter

**Implementation notes:**
- 5 anchor points with acoustically-derived XY positions
- Weight: `w_i = 1 / dist(cursor, anchor_i)^p` where `p = vowelFocus`
- Epsilon guard: if `dist < 1e-6`, snap to nearest vowel (avoid division by zero)
- Frequencies interpolated in log domain: `f_out = exp(sum(w_i * ln(f_i)) / sum(w_i))`
- Bandwidths and gains interpolated linearly
- Block-rate update (every 32 samples): compute interpolated formant parameters, update biquad coefficients

### Formant Biquad Filters

**Algorithm:** Direct Form II Transposed biquad, parallel topology

**Implementation notes:**
- Coefficients from `juce::dsp::IIR::ArrayCoefficients<float>::makeBandPass(sampleRate, freq, Q)` where `Q = freq / bandwidth`
- Custom struct stores b0, b1, b2, a1, a2, z1, z2, gain (32 bytes per filter, cache-friendly)
- 5 filters per voice, all process same input, outputs weighted by gain and summed
- Frequency clamping: `freq = clamp(freq, 20.0f, sampleRate * 0.5f - 100.0f)` to prevent instability
- Formant shift applied as: `freq *= pow(2.0f, formantShift / 12.0f)`
- Formant spread applied as: scale each frequency's distance from center-of-mass

### Consonant Noise System

**Algorithm:** KLATT-derived parallel noise branch with musical parameter mapping

**Implementation notes:**
- White noise -> variable bandpass (tone control) -> parallel sum with sibilance peak
- Tone control maps to crossfade between LP filtered noise (cutoff ~2kHz) and HP filtered noise (cutoff ~6kHz)
- Sibilance adds peaked BPF at 4-8kHz region, Q scales with `sibilance` parameter
- Plosive burst: 10-25ms noise burst triggered on `noteStarted()` if `autoConsonant` enabled
  - Burst amplitude envelope: exponential decay from velocity-scaled peak
  - Duration varies with velocity (higher velocity = shorter, punchier burst)
  - Crossfades with main ADSR attack

### ADSR Envelope

**Algorithm:** Standard ADSR via `juce::ADSR`

**Implementation notes:**
- Parameters updated per-block from APVTS
- `juce::ADSR::Parameters` struct set with: attack(s), decay(s), sustain(0-1), release(s)
- Attack/decay/release ranges use exponential skew for fast-end resolution
- Voice lifecycle: `noteStarted()` -> `adsr.noteOn()`, `noteStopped(allowTailOff)` -> `adsr.noteOff()` if tailing, else `clearCurrentNote()`

## Integration Points

### Feature Dependencies

- **VowelMorpher -> FormantFilterBank:** Morpher computes interpolated F/BW/Gain arrays; FilterBank uses these as coefficients
- **LFGlottalSource -> FormantFilterBank:** Glottal output is the input signal to all 5 formant BPFs
- **AspirationNoise -> FormantFilterBank:** Noise mixed with glottal before filtering
- **VibratoLFO -> LFGlottalSource:** Vibrato modulates F0 which drives glottal phase increment
- **PitchGlide -> VibratoLFO:** Glide smooths target frequency before vibrato applies
- **ConsonantEngine -> Voice Mix:** Consonant output added to formant output before ADSR
- **ADSR -> Voice Output:** Envelope shapes the mixed (formant + consonant) signal
- **MPE pressure -> AspirationNoise:** Per-note pressure modulates breathiness in real-time
- **MPE timbre -> VowelMorpher:** Per-note slide adds offset to vowelY for per-voice formant control
- **Velocity -> ConsonantEngine:** Note velocity scales plosive burst strength
- **StereoSpread depends on all voices rendering:** Applied during voice summation, not per-voice

### Parameter Interactions

- **vowelX/Y + formantShift + formantSpread:** All three affect formant filter coefficients. Morpher computes base frequencies from XY, then shift and spread transform them before coefficient computation.
- **breathiness + MPE pressure:** MPE pressure additively modulates breathiness. Total breathiness = `clamp(paramValue + pressureOffset, 0, 1)`.
- **vowelY + MPE timbre (slide):** MPE slide additively modulates vowelY. Total Y = `clamp(paramValue + slideOffset, 0, 1)`.
- **autoConsonant + velocity:** When autoConsonant is on, velocity controls burst intensity. High velocity = louder, shorter burst. Low velocity = softer, longer burst.
- **vibratoDelay + attack:** Both operate on time-since-note-on. Vibrato delay counter starts at noteStarted(), independent of ADSR.
- **consonantLevel = 0:** Entire consonant branch can be skipped (early-out optimization).
- **breathiness at extreme (1.0):** Glottal pulse fully replaced by noise; formants still apply, creating pure whispered vowels.

### Processing Order Requirements

**Per-voice processing (REQUIRED sequential order):**

1. **Read F0 from MPENote:** `getFrequencyInHertz()` combines note + pitchbend + master bend
2. **Apply pitch glide:** Smooth frequency transition if portamento enabled
3. **Apply vibrato:** Modulate F0 with LFO (only if delay period elapsed)
4. **Generate glottal pulse:** LF model at final F0 with current Rd
5. **Generate aspiration noise:** White noise, LP filtered, mixed with glottal
6. **Compute vowel interpolation:** Shepard weights from XY + focus -> formant params (block-rate)
7. **Apply formant shift + spread:** Transform formant frequencies (block-rate)
8. **Update filter coefficients:** Set biquad coefficients from transformed formant params (block-rate)
9. **Process formant filters:** 5 parallel BPFs on (glottal + aspiration), sum weighted outputs
10. **Process consonant branch:** Noise -> tone filter -> sibilance peak -> scale by level
11. **Mix formant + consonant:** Sum the two branches
12. **Apply ADSR envelope:** Multiply by envelope value
13. **Output voice sample:** Add to voice output buffer

**Post-voice processing (REQUIRED sequential order):**

1. **Sum all voices with stereo spread:** Per-voice pan position based on pitch
2. **Apply output gain:** `juce::dsp::Gain` on stereo buffer

### Thread Boundaries

**Audio thread (processBlock):**
- All DSP processing (glottal, filters, envelope, mixing)
- Parameter reads via atomic `getRawParameterValue()->load()` (lock-free)
- MIDI message dispatch to voices via `MPESynthesiser::renderNextBlock()`
- SmoothedValue advances
- No allocations, no locks, no file I/O

**Message thread (UI):**
- Parameter updates via APVTS (atomic writes)
- XY pad drag -> vowelX/vowelY parameter changes
- Preset loading/saving
- UI repaints

**No background thread needed:**
- No file I/O
- No heavy computation outside audio thread
- LF Newton-Raphson solvers run on audio thread (once per glottal cycle, ~1us each)

**Communication:**
- APVTS parameters: Atomic reads (audio thread) / atomic writes (message thread)
- No custom thread communication needed

## Implementation Risks

### LF Glottal Pulse Model

**Complexity:** HIGH

**Risk Level:** MEDIUM

**Risk factors:**
1. Newton-Raphson solvers for alpha/epsilon must converge reliably across all Rd values (0.3-2.7)
2. PolyBLEP correction at Te discontinuity must be correctly placed relative to phase
3. Numerical stability at extreme Rd values (very small Ra at low Rd, very large Ta at high Rd)
4. Phase accumulator precision at very low F0 (C0 = 16.35 Hz, period = 2669 samples at 44.1k)

**Alternative approaches:**
1. **Simplified LF (no Newton-Raphson):** Use pre-tabulated alpha/epsilon values for 128 Rd steps. Bilinear interpolation. Eliminates solver entirely.
2. **Pre-computed wavetable bank:** 128 Rd x 2048 samples, mipmapped. Zero per-sample computation, only table lookup. Higher memory (~1MB).
3. **Basic saw/pulse morphing:** Not LF model at all -- simple morphable oscillator. Much simpler but loses vocal character.

**Fallback architecture:**
- **Primary:** Direct LF computation with PolyBLEP
- **Fallback 1:** Pre-tabulated solver values (if Newton-Raphson causes clicks or NaN)
- **Fallback 2:** Pre-computed wavetable bank (if real-time LF computation too expensive)
- **Fallback 3:** Simple saw-to-noise morph with spectral tilt filter (last resort)

**Mitigation strategy:**
1. Implement and test LF model in isolation first (offline unit test)
2. Pre-validate solver convergence for all Rd values at build time
3. Add NaN guards: if solver diverges, use previous cycle's parameters
4. Existing reference code in `research/glottal-pulse-modeling-deep-dive.md` provides verified C++ implementation

### Vowel Interpolation

**Complexity:** LOW

**Risk Level:** LOW

**Risk factors:**
1. Shepard interpolation is mathematically simple and well-understood
2. Log-domain frequency interpolation prevents perceptual artifacts

**Fallback:** Linear interpolation (even simpler, slightly less smooth)

### Consonant Noise System

**Complexity:** MEDIUM

**Risk Level:** LOW

**Risk factors:**
1. Plosive burst timing must feel natural (too long = muddy, too short = clicky)
2. Crossfade between burst and ADSR attack must be seamless
3. Sibilance peak at very high Q can ring or become unstable

**Alternative approaches:**
1. **Simpler noise mix:** Just white noise with level control, no tone/sibilance shaping. Covers 80% of use case.
2. **No plosive burst:** Remove autoConsonant feature, simplify to continuous noise only.

**Fallback architecture:**
- **Primary:** Full KLATT-style dual branch with tone/sibilance/burst
- **Fallback 1:** Simple filtered noise mix (if burst/crossfade proves problematic)

### MPE Integration

**Complexity:** LOW

**Risk Level:** LOW

**Risk factors:**
1. `juce::MPESynthesiser` handles all MPE protocol details
2. Per-voice callbacks (`notePressureChanged`, `noteTimbreChanged`) are well-documented
3. `enableLegacyMode()` provides standard MIDI fallback

**No fallback needed** -- JUCE MPE support is mature and well-tested.

### Overall Project Risk

**Overall complexity:** MEDIUM-HIGH
- Novel DSP (LF model) is highest complexity, but well-researched with reference implementations
- Everything else (filters, envelopes, interpolation, MPE) uses standard patterns

**Highest risk component:** LF Glottal Pulse Model
- Represents ~40% of project risk
- Most algorithmically complex (Newton-Raphson solvers, PolyBLEP)
- No JUCE class (fully custom implementation)
- Multiple fallback options documented

**Recommended approach:**
1. Stage 2 Phase 1: Implement basic sine oscillator + formant bank + ADSR (validate architecture)
2. Stage 2 Phase 2: Replace sine with LF glottal model (highest risk component)
3. Stage 2 Phase 3: Add consonant system + vibrato + MPE modulation (incremental features)

## Architecture Decisions

### Voice Framework: MPESynthesiser (not basic Synthesiser)

**Decision:** Use `juce::MPESynthesiser` + `juce::MPESynthesiserVoice`

**Rationale:**
- Built-in MPE support (per-note pitch, pressure, timbre)
- `enableLegacyMode()` for standard MIDI fallback -- zero extra code
- Voice allocation and stealing handled automatically
- `getFrequencyInHertz()` auto-combines note + pitchbend + master bend
- Proven pattern used by O-Prism (wavetable synth) in this codebase

**Alternatives considered:**
1. **Basic `juce::Synthesiser`:** Rejected -- no MPE support, would need manual implementation of per-note expression
2. **Custom voice manager:** Rejected -- unnecessary complexity, MPESynthesiser is well-tested

### Formant Topology: Parallel (not Cascade)

**Decision:** All 5 formant filters process the input in parallel, outputs summed with per-band gain

**Rationale:**
- More musical control: each formant's amplitude is independently adjustable
- Simpler implementation: no filter-ordering dependencies
- Better for creative sound design: can boost/cut individual formants
- Klatt 1980 recommends parallel branch for consonants; using parallel for vowels too simplifies the architecture
- The research (O-Formant-deep-research.md) recommends parallel for v1

**Alternatives considered:**
1. **Cascade (series) topology:** Rejected for v1 -- natural spectral valleys but no per-formant gain control, more complex coefficient interaction
2. **Hybrid cascade+parallel:** Rejected for v1 -- adds complexity without clear benefit at this stage

**Tradeoffs accepted:**
- Parallel topology has weaker inter-formant spectral valleys than cascade -- acceptable for a synthesizer (not speech TTS)
- v2 can add cascade as an option

### Custom Biquad vs JUCE dsp::IIR::Filter

**Decision:** Custom `FormantBiquad` struct for per-voice formant filters; use `juce::dsp::IIR::ArrayCoefficients` only for coefficient computation

**Rationale:**
- 5 filters x 16 voices = 80 filter instances; JUCE `ProcessorState` overhead per instance is wasteful
- Custom struct is 32 bytes (cache-line friendly), processes one sample with 5 multiplies + 4 adds
- Coefficient computation delegates to JUCE (proven math), but state management is custom (minimal overhead)
- Same pattern used in O-Formant-deep-research.md reference code

**Alternatives considered:**
1. **Full `juce::dsp::IIR::Filter`:** Rejected -- ProcessSpec/AudioBlock overhead per voice per filter, designed for block processing not per-sample
2. **`juce::dsp::StateVariableTPTFilter`:** Rejected -- only LP/BP/HP modes natively, not suitable for parallel BPF bank with individual gains

### Anti-Aliasing: PolyBLEP for v1 (not wavetable)

**Decision:** Use PolyBLEP/PolyBLAMP correction on the real-time LF computation for v1

**Rationale:**
- Faster iteration during development (no need to pre-compute wavetable bank)
- Lower memory footprint (no 1MB wavetable)
- Good enough for musical use (~60dB alias rejection)
- Upgrade path to mipmapped wavetable is well-documented for polish phase

**Tradeoffs accepted:**
- Lower alias rejection than mipmapped wavetable (~60dB vs ~90dB)
- At very high pitches (>2kHz), some aliasing artifacts may be audible
- Acceptable because vocal synthesis typically operates below 1kHz fundamental

## Special Considerations

### Thread Safety
- All parameter reads use atomic `getRawParameterValue()->load()` (APVTS guarantees atomic access)
- Filter coefficient updates happen in audio thread (no allocations -- coefficients computed from existing arrays)
- Per-voice state (phase, filter z-states, envelope) is private to each voice -- no sharing
- SmoothedValue instances are per-component, not shared between voices
- `juce::Random` is per-voice (each voice gets its own Random instance to avoid contention)

### Performance
- **Per-voice cost:** ~95-100 FLOPS/sample
  - LF glottal pulse: ~15-20 ops (phase accumulation, piecewise evaluation, PolyBLEP)
  - Aspiration noise: ~5 ops (random, mix)
  - 5 biquad filters: ~50 ops (10 multiplies + 8 adds per filter)
  - Consonant noise: ~15 ops (noise gen, filter, mix)
  - ADSR + smoothing: ~10 ops
- **16 voices at 48kHz:** ~77 MFLOPS = ~1.5% single CPU core
- **32 voices at 48kHz:** ~154 MFLOPS = ~3% single CPU core
- **Block-rate updates (every 32 samples):** Vowel interpolation + coefficient computation amortized
- **Hot path:** Per-sample: glottal eval + 5 biquad processes + ADSR
- **Optimization opportunity:** Skip consonant branch entirely when `consonantLevel == 0`

### Denormal Protection
- Use `juce::ScopedNoDenormals` at the top of `processBlock()`
- Biquad z-states can accumulate denormals after voice release -- `reset()` called in `clearCurrentNote()`
- ADSR returns exactly 0.0 after release completes (no denormal tail)

### Sample Rate Handling
- `prepareToPlay()` sets sample rate on MPESynthesiser via `setCurrentPlaybackSampleRate()`
- Each voice receives sample rate via `setCurrentSampleRate()` (called by MPESynthesiser)
- LF glottal phase increment: `f0 / sampleRate`
- Vibrato LFO phase increment: `vibratoRate / sampleRate`
- Biquad coefficients recomputed with current sample rate (via `ArrayCoefficients::makeBandPass`)
- SmoothedValue reset targets recalculated for new sample rate
- Consonant burst duration (ms) converted to samples using current rate

### Latency
- Zero latency (no lookahead, no oversampling, no FFT)
- Report `setLatencySamples(0)` in `prepareToPlay()`
- No host compensation needed

## Notes

- v1 uses direct LF time-domain computation; upgrade to mipmapped wavetable in polish/v1.1
- No built-in effects (reverb, chorus) for v1 -- deferred to v1.1+
- reverbMix parameter from deep-research doc (section 7.1) is NOT included in parameter-spec-draft.md; keeping 21 params per spec
- Consonant system uses musical parameters (level/tone/sibilance) rather than phoneme-selection for accessibility
- Full MIDI range C0-C8 supported but practical vocal range is C2-C5; extreme ranges are creative sound design territory
- The Fant 1995 Rd regression is approximate; some literature uses refined Gobl 2003/2017 formulations -- the simplified version is sufficient for a musical instrument
