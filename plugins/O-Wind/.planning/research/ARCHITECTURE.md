## Core Components

### 1. Jet Exciter (Breath + Embouchure Model)

- **JUCE Class:** Custom implementation -- no JUCE class for jet excitation physics
- **Purpose:** Convert breath pressure into jet velocity, apply embouchure geometry, generate turbulence noise, and produce the excitation signal that drives the bore waveguide
- **Parameters Affected:** BREATH_PRESSURE, EMBOUCHURE, BREATH_NOISE, VIBRATO_RATE, VIBRATO_DEPTH
- **Configuration:**
  - Breath pressure maps to jet velocity via simplified Bernoulli: `U_j = sqrt(2 * p / rho_0)`, scaled to normalized 0-1 range with nonlinear curve `pressure^1.5`
  - EMBOUCHURE controls jet delay ratio relative to bore delay: range 0.3-0.6 of bore delay length
  - Lower embouchure values = focused/bright (short jet, favors higher registers)
  - Higher embouchure values = spread/dark (long jet, locks onto fundamental)
  - Vibrato applied as pressure modulation (NOT pitch modulation -- authentic flute vibrato)
  - `p_breath(t) = p_0 * (1 + depth * sin(2*pi*f_vib*t))`
  - MIDI velocity maps to attack ramp time: 127 = 5ms, 1 = 30ms
  - Aftertouch / CC2 (Breath) maps to breath pressure in real-time
  - CC74 (MPE Y / Slide) maps to embouchure in real-time
  - Note-off triggers breath pressure release envelope (20-100ms)

### 2. Turbulence Noise Generator

- **JUCE Class:** `juce::Random` for noise source + custom lowpass shaping filter
- **Module:** `juce_core` (Random), custom filter
- **Purpose:** Generate breath noise (turbulence) that scales with jet velocity squared -- defining characteristic of flute tone
- **Parameters Affected:** BREATH_NOISE, BREATH_PRESSURE
- **Configuration:**
  - White noise filtered through 1-pole lowpass with cutoff proportional to jet velocity
  - Amplitude: `noise_gain = k_noise * U_j^2 * BREATH_NOISE` (quadratic scaling -- louder playing = proportionally more noise)
  - Noise injected at embouchure summation point (before jet delay)
  - Default BREATH_NOISE = 0.15 provides subtle breathiness; 1.0 = very breathy/airy
  - Noise spectrum shaped to approximate Kolmogorov -5/3 power law rolloff above cutoff

### 3. Jet Delay Line

- **JUCE Class:** `juce::dsp::DelayLine<float, juce::dsp::DelayLineInterpolationTypes::Lagrange3rd>`
- **Module:** `juce_dsp`
- **Purpose:** Model jet travel time from player's lips to labium (sharp edge). Length relative to bore determines register (fundamental vs overtones)
- **Parameters Affected:** EMBOUCHURE (jet delay ratio)
- **Configuration:**
  - Jet delay length = EMBOUCHURE * bore_delay_length (range 0.3-0.6 of bore delay)
  - Lagrange3rd interpolation chosen because jet delay is modulated in real time for embouchure control
  - JUCE docs confirm: Thiran "is unsuitable for applications requiring fast delay modulation" -- Lagrange3rd "remains amenable to real time delay modulation"
  - Standard ratio ~0.4-0.5 = fundamental register
  - Shortening jet delay (higher pressure, lower embouchure) causes overblowing to octave
  - Maximum delay buffer: accommodate lowest note (C3, ~131 Hz) at 2x oversampled rate = ~672 samples
  - API: `pushSample(0, sample)` / `popSample(0, delayInSamples)` for per-sample feedback loop

### 4. Jet-Labium Nonlinearity

- **JUCE Class:** Direct computation (inline `std::tanh`) or `juce::dsp::LookupTableTransform<float>` if needed
- **Module:** `juce_dsp` (for LookupTableTransform)
- **Purpose:** Model amplitude-limiting interaction where jet hits labium. This is the core nonlinear element that sustains oscillation and shapes waveform
- **Parameters Affected:** REVERSED_JET
- **Configuration:**
  - Primary function: `output = tanh(gain * input)` (Verge/de la Cuadra model)
  - tanh chosen over STK's cubic `x - x^3` for stability (tanh saturates gracefully; cubic can diverge for |x| > 1)
  - Gain factor ~1.0-3.0, tuned per instrument preset
  - REVERSED_JET (0-1): blends between normal tanh and inverted tanh: `output = lerp(tanh(x), -tanh(-x), reversed_jet)` at 0% = normal, 100% = fully inverted phase relationship (creative parameter, not physics)
  - Start with direct `std::tanh` computation (only ~8 ops/sample). Switch to LookupTableTransform only if profiling shows benefit or if jet curve becomes more complex
  - Input range clamped to [-3, 3] for safety
  - This is the component requiring 2x oversampling (nonlinear saturation generates harmonics that alias)

### 5. DC Blocker

- **JUCE Class:** Custom implementation (2 state variables)
- **Purpose:** Remove DC offset accumulated by jet nonlinearity and feedback loop
- **Parameters Affected:** None (always active)
- **Configuration:**
  - Standard formula: `y[n] = x[n] - x[n-1] + 0.995 * y[n-1]`
  - Pole at 0.995 = ~7 Hz cutoff at 44.1 kHz (inaudible, prevents DC accumulation)
  - State: `float x_prev = 0.0f, y_prev = 0.0f` per voice
  - Placed immediately after jet nonlinearity, before bore injection
  - Not available from JUCE's IIR::ArrayCoefficients factory methods -- trivial custom inline filter

### 6. Bore Waveguide (Bidirectional Delay Lines)

- **JUCE Class:** `juce::dsp::DelayLine<float, juce::dsp::DelayLineInterpolationTypes::Thiran>` (x2: forward and backward)
- **Module:** `juce_dsp`
- **Purpose:** Model wave propagation in the flute bore. This IS the resonator AND body -- no separate body resonator needed (unlike O-Bowed)
- **Parameters Affected:** MIDI note (pitch), TONE_COLOR, AIR_COLUMN, END_REFLECTION, INFINITE_SUSTAIN
- **Configuration:**
  - Two delay lines: forward-traveling wave (p+) and backward-traveling wave (p-)
  - Total round-trip delay: `L = oversampled_sampleRate / f0` samples
  - Split into forward (L/2) and backward (L/2) halves
  - Thiran allpass interpolation for fractional delay (flat amplitude response -- critical for bore resonance accuracy)
  - Bore pitch changes discretely on fingering changes (MIDI note), not continuously (unlike string instruments)
  - Thiran statefulness is acceptable because bore length changes discretely, not via continuous modulation
  - Maximum delay buffer: accommodate lowest note (~C3 at 131 Hz) at 2x oversampled rate = ~672 samples
  - API: `pushSample(0, sample)` / `popSample(0, delayInSamples)` per sample
  - Concert flute range: C4 (262 Hz) to C7 (2093 Hz); shakuhachi: D4 to ~A6

### 7. Bore Loss Filter (Viscothermal + Tone Color)

- **JUCE Class:** `juce::dsp::IIR::Filter<float>` with custom coefficients
- **Module:** `juce_dsp`
- **Purpose:** Model frequency-dependent energy loss from viscous friction and thermal conduction at bore walls. Combined with tone color control
- **Parameters Affected:** AIR_COLUMN, TONE_COLOR, INFINITE_SUSTAIN
- **Configuration:**
  - Single two-pole lowpass combining viscothermal loss + tone color shaping
  - AIR_COLUMN (0-1) controls loss amount: 0 = bright (minimal HF loss), 1 = warm (heavy HF loss)
  - TONE_COLOR (0-1) maps to cutoff frequency: 1000-12000 Hz (log scale)
  - Physical basis: attenuation scales as sqrt(frequency) -- gentle HF rolloff
  - Coefficients calculated via `juce::dsp::IIR::ArrayCoefficients<float>::makeLowPass(sampleRate, cutoff, Q)`
  - Q = 0.7071 (Butterworth) modulated by AIR_COLUMN
  - INFINITE_SUSTAIN (0-1): Reduces overall loss toward zero (gain approaches 1.0), enabling drone-like infinite decay
  - Coefficients recalculated on parameter change (not per-sample)
  - Placed inside waveguide loop (processes traveling waves each round trip)

### 8. End Reflection Filter

- **JUCE Class:** `juce::dsp::IIR::Filter<float>` with custom coefficients
- **Module:** `juce_dsp`
- **Purpose:** Model frequency-dependent reflection at the open end of the bore. High frequencies radiate more, low frequencies reflect back
- **Parameters Affected:** END_REFLECTION
- **Configuration:**
  - Open-open bore: reflection magnitude |R| ~ 1 at low frequencies, decreasing toward 0 at high frequencies
  - Implemented as first-order lowpass with sign inversion (open end = pressure node)
  - END_REFLECTION (-1 to 1, default 0.5): scales reflection coefficient magnitude
  - Positive values = normal physics (energy returns to bore, sustains oscillation)
  - Negative values = inverted reflection (creative territory)
  - Higher |END_REFLECTION| = more sustain, stronger resonance
  - `juce::dsp::IIR::ArrayCoefficients<float>::makeFirstOrderLowPass(sampleRate, cutoff)` with cutoff ~2000-5000 Hz depending on bore geometry
  - Output multiplied by sign-inverted END_REFLECTION coefficient
  - Feeds back into bore waveguide (backward traveling wave) to complete feedback loop

### 9. Radiation Filter

- **JUCE Class:** `juce::dsp::IIR::Filter<float>` with custom coefficients
- **Module:** `juce_dsp`
- **Purpose:** Model radiation impedance at the open end. The radiated sound (plugin output) is high-pass filtered -- flutes radiate higher harmonics more efficiently
- **Parameters Affected:** None (fixed per instrument preset)
- **Configuration:**
  - First-order highpass: `H_rad(z) = 1 + R(z)` (complementary to reflection filter)
  - `juce::dsp::IIR::ArrayCoefficients<float>::makeFirstOrderHighPass(sampleRate, freq)`
  - Cutoff ~200-500 Hz depending on instrument type
  - Concert flute: ~300 Hz (bright radiation)
  - Shakuhachi: ~200 Hz (more fundamental present)
  - Taps output from forward-traveling wave at bore end, post-reflection
  - This is the per-voice mono output before mixing and stereo processing

### 10. Tone Hole System (Two-Tier)

- **JUCE Class:** Custom implementation with `juce::dsp::IIR::Filter<float>` for Tier 2
- **Module:** `juce_dsp`
- **Purpose:** Control pitch by changing effective bore length via tone hole open/close states
- **Parameters Affected:** MIDI note number (determines fingering)
- **Configuration:**

  **Tier 1 (Default -- Bore Length Switching):**
  - MIDI note -> lookup table -> effective bore delay length
  - Fingering table: maps each MIDI note to a single bore delay value
  - On note change: crossfade bore delay length over 2-5ms using `juce::SmoothedValue`
  - No per-hole modeling -- tone holes abstracted as bore length changes
  - Computationally free (just a delay length change)
  - Produces correct pitches but lacks half-holing and cross-fingering effects

  **Tier 2 (Enhancement -- Keefe 3-Port Scattering Junctions):**
  - 6-8 tone hole junctions inline with bore waveguide
  - Each junction: second-order IIR filters for open and closed states
  - Open-hole reflectance: `juce::dsp::IIR::ArrayCoefficients<float>::makeLowPass(sampleRate, freq, Q)`
  - Closed-hole transmittance: `juce::dsp::IIR::ArrayCoefficients<float>::makeHighPass(sampleRate, freq, Q)`
  - Scattering coefficients: `R = (Z_hole - Z_bore) / (Z_hole + Z_bore)`
  - Half-holing: continuous parameter (0=closed, 1=open) sweeps impedance
  - Cross-fingering: enables alternate fingerings with different timbres for same pitch
  - CPU: ~8 ops per junction = ~48-64 ops total for 6-8 holes
  - Implement as optional enhancement after Tier 1 validates

### 11. 2x Internal Oversampling

- **JUCE Class:** `juce::dsp::Oversampling<float>`
- **Module:** `juce_dsp`
- **Purpose:** Reduce aliasing from jet nonlinearity (tanh saturation generates harmonics)
- **Parameters Affected:** None (always active)
- **Configuration:**
  - 2x oversampling with polyphase halfband filter
  - Oversampled section: jet nonlinearity + bore waveguide loop (coupled via feedback, must run at same rate)
  - Latency: reported via `getLatencyInSamples()` and passed to `setLatencySamples()` in `prepareToPlay()`
  - NOTE: Brief says "0 samples algorithmic latency" -- this refers to the causal waveguide model. Oversampling introduces minimal latency (~8 samples for 2x polyphase) which is acceptable and reported to host
  - All delay lengths calculated at oversampled rate: `internalSampleRate = sampleRate * 2`
  - Process per-voice (each voice has its own oversampling context)

### 12. Stereo Width Processor

- **JUCE Class:** Custom implementation (mid-side encoding) -- shared pattern with O-Bowed
- **Purpose:** Generate stereo spread from mono waveguide output
- **Parameters Affected:** WIDTH
- **Configuration:**
  - Mono waveguide output decorrelated via slight per-voice delay offset or allpass filter
  - WIDTH parameter (0.0-2.0):
    - 0.0 = mono
    - 1.0 = natural stereo (slight decorrelation)
    - 2.0 = wide (exaggerated stereo, side boosted)
  - Mid-side matrix: `M = (L + R) / 2, S = (L - R) / 2`
  - `L_out = M + S * widthFactor, R_out = M - S * widthFactor`
  - Applied post-voice-summation (operates on mixed output, not per-voice)

### 13. Sub-Harmonics Generator

- **JUCE Class:** Custom implementation (nonlinear feedback injection)
- **Purpose:** Generate sub-octave content for "impossible physics" creative sound design
- **Parameters Affected:** SUB_HARMONICS
- **Configuration:**
  - Frequency-halving circuit: asymmetric clipping in feedback path
  - Injects sub-octave energy into waveguide at half the fundamental frequency
  - SUB_HARMONICS (0-1): controls injection level (0 = bypassed, 1 = prominent sub-octave)
  - Applied inside waveguide loop (pre-radiation filter)
  - Same pattern as O-Bowed sub-harmonics generator

### 14. Microtonal Tuning System

- **JUCE Class:** Shared module at `modules/tuning/scala-tuning-engine`
- **Module:** Custom (pre-existing shared module)
- **Purpose:** Support Scala/TUN import, MTS-ESP, and standard 12TET tuning
- **Parameters Affected:** (Internal -- reference pitch and tuning system are preset-level, not APVTS)
- **Configuration:**
  - TuningEngine pointer passed to each voice (same pattern as O-Bowed, O-Prism, O-Lyrica)
  - MIDI note -> frequency via `tuningEngine.getFrequency(noteNumber)` -> bore delay length
  - Default: 12TET at A4 = 440 Hz
  - Scala file loading on message thread, tuning table passed to audio thread atomically

## Processing Chain

```
MIDI/MPE Input
     |
     v
[Voice Allocation] (juce::Synthesiser, 8 max voices, 4 default)
     |
     v
PER VOICE:
     |
[Breath Envelope] <-- Velocity (attack ramp), BREATH_PRESSURE, CC2/Aftertouch
     |
     v
[Bernoulli: jet velocity] = sqrt(2 * pressure / rho)
     |
     v
[Turbulence Noise] = noise * U_j^2 * BREATH_NOISE
     |
     +--[Vibrato LFO] --> modulates breath pressure
     |        ^-- VIBRATO_RATE, VIBRATO_DEPTH, CC1
     |
     v
[Embouchure Summation] <---- bore_feedback * JET_REFLECTION (from previous sample)
     |
     |   +------ [2x Oversampling Upsample] ------+
     |   |                                          |
     v   v                                          |
[Jet Delay Line] (Lagrange3rd, length = EMBOUCHURE * bore_delay)
     |                                              |
     v                                              |
[Jet-Labium Nonlinearity] (tanh saturation)         |
     |        ^-- REVERSED_JET blends normal/inverted
     |                                              |
     v                                              |
[DC Blocker] (y[n] = x[n] - x[n-1] + 0.995*y[n-1])
     |                                              |
     v                                              |
[Bore Waveguide] (Thiran, bidirectional)            |
     |    |                                         |
     |    +---> [Tone Holes] (Tier 1: bore length switch, Tier 2: scattering)
     |                                              |
     v                                              |
[Bore Loss Filter] <-- TONE_COLOR, AIR_COLUMN, INFINITE_SUSTAIN
     |                                              |
     v                                              |
[End Reflection Filter] <-- END_REFLECTION          |
     |                                              |
     +-----> feedback to Embouchure Summation       |
     |                                              |
     |   +------ [2x Oversampling Downsample] -----+
     |
     v
[Radiation Filter] (highpass, models open-end radiation)
     |
     v
[Sub-Harmonics] (if SUB_HARMONICS > 0) <-- inside waveguide loop
     |
     v
Per-Voice Mono Output

AFTER VOICE SUMMATION:
     |
     v
[Output Level] <-- OUTPUT_LEVEL parameter (dB)
     |
     v
[Stereo Width] <-- WIDTH parameter
     |
     v
Output (L, R)
```

**Routing notes:**
- Jet delay, jet nonlinearity, DC blocker, bore waveguide, bore loss, end reflection all run at 2x internal sample rate
- Radiation filter runs at 2x rate (inside oversampled section for simplicity)
- Stereo width is post-voice-summation (not per-voice)
- Output level applied after voice summation, before stereo width
- Feedback loop: bore end -> end reflection filter -> scaled by JET_REFLECTION -> back to embouchure summation (uses previous sample -- no implicit equation)
- Sub-harmonics injection inside waveguide loop (pre-radiation)
- Infinite sustain modifies bore loss filter gain (inside waveguide loop)
- No separate body resonator (bore IS the body -- key simplification vs O-Bowed)

## System Architecture

### MIDI Routing

**Input handling:** MPE-aware (per-note expression) with legacy MIDI CC fallback

**Note mapping:**
- MIDI note number determines bore delay length: `f0 = tuningEngine.getFrequency(noteNumber)`, `delay = internalSampleRate / f0`
- Velocity maps to breath attack ramp time: 127 = 5ms (sharp tongued attack), 1 = 30ms (gentle entry)
- Channel handling: MPE mode (per-note channel) or legacy omni mode

**MPE Dimensions:**

| MPE Dimension | Target Parameter | Range |
|---------------|-----------------|-------|
| Note velocity | Breath attack ramp time | 1-127 -> 30ms-5ms |
| Aftertouch (Z) | Breath pressure | 0-127 -> 0.0-1.0 |
| Slide (Y / CC74) | Embouchure | 0-127 -> 0.0-1.0 |
| Pitch bend (X) | Bore delay length modulation | +/- configurable semitones |

**Legacy CC Mapping:**

| CC | Target | Description |
|----|--------|-------------|
| CC1 | Vibrato depth | Mod wheel |
| CC2 | Breath pressure | Primary wind controller dynamics |
| CC11 | Output level | Expression |
| CC74 | Embouchure | Brightness / MPE Y fallback |

**JUCE classes:**
- `juce::MidiBuffer` -- MIDI event iteration in processBlock
- `juce::MidiMessage` -- individual message parsing
- `juce::Synthesiser` + `juce::SynthesiserVoice` -- voice allocation with MIDI routing
- Optional: `juce::MPESynthesiser` + `juce::MPESynthesiserVoice` for full MPE (evaluate during implementation -- standard Synthesiser may suffice with manual CC74/Aftertouch handling)

**Processing:**
- MIDI messages processed in `processBlock()` on audio thread
- Note-on: allocate voice, configure bore delay from note, start breath attack ramp
- Note-off: start breath release envelope (ramp pressure to 0 over 20-100ms)
- CC2/Aftertouch: update breath pressure per-voice in real-time via atomic reads
- CC74/Slide: update embouchure per-voice
- Pitch bend: smooth portamento via bore delay interpolation (SmoothedValue)

### State Persistence

**What state is saved:**
- APVTS parameters: All 13 automatable parameters (automatic via APVTS)
- Custom state:
  - Current instrument preset selection (concert flute, shakuhachi, bansuri, etc.)
  - Tone hole tier selection (Tier 1 / Tier 2)
  - Scala/TUN file path (if tuning system = Scala)

**Serialization format:**
- APVTS parameters: Automatic via `AudioProcessorValueTreeState`
- Custom state: `juce::ValueTree` with XML serialization

**JUCE classes:**
- `juce::AudioProcessorValueTreeState` -- parameter persistence (automatic)
- `juce::ValueTree` -- custom state tree
- `juce::File` -- Scala/TUN file path storage

**Save/restore methods:**
- `getStateInformation(MemoryBlock& destData)` -- serialize APVTS + custom ValueTree
- `setStateInformation(const void* data, int sizeInBytes)` -- deserialize and restore

**Restore behavior:**
- Missing Scala file: fall back to 12TET, show warning in UI
- Invalid state data: use defaults (all parameters at default values)
- Version migration: future-proofed via ValueTree versioning

## Algorithm Details

### Jet-Drive Model (Core Excitation)

**Algorithm:** Simplified Verge/de la Cuadra jet-drive with tanh saturation

**Implementation notes:**
- Breath pressure -> Bernoulli jet velocity: `U_j = normalized_pressure ^ 1.5` (perceptual nonlinear curve)
- Turbulence noise: `noise_out = random() * lowpass_filter(U_j^2 * breath_noise_gain)`
- Embouchure summation: `excitation = U_j + noise_out + bore_feedback * jet_reflection`
- Jet delay: `jet_out = jetDelayLine.popSample(0, embouchure * bore_delay_length)`
- Jet nonlinearity: `labium_out = tanh(jet_gain * jet_out)` (gain ~1.0-3.0 per preset)
- DC blocker: `y = x - x_prev + 0.995 * y_prev`
- This is a one-directional exciter (reads bore output from PREVIOUS sample, injects new energy)
- No circular dependency, no iterative solver needed (key simplification vs O-Bowed friction junction)

### Bore Waveguide Loop

**Algorithm:** Bidirectional digital waveguide with Thiran fractional delay

**Implementation notes:**
- Forward wave: `p_plus[n] = bore_fwd.popSample(0, half_delay)`
- Backward wave: `p_minus[n] = bore_bwd.popSample(0, half_delay)`
- Bore input (from excitation): injected into forward wave at embouchure end
- Bore output (at open end): forward wave tapped for radiation + reflection
- End reflection: `reflected = end_reflection_filter.processSample(p_plus_end) * -end_refl_coeff` (negative for open-end pressure node)
- Reflected wave fed back into backward delay line
- Bore loss filter applied per round trip (inside loop)
- Infinite sustain: loss filter gain approaches 1.0 as parameter increases (reduces per-cycle damping)

### Overblowing Mechanism

**Algorithm:** Physics-based register transition via jet-to-bore delay ratio

**Implementation notes:**
- At standard jet ratio (~0.4-0.5 of bore delay): fundamental register speaks
- Shortening jet delay (via EMBOUCHURE parameter decrease or breath pressure increase): system jumps to 2nd harmonic (octave)
- Further shortening: 3rd harmonic (octave + fifth)
- Phase balance condition: `arg(Y) + pi/2 - omega * tau = 2m*pi` (m = mode number)
- Hysteresis: use SmoothedValue on embouchure parameter to prevent abrupt register jumps
- Regime change is natural property of the feedback loop -- no explicit mode-switching logic needed
- The jet nonlinearity (tanh) provides natural amplitude limiting during register transitions

### Tone Hole Bore Length Switching (Tier 1)

**Algorithm:** Lookup table mapping MIDI note to effective bore delay length with crossfade

**Implementation notes:**
- Fingering table: `std::array<float, 128>` mapping each MIDI note to bore delay in samples
- Pre-calculated at prepareToPlay for current sample rate
- On note change: `juce::SmoothedValue` ramps bore delay length over 2-5ms
- Crossfade prevents clicks during pitch transitions
- For legato: maintain jet oscillation during crossfade (no re-attack)
- For tongued articulation: brief breath pressure dip (10-30ms) during transition

### Instrument Preset System

**Algorithm:** Parameter-set switching for different flute types

**Implementation notes:**
- Each instrument preset defines a set of internal (non-exposed) parameters:
  - Bore diameter, jet gain, noise spectrum shape, radiation filter cutoff, loss filter characteristics
  - Jet delay ratio range, overblowing ease, default embouchure sensitivity
- Preset table (reference data from acoustic research):

| Preset | Bore Type | Jet Gain | Noise Level | Radiation Cutoff | Character |
|--------|-----------|----------|-------------|-----------------|-----------|
| Concert Flute | Cylindrical 19mm | 2.0 | Moderate | 300 Hz | Clear, bright, projecting |
| Shakuhachi | Conical+flare 20mm | 1.5 | High | 200 Hz | Breathy, expressive, meri/kari |
| Bansuri | Cylindrical 18mm | 1.8 | Moderate-High | 250 Hz | Warm, airy, meend capable |
| Native American | Dual-chamber 22mm | 1.3 | Moderate | 180 Hz | Warm, haunting, overblows easily |
| Recorder | Cylindrical 13mm (fipple) | 2.5 | Low | 400 Hz | Bright, fixed embouchure |
| Pan Flute | Cylindrical 10-20mm | 1.0 | High | 350 Hz | Breathy, individual pipes |

- Preset changes apply immediately (coefficient swap, no crossfade needed for internal parameters)
- User-facing parameters (BREATH_PRESSURE, EMBOUCHURE, etc.) remain independent of preset

## Integration Points

### Feature Dependencies

- **Jet Exciter -> Jet Delay -> Jet Nonlinearity -> DC Blocker -> Bore Waveguide:** Strict sequential per-sample chain
- **Bore Waveguide -> End Reflection -> Feedback to Embouchure:** Feedback loop (uses previous sample's bore output)
- **Bore Waveguide -> Radiation Filter -> Output:** Parallel path (taps output while feeding back)
- **Tone Holes <-> Bore Waveguide:** Tier 1 modifies bore delay length; Tier 2 inserts scattering junctions inline
- **Vibrato LFO -> Breath Pressure:** Modulates excitation, NOT bore length (authentic flute vibrato)
- **Oversampling wraps entire per-voice waveguide loop:** Jet + bore + feedback all at 2x
- **Tuning System -> Bore Waveguide:** Provides frequency for delay length calculation
- **Turbulence Noise -> Embouchure Summation:** Additive mix before jet delay

### Parameter Interactions

- **BREATH_PRESSURE + EMBOUCHURE:** Together determine which register speaks. High pressure + low embouchure = octave overblow. Moderate pressure + moderate embouchure = fundamental. This is the primary expressive axis.
- **BREATH_PRESSURE + BREATH_NOISE:** Noise scales with U_j^2, so louder playing is automatically breathier. BREATH_NOISE parameter is a gain multiplier on top of this physics-based scaling.
- **JET_REFLECTION + END_REFLECTION:** Both control sustain character. JET_REFLECTION controls how much bore energy feeds back to excite the jet. END_REFLECTION controls how much energy returns into the bore. Both near 0 = very short decay. Both near 1 = long, resonant sustain.
- **INFINITE_SUSTAIN + bore loss filter:** Directly reduces per-cycle loss. At 100%, bore ringing never decays (drone mode). Interacts with END_REFLECTION -- high sustain + high reflection = infinite sustain.
- **TONE_COLOR + AIR_COLUMN:** Both affect the bore loss filter. TONE_COLOR sets cutoff frequency; AIR_COLUMN sets rolloff steepness. Bright + low air column = full spectrum. Dark + high air column = muffled, woody.
- **REVERSED_JET + normal jet:** Crossfade between normal and inverted tanh. At 50%, jet nonlinearity is flattened (neither normal nor inverted), producing unusual timbres with reduced sustain.

### Processing Order Requirements

**Sequential processing order per voice (REQUIRED):**

1. **Read MIDI/MPE input:** Parse note events, CC changes, pitch bend, aftertouch
2. **Update breath model:** Calculate breath pressure from envelope + CC2 + aftertouch + vibrato
3. **Calculate jet velocity:** Bernoulli conversion from breath pressure
4. **Generate turbulence noise:** Scale by U_j^2, filter, scale by BREATH_NOISE
5. **Read bore feedback:** Get bore output from PREVIOUS sample (stored in variable)
6. **Embouchure summation:** jet_velocity + noise + (bore_feedback * jet_reflection)
7. **Upsample to 2x** (juce::dsp::Oversampling)
8. **For each oversample (2 iterations per output sample):**
   a. Push excitation into jet delay line
   b. Pop from jet delay line with embouchure-controlled delay
   c. Apply jet nonlinearity (tanh)
   d. Apply DC blocker
   e. Inject into bore waveguide (forward wave)
   f. Advance bore waveguide one sample (both directions)
   g. Apply tone hole processing (Tier 1: just delay length; Tier 2: scattering)
   h. Apply bore loss filter (forward and backward waves)
   i. Apply end reflection filter at bore open end
   j. Store bore output for next sample's feedback (step 5)
   k. If SUB_HARMONICS > 0: inject sub-harmonic content
   l. Tap output via radiation filter
9. **Downsample from 2x** (juce::dsp::Oversampling)
10. **Apply output level** (dB to linear gain)

**Post-voice-summation:**

11. **Sum all voice outputs** (juce::Synthesiser handles this)
12. **Apply stereo width** (mid-side processing)
13. **Write to output buffer**

**Why order matters:**
- Jet delay MUST process before jet nonlinearity (temporal causality)
- DC blocker MUST be after jet nonlinearity (removes DC from saturation)
- Bore feedback uses PREVIOUS sample's output (breaks circular dependency without solver)
- End reflection MUST be after bore propagation (feeds reflected wave back)
- Radiation filter taps output parallel to reflection (not in series)
- Oversampling MUST wrap the entire nonlinear feedback loop (partial oversampling causes aliasing at loop boundary)
- Stereo width MUST be last (operates on final summed signal)

### Thread Boundaries

**Audio thread:**
- All DSP processing (jet, bore, filters, noise, width)
- Parameter reads via `APVTS::getRawParameterValue()->load()` (atomic)
- MIDI message processing in `processBlock()`
- Voice allocation via `juce::Synthesiser`
- Sample-by-sample processing within each voice

**Message thread:**
- Parameter updates from UI via APVTS (atomic writes)
- Preset loading/saving (instrument preset selection)
- UI repaints
- Scala/TUN file loading (parse file, build tuning table)
- Trigger tuning table swap to audio thread via atomic pointer

**Communication:**
- APVTS parameters: atomic reads (audio thread) / atomic writes (message thread)
- Tuning table: atomic pointer swap (message thread builds table, audio thread reads)
- Instrument preset selection: atomic int (message thread writes, audio thread reads and updates internal coefficients)
- Tone hole tier selection: atomic int
- No mutexes on audio thread -- all communication lock-free

## Implementation Risks

### Jet-Labium Oscillation Startup

**Complexity:** MEDIUM

**Risk Level:** LOW

**Risk factors:**
1. Model may fail to self-oscillate with certain parameter combinations
2. Initial transient may be harsh or "pop" at note onset
3. Edge cases with very low breath pressure may produce no sound

**Alternative approaches:**
1. **Noise burst seeding:** Inject brief broadband noise burst at note-on to kick-start oscillation (STK approach)
2. **Pre-loaded waveguide state:** Initialize bore with one cycle of expected waveform

**Fallback architecture:**
- Primary: Breath pressure + noise provides continuous excitation (more forgiving than bowed string)
- Fallback: If oscillation fails to start, inject 1ms noise burst at note-on

**Mitigation strategy:**
1. Breath input provides continuous energy -- unlike bowed string, any nonzero pressure + feedback will produce oscillation
2. BREATH_NOISE at default 0.15 provides natural seeding noise
3. STK flute model has been stable for 30+ years with similar architecture
4. Clamp all signals to prevent NaN propagation

### Overblowing Instability / Register Jumps

**Complexity:** MEDIUM

**Risk Level:** MEDIUM

**Risk factors:**
1. Incorrect jet delay ratio can cause unpredictable register jumping
2. Rapid embouchure changes may cause transient multiphonic states
3. Different instrument presets may have different stable regions

**Alternative approaches:**
1. **Constrained embouchure range:** Limit EMBOUCHURE parameter to values producing stable results per preset
2. **Hysteresis tracking:** Once model locks onto a register, resist small perturbations
3. **Explicit register forcing:** Use pitch detection to force jet delay ratio to nearest stable mode

**Fallback architecture:**
- Primary: Physics-based register transition (natural, musical)
- Fallback 1: If registers are unstable, add stronger hysteresis (resist mode changes)
- Fallback 2: If still unstable, constrain embouchure range per instrument preset

**Mitigation strategy:**
1. SmoothedValue on embouchure parameter prevents abrupt ratio changes
2. Test across full MIDI range for each instrument preset
3. Document stable embouchure ranges per preset for UI guidance

### Tone Hole Click Artifacts (Tier 1)

**Complexity:** LOW

**Risk Level:** LOW

**Risk factors:**
1. Discrete bore delay length changes cause discontinuities
2. Fast trills (rapid note alternation) are worst case for clicks

**Alternative approaches:**
1. **Longer crossfade:** 5-10ms instead of 2-5ms (more click-free but less responsive)
2. **Dual read pointer:** Cross-fade between two bore read positions

**Fallback architecture:**
- Primary: SmoothedValue crossfade over 2-5ms
- Fallback: Increase crossfade to 10ms if clicks persist

**Mitigation strategy:**
1. SmoothedValue with 2-5ms ramp time is proven pattern (used in O-Bowed portamento)
2. Test with fast trills (32nd notes at 120 BPM) as worst case
3. Click prevention is well-understood -- same technique used across all waveguide plugins

### Tone Hole Scattering Junctions (Tier 2)

**Complexity:** HIGH

**Risk Level:** MEDIUM

**Risk factors:**
1. 6-8 scattering junctions inline with bore adds significant per-voice computation
2. Filter stability during rapid open/close transitions
3. Keefe impedance model requires careful coefficient derivation per instrument
4. Half-holing interpolation between open and closed filter states may produce unstable intermediate coefficients

**Alternative approaches:**
1. **Fewer holes:** Model only 4-5 most important holes instead of full 6-8
2. **Simplified junction:** Single-multiply loaded junction (Smith & Scavone 1997) instead of full Keefe model
3. **Stay on Tier 1:** Bore-length-switching produces correct pitches; Tier 2 adds realism but is not essential

**Fallback architecture:**
- Primary: Full Keefe 3-port scattering (6-8 junctions with 2nd-order IIR filters)
- Fallback 1: Simplified loaded junction (1 multiply + 1 filter per hole)
- Fallback 2: Remain on Tier 1 (bore length switching) -- still a complete, playable instrument

**Mitigation strategy:**
1. Implement Tier 1 first, validate complete instrument playability
2. Add Tier 2 as enhancement only after Tier 1 is solid
3. Recalculate coefficients from interpolated parameters (freq/Q) rather than raw coefficient lerp (O-Bowed lesson)
4. Test stability with rapid multi-hole transitions

### Sub-Harmonics Generator

**Complexity:** MEDIUM

**Risk Level:** LOW

**Risk factors:**
1. Nonlinear feedback injection can destabilize waveguide loop
2. Sub-octave locking may not work at all pitches

**Fallback architecture:**
- Primary: Asymmetric clipping in feedback path (same as O-Bowed)
- Fallback: Ring modulation with half-frequency oscillator (simpler, more predictable)

### Overall Project Risk

**Overall complexity:** MEDIUM-HIGH
- Simpler than O-Bowed (no iterative solver, no body resonator, one-directional exciter)
- Primary risk: overblowing stability and tone hole Tier 2
- Core model (Tier 1) is LOW risk based on 30+ years of STK/Faust reference implementations

**Highest risk component:** Overblowing Register Stability
- Represents ~40% of project risk
- Natural physics behavior but requires careful parameter range tuning per instrument preset
- Well-documented in literature (Auvray 2012, de la Cuadra 2005) -- solutions exist

**Recommended approach:**
1. Phase 1: Minimal model (jet + bore + reflection + Tier 1 tone holes) -- validate oscillation and pitch
2. Phase 2: Add expression (vibrato, breath noise, oversampling, embouchure dynamics)
3. Phase 3: Add Tier 2 tone holes and impossible physics parameters
4. Phase 4: Instrument preset tuning and polish

## Architecture Decisions

### Decision 1: One-Directional Jet Exciter (No Iterative Solver)

**Decision:** Use a one-directional jet-drive model where the jet reads bore output from the PREVIOUS sample, rather than a simultaneous bidirectional coupling requiring iterative solving

**Rationale:**
- Flute jet physics is inherently one-directional: air jet travels from lips to labium with finite delay
- The jet delay provides natural temporal separation in the feedback loop
- No circular dependency (unlike O-Bowed's bow-string friction junction)
- Eliminates Newton-Raphson solver entirely -- the highest-risk component in O-Bowed
- Perry Cook's STK flute uses this exact approach (30+ years proven)
- CPU savings: ~0 ops for solver vs ~20-40 ops for NR solver

**Alternatives considered:**
1. **Full Verge model with simultaneous coupling:** More physically accurate but requires implicit equation solving. Rejected because the jet delay (minimum several samples) makes simultaneity unnecessary -- the delay IS the physics.
2. **Block-based processing with ProcessorChain:** Rejected because feedback loop requires per-sample computation.

**Tradeoffs accepted:**
- Slightly less accurate jet-bore coupling at very high frequencies where jet delay is < 1 sample
- Acceptable because: this condition only occurs at frequencies above the instrument's normal range

### Decision 2: tanh vs Cubic Polynomial for Jet Nonlinearity

**Decision:** Use `tanh(gain * x)` for the jet-labium nonlinearity

**Rationale:**
- tanh saturates gracefully for all input values (bounded between -1 and +1)
- STK's cubic `x - x^3` diverges for |x| > 1, requiring additional clamping
- tanh matches the physical hyperbolic tangent saturation from Verge's model
- Harmonics generated by tanh are more natural for flute timbre
- Direct computation is only ~8 ops (comparable to cubic's 3 ops + clamp)

**Alternatives considered:**
1. **Cubic `x - x^3`:** STK default. Rejected for stability concerns at high gain.
2. **LookupTableTransform:** Would be faster for complex curves but overkill for simple tanh.
3. **Polynomial approximation of tanh:** Faster but less accurate at extremes.

### Decision 3: No Separate Body Resonator

**Decision:** The bore waveguide IS the body. No parallel biquad bank for body resonance (unlike O-Bowed's 8-biquad body resonator)

**Rationale:**
- In flutes, the bore geometry (with tone holes) defines the instrument's formant structure inherently
- The radiation filter and loss filters shape the output spectrum sufficiently
- Adding a body resonator would be redundant and could introduce phase/frequency artifacts
- Major CPU saving: eliminates 8 biquad evaluations per sample per voice
- Instrument-specific character comes from bore parameters (diameter, taper, loss characteristics) not from a separate resonator

**Alternatives considered:**
1. **Parallel biquad bank (O-Bowed style):** Rejected as physically incorrect for flutes. Body IS the bore.
2. **2-3 formant filters for "material" character:** Could add bamboo vs metal coloring. Deferred to post-v1.0 enhancement if needed.

### Decision 4: Pressure Vibrato (Not Pitch Vibrato)

**Decision:** Vibrato modulates breath pressure, not bore length

**Rationale:**
- Real flute vibrato is breath-driven, producing correlated pitch AND amplitude modulation
- Pitch-only vibrato sounds artificial on flute models
- Pressure vibrato naturally produces ~2-5% pitch variation (from jet speed modulation) plus amplitude variation
- This is the approach used by SWAM Flutes and all serious flute models

### Decision 5: Two-Tier Tone Hole Architecture

**Decision:** Implement Tier 1 (bore length switching) as default, with Tier 2 (Keefe scattering) as optional enhancement

**Rationale:**
- Tier 1 produces correct pitches with minimal CPU and zero additional complexity
- Tier 2 adds realism (half-holing, cross-fingering, key click) but is complex and risky
- Tiered approach allows shipping a complete instrument even if Tier 2 proves too complex
- Same tiered strategy proven successful with O-Bowed friction tiers

### Decision 6: Synthesiser vs MPESynthesiser for Voice Management

**Decision:** Start with `juce::Synthesiser` + `juce::SynthesiserVoice` with manual CC74/Aftertouch handling per-voice. Evaluate `juce::MPESynthesiser` during implementation.

**Rationale:**
- Standard Synthesiser is simpler and well-proven across O-Bowed, O-Lyrica, O-Bells, O-Formant
- MPE can be handled manually by routing CC74 and aftertouch to per-voice parameters
- MPESynthesiser has 6 pure virtual methods and different voice lifecycle -- more complex integration
- O-Formant (also MPE) chose standard Synthesiser with manual MPE routing

**Alternatives considered:**
1. **MPESynthesiser:** Full MPE support built-in. More complex API. Would revisit if manual routing proves insufficient.

## Special Considerations

### Thread Safety
- All parameter reads use atomic `getRawParameterValue()->load()`
- Bore loss filter coefficient updates happen on parameter change (not per-sample)
- Instrument preset coefficients stored in struct, swapped via atomic pointer
- Tuning table swapped atomically (message thread builds, audio thread reads)
- No allocations on audio thread
- No mutexes on audio thread

### Performance
- Per-voice CPU (Tier 1, 2x oversampling, 44.1 kHz): ~2.0-2.5% single core
- Per-voice CPU (Tier 2, 2x oversampling, 44.1 kHz): ~2.5-3.5% single core
- 4 voices (default): ~10-14% total
- 8 voices (max): ~20-28% total
- 30-50% cheaper per voice than O-Bowed (no solver, no body resonator)
- ~135 ops/sample/voice at 2x oversampled rate
- Hot path: per-sample waveguide loop (jet delay + nonlinearity + bore read/write + filters)
- SIMD opportunity: pack multiple voices into SSE registers (struct-of-arrays layout)

### Denormal Protection
- Use `juce::ScopedNoDenormals` in processBlock()
- DC blocker prevents DC accumulation (primary denormal source in feedback loops)
- Clamp bore delay line output to prevent subnormal values after many round trips
- All JUCE dsp::IIR::Filter instances handle denormals internally

### Sample Rate Handling
- All delay line lengths recalculated in prepareToPlay() at oversampled rate
- `internalSampleRate = sampleRate * 2` (2x oversampling)
- Bore delay: `internalSampleRate / f0` samples
- Jet delay: `embouchure_ratio * bore_delay` samples
- Loss filter coefficients recalculated at oversampled rate
- Maximum delay buffer sized for lowest note at highest expected sample rate: `2 * 192000 / 65 = ~5900` samples (C2 at 192kHz 2x)
- Vibrato LFO phase increment: `(vibrato_rate * 2 * pi) / sampleRate` (NOT oversampled -- modulates breath, not waveguide)

### Latency
- Algorithmic latency: 0 samples (causal waveguide model, no lookahead)
- Oversampling latency: ~8 samples (2x polyphase halfband) -- reported to host via `setLatencySamples()`
- Total reported latency: oversampling latency only
- NOTE: `getLatencySamples()` is NOT virtual in JUCE 8 -- use `setLatencySamples()` in prepareToPlay()

## Notes

- O-Wind is architecturally simpler than O-Bowed: no iterative solver, no body resonator, one-directional exciter. Core risk is MEDIUM vs O-Bowed's HIGH.
- The bore IS the body -- this eliminates O-Bowed's entire morphable body resonator system (8 biquad parallel bank + coefficient morphing + preset banks). Major simplification.
- Shared modules with O-Bowed: tuning engine, stereo width, MPE routing patterns, parameter smoothing. These are proven patterns.
- Instrument preset differentiation comes from internal parameters (bore diameter, jet gain, noise spectrum, loss characteristics) not from a separate body resonator.
- tanh jet nonlinearity is safer than STK's cubic -- no divergence risk.
- Tone hole Tier 2 is the main complexity premium. Tier 1 is sufficient for a shippable product.
- Performance target of <14% CPU for 4 voices is very achievable given ~135 ops/sample/voice estimate.
- The ethnic flute coverage (shakuhachi, bansuri, Native American) is the primary market differentiator -- no competitor offers dedicated physically-modeled versions of these instruments.
